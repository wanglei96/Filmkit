## 1. GPU / 驱动快照（实测）

| 项 | 实测值 | 对管线的意义 |
|----|--------|--------------|
| GL 版本 | OpenGL ES **3.2**（SL 3.20） | compute / 图像读写可用 |
| 渲染器 | **Mali-G1-Ultra MC12**（vendor ARM），驱动 v1.r54p1-11eac0 | quirk 注册表主键 |
| es31Compute | true | §10 全 GPU 路径成立 |
| extColorBufferHalfFloat | true | RGBA16F FBO 前提成立 |

## 2. 首跑发现的问题（已修复）

| # | 问题 | 根因 | 修复 | 版本 |
|---|------|------|------|------|
| 1 | spike 失败：`S0032: no default precision defined for variable 'uImage'` | GLSL ES 3.1 image uniform **无默认精度**，Mali 强制要求；桌面驱动普遍宽松 | compute shader 显式 `highp image2D`；同时移除 `uSize` 上 ES 3.0 不合法的 `layout(location)` 写法 | 0.1.1-m0 |
| 2 | 日志首行 `ts` 乱码、时区显示 `+01:08`（应为 +08:00） | timestamp 格式符与实参错位（UB） | 格式串重写（显式符号位 + 时/分分离） | 0.1.1-m0 |

**quirk 注册表初始化**（engine 侧 per-device workaround，随 M3 落地）：

- `device.renderer 含 "Mali"` → 无 16F 线性过滤（编译期恒用 NEAREST，无需运行时分支，注册为已知事实）。
- `Mali 驱动对 shader 规范检查严格` → 所有 ES 3.1+ shader 必须显式声明精度（CI golden 编译用 Mali 行为为标准）。

## 3. v0.1.1 复验结果（2026-09-17，M0 验收通过）

spike 三段 pass 全过（`readbackOk=true`），compute 路径启用，GPU 计时器工作正常：

| pass | gpu 中位数 | gpu p90 | cpu 中位数 |
|------|-----------|---------|-----------|
| 1.scene_fill_compute（1024²） | 0.399 ms | 0.416 ms | 0.779 ms |
| 2.transform | 0.291 ms | 0.415 ms | 0.701 ms |
| 3.output | 0.187 ms | 0.264 ms | 0.541 ms |

作为 §3.3 指标表的 X300 列初值。注意 cpu 中位数 > gpu 中位数属预期：M0 的 `GpuTimer::endMs` 内含 `glFinish`（见 GpuTimer.h 约束），M1 改延迟收集后 cpu 数字才有参考意义。

**遗留修复（v0.1.2-m0）**：
1. UI：Tab 被状态栏遮挡（targetSdk 35+ 强制 edge-to-edge 未做 insets 处理）→ 根布局加 `WindowInsets.safeDrawing` 留白。**用户反馈的适配问题，后续所有界面一律经 safeDrawing/sistemBars insets 处理，记入开发规范。**
2. 结果 JSON `useCompute` 误报 false（结构体字段漏初始化，实际 compute 已启用）→ 已修复。
