## 1. 项目定位与目标

### 1.1 目标

| # | 目标 | 验收口径 |
|---|------|----------|
| G1 | RAW 路径：Camera2 `RAW_SENSOR` → 胶片风格成片（JPEG/HEIF），保留 DNG 原片 | 12MP RAW 全链路导出 ≤ 900ms（中端 SoC），高质量档 ≤ 2.5s |
| G2 | YUV 路径：`YUV_420_888` → 实时胶片预览与成片 | 1080p 预览（含胶片模拟 + 效果）≥ 30fps |
| G3 | 解析力：自研去马赛克 + 全链路半精度处理 | ISO12233 测试卡 MTF50 不低于系统相机直出，盲测优于 bilinear 基线 |
| G4 | 胶片模拟内核 + 3D LUT 可嵌套组合 | 嵌套后预览帧率不因 LUT 数量下降（链式 LUT 融合为单一 LUT） |
| G5 | 资产互通：LUT（.cube / Hald PNG）、预设（JSON/zip 包）、整体设置（JSON）导入导出 | 与 Resolve / PS / 手机调色 App 互通 |
| G6 | 全链路结构化日志 + 逐阶段性能计时 + 一键导出诊断包 | 每次成像可复现参数与耗时 |
| G7 | **专项机型适配：vivo X300** 作为 Tier-0 参考机型全链路达标 | RAW 采集/成片正确、200MP tile 导出成功、§3.3 性能表在 X300 实测达标（详见 §9.2） |

### 1.2 非目标（本期不做）

- 不做视频录制胶片化（仅照片；预览实时效果为视频化打基础）。
- ~~不做多帧堆栈~~ → 移入 **Backlog（M6 后评估，见 §0-D12）**。
- 不做 RAW 编辑器（去马赛克结果不回存为可编辑工程，DNG 原片即"底片"）。
- 不承诺逆向某真实胶片品牌配方（预设为风格化近似，命名中性化避免商标风险）。

### 1.3 平台与技术选型（假设与理由）

> 「raw / YUV」对应 Android Camera2 的 `RAW_SENSOR` 与 `YUV_420_888`，**首发平台为 Android**（评审确认：本期仅 Android，iOS 不在范围）。

| 层 | 选型 | 理由 |
|----|------|------|
| UI | Kotlin + Jetpack Compose | 现代声明式 UI，相机预览绑定成熟 |
| 采集 | Camera2 API（不用 CameraX 高层封装，保留对 per-frame 元数据的完全控制） | RAW 管线需要 dynamicBlackLevel、lensShadingMap、noiseProfile 等逐帧元数据 |
| 核心引擎 | **C++20（NDK）+ OpenGL ES 3.1 Compute Shader**，引擎层不依赖 Android 类型 | 性能主战场；GLES 3.1 覆盖率远高于 Vulkan Compute，兼容性优先，Vulkan 后置 |
| 中间格式 | 全链路 half-float（RGBA16F / R16F），仅最终输出量化到 8bit | 位深是解析力与层次的前提（见 §3.4） |
| 色彩工作空间 | 线性 Rec.709/sRGB 原色（可选 Rec.2020 域） | 与 .cube LUT 生态、显示输出兼容 |
| YUV 转换 | GPU shader 直采样平面（备选 libyuv CPU 路径） | 避免 CPU 中转开销 |
| 第三方 | glm、stb_image、libjpeg-turbo、libheif、moodycamel::ConcurrentQueue | 授权干净（BSD/Zlib/MIT）；**不引入 GPL 代码**（darktable/RawTherapee 仅参考论文与算法思路） |

## 2. 总体架构

### 2.1 分层

```
┌─────────────────────────────────────────────────────┐
│ UI 层 (Compose)：取景器 / 参数面板 / 资产管理 / 日志页  │
├─────────────────────────────────────────────────────┤
│ 应用服务层 (Kotlin)：采集会话 / 资产仓库 / 设置 / 日志  │
├─────────────────────────────────────────────────────┤
│ 引擎层 (C++20 + GLSL)  ←  本项目核心                  │
│  ┌──────────┐   ┌──────────────────────────────────┐│
│  │ RawSource │──▶│                                  ││
│  └──────────┘   │   共享后段 FilmRenderer           ││
│  ┌──────────┐   │  白平衡/曝光 → 胶片模拟内核        ││
│  │ YuvSource │──▶│  → 效果层 → LUT 链 → 输出变换     ││
│  └──────────┘   └──────────────────────────────────┘│
├─────────────────────────────────────────────────────┤
│ 平台适配：GL context / AHardwareBuffer / ImageReader  │
└─────────────────────────────────────────────────────┘
```

**关键架构决策：RAW 与 YUV 两条入口管线在「场景线性 RGB」处汇流，共用同一 FilmRenderer。** 两条路径的差异（去马赛克、降噪、位深、白平衡来源）全部收敛在前段 Source 内，后段胶片风格化代码零重复、观感一致。

### 2.2 关键决策记录

| 决策点 | 结论 | 备选与理由 |
|--------|------|-----------|
| GPU API | OpenGL ES 3.1 Compute | Vulkan Compute 更快但碎片化与开发成本高；后置 v2 |
| 去马赛克默认 | 预览用 GPU bilinear/AHD，成片默认 GPU PPG，高质量档 GPU RCD（评审确认：全 GPU，无 CPU 回退） | 见 §3.2/§3.4 |
| LUT 应用位置 | 引擎维护**域感知 LUT**：声明为 display 域的 LUT 插在输出 OETF 之后，scene-linear 域的插在胶片模拟之后 | 绝大多数 .cube 是显示域 LUT，直接放线性域会错色（行业常见坑） |
| 胶片模拟实现 | 参数化分析模型（曲线 + 染料矩阵），支持烘焙为 LUT | 纯 LUT 无法随 ISO/曝光自适应，且无法导出参数 |
| 预设格式 | JSON（schemaVersion 化）+ zip 预设包（内嵌 LUT 与预览图） | 纯 JSON 无法携带 LUT 资产 |
| 日志 | 自研轻量 JSONL 结构化日志（不引入 spdlog） | 需要与性能计时、参数指纹深度集成，自研更可控 |

## 3. RAW 管线重点设计

### 3.1 采集

- 能力探测：`REQUEST_AVAILABLE_CAPABILITIES` 含 `RAW`；无 RAW 设备自动降级 YUV 并在 UI 标注。
- 逐帧元数据（`CaptureResult`）全程随帧流转：`sensor.blackLevelPattern`、`sensor.dynamicBlackLevel`（逐帧）、`sensor.neutralColorPoint`、`sensor.colorTransform1/2`、`sensor.forwardMatrix1/2`、`sensor.calibrationTransform1/2`、`statistics.lensShadingMap`、`sensor.noiseProfile`。
- 原片保存：M2 用系统 `DngCreator` 快速落地；M4 自研 DNG Writer（写入完整色彩矩阵与噪声档案，支持曝光偏置），保证"底片"可被第三方 Raw 冲图软件正确打开。

### 3.2 处理链（质量主线，阶段顺序即依赖顺序）

| # | 阶段 | 内容 | 执行域 |
|---|------|------|--------|
| 0 | 解包 Unpack | 10/12/14bit 传感器流 → 16bit（SIMD/位移），Sensor 16bit 直读 | CPU SIMD → GPU 上传 |
| 1 | 黑阶扣除 | `blackLevelPattern` 分通道 + 逐帧 `dynamicBlackLevel` | GPU（合并进阶段2） |
| 2 | 白平衡 | 线性域分通道增益（as-shot `neutralColorPoint` 或用户色温 CCT 推导） | GPU（合并进阶段1 pass） |
| 3 | 镜头阴影校正 | `lensShadingMap` 网格纹理双线性采样 | GPU（同一 pass） |
| 4 | 高光重建 | G 通道饱和区用 R/B 线性外推恢复色彩，强度可调 | GPU |
| 5 | 去马赛克 Demosaic | 三档：bilinear+中值抗伪彩（预览）/ PPG+AHD 混合（标准）/ RCD 两遍迭代（高质量） | GPU（全 GPU） |
| 6 | 降噪 | 按 `noiseProfile` 自适应启用；demosaic 后 RGB 域引导滤波 + NLM-lite；ISO 与快门联合调参 | GPU |
| 7 | 色彩空间转换 | camera native → XYZ(D50) → Bradford 适应 D65 → 线性 sRGB 工作域（DNG 标准矩阵链）；clip 到工作域原色 | GPU（3×3 矩阵合并） |
| 8 | 曝光/基础影调 | 线性域曝光补偿、黑点抬升 | GPU（合并进阶段7 pass） |
| — | **汇流点：场景线性 RGB** | 以下与 YUV 路径完全共享 | — |
| 9 | 胶片模拟内核 | 见 §5 | GPU |
| 10 | 效果层 | grain / halation / bloom / 暗角 | GPU |
| 11 | LUT 链 | 见 §6 | GPU |
| 12 | 输出变换 | 线性 → sRGB/P3 OETF（胶片曲线已含 tone 时可跳过 filmic 映射）+ 蓝噪声 dither 量化 8bit | GPU |
| 13 | 编码 | JPEG（libjpeg-turbo）/ HEIF / PNG；可选 16bit TIFF（M6） | CPU |

### 3.3 高性能设计（成像速度）

1. **全 GPU 半精度管线**：所有中间结果 RGBA16F 纹理；仅输出量化 8bit。避免任何 CPU 中转往返。
2. **Pass 合并**：阶段 1–3 合并为一个 pass；7–8 合并；10–12 中无依赖的效果尽量合并。目标：12MP 全链路 **≤ 8 个 pass**。
3. **异步流水线**：
   - 预览链：低分辨率（≤1080p）+ 低档去马赛克，30fps；
   - 成片链：全分辨率 + 高质量档，后台队列执行，GL 纹理池复用（杜绝每帧分配）；
   - 参数变更防抖 300ms 后增量刷新成片。
4. **零拷贝/快上传**：YUV 走 SurfaceTexture/AHardwareBuffer 零拷贝；RAW 走 ImageReader + PBO 环形上传。
5. **LUT 融合**（嵌套不降速的关键）：LUT 链在参数提交后由 CPU 用四面体插值链式采样，**烘焙为单个 65³ 3D 纹理**，运行时只做一次 3D 采样；参数再变更则后台重烘焙。GPU 成本与 LUT 数量无关（G4 验收项）。
6. **grain 旁路**：颗粒使用预生成平铺噪声图集（蓝噪声 + 高斯金字塔）+ 随机偏移采样，不逐帧全屏生成噪声。
7. **计时闭环**：`EXT_disjoint_timer_query` 逐 pass 计时 + CPU 段计时，全部进日志（§8），性能回归有据可查。
8. **tile 化导出**：≥ 24MP 时按 tile（如 2048²，带重叠区）处理，控制内存峰值；tile 边界使用扩边保证去马赛克/模糊类效果无缝。

**性能指标（中端机，如 Snapdragon 7s / Dimensity 8200 级）：**

> 出口标准：下表指标以 **vivo X300（天玑 9500，Tier-0 参考机型）** 实测确认为准，中端机数值作为底线。

| 指标 | 目标 | 底线 |
|------|------|------|
| 12MP RAW 标准档全链路 | ≤ 900ms | ≤ 1.5s |
| 12MP RAW 高质量档（RCD） | ≤ 2.5s | ≤ 4s |
| 1080p 预览帧率 | ≥ 30fps | ≥ 24fps |
| 内存峰值（12MP） | ≤ 400MB | ≤ 600MB；tile 后 ≤ 250MB |
| LUT 链加入（≤5 个）后帧率损失 | 0 | ≤ 5% |

### 3.4 高质量设计（解析力与层次）

1. **位深策略**：从传感器位深（≥10bit）到最终 dither 前全程 ≥ half-float，禁止中途 8bit 量化——banding 与解析力损失的主要来源。
2. **去马赛克分级**：
   - 预览档：bilinear + 3×3 中值抗伪彩（GPU，1 pass）；
   - 标准档：PPG（梯度修正）+ AHD 方向插值混合（GPU）；
   - 高质量档：**RCD（Ratio Corrected Demosaic）** 两遍迭代 + 伪彩后抑制——RCD 在高频区边缘恢复显著优于 bilinear/AHD，是"解析力"验收的核心。评审确认**全 GPU 实现**：重点控制 shader 分支发散（比值共用采样、两遍迭代合并 pass），M3 预留 1 周专项调优。
3. **高光重建**：饱和通道用未饱和通道外推（比值法），避免胶片曲线前就丢高光色彩。
4. **色彩流水线符合 DNG 标准**：calibrationTransform → colorTransform（插值 CCT）→ forwardMatrix 路径，保证与 Adobe 冲图观感可比。
5. **四面体插值**：3D LUT 全部使用 tetrahedral 采样（三线性在 33³ 下有明显色差）。
6. **输出 dither**：蓝噪声抖动量化，消除 8bit 输出 banding。
7. **效果域正确**：grain/halation 在显示域叠加（贴近扫描负片观感），胶片曲线在 log/density 域计算（见 §5），不出现"先 gamma 后饱和"式的双重饱和。
8. **量化评价体系**：
   - ColorChecker 24 色：标定模式下平均 ΔE2000 ≤ 3（胶片模式不做此约束）；
   - 20 级灰阶梯：无可见 banding（梯度方差阈值）；
   - ISO12233 卡：MTF50 相对基线不劣化；
   - golden image 回归：固定输入 + 固定参数，SSIM ≥ 0.999。

## 4. YUV 管线设计

- 输入：`YUV_420_888`（shader 直采样 Y 平面 + 交叠/平面 UV），自动识别 BT.601/709 与 limited/full range（取自采集色彩空间元数据），备选 libyuv CPU 路径兜底。
- 线性化：反 OETF 到近似线性域（8bit 源，动态范围有限）→ **汇流进共享 FilmRenderer**。
- 差异补偿：无 demosaic/降噪需求；白平衡信任相机 AWB 结果；因动态范围窄，胶片曲线前加 soft-roll-off 保护高光，负片 toe 适当减弱。
- 定位：预览、连拍、不支持 RAW 的设备成片；后续 P010（10bit HDR YUV）作为 v2 扩展。
- 交付顺序：**YUV 路径先行（M1）**，用低成本路径先把共享后段（胶片内核、LUT、资产系统）跑通，RAW 再接入同一后段。

## 5. 胶片模拟内核（共享核心）

参数化分析模型，全部参数可入预设：

| 组件 | 数学模型 | 说明 |
|------|----------|------|
| 特性曲线 | per-channel density 域 S 曲线：D = f(logE)，slope / toe / shoulder 三参数平滑函数 | 负片：toe 柔和 + 肩部缓压；正片：高反差陡曲线 |
| 染料串扰 | log 域 3×3 矩阵（负片色罩修正） | 负片橙罩/层间串扰的来源，决定"胶片味" |
| 分区色彩 | 阴影/中间调/高光三段独立饱和度与色相偏移 | 按亮度加权 |
| 颗粒 grain | 预生成高斯噪声图集；强度按亮度中间调加权；尺寸 0.5–2px 随 ISO 参数缩放；亮度颗粒 / RGB 颗粒两种模式 | 显示域叠加 |
| 光晕 halation | 红通道高光阈值 → 多级可分离高斯模糊 → 加性复合 | 胶片基底透光特征 |
| 柔光 bloom | 全通道小半径高光柔化 | 正片/夜景风格 |
| 暗角 vignette | 径向乘性衰减 + 可选边缘色偏 | |

- 域选择：曲线与串扰在 log/density 域；颗粒/halation/暗角在显示域。中间转换由内核内部管理。
- **烘焙导出**：整套胶片模型（曲线+矩阵+分区色彩，不含 grain/halation 等空间效果）可烘焙为 .cube LUT 导出，供第三方软件使用（亮点功能，复用 §6 烘焙器）。

## 6. LUT 引擎：嵌套与导入导出

### 6.1 嵌套模型

- LUT 链：`L1 → L2 → … → Ln`，每级节点 = `{LUT 资产, 强度 opacity, 混合模式(normal/linear-light/soft-light), 域标签(scene-linear|display), clip 开关}`。
- **域感知插桩**：display 域 LUT 自动插到输出 OETF 之后，scene-linear 域插在胶片模拟之后——用户导入任意来源 LUT 都不会错域。
- **胶片模拟 × LUT 三种嵌套顺序**（可切换）：`胶片 → LUT`（默认）、`LUT → 胶片`、`胶片烘焙 + LUT 融合为单 LUT`。
- 执行优化：链式融合为单一 65³ LUT（§3.3-5）；节点数 > 5 或 65³ 精度不足时退化为 GPU 链式两级采样（仍单 pass）。

### 6.2 导入 / 导出

| 格式 | 导入 | 导出 | 备注 |
|------|------|------|------|
| .cube（Iridas/Resolve） | ✅ 1D/3D，解析 TITLE/LUT_3D_SIZE/DOMAIN_MIN/MAX | ✅ 3D | 主格式 |
| Hald CLUT PNG | ✅ Level 8/12 自动识别 | ✅ | 与 PS / 手机调色 App 互通 |
| .3dl | ✅（可选，M6） | ❌ | 兼容老工作流 |

- 解析器要求：容错（大小写/空白/CRLF）、尺寸上限 128³、非法文件白名单校验、导入即生成缩略图预览（标准色卡图）。
- 导出选项：源域标签自动写入 .cube 注释（域感知依据）。

## 7. 预设系统与整体设置

### 7.1 预设（Preset）

- 内容 = 胶片模拟全参数 + 效果参数 + LUT 链引用 + 基础影调（曝光/白平衡偏移）。**不含**设备相关项（降噪 ISO 阈值等由引擎自适应）。
- 单文件预设：JSON，带 `schemaVersion`、参数范围声明（版本迁移函数链升级）。
- 预设包（推荐交换格式）：zip = `manifest.json + lut/*.cube + preview.jpg`，扩展名 `.filmkit`（自定义）。
- 内置预设（M4 交付约 10 个，命名中性）：人像负片 400 / 风光反转 50 / 街拍黑白 400 / 高感报道 800T 风格 / 柔焦清新 100 等。
- 导入：单文件 / 批量 / 冲突策略（重命名/覆盖）；导出：单个或打包合集。

### 7.2 整体设置（Settings Backup）

- 范围：相机默认参数、质量档、UI 偏好、预设库索引与哈希、LUT 库索引、日志策略。
- 格式：JSON + `schemaVersion`，导入时逐级迁移；敏感项（路径等）不导出。
- 与预设包共用 zip 打包器；支持"仅设置不含资产"的轻量模式。

## 8. 日志系统与诊断导出

- **分层模块**：`app`（UI 事件）、`engine`（管线事件/错误）、`perf`（逐 pass 耗时）、`io`（文件/导入导出）、`camera`（采集元数据摘要）。
- **格式**：JSONL——`{ts, level, module, event, kv}`；关键 kv：stage 名、耗时 ms、分辨率、参数指纹（预设内容 hash）、设备/传感器信息。
- **存储**：内存环形缓冲（最近 500 条，UI 实时查看）+ 滚动文件（按天 + 大小上限，自动清理）。
- **成像会话摘要**：每次成片生成一条 summary——各阶段耗时、参数指纹、输入类型（RAW/YUV）、分辨率、设备温度/电量（可选），是性能与质量问题的第一现场。
- **诊断包一键导出**：zip = 最近日志 + 当前会话摘要 + 当前预设 + 设备信息 + 可选脱敏缩略图。用户报 bug 一键附上。
- **性能回归**：基准图 + 基准参数跑分脚本，结果写 perf 日志并在 CI 中对比阈值，防退化。

## 10. 技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 设备碎片化：RGBA16F 可渲染/可过滤支持差异、compute 支持参差 | 部分机型走不了 GPU 链 | 评审确认坚持全 GPU：能力探测后两级降级 GPU compute → GPU fragment；低于 GLES 3.1 的机型列为不支持，安装页明示最低要求 |
| RAW 元数据各厂商实现不一致（黑阶/矩阵缺失） | 偏色 | 元数据缺失时回退默认矩阵 + 手动白平衡兜底；问题机型进兼容矩阵 |
| 迭代型去马赛克在 GPU 分支发散 | 性能不达标 | RCD 仅 GPU 实现（评审确认）：减少分支（比值查表、共用采样点）、两遍迭代 pass 合并、tile 并行；M3 预留 1 周专项调优，仍超时则高质量档给出预计耗时提示（2.5–4s） |
| 域错误使用用户 LUT | 整体偏色、口碑受损 | 域感知插桩（§6.1）+ 导入预览强提示 |
| 热节流导致帧率抖动 | 体验不稳 | 预览链分辨率/档位动态降级；基准取多轮中位数 |
| 商标/版权 | 法务风险 | 预设中性命名；不引入 GPL 代码；胶片配方为风格化近似并在关于页声明 |

### M1 追加修复（v0.2.6）：根因定案——预设白平衡增益为零

- v0.2.5 填充测试实验五信息互证定案：**pass1 输出全黑的根因是预设 `DoubleArray(28)` 中白平衡增益（索引 1–3）从未赋值（=0）**，`lin = rgb × wb × exposure` 整帧乘零；填充测试着色器不含 uWb 故能看到内容。「负片蓝/标准白」= pass2 串扰与分离色调作用在黑输入抬升后的灰上，预设响应正确的旁证。
- 修复：三个内置预设补 `wb=1,1,1`；C++ `FilmParams::fromDoubles` 加防呆（wb 全零回退中性）。
- 经验沉淀：跨语言参数数组的「沉默零值」是高危模式——M4 预设系统必须带参数范围校验（§7.1 schema 已含）+ 单测覆盖默认值。

### M1 追加修复（v0.2.7）：log 域映射范围错误（灰白画面根因）

- v0.2.6 验证：wb 修复后 pass1 输出真实画面（diag (0, 0.11, 0) 反推矩阵方程为真实暗像素），pass2/pass3 依然正确执行——但「负片发灰看不清、标准一片白」。
- 根因：**log 域映射 `lg=log2(lin)*0.5+0.5` 仅覆盖 lin∈[0.25, 4.0]**；YUV 经 gamma 2.2 解码后的场景线性值绝大部分 < 0.25（中灰≈0.21），整个暗部被夹断到 lg=0 后映射回 0.5 中灰——暗部整体灰化。
- 修复：log 域改为以 0.18 中灰为轴、±4EV 标准映射（`lg=log2(lin/0.18)/8+0.5`，逆映射 `0.18·exp2((lg−0.5)·8)`），黑不再被抬升；帧首消费残留 GL 错误，使 `pass3_cap` 诊断只反映本帧问题。

### M1 架构修正（v0.3.0）：预览改走 SurfaceTexture 系统路径

- v0.2.7 验证：负片已见画面（wb + log 域修复生效），但 pass1 采样仍异常——**UV 纹理恒读 (0,0)**（反推：G = yv+0.602、R/B 被 clip，与「绿主导」现象完全吻合），间歇 `render.upload_glerr 1282`。结论：RG8 TexSubImage2D 在该 Mali 驱动上静默失败。
- 参照用户指出的 PhotonCamera (github.com/bjzhou/PhotonCamera) 的做法：**预览不做 YUV 平面手动上传，改走 SurfaceTexture 系统路径**——Camera2 → SurfaceTexture（厂商 GPU 完成 YUV→RGB）→ `samplerExternalOES` + `getTransformMatrix` 采样 → 胶片链 → 上屏。该路径是所有相机 App 验证过的最稳方案，同时天然解决行翻转/旋转/裁剪（STMatrix）。
- 变更：删除手动 YUV 上传模块（yuv/YuvUploader）；pass1 改 OES 采样；拍照改为取最近预览帧渲染结果（全分辨率静拍流由 M2 RAW 路径取代，M1 记录为已知偏差）；「填充测试」保留（绕过 OES 采样的二分开关）。
- 方向修正：此前「左右颠倒」为 Y 平面行序（顶行在上）与 GL 纹理原点（底行）不一致 + 旋转叠加所致；STMatrix 路径下由生产者矩阵接管。

### M1 追加修复（v0.3.4）：静拍颜色量纲 + 方向跟随
