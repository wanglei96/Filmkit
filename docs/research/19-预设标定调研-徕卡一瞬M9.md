# 19 - 预设标定调研：徕卡一瞬（Leica M9）

状态：调研完成，未动工。日期：2026-10-25。
对标：小米 17 Ultra by Leica「徕卡一瞬」模式的 M9 滤镜（重现徕卡 M9 CCD 发色）。

## 1. 目标效果拆解

官方描述「重现徕卡 M9、M3 等经典相机的画质与摄影风格」。社区拆解（爱范儿
1650532 模仿教程 + 口碑）——**德味四要素**：

1. **克制的影调**：影调沉稳、高光油润不刺眼（琥珀感）、暗部透气；
2. **浓郁的色彩**：红蓝浓郁油润（柯达 KAF CCD 的发色）；
3. **一点点偏色**：**白平衡死盯日光**（不随光源校正，暗光下保留偏色）；
4. **一圈暗角** + 细颗粒。

实现背景：小米版是"数十万张徕卡照片训练的大模型"（云增强）——**场景自适应**
的差异化映射。静态预设（参数+LUT）覆盖不了这一层，是与小米版的结构性差距。

## 2. 三条可行路线

**A. PC 固件考古路线（一手实现，已存在）**：`/tmp/pc-full` 有完整的 M9
配方提取工程——从用户提供 M9 固件 `m9-1_216.upd`（XOR/PWAD/S-record 逐层
校验）提取 `PROCESS/LUTS.bin`（427KB）：
- **20 条 2048 点 1D 曲线**（5 色彩空间 × 4 对比度，取 sRGB/标准饱和/标准对比）；
- **双分支 3×3 有符号矩阵**（按 `R≥G / R<G` 选矩阵——逆向 M9 固件
  `ASMExecuteColorMatrix_10` 的条件色彩映射，表达力 > 亮度分区的 interlayer）；
- **M9 传感器真实标定**（双光源 ColorMatrix1/2，illum 17/21，DNG 语义）。
  实现载体 `LeicaProfile.kt`，注释明示"M9 1.216 matrix/LUT recipe；空间处理
  仍走上游管线"。**注意**：资产提取自 M9 固件，分发需自行评估版权；PC 只在
  APK 内使用。

**B. 现有参数链路线**：引擎 0 filmic（M9 latitude 配方已量化验证，见调研 17）
+ LUT + 槽位参数。

**C. 小米 AI 路线**：不可行（无数据无算力），只有"静态近似"一条命。

## 3. 现有槽位够不够

**约 80% 够**（builtin.json 已有一条旧「徕卡一瞬」预设置于这些槽位上，本次
重新标定、旧值仅作参考不作起点）：

| 效果要素 | 承载槽位（均已存在且拍照链生效） |
|---|---|
| 沉稳影调/高光油润 | [37][38] 黑白点 + [5..10] per-channel latitude + [4] contrast + [36] teq |
| 浓郁色彩 | [20..22] 分区饱和 + [32][33] look + [69..77] 层间效应 |
| 偏色（分离色调） | [23][24] 阴影暖/高光冷 + [88][89] temp/tint（整体偏色，两侧生效） |
| 颗粒 / 暗角 | [26][27][60][61] / [66..68] |
| 高光油润的物理成分 | [62..65] halation（预设未用，待标定） |
| LUT | [31..34] 强度（leica_m9.lut，33³，display 域） |

**三个真缺口**：

1. **WB「死盯日光」表达不了**：预设 schema 只带渲染参数，锁定 WB 是采集行为
   （HAL AWB 策略）。需要「预设携带采集行为」的新机制，或预设 note 提示手动锁。
2. **CCD 色彩响应的条件映射**：[69..77] 是亮度分区×通道增益，表达不了
   「按 R/G 关系分支」的矩阵；33³ LUT 能表达全空间映射但有精度与职责问题（见 §4）。
   → 最佳解 = **新引擎 2（Leica 配方引擎）**，形态照抄 PC `LeicaRenderPlan`
   （分支矩阵 + 2048 点曲线），注入 `kFsFilm` 引擎契约（引擎 = 1 pass）。
3. **[90..94] 影调分区（白/黑/褪色）拍照链不读**（`kFsStyle` only）——非硬缺口
   （等价承载在 filmic 黑白点/latitude/teq），但若标定想要"白色色阶 -20"式
   旋钮，需补 U-4 遗留的接线。

## 4. leica_m9.lut 质量评估（实测数据）

- **数据质量：合格**。空间平滑（三轴相邻格点跳变 ≤19 LSB、无坏点/硬切割）；
  灰轴中性不偏色（R-B=0）；白点保（255→255）、黑位轻抬（32→22）、中灰压暗
  （128→111）；饱和端点为暖调映射（黄→B 压至 115、绿→R 压至 86）。
- **职责问题：影调成分过重**。对数域影调斜率 **1.19**（42 枚内置 LUT 中第二重，
  仅次于 ricoh_hdf 1.27；胶片模拟主流 0.6~0.9）——中灰→白段被拉伸 19%。
  这是"端到端从 M9 成片反推"的 LUT，影调+色彩全打包 ⇒ 与 filmic 配方双重作用
  ⇒ 只能低强度混合 ⇒ 色彩表达同步被压缩。**它不是坏 LUT，是与参数链抢职责的
  LUT**。
- 33³ 网格密度在暖肤色区可接受，64³ 更稳（引擎已支持多尺寸）。

## 5. 引擎推荐（"调出那个味儿"的最佳选择）

**结论：现有引擎够 —— CCD 色彩响应不需要新引擎，需要的是换 LUT 的来源。**

**关键论证**：M9 配方（分支 3×3 矩阵 + 1D 曲线）在数学上是一个 3D→3D 色彩
映射，**3D LUT 是它的天然载体**——分支条件在烘焙时逐格点求值，任意精度逼近。
所以正确路线不是"新引擎"，而是**烘焙**：

- **不烘** M9 的 1D 曲线：其输入域语义不明（in 0.18→out 0.59 的形状说明输入
  不是线性反射率，可能是 log/域内特定编码，需逆向 PC shader 调用上下文才能
  确认）；且影调职责本来就该归 filmic latitude（已量化验证的标准表达）。
- **烘** 分支 3×3 矩阵（已解码：两分支均为**行和=1 的保白平衡色彩矩阵**，
  系数如分支0 R 行 [1.667, −0.544, −0.123]——强通道耦合的色度重构，这就是
  "CCD 发色"的数学；分支差异集中在 R 行与 B 行的 R 系数）。矩阵是线性映射，
  对输入亮度分布依赖弱，用我们的 display 线性域直接烘焙（64³），真机 A/B
  验证域偏差。
- 资产与脚本：`LUTS.bin` 解码逻辑已验证（SHA256 锁定），烘焙脚本 = 一次性
  工具活（半天级）；**新引擎（原生分支矩阵 pass）降级为备选**——仅当烘焙
  LUT 的域偏差/插值精度在真机上不满意时再上（数天）。

**M9 直出指纹（11 张彩色样张多场景统计，`docs/research/leica-m9-samples/`：
IT之家 3 张 + 爱范儿 8 张，网页压缩图、方向锚点性质）**：

| 指纹 | 中位 | 范围 | 标定含义 |
|---|---|---|---|
| 黑位 p25 | **21** | 8~26 | 黑位紧而深，**不是柔黑**（`filmic_black_ev` 深黑 + toe） |
| 高光 p95 | 165 | 115~254 | 高光压缩狠（见下） |
| ≥240 占比 | **0.1%** | 0~7.7% | 顶白只在强光源（太阳/灯芯，仅 1 张 7.7%）；我们当前 base 最高 11% |
| 色彩像素 C\*P90 | **24.5** | 14~53 | 浓郁度目标量级（我们同亮度天空 C\*p90 仅 7.1） |
| 主色相带 | 30~90°（暖黄绿）+ 240~270°（青蓝） | 双向浓郁 | 不是单向偏色，split+LUT 双管 |

单张（ithome-45 蓝天）"白位 172"是场景特例；**普适指纹 = 高光压缩狠 +
顶白只留给强光源 + 黑位紧 + 双向浓郁色**。另：暗部同样带色（夜景样张
C\*P90 42）——CCD 暗部色彩不收干，标定时暗部饱和不要压。

## 5b. 分层总结

- **影调层**：引擎 0 filmic + M9 latitude 配方（黑白点/latitude 待按指纹重标：
  白位收敛到 ~0.43 线性）。
- **色彩层**：烘焙 LUT（PC 配方分支矩阵，纯色彩无影调）——一期即可上。
- **质感层**：halation[62..65] + 颗粒[26..27] + 暗角[66..68]（全已有）。
- **采集层**：WB 锁定机制（唯一新机制，单独立项）。
- **原 leica_m9.lut**：降级为 A/B 对照，不作为色彩主载体。

## 6. 标定路径建议（待拍板后执行）

1. **风格锚点 = 网络样张集**（`docs/research/leica-m9-samples/`，已建 11 张彩色
   多场景库；用户无小米实机，此库即唯一效果参照，网页压缩图的局限已记）。
   **管线正确性判据 = PC 配方数学本体**：成片过烘焙 LUT ≈ 配方直算（逐位级
   对照），这条不依赖任何小米样张。
2. **烘焙脚本**：`LUTS.bin` 分支矩阵 → 64³ 纯色彩 display 域 LUT（半工具活）。
3. **一期标定顺序**（单变量、逐槽）：黑白点/latitude（黑位 p25≈21、高光
   压缩按指纹）→ 分区饱和 + temp/tint（C\*P90→20+ 量级）→ halation + 颗粒 +
   暗角（质感）→ 烘焙 LUT 强度扫描（补色彩响应）。
4. **判据**：多场景与样张集并排（色彩倾向/影调分布/暗角深度）+ 定量
   （CIELAB ΔE、影调分位曲线对齐指纹表）+ 目视（100% 裁剪）。
5. **决策点**：色彩层差距若肉眼明显 → 上新引擎（原生分支矩阵 pass）。
