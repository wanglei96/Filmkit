## 0. 结论速览（TL;DR）

1. **PC 的 HDRNet PGTM 是"复刻 Google Camera 私有引擎"的产物，不是自训练模型**。模型资产 `app/src/main/assets/mgc_hdrnet/hdrnet_coefficients.tflite`（1.58 MiB）、引导曲线 `guide_coeffs.pb`（MD5 `046e9e01…`）、增益上下限、伽马表**全部逆向提取自 MGC（= modded Google Camera，9.6/9.7.047 V25）的 `libgcastartup.so` / 内嵌 protobuf**。许可上是**专有资产**，不可照搬；方法论可借鉴。
2. PC 的落地方式极具参考价值：**HDRNet 只负责预测一张低分辨率 bilateral grid 系数（12×16×8×2），再烘焙成 DNG `ProfileGainTableMap2`（64×48 空间格 × 257+ 强度节点）**。运行期零 NN 成本——推理发生一次，产物是查表。这是"学习型影调进场但不在成片路径上"的关键工程范式。
3. **推理是 CPU（XNNPACK，4 线程），不是 GPU/NNAPI**（`setUseXNNPACK(true)`，`Interpreter` 未挂任何 delegate）。1.58 MiB 模型 + 192×256 输入的 CPU 代价量级很低，但 PC 未在仓库记录耗时 → **耗时未取证**。
4. 对本项目痛点（filmic 黑白点手调）的直接回答见 §4：**免手调可由"学 LUT / 学 gain map"达成，但"免手调"≠"免控制"**；且本项目已有更便宜的一手路径（曲线参数化解耦，见 §3.1）。学习型路线的正确位置是**升级为 image-adaptive 3D LUT / gain map**，而非替换整条影调链。
5. **风险对称于历史教训**（`.zcode/memory/facts.md` 第 114 行附近 NN 降噪判死）：跨域模型不可直接用、微调过拟合、数值指标好而观感零改善。HDRNet 系方法的风险不在"训不出来"，而在**目标域不匹配与缺乏可控回退**。

### 1.2 模型结构与 I/O（代码级证据）

**张量形状由运行时 `check()` 硬校验**（`DngPhotonProfileGainTableAlgorithm.kt:2852-2900`）：

```
input  tensor: [1, 192, 256, 4]  FLOAT32     // HDRNET_INPUT_HEIGHT=192, WIDTH=256
output tensor: [1, 12, 16, 8, 1, 2] FLOAT32  // GRID_HEIGHT=12, WIDTH=16, DEPTH=8, COEFF=2
```

- **双支路 / 低分辨率引导**：这是 HDRNet 的经典 **bilateral guided upsampling** 形态——网络只在 192×256 低分辨率上跑，输出的是 **bilateral grid 系数**（12×16 空间 × 8 深度 bin × 2 个仿射系数 = 3072 floats），**不是全分辨率 RGB**。全分辨率由 `dng_hdrnet_pgtm_jni.cpp` 用该 grid 做**引导上采样**展开成逐像素 gain（`SampleCoefficient` @ :164、`SampleModelRgb` @ :143、`TableIntensity` @ :442）。
- **引导（guide）**：不是另给一张 guide 图，而是**模型输入的通道 4**。`docs/photon-dehaze-pipeline.md:15` 明确：
  `HDRNet tensor [short R, G, B, min(short BT601 luma * r, 12)]` —— 第 4 通道 = 短曝光 BT.601 亮度 × `hdrRatio r`，上钳到 12。
- **输入域**：RAW camera RGB 经 `s0 * 2^e` 与 working-space CCM 后，**per-pixel `min(RGB,1)` → box average → clamp(mean,0,1)**，即**低分辨率下采样后的线性工作空间**（`photon-dehaze-pipeline.md:11-19`）。负值逐像素保留、只钳正上界，与 MGC `apply_lsc_and_ccm.frag` 对齐（同文 :27-30）。
- **输出域不是 RGB，是 gain**：网络预测仿射亮度 → 转成 gain → 被 `uGainLimits` 钳到 **[0.03, 30]**（`DngPhotonProfileGainTableGenerator.kt:20-28`，注释原文："Exact uGainLimits uploaded by MGC 9.6/9.7 Fast Moments' HDRNet renderer"）。
- **引导曲线（16 项 hinge）**：`HDRNET_GUIDE_SHIFTS` / `HDRNET_GUIDE_SLOPES`（同文件 :45-80），注释原文："Exact 1 × 16 guide parameters from MGC's embedded `guide_coeffs.pb` (MD5 `046e9e017194f8293245c33bf3b45b44`). The protobuf's leading/trailing 1 × 2 matrices are both `[1,0]`, so only this learned piecewise-linear curve changes luma." → **上采样是"学出来的分段线性亮度曲线 + 仿射"，不是手工双线性**。
- **最终产物**：DNG `ProfileGainTableMap2`，空间格 **64×48**（`HDRNET_PGTM_GRID_WIDTH/HEIGHT`），强度节点 `pointCount = max(257, ceil(M*257)+1)`，上传纹理固定 `64*48`，上限 `min(4096, GL_MAX_TEXTURE_SIZE)`（`photon-dehaze-pipeline.md:68-77`）。**运行期只查一次表**。

### 1.4 推理位置与耗时

- **后端：CPU / XNNPACK，非 GPU、非 NNAPI**。`ensureHdrNetInterpreter`（`DngPhotonProfileGainTableAlgorithm.kt:2855-2861`）：
  ```kotlin
  val candidate = Interpreter(
      FileUtil.loadMappedFile(context.applicationContext, HDRNET_MODEL_ASSET),
      Interpreter.Options().apply {
          setNumThreads(4)
          setUseXNNPACK(true)
      },
  )
  ```
  该 `Options` **未设置任何 `Delegate`**（无 `NnApiDelegate`、无 `GpuDelegate`）。仓库虽依赖 `tensorflow-lite-gpu:2.17.0`（`app/build.gradle.kts:241-244`）并 `noCompress += "tflite"`（:131），但那是给别的模型用的——例如 `ml/DepthEstimator.kt` 用 `NnApiDelegate`。**HDRNet 本身走 CPU。**
- **调用形态**：`interpreter.run(modelInputBuffer, modelOutputBuffer)`（:1711）同步阻塞调用，输入/输出缓冲直连（`ByteBuffer` 或 `Array`），单次推理。
- **推理频率**：**不是每帧**。它在**生成/刷新 DNG PGTM 时**执行；曝光匹配阶段会对候选 EV 逐一推理（`photon-dehaze-pipeline.md:39-41`：候选范围 `-4..4 EV`，"GPU 输入缓冲和推理器复用，内存只保留最近一个完整候选"）。属**导入期一次性的有界搜索**，不在取景/成片热路径。
- **耗时：未取证。** 仓库内未见 HDRNet 专属耗时日志或 benchmark（`HDRNET_PGTM_RANGE` @ :1702 与 `HDRNET_MATCH stage=SELECTED` 只记录范围/参数，不含时间）。**据 1.58 MiB 模型 + 192×256×4 输入 + 4 线程 XNNPACK 推断其量级为十毫秒级，但这是未验证推断，不作为结论。**

### 1.5 与传统 PGTM 的关系

- **是替换 + 可选开关，并在"是否复用内嵌表"上分层**。`photon-dehaze-pipeline.md:86-92` 给出策略：普通打开/开关动态范围优化时**复用有效内嵌 Photon PGTM**（不重算）；新配方显式重生成时恢复 `s0/r/e` 只算该候选；旧配方重生成时用旧响应重建参考再解新 input EV。
- **HDRNet 与 Dehaze/DHA 是串联且共同烘焙**：`Dehaze 不进入模型 tensor`，统计来自 HDRNet 推理后的 256×192 图像（:45-51），最终**一起烘焙进同一张 PGTM**（:3-4）。即传统上"单独的 PGTM + 单独 dehaze pass"被**合并为一次表查询**。
- **开关粒度**：`PhotonCoreImagingTuning.kt:9-10, 183-212` 的 `dehaze: PhotonDehazeTuning`（`enabled=true` 默认）控制 Dehaze/DHA 段；`docs/research/lumix-rendering-engine.md:63-69` 说明 **HDRNet PGTM 对新导入 RAW 默认关闭、不继承拍摄全局开关，且不冒充 HDRNet**（用户选的第三方 DNG profile 走自己的策略）。
- **未取证**：HDRNet 总开关的**具体字段名与默认值**未在本轮定位到单一权威行（`useHdrNet*` / `enableHdrNet*` 均无命中，开关很可能由 profile 选择链 + `enabled` 组合决定）。标注为待补。

## 2. HDRNet 及其后继的方法论（2024–2026）

> 取证方式：arXiv 官方 API（`export.arxiv.org/api/query`）拉取标题/摘要/DOI/期刊卷期，**逐条为论文原文元数据**；代码仓库链接取自论文摘要原文（非检索推测）。`web_search` 在本会话不可用（无 API key），故未做覆盖式检索——**可能存在遗漏，属已知局限**。

### 2.1 原点：HDRNet 的方法论内核

**Gharbi, Chen, Barron, Hasinoff, Durand, "Deep Bilateral Learning for Real-Time Image Enhancement", ACM TOG 36(4):118, SIGGRAPH 2017**，arXiv:[1707.02880](https://arxiv.org/abs/1707.02880)，DOI [10.1145/3072959.3073592](https://doi.org/10.1145/3072959.3073592)。官方实现：[github.com/google/hdrnet](https://github.com/google/hdrnet)（`An implementation of 'Deep Bilateral Learning for Real-Time Image Enhancement', SIGGRAPH 2017`，已核实可达）。

方法论内核（摘要原文）：
> "the neural network consumes a **low-resolution version** of the input image, produces a set of **affine transformations in bilateral space**, upsamples those transformations in an **edge-preserving fashion using a new slicing node**, and then applies those upsampled transformations to the **full-resolution** image."

三个关键点，直接决定它为什么能上手机：
1. **网络只看低分辨率**（PC 用 192×256）⇒ NN 成本与成片分辨率解耦；
2. **产出是"变换的参数"而非像素**（bilateral grid 仿射系数）⇒ 输出张量极小（PC: 12×16×8×2 = 3072 floats）；
3. **上采样是 edge-preserving slicing**（保边）⇒ 避免低分辨率决策产生光晕/色边。
论文自述："processes high-resolution images on a smartphone in milliseconds, provides a **real-time viewfinder at 1080p resolution**"，且"trained **off-line** from data and therefore **does not require access to the original operator at runtime**"——**这句是"免人工调参"的理论基础：目标只需以成对样本形式存在，不需要可微的参考实现**。

### 2.2 两条继承路线

| 路线 | 代表 | 产出物 | 与 PC 的关系 |
|---|---|---|---|
| **A. 双边网格 / 增益图** | HDRNet 2017 → DNG `ProfileGainTableMap`(Adobe) → Ultra HDR gain map | 低分辨率 gain/仿射栅格，运行期切片查表 | **PC 走的正是这条**（§1），Python/工程上最易与既有管线对接 |
| **B. image-adaptive 3D LUT** | Zeng 2020 → AdaInt / SepLUT / NeuralLUT / 4D LUT → 2025–2026 一批 | 一个（或 K 个 basis 融合出的）3D LUT，运行期三线性插值 | **本项目管线里已有 3D LUT 槽位**（98 槽管线的 LUT 段），迁移摩擦最小 |

**两路线同源**：都是"低分辨率 CNN 做全局/内容相关决策 → 全分辨率用 O(1) 插值应用"。区别只是"决策"落在双边网格还是 LUT 顶点上。

### 2.3 image-adaptive 3D LUT 系谱（含开源与预训练权重）

### 2.5 ★ Deep Analog：对"固定 LUT 基 + 自适应权重"范式的证伪与替代

这篇 2026 年的硕士论文（arXiv:[2608.14702](https://arxiv.org/abs/2608.14702)，代码 `github.com/EtonMu/deep-analog`）**直接挑战了 §2.3 主流范式**，四条结论对本项目是重要预警：

1. **"K 个 basis LUT + 每图权重"实质是 gated mixture of experts，并继承其失败模式**：端到端按重建损失训练时，**gate 会坍缩到单一 expert**——"a bank of K LUTs delivers the capacity of one"。加熵正则（MoE load balancing 的类比）可恢复利用率，约 **+1 dB PSNR**。
2. **更深的约束无法绕过**："a fixed LUT basis is **closed-set**, freezing the achievable looks at training time" ⇒ **想覆盖训练时没见过的胶片/风格，固定基做不到**。这对"98 槽 + 固定曲线族"的我们同样成立。
3. **替代方案 StyleLUTNet**：丢掉 basis，**从参考图直接预测单个 3D LUT 作为残差**；用**程序生成的颜色变换做自监督**训练 ⇒ **无需成对数据、无需重训即可 open-set 泛化到未见胶片**。
4. **可量化的落地形态**：350 组自监督样本上，颜色段 22.05 dB PSNR / 0.925 SSIM，整链 21.72 dB / 0.923；**颜色路径 1080p 5.2 ms（192 FPS）**；并**导出便携 `.cube` LUT** 供标准工具使用。
   另报告第二个退化现象 **residual-scale collapse**，并给出一般原则：**辅助正则必须从属于重建目标**（auxiliary regularization must stay subordinate to reconstruction）。

> **对本项目的直接含义**：若走"学习型影调"，**不要**去训练"K 个 basis LUT + 权重网络"（gate collapse + closed-set 双重坑）；应优先"**从参考/样片直接回归一张 LUT 或一张 gain 曲线**"，并**保留导出成静态资产（`.cube` / 参数表）的能力**——后者恰好让"离线验证 → 真机 A/B"成为可能（§5）。

### 3.2 与兄弟报告的分工（避免重复，明确互补）

`16-影调科学前沿与自动白点.md` 已判定："**用算法猜白点**（自适应/自动 tune）"**无效**（`:24`），理由是该做法**仍是"场景端点"参数化，只是由统计量驱动**；并记录本仓 `auto_tone`（`[35]`）**三次真机证伪**（`:316`，v0.10.16/17/18）。

**本报告的补充与差异**（这是"学习型"这一格的价值所在）：

- 16 号证伪的是「**在同一参数化内换估计器**」；学习型路线的定义性特征是「**换掉参数化本身**」。
- R-3 的 `--lat-split` 提供了**关键旁证**：一旦把绑定解耦（shoulder/toe），残差立刻改善 ⇒ **参数化缺陷是可被工程手段部分修复的**，这为"学习型路线要么解耦、要么绕过"提供了本仓实测依据。
- 因此对治路径有**两条并行**，且**第一条不需要任何 ML**：
  - **路径 A（零 ML，应优先）**：继续解耦参数化——根因是 `output_power` 由白点算出（`FrameRenderer.cpp:13442 derive_power` ≡ darktable `_compute_output_power`），把 `output_power` 从白点解绑即可让"改白点不改形状"。
  - **路径 B（学习型，本报告主题）**：换掉参数化，直接学 LUT / gain 曲线（§3.3-c）。

### 3.3 三条升级路径对比

| 路径 | 机理 | 免手调程度 | 实施代价 | 风险 |
|---|---|---|---|---|
| **(a) 可微渲染** | 把"参数 → 曲线 → 影像"做成可微，端到端对目标样片梯度下降 | ⚠️ 半：仍需给目标样片，但免去人工试参 | **中**：曲线本身是解析三段多项式（`computeFilmicSpline`），可微化主要是包装；颗粒/dither 不可微但**不参与影调拟合**，可不进图 | 离线/真机域差（§3.5）；梯度并非必需——R-3 用单纯形法（无梯度）已达 14.78 |
| **(b) 代理模型 + 贝叶斯优化** | 采样 (θ→指标) 训代理（GP/小 NN），BO/CMA-ES 搜 | ⚠️ 半 | **低-中** | **本项目里是多余的中间层**：oracle 已是真引擎，代理只引入近似误差；仅当需要海量评估时才值得 |
| **(c) ★ 直接学 LUT / gain 曲线（推荐主路径）** | 从（输入图，目标图）回归一张 3D LUT 或一条 gain 曲线，**导出静态资产**，运行期零 NN | ✅ **是**（目标 = 样片，不是参数） | **中**：一次性训练 + 资产管线；运行期成本≈0（复用现有 3D LUT 槽） | 训练数据来源（§4.2-4）；**必须避开 basis+gate 范式**（§2.5） |

**为什么 (c) 优于 (a)/(b)**：痛点的根因是**参数化结构性缺陷**（改白点必改形状）。(a)/(b) 只是**更聪明地在坏参数化里找解**——R-3 已证明这条路能走（14.78），但仍要靠 `--lat-split` 人工解耦、靠 `--hi-floor` 人工设约束，**约束和自由度都得人来定**。而 (c) **让白点不再是曲线的输入**，从结构上消灭"反复调黑白点"这件事。这与 §1 中 PC 的做法同源，也与 Deep Analog 的结论一致（固定基 closed-set，但**从参考直接回归单张 LUT** 可行且可导出 `.cube`）。

### 3.5 如何避免"离线好看真机判死"（本报告的强制约束）

**根因已一手核实**：`tools/engine-shader-offline.py` 文件头 :19-23 明确列出**未接入**的 pass：
- P0 前置的 **HR（高光重建，需要块级参考场）**
- **ESD3D2（`kFsPc3d`，多尺度 + LSC 纹理）** ← 即"不含 PC3D"
- `passOutput` 的 **OETF / 颗粒 / dither**（该脚本用 `srgb_encode` 近似）

⚠️ **一处必须实测确认的不一致**：脚本 `:126` 存在 `--pc3d` 参数（`default=0`，help 写 "1 = 执行 kFsPc3d（需 LSC，暂用恒等）"），但能力清单把 `kFsPc3d` 列为"未接入"。**二者矛盾 ⇒ 该 pass 的离线保真度不可假定**，任何依赖 PC3D/LSC 的拟合结论在补齐前都不成立。

**五条硬性对策**：

1. **拟合目标下沉到"引擎两端一致的中间量"**：不要拟合整链输出像素，优先拟合 **filmic 曲线本身**——`computeFilmicSpline` 是解析的，且 `recipe-fit.py` **已经用 clang++ 真跑引擎这份代码**（:273-276），不存在域改写误差。曲线一致 ⇒ 真机一致。
2. **补齐离线执行器到成片链一致**：至少接入 PC3D（需 LSC 纹理）与 HR，否则"含 LSC/高光重建"的环节全是盲区。
3. **判据必须用真机口径**：沿用 R-3 的做法（"含 LUT 口径"+ 引擎实测 `max|Δ|`），**禁止只用离线指标签收**。
4. **真机 in-the-loop**：把优化/验证循环的评估器指向真机（R-1/R-2/R-3 已是此模式：真机日志引自引擎）。
5. **强制导出静态资产**（`.cube` / 参数表 / gain 曲线），并在验收中**用导出的资产在真机重放**——禁止"只在训练框架里好看"。Deep Analog 导出 `.cube`、PC 烘焙 DNG PGTM，都证明这条路可行。

## 4. 对治黑白点的直接回答

### 4.1 哪些方法真能做到免人工调参？

| 方法 | 免手调 | 机制 | 主要失败模式 |
|---|---|---|---|
| 统计自适应（本仓 `auto_tone` `[35]`） | ❌ 部分 | 场景分位猜端点（P0.1/P99/P99.9/max） | **仍在同一参数化内** ⇒ 改白点必改形状；已三次真机证伪（16 号报告 :316） |
| sigmoid / ACES 2.0 | ✅（**架构性取消**） | 曲线对无界输入渐近收敛，`f(∞)=显示白` ⇒ **把估计问题消掉**，白点参数从 schema 消失 | 非学习型；取舍转移到 `contrast`/`skew`/`peak`；8bit 下仍会量化饱和（16 号报告 :310, :322） |
| **image-adaptive 3D LUT**（Zeng/AdaInt/SepLUT/4D LUT） | ✅ | 低分辨率 CNN 预测 LUT 或基权重 ⇒ **白点不再是曲线输入** | **gate collapse**（Deep Analog 实测：K 个 basis 只给 1 个的容量，需熵正则、约 +1dB）；**closed-set**（固定基把可达到的 look 冻结在训练时） |
| **参考条件单 LUT 回归**（Deep Analog / StyleLUTNet） | ✅ 且 **open-set** | 从**参考图**直接回归单张 3D LUT 残差；程序化颜色变换自监督 ⇒ 免成对数据、免重训泛化到未见风格 | 需要"给一张参考/样片"（**不是零输入**）；residual-scale collapse；辅助正则须从属重建 |
| **双边网格 / gain map**（HDRNet；PC 落地形态） | ✅ | 学低分辨率仿射系数 + 保边 slicing 上采样到全分辨率 | **跨域不匹配**（PC 的权重是 GCam 专有资产，本仓不能用）；许可 |
| **从样片拟合 98 槽**（recipe-fit 升级） | ⚠️ 半 | 真引擎 in-the-loop 约束 minimax | 参数化结构性缺陷仍在（除非先做阶段 1 解耦）；约束与自由度仍靠人定 |

**一句话回答**：**能免手调的是"换参数化"的三类——sigmoid/ACES2（取消端点参数）、学习型 LUT/gain（白点不再是曲线输入）、以及参考条件 LUT 回归（连训练时没见过的风格也能覆盖）。而"在同一参数化内猜端点"（含本仓 `auto_tone`）已被证明不能免手调。**

**但必须讲清一个本质**：学习型方法的"免手调"**不是"无目标"，而是把目标的表达从「参数空间」搬到「图像空间」**——人不再调 98 个槽，而是给一张（或一组）样片。真正"零目标"的只有 sigmoid/ACES2 这类架构性取消，而它不是学习型。**这是选型时最容易被含糊过去的一点。**

### 4.2 失败模式清单（对照本项目历史教训）

| 失败模式 | 本项目已发生的先例 | 在学习型影调上的表现 | 缓解 |
|---|---|---|---|
| **过拟合** | NN 降噪：四次微调在 4 场景过拟合（`.zcode/memory/facts.md:114` 附近） | 只在少数样片上拟合 ⇒ 换个场景 look 崩 | 场景多样性 + 留出集 + 以"跨场景一致性"为验收项 |
| **风格漂移 / look 不稳定** | `auto_tone` 三次真机证伪 | 每图自适应 ⇒ 同一预设跨场景观感不一致 | **离线烘焙成静态资产**（同预设恒定）；自适应只在"生成资产"时用，不在成片时用 |
| **可控性/确定性丧失** | —（新风险） | 每帧 NN 推理 ⇒ 同场景不同帧可能不同；无法复现 | 同上：**推理一次 → 静态 LUT/表**，成片路径零 NN（PC 与 Deep Analog 的共同形态） |
| **数值指标好而观感零改善** | NN 降噪：公式逐位吻合但文字梯度 −24%、斑块伪影 | PSNR/SSIM 提升但"胶片味"变淡/变塑料 | 验收必须含**观感判据**（R-3 的"高光段斜率 LSB/0.1EV"、"胶片味未变淡"是正确范式） |
| **跨域模型不可直接用** | NN 降噪：跨域模型不可直接用 | 直接拿 GCam/公开权重套本项目管线 ⇒ 域不匹配（§1.3） | 权重自训练或用程序化自监督；**不复制专有资产** |
| **训练数据来源** | —（最硬的新问题） | 无成对数据就无法监督 | 三条现成来源（§3.4）：拟合器自举 / 仓内风格资产 / 程序化自监督（Deep Analog 路线） |
| **closed-set 冻结** | 固定曲线族 = 同类问题 | 训练时未见过的风格永远做不出来 | 走 Deep Analog 的"无 basis、参考条件"设计（§2.5） |

### 4.3 工程保障：确定性优先

**核心建议：不要把 NN 放在成片热路径上。** PC 的形态（推理一次 → 烘焙 DNG PGTM → 运行期只查表）与 Deep Analog（导出 `.cube`）给出同一个答案：

- **确定性**：同一输入 + 同一资产 ⇒ 逐位可复现（可回归测试）；
- **可回滚**：资产是文件，出问题换回旧资产即可；
- **零运行期成本**：不增加 GPU/显存/功耗，不引入帧率抖动；
- **可审计**：LUT/曲线可被人类读懂与手改（LoR-LUT 的 Viewer 滑杆、AdaInt 的采样间隔可视化，都是这个方向）。

## 5. 与现有引擎的接口点

### 5.1 接在哪一段：一个决定性的域论证

管线：多帧融合 → 黑阶+WB → 去马赛克 → LSC → 高光重建 → CCM → 局部色调映射(可选) → **filmic/AgX** → 曝光+EV → 高光滚降 → 锐化 → OETF → **3D LUT** → 颗粒 → JPEG

| 接点 | 位置/域 | 能治什么 | 判定 |
|---|---|---|---|
| **A. filmic 段（推荐）** | `kFsFilm` 所在段，**线性工作域**，与 PC 的 HDRNet 同域 | **黑白点/死白/高光层次**——即本痛点 | ✅ **唯一能治根因的接点** |
| B. 3D LUT 槽位 | OETF **之后**，显示域 | 风格/色彩，**治不了死白** | ⚠️ 见下述论证 |
| C. 局部色调映射段 | CCM 之后、filmic 之前 | 局部对比/动态范围压缩 | ✅ 可作学习型 gain 的落点 |

**为什么 B 治不了痛点（关键）**：3D LUT 在 OETF 之后，而 R-3 已实测证明旧配方的**白纸亮度比"无 LUT 上限"还高**（黑白 248.8 vs 246.66）= **白纸已贴上死白平台**。8bit 量化后的平顶是**信息不可逆丢失**，下游任何 LUT 都无法恢复被压掉的高光层次。⇒ **学习型路线必须落在线性域（接点 A/C），不能只在末端加一张 LUT 了事。**

### 5.2 需要的资产与 ABI 增量

**现状**：参数经 98 槽数组传递到 `FilmParams`（`FilmParams.h:547-551` 形态：`if (n > 37) filmic_black_ev = static_cast<float>(v[37]);`），JNI 走 `core/engine/src/jni/Bridge.cpp`（916 行）的 `EngineBridge` 导出（`nativeEngineStart` / `nativeStillStart` 等）。

**增量建议（按侵入度从低到高）**：

| 方案 | 新增资产 | ABI 改动 | 运行期成本 |
|---|---|---|---|
| **A1. 学习型 gain 曲线（最小）** | 一张 1D gain 曲线表（如 1024 点 float ≈ 4 KB）或解析系数 | **无需改 98 槽**：走 side-channel 资产 + 一个"资产选择器"槽 | ≈0（一次纹理查找/像素） |
| **A2. 双边网格（PC/HDRNet 范式）** | grid 系数 `16×12×8×2` floats ≈ **3 KB** + guide hinge `16×2` | 同上；新增 1 个 slicing pass | 1 次额外纹理采样/像素，可忽略 |
| **A3. 学习型 3D LUT（风格层）** | `.cube` 或现有 LUT 资产形态（33³×3 ≈ 430 KB） | **复用现有 3D LUT 槽**，零 ABI 改动 | 现有成本（已在管线内） |

**显存/带宽量级**：A1/A2 均为 **KB 级**，相对现有 98 槽与多帧缓冲可忽略；A3 复用已有槽位。**实施代价主要在"训练数据管线 + 曲线参数化改造"，不在运行期。**

### 5.3 离线验证 → 真机 A/B 路径与判据

| 阶段 | 环境 | 判据（必须可量化） |
|---|---|---|
| **V0. 曲线级** | `recipe-fit.py`（真跑引擎 GLSL + clang++ 编译的引擎曲线函数） | 单调性；**死白起点 ≥ 3.5 EV**（R-2/R-3 判据）；minimax `max\|Δ\|`；高光段斜率（胶片味）不下降 |
| **V1. 整链离线** | `engine-shader-offline.py`（**须先补 PC3D/HR**） | 白纸/中灰/暗部 LSB 差；无"平顶"（8bit 极差 >1 LSB 的跨度） |
| **V2. 真机 A/B** | vivo X300 实拍，同场景同曝光 | ① **含 LUT 口径**的白纸/中灰 LSB；② 死白起点；③ 高光层次预算（LSB）；④ **跨场景一致性**（不同场景同预设的观感漂移）；⑤ 观感判据（"胶片味"是否变淡） |

**红线**：**禁止以离线指标签收**。任何方案在 V2 通过前不得上线——这正是历史多版"离线好看真机判死"的教训（根因是离线执行器缺 PC3D 等 pass，§3.5）。

**待决问题（需用户/架构师拍板）**

1. **路径 A（零 ML：解耦 `output_power`）与路径 B（学习型）的优先级**：R-3 已证解耦有效且便宜；学习型是结构性替代。是否先做 A 作为 B 的前置（提升基线）还是并行？
2. **学习型资产的目标形态**：gain 曲线（A1）/ 双边网格（A2）/ 3D LUT（A3）——三者成本相近，但**只有 A1/A2 在线性域**（§5.1）。
3. **"目标"的输入形态**：一张样片（参考条件，Deep Analog 范式，open-set）还是固定预设（closed-set，风格恒定）？二者在"用户是否需要每次给参考"上体验完全不同。
4. **黑点 `[37]` 的约束化**：R-3 只解决了白点。黑点的"免手调"判据（暗部不压死 / 噪声底 / 阴影层次）需要先被定义成可量化约束（阶段 0）。
5. **是否需要先补 PC3D 到离线执行器**：这是所有后续离线验证的前提（§3.5）。

**建议的下一步（最小动作）**：先做 **阶段 0（黑点约束化）+ 阶段 1（`output_power` 解耦）**——两者都是零 ML、可用现有 recipe-fit 流程与真机 A/B 闭环验证，且能把基线抬高；随后再评估学习型资产（阶段 2）是否仍有增量。这与项目铁律"先 100% 按原版完整实现并跑通 → 真机实测 → 用实测数据评估是否偏离"一致。
