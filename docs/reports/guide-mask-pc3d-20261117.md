# 高光 guide/mask 与 PC3D 质量评估

日期：2026-11-17。生产版本仍为 0.14.23 / 820；没有安装新包、修改偏好、提交或推送。
首轮仅回放；后续按用户明确授权补拍一次室内完整 RAW burst，结果见第6节。
用户已关闭 PC3D 和强边缘色度门，均保留。为隔离回放与实时预览争用，测试中用 Home
将 App 暂时切到后台，结束时留在桌面。生产成像源码未修改。

## 结论

- 本轮真实逆光 RAW 没有显示 PC3D 有明显、普遍的成片优势。它在云边减少了细小色度变化，
  同时有轻微颜色与亮度纹理变化；不能将变化量更低直接当成质量更好。
- 当前 PC3D 关闭会启用 P4 和多尺度色度降噪，因此关闭后仍有完整降噪路径。
  本轮比较的是两条实际生产路径，不是仅移除一个算子的纯消融。
- 强边缘色度门只进入 P4 / D-1；PC3D 替换档旁路它。关闭该门后，本样本的云边和栏杆
  未见明显新生紫/绿边；尚不能据一个场景删除功能或判断其他镜头、织物、高 ISO 都不需要。
- 高光保留三个独立 guide 的计算域、完整 RGB 误差、native CFA footprint 和整帧准入。
  可严格等价优化的有限值检查实测约省 16–18ms；候选保留在独立目录，未接入生产。
- 发现 PC3D 关闭时两趟色差中值的输出没有消费者，但计算仍执行。
  这是潜在冗余工作，不是建议改变关闭档输入。应以“跳过无人消费的计算”候选做全链逐字节回归，
  不能改成把中值接入 P4，否则那是画质变化。

## 3. 严格等价的 finite 检查候选

ARM64 每次检查四个 float 的 exponent 位，聚合任何 Inf/NaN 标志；不修改浮点值。
尾部逐值检查，其他架构使用原有限值判断。完整保留输入校验与失败清空语义。
未使用 fast-math、FP16 代替统计、旧帧缓存或精度降级。

生产参考与候选同进程，四个 ABBA/BAAB 区组，每条件八次，4096×3072：

|无裁剪|94.678|76.528|-18.150|

十二个区组的 mask 配对均值均更快，但全裁剪有一个区组仅快2.571ms，不能称每组都有大收益。
三种分布分开测，随机裁剪组在较热设备状态下，不能横向比较其绝对耗时。
三个完整尺寸 guide/mask 逐字节相同；Host 与 Android 均通过240组对照，
Android 通过108组非有限值拒绝检查（3 guide × RGB/variance × 6位置 × Inf/-Inf/NaN）。
候选未接入 App、未安装、未做接受高光的真实照片 A/B，所以只称独立候选收益。

## 4. 后续可落地位置与边界

1. finite 检查：收益小但保持数学结果；适合与后续明确优化一起评审和全链验证。
2. CPU guide 与 GPU pyramid 重叠：guide 不读取 GL 状态，两个 RAW view 在 submitRawBurst
   返回前有效；金字塔尺寸可由 RAW 推出，guide 结果在几何支持判定前再等待。
   需要异常/退出时 join、限制 worker 预算并实测预览竞争；收益上限是可重叠的 pyramid 时间，
   不能宣称整个 guide 时间都能消失。暂未实现。
3. 重复短帧 pyramid：时域循环已经为同一短帧、同一 frame_scale 计算过；高光阶段又生成读取。
   可研究保留该帧 pyramid，必须处理 align_l1=false 的补读与 FBO 当前归属；暂未实现/计时。
4. merge-mask 重采样和3×3 min/max 在两个串行循环内，计入 uploadMs 而非 maskMs。
   可独立并行逐行，不改量化与奇数尺寸采样；还未证明真实收益。
5. PC3D 关闭的无消费者中值：见 FrameRenderer.cpp 的 p4_src/cm_src 和 passColorMedian。
   不应顺手接入 P4；先验证跳过计算时 RGBA、HDR、统计、GL 状态及协方差消费均相同。

本轮不采用已拒绝的 native clipping 全图缓存候选，也不因没有可见紫边就预删降噪算法。

### 回放口径及限制

工具新增 `--film-params` 104槽有限值输入、`--ae-hal` 曝光入口；不修改App。
App为非debuggable，无法用run-as读取私有完整参数快照，未绕过权限。
因此从neutral基线加日志可核实的曝光、对比度、黑白点、锐化、清晰度等重建固定配方，
并明确使用日志确认的filmic、LUT关闭。它不是私有参数快照的逐字节复原。

早期试跑缺少预览测光历史，aeEv为+1.058；此后选用生产HAL曝光模式固定aeEv=0。
最终两档一致使用 EV=.1（日志base .7加本次显示闭环-.6）、contrast=1.098、
相同固定黑白点，避免将每档不同的全局提亮混入降噪比较。
这属于固定曝光下的完整渲染路径比较，**没有复现App预览历史与显示闭环**。
同一neutral基础及相同固定曲线应用于两档；实际App显示闭环、最终JPEG/R的HDR观感
仍需另测，不能以本轮替代。预试跑日志与final matched组分开，不混算。
