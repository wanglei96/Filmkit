# R-2 报告：内置预设白点 2.7 是否导致"高光死白"

> 分析卡（**未改任何产品代码**）｜2026-10-12｜用户原话：「白点默认才 2.7？那杯子高光变白的 bug 不就又出来了！」
> 工具：`tools/preset-exp/r2-white-point.py`（主）、`r2-white-point-sweep.py`、`r2-rolloff-knee.py`（补充）
> 链路：**引擎自己的代码**——系数 = `FrameRenderer::computeFilmicSpline` 提取后 `clang++` 真编译真跑；
> 渲染 = 真跑 GLSL `kFsFilm` → `kFsOut`（只做 `#version 300 es → 330 core` 机械改写）。

## 0. 结论（4 条）

1. **机制成立，用户没记错**：`filmicScalar` 的 `e = clamp((log2(s/grey) − blackEv)/DR, 0, 1)` —— 输入 ≥ `white_ev`
   时 `e` 恒等于 1，`spline(1) = white_disp = 1.0` ⇒ **filmic 输出逐位恒定**。实测（m9，白点 2.7471）：
   从 **2.75 EV** 起 `kFsFilm` 输出恒 `0.998535`，8bit 层面从 **2.55~2.60 EV** 起整段差 ≤1 LSB。
   → **"多个不同输入 → 同一个输出"确实存在，起点 ≈ 白点本身。**
2. **但"2.7 是否闯祸"取决于高光 EV，而引擎自己的真机日志显示高光经常越过它**：
   白壶（162012）渲染域最亮 **1.02 = 2.47 EV**；边缘白墙经 LSC 3~5× 后 **+2.5~3 EV**；auto 白点曾估到 **5.494 EV**
   （`FrameRenderer.cpp:11918`、`13411`）。三条预设白点 2.54/2.61/2.75 ⇒ **余量 0.07~0.28 EV**。
3. **提高白点有效，但不是免费的**：白点 4.56 时死白起点推到 4.05~4.20 EV（反射率 3.0~3.4，够用），
   代价是**整条亮部压暗**（无 LUT 口径：m9 白纸 0.9 = 239 → 202）＋ R-1 目标残差 **8.06 → 30.84**（3.8×）。
4. **建议：内置三条白点 2.54/2.61/2.75 → 3.5（折中）或 4.0（推荐）**，并强烈建议改走"**场景自适应 + 用户可调**"
   （引擎 auto 路径已有 P99.9/max 上探 + `[2.438, 4.556]` 钳制，**预设固定曲线路径完全没走**）。
   单靠一个固定白点无法同时满足"白瓷够白"与"高光不糊"—— 见 §5 的引擎真机证据。

## 3. 代价：提高白点会失去什么（含预设 LUT = 真机口径；**必须一起看，否则会把"死白"修成"发灰"**）

| 白点 | 白纸 0.9（2.30EV） | 白瓷面 0.74（2.0EV） | 死白起点（无 LUT） | R-1 目标 max\|Δ\|（含 LUT） | 243→目标 233.4 残差 |
|---|---|---|---|---|---|
| 2.7471（现状） | 241.3 | 225.7 | 2.60 EV | **8.06** / 10.46 / 11.83 | **+7.2** |
| 3.0 | 232.6 | 214.7 | 2.85 EV | 12.68 / 18.02 / 17.59 | −1.9 |
| 3.5 | 213.9 | 198.2 | 3.30 EV | 24.10 / 27.68 / 19.95 | −20.6 |
| 4.0 | 206.9 | 194.0 | 3.75 EV | 27.34 / 33.86 / 19.80 | −27.3 |
| 4.56 | 203.3 | 191.8 | 4.20 EV | 30.84 / 37.64 / 20.40 | −30.8 |

R-1 拟合的初衷（`preset-sample-fingerprint-RESEARCH.md:510`）：**M9 的"高光软肩"= 243 落到 233.4**。
白点提高 = 高光被压得更狠 ⇒ 拟合残差 3~4 倍。**"胶片高光软肩"与"高光不死白"在本引擎里是同一个自由度的两端**
（显示域上限只有 ~246.5，白纸与上限之间的总余量是固定的）。

## 4. 排除法：两个"想当然的补偿旋钮"实测都无效

| 旋钮 | 实测结果（m9，现状白点） | 结论 |
|---|---|---|
| `contrast` [4] 提到 1.4~1.6 把白纸拉回 240 | 白纸 239.2→244.0，但死白起点 2.55→**2.35**（更早） | **无效**：曲线更陡 ⇒ 更早到顶 |
| `highlightRolloff` knee 0.80→0.50 | 白纸 239.2→226.6，上限 246.7→233.3，**预算 7.5→6.7 不变**，死白起点恒 2.55 | **无效**：白纸与上限同步降 |

⇒ 能真正扩大"高光层次预算"的旋钮只有 **白点（以及 black/DR）**。

## 5. 为什么"单靠固定白点"治不好（引擎自己的真机证据）

`FrameRenderer.cpp:13421-13424`（v0.10.111）逐字：「"高光点密集、面积很小"的场景（**釉面/白瓷**）P99 只有 ~1.0EV，
白点被钉在 2.44~2.53 ⇒ 比场景高光高 1.4~1.5EV ⇒ 1% 以上的高光全落在肩部**以下**、根本不被压缩 ⇒
**密集高光点一路白上去（2026-10-03 真机红杯实测）**」；`12894`/`13389`（v0.10.28）：「渲染域最亮 1.02 …
4.1% 的白壶身渐变被肩部压进 245+ 平台（"水壶压不住"）」。
两条说的都是**用户现在这个现象**，而引擎的修复是**场景自适应白点**（`w = clamp(w, w_floor, 4.556) + ev_shift`，
含 P99.9/max 上探 + `cp` 补偿）—— **固定曲线的预设路径不走这段代码**（`auto_tone = 0`）。

## 6. 建议

1. **把内置三条 `filmic_white_ev` 从 2.54/2.61/2.75 提到 3.5**（最低可接受）**~ 4.0**（推荐）：
   3.5 ⇒ 死白起点 3.2~3.3EV（反射率 1.8）、白纸 213.9、层次预算 23~35 LSB；
   4.0 ⇒ 死白起点 3.6~3.75EV（反射率 2.2~2.5）、白纸 206.9、预算 30~41 LSB。
   依据：真机高光实测分布 2.47（白壶）~3.0 EV（边缘白墙）⇒ **3.5 是覆盖它的最小值，4.0 留 1EV 余量**。
2. **提白点必须同时重跑 R-1 拟合**（`recipe-fit.py --fit`，白名单含 [4][5..10]），否则 M9 目标残差
   从 8.06 恶化到 24~31（白纸会比 M9 样片暗 20+ LSB）。**不要只改 [38] 一个槽。**
3. **更好的方向（建议单开卡）**：预设也走场景自适应白点（复用 `updateFilmicEV` 的上探逻辑），
   并把 [37][38] 在 UI 暴露给用户（用户原话"黑白点要可调"）。固定 2.7 的问题不是"值错"，
   而是"**它对高光只有 0.1~0.3EV 余量**"，而场景高光 EV 天然是变化的。
4. **不建议**用提高 `contrast` 或降低 rolloff `knee` 去补偿（§4 实测无效）。

## 7. 方法 / 复现 / 诚实标注

```bash
python3 tools/preset-exp/r2-white-point.py --json /tmp/r2wp.json   # §1/§2/§3 全部表格
python3 tools/preset-exp/r2-white-point-sweep.py                    # §3 白点×contrast 联合扫描
python3 tools/preset-exp/r2-rolloff-knee.py                         # §4 knee 扫描（离线替换常量）
```
- **实测**（引擎源码真编译 + 引擎 shader 真跑）：所有输出数值、平顶/死白起点、R-1 残差、knee/contrast 扫描。
  系数来自 `computeFilmicSpline`（clang++ 真跑），渲染来自 `kFsFilm`/`kFsOut`（GL 真跑），
  每列 64 行取中位数去掉 `kFsOut` 结尾的无条件 dither。
- **工具对拍**（`python3 tools/preset-exp/recipe-fit.py`，另一条独立链路：C++ `filmic_scalar` 后直接接 `kFsOut`，
  跳过 `kFsFilm` 的 sat/split/mono）—— R-1 拍照口径 max|Δ|：本卡 **8.06 / 10.46 / 11.83**，
  recipe-fit **8.33 / 11.85 / 12.01**（差 0.27 / 1.39 / 0.18；理光差最大 = 它的 `split_cool=0.5562` 与
  三段 sat 被 recipe-fit 跳过）。⇒ 本卡链路与既有工具同口径，§3 的残差可直接与 R-1b 报告对比。
- **口径**：输入 = 场景线性反射率，`s = 0.1845·2^EV`（中灰 0.1845）；`uLocalStrength=0`（局部提亮只作用于暗区）、
  `uSharpen=0`、暗角/颗粒/清晰度 = 0、`[90..94]` = 0、`uGamut=1`（真机默认）。
  **未接入**：RAW 解码 / WB / CCM / LSC / HR —— 白点作用点在 CCM 之后，这些段只改变"反射率→EV"的标定，
  不改变 §0 的机制。
- **手算/引用（非本卡实测）**：§0 第 2 条的真机高光 EV（1.02 / 2.5~3 / 5.494）引自引擎注释里的真机日志；
  "反射率 0.9 = 白纸"是物理常识换算，本项目**没有**真机 RAW 高光分布统计 —— 这是本卡最大的证据缺口，
  建议补一张真机 DNG 的高光 EV 直方图卡来定最终白点。
