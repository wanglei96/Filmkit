# RAW D1 → Vulkan Hanatos：去掉六级水平中间图的实测

2026-11-26 · vivo V2509A / Mali-G1-Ultra MC12 · FilmKit 0.14.56（853）。目标不是把 GLES pass 原样搬成 Vulkan，而是减少实际写回，并以完整链路而不是单个 kernel 验收。

- **模式 2（现版数据路径）**：原 GLES P4、D1，成图分带读回交给 Vulkan Hanatos。
- **模式 5（直接共享对照）**：原 GLES D1 写入 RGBA16F AHardwareBuffer，Vulkan Hanatos 从同一图像采样，不 readback、不 blit。
- **模式 7（融合候选）**：仍用 GLES 做 RAW 和 D1，但把每一级完整 B3 的水平、垂直两轴与 detail shrink 放进同一个 compute dispatch。8×8 输出工作组按纵向 stride 的余数排列，从 8×12 个水平结果在组内取值；原顺序、每轴五 taps、FP32、六级、126 行最大 halo、边界 clamp、噪声协方差、门控和高光保护均保留。两组 RGBA32F ping-pong 记录粗色度和累计移除量，现有应用 pass 恢复 RGB 后写同一个共享图，Vulkan 继续原投影。FP64 光谱后段与 HDR 未改。这不是“D1 全改 Vulkan”。

模式 7 不再生成每一级的全带 RG32F 水平结果。以 3072×4080、四带含 halo 计，理论上删除约 **680 MiB 的纹理写入请求**，另删后续对该纹理的采样。它不是 680 MiB 的实测 DRAM 流量；计算版本还会在工作组边界重复生产部分水平结果，并有组间调度和显式屏障成本。

计时区间：`D1→投影` 从 CPU 进入 D1 到完整 Vulkan 投影与 FP64 输入转换就绪，包含此前排队的 GPU 尾部、提交、资源及等待；GPU 查询单独框住 D1，不加 `glFinish`，丢弃 disjoint；RAW 引擎总时间含 HDR 增益图，不含采集、App JPEG/R、MediaStore。此次显式关掉上轮直接路径误触发的诊断读回，并检索日志确认所有计时记录无该标记。取景为 30 Hz 合成交付，不是实拍相机预览。

## 48 张室内四帧 A/B/C

同一 3072×4080 室内四帧、8 位、HDR、颗粒及 PC3D 关、并发合成取景。每配方四个配对块，每块三条路线交错，每进程两张，共 48 张；所有起止均热状态 0、屏幕亮。全部 RGBA、增益图、回放 JPEG 在各配方内与现版的固定四帧哈希完全一致。下表为各组同张次中位数，单位 ms；GPU 查询第二张均 disjoint，不填入数字。

- **直接共享的收益可复现**：按同一块内配对差中位数，2→5 的 D1→投影首张／第二张少 **37／44 ms（Gold）**、**32／29 ms（Provia）**。Gold 四个比较块均正向，Provia 每个张次四块中三块正向。同期第二张引擎配对差约 **134／121 ms**，其中额外的百毫秒量级差值不能全部归因给共享；原因未锁定。合成取景 P95 未见一致性恶化。
- **额外融合没过门槛**：5→7 首张的 D1 GPU 区间配对少 **15／13 ms**，但 D1→投影的完整等待两配方首张均多约 **41–42 ms**，第二张 Gold 基本持平，Provia 少约 **11 ms**。第二张引擎组中位数 Gold 只快约 9 ms，Provia 慢约 2 ms。Gold 首张合成取景 P95 增约 5.6 ms。查询区间和提交墙钟不同，也会重叠，不能相减来断定某个驱动开销。这个结果不能外推为原生 Vulkan D1 已被测试或没有收益。
- 总体选择：**优先保留模式 5 做实拍候选，不将模式 7 接进正式 app**。模式 5 还需覆盖 Vulkan 设置冻结、互操作失败回退、跨尺寸和实拍取景；本轮不发包。若继续做原生 Vulkan 的更大区段，至少把 P4 输入到 D1/Hanatos 的整体依赖与 HDR 消费一并接通，不能仅搬 D1 然后增加一次往返。此次数据说明中间写回变少并不足以确保整链提速。

完整样本、配对差和有效查询数见 `test_temp/spektrafilm-vulkan-d1-fused-20261126/perf-summary.json`。性能脚本尾部在保存完整最后一组后因运行中编辑脚本而返回非零；保留原日志，已独立核对 24 组起止温度、交付、完整路径和全部输出哈希，质量批另起进程。
