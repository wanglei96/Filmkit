## 4. 方向性检查：中灰与高光

### 4.1 中灰（成片域，shader 实跑）

合成 EV 阶梯（`s = 0.1845·2^EV`，−6…+8 EV 步长 0.02）喂**真实 shader**，`0 EV` 处两引擎输出
**都是 118.992 LSB** ⇒ 判据②（≤1.3 LSB）在 shader 实测下**偏差 0.000 LSB** ✅。
这与 §5 的纯曲线口径（119.008 LSB）差 0.016 LSB —— 全部来自 **RGBA16F 纹理量化**，不是模型差异。

### 4.2 高光层次（ramp 口径；真实 ROI 无高光，见 §3）

同一 ramp 上两引擎的显示域 LSB（离线链默认 filmic 参数 `white_ev=4.56 / lat=0.01`）：

| EV | 引擎 0 filmic | 引擎 1 sigmoid |
|---|---|---|
| 2.30（白纸） | 207.51 | 203.59 |
| 3.00 | 230.09 | 221.74 |
| 4.00 | 251.35 | 238.54 |
| **5.00** | **255.00（死白）** | **247.35** |
| 6.00 | 255.00 | 251.52 |
| 8.00 | 255.00 | 254.29 |

- 首次"量化后不再增长"：引擎 0 @ **4.52 EV**，引擎 1 @ **6.22 EV** ⇒ 引擎 1 多保留 **1.7 EV** 层次。
- 每 0.1 EV ≥1 LSB 的可分辨跨度（从白纸 2.30 EV 起）：引擎 0 **1.80 EV** / 引擎 1 **2.00 EV**。
- 换成架构师的端到端口径（`white_ev=4.0` + M9 latitude）：引擎 0 = **214.06~215.36 LSB**（逐通道 latitude 三档）/
  跨度 **1.40 EV**；引擎 1 = **203.59 LSB** / **2.00 EV** —— 与架构师独立复跑（214.20 / 1.40 EV / 2.00 EV）
  一致（白纸差 ≤0.9 LSB，来源是**离线执行器只支持单值 latitude**（三通道同值），真机是逐通道 M9 值）。

### 4.3 GLSL 实现 == CPU 模型（独立验证，非任务书要求但能堵住"公式两处实现"的漂移面）

701 点 ramp，引擎 1 的 shader 输出 vs `tools/sigmoid-params-ref.py`：

| 量 | 实测 |
|---|---|
| 线性域最大绝对差 | **4.87e-4**（@ 2.60 EV；架构师独立复跑 5.91e-4，量级一致） |
| 8bit 最大差 | **0.0773 LSB**（架构师 0.0846 LSB） |
| 最大偏差 / float16 ULP | **0.998 ULP**；**超过 1 ULP 的点数 = 0 / 701** ✅ |

⇒ 差异**全部**来自 RGBA16F 纹理量化 ⇒ **GLSL 的 sigmoid 曲线 == CPU 数学模型**（`uSig*` 接线无错位）。
（灰阶输入下 hue-preservation 段是恒等：`chroma=0 ⇒ midScale=0 ⇒ correctedMid = perMid` ⇒ 本比对直接检验曲线本体。）

## 7. 未验证 / 已知边界（诚实标注）

1. **本机素材（整张 DNG）没有高光** ⇒ **判据① 的本机证据 = 合成 EV 阶梯（真实 shader 执行，§4.2）+
   纯曲线扫描（§5）**，**不是真实照片**。三个 ROI（书桌 / 白墙 / 暗区）的引擎 0 最大都在 175 LSB 以下，
   ≥200 LSB 像素 = 0；架构师独立复跑同一结论。**真实高光场景的验证只能归判据④（真机 A/B）** ——
   本报告不含"真实图像验证了判据①"这类主张（那会是假证据）。
   真实图像能提供的只是"**引擎 1 不劣化**"的佐证：三个 ROI 上两引擎 8bit 差的中位都在 0.6 LSB 以内
   （基线 ROI 0.12 / 白墙 0.58），中灰档 ≤0.016 LSB，且 NaN / Inf 全为 0。
   真机场景清单里"白瓷 / 白墙逆光 / 阴天天空"就是为补这一条。
2. **判据③ 不能用端到端（GL/RGBA16F）口径测**：float16 在高光端会量化出相等值 ⇒ 两端都会假报"非严格单调"。

### 9.4 用户观察："+1.5 EV 时杯口反光出现白带（两包均出现）"

技术判读（架构师，附量化）：

- **位置 = 釉面镜面反射**。陶瓷釉面是介电质，其镜面反射**本身就是无色的**（白）；0 EV 时它弱到
  被漫反射的红色压住，+1.5 EV 把强度 ×2.83 后显现出来。
- **+1.5 EV 是线性域曝光**（`EngineRegistry.cpp` 的 `ExposureDomain::kLinear`，与 PC 的
  `exposureCompensationDomain = Linear` 同约定）⇒ 反光处的**输入**被推到曲线的**高光端**。
- ⚠ **口径更正（架构师自纠 · 2026-10-14 用户质疑"新引擎不是没有白点吗"后重写）**：
  我先前写成"反光**越过白点**" —— **这是错的**：`sigmoid` **没有白点参数**（它是渐近曲线，
  `∞ → white_target = 1.0`；`EngineRegistry` 的 sigmoid 项也不含任何白点字段）。
  正确机制与"有没有白点"**无关**：**两条曲线都是饱和型** —— 输入足够大时输出都逼近显示白 1.0 ⇒
  镜面反射的无色光压过漫反射的红 + 高光去饱和 ⇒ 视觉白带。
  至于 `kFsOut` 的高光滚降，它作用在**输出域**（引擎输出之上），触发条件是"引擎输出接近 1.0"
  而不是"场景越过白点"。

  **两引擎的真正差别在"逼近显示白之后还有没有层次"**（`tools/sigmoid-criteria-scan.py` 实测，
  纯曲线口径，步长 0.02 EV 扫 −1.0~11.0 EV）：

  | 引擎 | 高光端行为 | 实测 |
  |---|---|---|
  | 引擎 0 filmic | **硬平顶**（白点是显式**输入端点**） | 非正差 **350** 处，**首次零差 @ 4.02 EV** ⇒ 该点之后层次**真的丢** |
  | 引擎 1 sigmoid (c=1.2) | **无端点、渐近** | 非正差 **0**，最小相邻差 **8.404e-06**（@ 11 EV）⇒ 到 11 EV **仍严格单调** |

  渐近实测（sigmoid c=1.2）：`f(+12 EV) = 0.999779`、`f(+20 EV) = 1.000000`
  （要到 +20 EV 才在 float32 分辨率下取到 1.0）。
  ⇒ 真机 +1.5 EV 下"**两包都出现白带**"是**预期一致**的（反光都被推近显示白）；
  但**引擎 1 的白带里仍有层次** —— 与真机实测吻合（同一场景 filmic 有 0.001 % 死白、
  sigmoid **0**）。**这正是判据①「可分辨跨度」的物理含义，也是引擎 1 的价值所在**：
  新引擎不是"不会出现白"，而是"**白区里还能分辨**"。
- **量化**：反光带内最亮的 R 通道 = **248（引擎 0）/ 243（引擎 1）**，均 **< 250**；
  整图死白占比 **0.001 % / 0.000 %**，clip% = 0 ⇒ **滚降正常工作，无硬截断**。
- **两包共有** ⇒ 属**公共链路**（线性域曝光 + `kFsOut` 滚降）行为，**不是引擎 1 的回归**。

**结论：白带是过曝 1.5 档的物理正确表现**（真实相机在 +1.5 EV 下同样会出现白色反光带），
**不构成验收不通过项**。但据此也说明：**该场景无法充分体现判据① 的优势** —— 若要拿到强证据，
需要真正过曝的场景（直射灯 / 窗）。
