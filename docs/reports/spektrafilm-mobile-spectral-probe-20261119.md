# Spektrafilm 移动端光谱归约与全链实测

日期：2026-11-19。设备：vivo X300（V2509A）。前半记录桌面参考、Android CPU 探针和隔离环境 D0 到 SDR 成片；这些阶段没有安装 APK 或改设置。后续 APK 实拍见末尾单列记录，不将隔离探针结论视为生产验收。上游固定 `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`。

## 结论

- 最新自研 C++ 单进程负片整链已在 X300 用自身颗粒和眩光随机采样跑通。人像全帧 4/8/8/4 线程为 17.990 / 14.259 / 14.339 / 17.982 s；固定 8 线程、只把空间滤波改成四线程后，同一二进制交错均值 14.095 → 11.783 s。优化前后的整帧 FP64 输出逐字节相同。该计时排除 RAW 前链、配置初始化、编码保存与 ADB，不是拍照延迟。
- 手机端可以避免整帧光谱缓冲而不减少波段或降低精度。4 线程探针对 12,533,760 像素执行 81 波段、FP64、逐像素归约；各用例与上游光谱阶段输出比较，非有限值和超过 `1e-12` 的分量数均为 0。该阈值仅用于本探针，不是 G1 的全链预算。
- 内存可行不等于保存可用。早期多线程单个内核的实测约 3.6–7.3 s；最新独立 C++ 整链仍超过 10 s，尚未包含相机前链。当前 CPU 路径应作为校验和优化基线，不宜直接作为默认相机实现。

## 桌面负片全链

- 复用上次真实 RAW 的 D0 场景线性 Rec.2020 输入。关闭 preview/LUT shortcut，固定曝光，Portra 400 + Endura。只把相纸曝光和扫描中的两个逐像素光谱函数按 32 行调度，调用的仍是原函数，保留整幅分辨率、全部波段/FP64、其余原始拓扑和空间处理。D0 数组顺序为高 4080、宽 3072。单个 32 行光谱数组约 60.75 MiB，原整帧单数组约 7.56 GiB；两者都不是进程总内存。
- 六个 tap 全部产出，最终 `rgb_out` 为 `(4080, 3072, 3)` FP64、全有限、非恒定；文件 SHA-256 为 `95375036f9bc879c1c776d1e679ef2becb5f283452a6767e2f1f6f62e4246c1d`。桌面 87.19 s（含导出和哈希），最大 RSS 3.40 GiB，峰值 footprint 9.69 GiB。
- 这是分条后的完整原版拓扑首次跑通该负片样本。此前整帧实现没有最终输出，故不能称最终 RGB 已过整帧逐像素对拍；随机场复现、配置覆盖和端到端误差预算也未验收。

## X300 全分辨率 D0 到成片

- 在 Android 的 shell 临时目录运行 ARM64 glibc / Python 3.13.12，版本对齐桌面 NumPy 2.5.5、SciPy 1.18.1、Numba 0.68.1、llvmlite 0.50.0、colour-science 0.4.7、pyFFTW 0.15.1。环境使用 OpenBLAS ARMV8、禁用 NumPy SVE、Numba generic CPU，以避开本次隔离环境中的指令分派错误。Numba 报 `/dev/shm` 信号量警告，测试为单进程 workqueue。
- 共用同一真实 RAW 派生的全尺寸 D0 场景线性 Rec.2020 D65，宽 3072 × 高 4080，SHA-256 `0452d6f65a738cc5908ab97036bc6f688697201d6255e4f65ce5768dbb86d450`。执行上游拓扑并在各阶段后释放已消费帧；关闭预览模式、放大机光谱 LUT 和扫描光谱 LUT。大帧光谱归约用 81 波段 FP64 NEON，小尺寸校准与空间处理仍为原函数。
- Portra 400 + Endura 固定曝光：六个 tap 全部有限且最终 RGB 非恒定。底片颗粒与相纸眩光均在手机生成。渲染含阶段验证、不含导出和 ADB，共 233.07 s，峰值 RSS 2,345,220 KiB（2.24 GiB），Android 热状态 0 → 2。预处理 / 底片曝光 / 底片显影 / 相纸曝光 / 相纸显影 / 扫描至编码分别为 2.84 / 17.73 / 41.96 / 3.65 / 0.25 / 163.87 s；两个光谱归约为 1.19 / 1.08 s，抽样相对原版最大绝对差为 3.33e-16 / 4.44e-16。该负片未测扫描内部耗时。

## 自研 C++ 显影曲线对拍

## 原版颗粒是否包含色度波动

针对用户对彩色颗粒的疑问，重新检查固定上游 `model/grain.py:145`：原版分三个染料通道、每通道三个子层独立调用颗粒抽样，种子为 `seed[ch] + sl * 10`，并不是往最终 RGB 叠同一张黑白噪声。当前 Portra 配方的颗粒面积系数为 `[1.6, 1.6, 3.2]`，均匀度为 `[0.97, 0.99, 0.97]`，最终 blur 为 0.65 px。三个通道密度经过相纸曝光、显影和光谱扫描后会产生 RGB 色度波动；此结论针对该原版模型，不是对所有颗粒模拟方法的概括。

新增可复现检查 `tools/spektrafilm-grain-colour-check.{py,cpp}`。使用线性 Rec.2020 纯灰输入 0.005 / 0.02 / 0.08 / 0.18 / 0.5，每张 256 × 256，物理像素间距固定为实拍的 8.578431 µm。自研直接加载 APK 的 Portra400 / Endura 配方；对照为未修改的固定上游。完整保留负片、相纸、扫描、色域和扫描滤波。只在诊断配置中分别开关颗粒，将相纸眩光 roughness 设为 0，保留眩光均值；没有传感器输入、JPEG 或 HDR。更改均在参数 digest 之后，避免被 stock-specific overrides 覆盖。

先在 Mac 构建自研，再直接链接当前 APK 构建的 ARM64 Spektrafilm 对象和 `libspektrafilm_exp10.a`，在 X300 运行同组纯灰测试。原版和自研各自抽样，不要求逐像素相同。剔除各边 16 px 后，对编码 sRGB 的开/关颗粒差值去均值，按 8 位码值计算 Rec.709 加权亮度标准差和 `sqrt(mean(Cb² + Cr²))`；此指标不是感知色差 ΔE。
