## 0. 结论先行

1. **口径核实：任务描述属实**。CPU 侧 `p4A/p4B` 是**逐通道、未预乘 luma 权重**的
   （`denoiseParams` :5809-5819），而 P4 shader 用 `dot(uNoiseA, LUMA)` 把三通道**按 luma 权重合并**
   （:784-785），再用这个标量去除一个**三维欧氏距离** `length(cd-cd0)`（:801）。
   两者不是同一个量，存在**系统性口径失配**。

2. **偏差的真实根源不是「忘了投影」，而是「用 luma 权重平均了色差噪声」**。
   等噪声（σ_R=σ_G=σ_B）时，正确因子 `3−2+3‖w‖² = 2.6858`，而 CPU 侧已有的 `2.25 = 1.5²` 标定
   ≈ 同一个数（差 9%）—— **所以这个失配在等噪声假设下几乎看不出来，历史标定"碰巧是对的"**。
   真机 WB 增益让 R/B 的 σ 达到 G 的 1.24× / 1.94×（203843，y0=0.12，g=(1.49, 1, 3.24)）后，
   `Σwⱼσⱼ²`（G 占权重 71.5%）与 `Σcⱼσⱼ²`（G 只占 4.9%）彻底分道扬镳。

3. **量化偏差：引擎的 σ 相对"统计自洽"的色差噪声尺度偏小 2.0~2.3×（解析口径）**；
   计入实测的色度噪声空间相关后是 **1.7~1.8×**。逐像素比值 P50/P90/P99 见 §3。
   D-1 的偏差**不对称**：`var(B−Y)` 路径 1.71×、`var(R−Y)` 路径 1.06×（ISO 445）——
   这正是"彩噪偏蓝紫"的算术来源。

4. **修正方向是「降噪变强」**（σ 变大 ⇒ `wc = ‖Δ‖/sc` 变小 ⇒ 权重变大）。
   203843 离线（mix=1.0）：平坦区 σ(B−G) 0.00461→0.00225，2px 色度带通 −53%，
   代价是真实色度边缘梯度保留 0.870→0.782、边缘色度改动量 +68%。

5. **建议：不要"只改形式保留 2.25"（那等于 σ×2.0~2.3，与 v0.10.119 被真机否决的修正同向且量级相当）。**
   若要动，只有两条可辩护的路：
   **(a) 改形式 + 同步取消 1.5² 标定** ⇒ σ×1.35~1.56（三图），净变化温和；
   **(b) 优先修 D-1 的 `B−Y` 路径**（不对称偏差、且对症 4-32px 色块）。
   无论哪条，按项目铁律都必须真机 A/B 实测后再定。

6. **反方证据很强**（§6）：真机 P4 的输入已被 MFNR（÷4 方差）+ P0 降噪，而 σ 用的是**融合后未再降噪**的理论值
   ⇒ 真机的"σ/实际残余噪声"比我的离线估计**更大**，现状未必如离线所示那么"欠降噪"。
   加之去马赛克后色度噪声强空间相关（ρ̄≈0.85），"正确"值本身有 1.7~3.2 的区间。

## 2. 正确形式推导

### 2.1 P4：三维投影口径

设 `c = c₀ + ε`，`ε` 为通道噪声（协方差 `Σ`），`W = 1·wᵀ`（每行都是 luma 权重），则
`cd = c − y = (I−W)c`，`cd − cd₀ = (I−W)(c−c₀) = (I−W)Δε`。于是

```
E‖cd − cd₀‖² = E[Δεᵀ(I−W)ᵀ(I−W)Δε] = trace((I−W)·Cov(Δε)·(I−W)ᵀ)
```

**(a) 邻居噪声独立**（`Cov(Δε)=2Σ`，`Σ=diag(σⱼ²)`，通道间不相关）：

```
E‖·‖² = 2·Σⱼ σⱼ²·[(I−W)(I−W)ᵀ]ⱼⱼ = 2·Σⱼ σⱼ²·(1 − 2wⱼ + ‖w‖²)
```

- `w = (0.2126, 0.7152, 0.0722)`，`‖w‖² = 0.56192264`
- 权重向量 `c = 1 − 2w + ‖w‖² = (1.13672264, 0.13152264, 1.41752264)`
- **不需要协方差项**：只有 `(I−W)(I−W)ᵀ` 的**对角元**被 `σⱼ²` 取到，非对角元乘的是 `E[εᵢεⱼ]=0`。
  但**若通道间相关**（CCM 混色、去马赛克残留），则 `E‖·‖² = Σⱼ σⱼ²‖(I−W)M eⱼ‖²`，必须带 M。
- 等噪声下 `Σcⱼ = 3 − 2 + 3‖w‖² = 2.68576792` ⇒ σ 比 `√2.6858 = 1.6388`。
  **注意 `2.25 = 1.5²` 与之只差 9%** —— 这是全文最关键的一个数字。
- **G 的系数只有 0.1315**（luma 里 G 占 0.7152，`c−y` 把 G 分量几乎消掉），
  R/B 的系数 > 1（几何上 R/B 在色差里被"放大"）。引擎的 `Σwⱼσⱼ²` 恰好相反：G 占 71.5%。

**(b) 邻居噪声不独立**（实测，见 §3.3）：`Cov(Δε) = 2(Σ(0) − Σ(k))`，可写为

```
E‖·‖² = 2·Σⱼ σⱼ²·cⱼ·(1 − ρ̄ⱼ)  ⇒  定义 f = 2(1−ρ̄)（8 邻居按空间核加权平均）
```

### 2.2 D-1：二维 `(B−Y, R−Y)` 口径——**两路不对称**

```
B−Y = (1−w_B)B − w_R·R − w_G·G
R−Y = (1−w_R)R − w_G·G − w_B·B
```

独立假设下：

```
var(B−Y) = 0.045199·σ_R² + 0.511511·σ_G² + 0.860813·σ_B²    (系数和 1.417523 = c_B)
var(R−Y) = 0.619999·σ_R² + 0.511511·σ_G² + 0.005213·σ_B²    (系数和 1.136723 = c_R)
引擎用    = 0.212600·σ_R² + 0.715200·σ_G² + 0.072200·σ_B²
```

- 系数和恰好等于 P4 的 `c_B / c_R` —— 两处同源，**D-1 只是 P4 三维口径丢掉了 G 那一维**。
- **`var(B−Y)` 与 `var(R−Y)` 不相等，而 shader 里 Cb/Cr 共用同一个 σ**（:994/:998）——
  这是 D-1 的第二个结构性问题（第一个是合并权重）。
- 等噪声下 `var(B−Y)/引擎 = 1.4175`、`var(R−Y)/引擎 = 1.1367`。

### 2.3 与 `/tmp/phase4b/REPORT-4b-precheck.md` 口径的区别（必须说明）

| | 4b 报告 | 本报告 |
|---|---|---|
| 色度参数化 | **标量** `R−G`、`B−G`（两条独立通道差） | P4：**三维** `c − y`；D-1：**二维** `(B−Y, R−Y)` |
| "正确"表达 | `Var(R−G) = g_R²σ_R² + g_G²σ_G²`（简单和，无投影） | `(1−2wⱼ+‖w‖²)` 加权（含 luma 投影） |
| 被比较的"旧式" | `σ̂² = (g_R²+g_G²)σ0²/2`（三通道等噪声代理） | `Σwⱼσⱼ²`（luma 权重合并） |
| 结论 | 旧式对 G **高估 49.8–119.1%**、对 R 低估 19.8–25.3%、B −63.1%~+8.4% | 引擎 σ 偏**小** 2.0–2.3×（正确/引擎） |

**共同根源**都是 WB 增益让三通道 σ 不等；**但数学后果不同**：
4b 的"旧式"是**对某个通道的等效 σ 估计偏差**（可正可负），本文的偏差是**合并权重选错**
（G 权重 0.715 vs 0.132），方向恒为"低估色差噪声"。**4b 的百分比不能套用到引擎上**，
两者分母不同（一个是"通道 σ 的等效值"，一个是"色差向量的尺度"）。

## 3. 量化偏差（真机 DNG + 真机日志系数）

### 3.1 方法与假设

- **像素数据**：`rawpy` 重建 `output_color=sRGB, gamma=(1,1), no_auto_bright, output_bps=16`，
  `user_wb` = 该图实测 WB 增益，去马赛克 AHD（另做 LINEAR/DCB 敏感性 ⇒ §3.3）。
  即近似"CCM 后的场景线性 RGB"（P4 的输入域）。
- **系数**：ISO 与 WB 增益从 DNG 元数据取（`ISOSpeedRatings` + `AsShotNeutral` 反推），
  用内置主摄模型解析式复现 `p4A/p4B`（已用日志逐位验证，误差 <0.4%）。
  **σ 与 DNG 单帧匹配 ⇒ 用 `neff=1`（×4）**；比值与 `neff` 无关（A、B 同乘 1/neff）。
- **ISO**：203843 = ISO 445（与 `filmkit-logs-20261004-203904` 的 ISO 445 同批）；
  182547 = ISO 161；162411 = ISO 50（后两张无同时刻日志，系数由模型解析式给出）。
- **glY = 1**（画面中心口径；LSC 网格值未下发到日志，仅知 center=1.000 / corner=6.0~6.2）。
  glY 同时进入两个口径，对**比值**的影响是把 B 项占比推高（比值趋向纯 B 项极限，1.6~3.0），方向不变。
- 有效像素掩码：`2e-3 < y0 < 0.9`。

### 3.3 关键对抗性自检：色度噪声的空间相关（推翻"独立"假设的一部分）

方法：平坦区，**16×16 块常数去趋势**（保证块内差分无偏），按 P4 的空间核权重
（σ_s=2.2）加权 48 个邻居，测 `R_meas = E[Σw_s‖cd(p+d)−cd(p)‖²/Σw_s]`，
与独立假设预测 `2Σcⱼσⱼ²`（逐像素 `y0`）相比，得 `f = R_meas/预测`：

| 图 | AHD | LINEAR | DCB | 等价 ρ̄ = 1−f/2 (AHD) |
|---|---|---|---|---|
| 203843 | **0.299** | 0.493 | 0.387 | 0.85 |
| 182547 | **0.368** | 0.616 | 0.478 | 0.82 |
| 162411 | **0.328** | 0.474 | 0.355 | 0.84 |

独立判据旁证：色度差通道 lag-1 自相关 ρ₁ = **0.66~0.70**（`noise_corr.py`），
lag-1 差分 σ 只有单像素 σ 的 **0.55~0.58**（独立时应为 1.0）。
即**去马赛克后的色度噪声是强空间相关的**，"独立假设"的 σ 会高估 1.3~1.9×。
（`LINEAR` 相关性最弱 f≈0.5，因为双线性不额外平滑色度。）

**同时排除一个反方假设**：去马赛克（插值平均）是否把色度噪声降低了，从而让 raw 域模型高估？
实测 203843 白墙 `σ(R−G)=0.0083`（去低频后），raw 域理论 `√(σ_R²+σ_G²)=0.0094`
（去趋势衰减 ~6% 后应约 0.0088）—— 两者一致，**未发现去马赛克额外降噪**。该反方假设不成立。

## 5. 结论与建议

### 5.1 这个偏差值得修吗？

**事实层面**（可辩护）：
- 口径失配**客观存在**，且是"用 luma 权重平均色差噪声"这一结构性错误，不是标定偏差。
- 偏差量级：**σ 偏小 2.0~2.3×（解析/单像素口径）**，1.5~2.0×（含 CCM 混色），
  1.7~1.8×（含实测空间相关）。**这是本次最硬的结论**（系数经日志逐位验证、比值由系数决定）。
- 偏差随 WB 增益与 ISO 增大，且 **`B−Y`/Cb 一路最严重**，与"蓝紫色噪/色斑"的现象吻合。
- 收益侧：203843 平坦 σ(B−G) 可再降 51%、2px 色度带通再降 29pp。
- 代价侧：真实色度边缘梯度保留 0.870→0.782，边缘 ΔC +68%（离线、mix=1.0、单帧、无 D-1）。

**判断层面**：
- **不建议"只改形式、保留 2.25"**：那是 σ×2.28。项目里最近一次同向修正
  （:788-790，v0.10.119 "A 项乘 glY"，边缘 σ×1.7~2.2）被真机实测否决
  （降噪 21~32%→43~62%、发糊、色块无改善）——**本文的修正量级与它相当或更大，且是全图的**。
  在没有真机 A/B 数据前，重复这个动作是不负责任的。
- **若要动，两条可辩护的路径**：
  - **(a) 改形式 + 同步取消 1.5² 标定** ⇒ σ 净 ×1.35~1.56（≈`indep_no225`；203843 = ×1.56）。
    这是"先把 1.5 这个经验补偿从公式里拿掉、由投影因子自然承担"的最小自洽改动。
    离线代价：边缘保留 0.870→0.816，收益：平坦 σ(B−G) 0.00461→0.00329。
  - **(b) 先修 D-1，而不是 P4。** D-1 管 4-32px（用户抱怨的"色块"尺度），
    且偏差**不对称**（Cb 1.71× / Cr 1.06×）。把 `oSigma` 拆成两路：
    `σ_Cb = √(0.0452σ_R²+0.5115σ_G²+0.8608σ_B²)/2`、`σ_Cr = √(0.6200σ_R²+0.5115σ_G²+0.0052σ_B²)/2`
    —— 只影响蓝色色斑方向，风险面比动 P4 小得多，而且**正对症**。
    这也与 v0.10.120 的教训一致：**σ 的量级不是"色块"的根因，但 σ 的"分路结构"是。**
- **无论走哪条**：按项目铁律（`AGENTS.md`：性能/取舍必须实测、不许拍脑袋），
  必须真机同场景同 ISO A/B，用日志 + 目视判定后再定。离线数据只能决定"值不值得试"，
  本文的结论是：**(a)/(b) 值得各做一次真机 A/B；(a) 单独做必须带 (b) 或先做 (b)**。

### 5.2 一个必须写下来的副产品洞见

`2.25 = 1.5²` 与等噪声下的正确因子 `2.686 = 1.639²` 只差 9%。
**换句话说：现在这套公式在"三通道等噪声"的假设下几乎是对的，它只在 WB 增益把三通道噪声拉开时才失效。**
这解释了为什么这个问题长期没暴露（离线调参多半在中性/等噪声假设下做），
也说明修它必须**用真机 WB 后的系数**去验，不能用"典型 σ"。

## 6. 反方证据：如果本文结论错了，最可能错在哪

按"最可能"排序：

1. **P0 / MFNR 的存在会让"σ 偏小"变成"恰好"（最可能出错处）。**
   日志实测 `p4A = S·g·2.25/4`，即 σ 是**4 帧融合后、未再降噪**的理论噪声；
   而 P4 的输入已经过 P0（RAW 域 9 邻域 bilateral）+ MFNR。
   ⇒ 真机 P4 输入的实际残余噪声**低于** σ 所描述的值，`d/σ` 被系统性**缩小**，
   等价于"降噪比名义更强"。这与"σ 偏小 ⇒ 降噪偏弱"方向相反，可能已经抵消了本文指出的偏差。
   **本文无法验证这一点**（需要真机 P4 输入纹理或 P0 前后统计），只能标为最大不确定性。
2. **空间相关结构随算法/上游变化。** 我实测 `f=0.30~0.62`（AHD/DCB/LINEAR），
   真机是 RCD + MFNR + P0，其 ρ̄ 未知。若真机 ρ̄ 更低（f→1），"正确/引擎"回到 2.0~2.3；
   若更高，则更低。**"正确"值本身有 1.7~3.2 的区间**，我给的是包围范围而非点值。
3. **CCM 口径不确定。** 引擎实际 CCM 由 Kotlin 侧按 AWB 插值给出，日志只留 `fm1/fm2`。
   `b_ccmF1` 与 `b_indep` 差 15~25%（1.52~2.29 vs 2.03~2.35）。若真机 CCM 更接近 fm1，偏差偏小。
4. **域混用（既有 S4 问题）。** `p4A/p4B` 是 **raw 域**（demosaic 前、白点 1.0）系数，
   而 `y0` 是 **CCM 后 sRGB 线性**的 luma。203843 白墙 raw 域 G≈0.204 vs CCM 后 y0≈0.15
   （量级差 ~1.3×），会让 A 项贡献被低估、比值略偏高（估计 <5%）。这个混域本身是独立缺陷。
5. **离线复现的简化。** 未复现 D-1/defringe/P0/MFNR；单帧 + 单帧 σ；AHD 而非 RCD；
   `glY=1`。这些都会改变**绝对**数值，但对"eng vs indep"的**相对**比较影响有限
   （两者共用同一输入与同一 σ 结构）。若某条简化对两个变体的影响不是同向的，结论可能被削弱。
6. **真机 JPG 交叉检查（仅定性，不可定量）。** 203843 成片白墙的 `σhp(R−G)/σhp(Y)=0.494`，
   低于我离线 `indep` 变体的 0.716、远低于 `ref` 的 1.518；而其**等效线性彩噪**
   （0.00495 / 0.00743，按 sRGB OETF 局部斜率折算）更接近 `eng`（0.00541/0.00879）而非 `indep`
   （0.00382/0.00580）。两种读法指向不同结论（总量 vs 绝对量），且受 filmic/锐化/JPEG 干扰
   （真机 Y 的高频噪声被放大，折算斜率在暗部误差可达 2×），**故不作为证据，只作提示**：
   真机链的色度降噪总量可能已不低，加强 P4 的边际收益应打折。

## 7. 未验证项清单

1. **P0 与 MFNR 对 P4 输入噪声的实际降幅与相关结构**（最关键，未验证）。
   日志只有 `p0s=96` 等计数，没有 P0 前后的 σ 读数。
2. **真机 RCD 去马赛克后色度噪声的 ρ̄ / f**（未验证；本文用 AHD/LINEAR/DCB 代替）。
3. **引擎实际使用的 CCM 矩阵**（未验证；用日志 `fm1/fm2` 做包络）。
4. **LSC 增益网格的真实逐像素分布**（未验证；`raw.lsc` 只给 center/corner，
   glY 用 1，故画面边缘的 B 项放大未计入）。
5. **D-1 的实际滤波效果**（未离线复现 à trous；本文对 D-1 只做解析推导，无滤波对比）。
6. **defringe（v0.10.134）与 D-1 对"边缘 ΔC"的贡献**（未离线复现，边缘指标只反映 P4）。
7. **真机 JPG 与离线变体的定量对齐**（未验证；tone curve/LUT/锐化/JPEG 均未建模，
   折算斜率误差可达 2×）。
8. **合成数据未使用**：本文所有像素统计均来自真机 DNG；但**去马赛克与域重建**是
   `rawpy`+`fm1/fm2` 近似，不是引擎本体（无法在真机中间域取数）。
9. **未做真机 A/B**：本文全部结论是离线推断，不含任何真机实拍对照。
