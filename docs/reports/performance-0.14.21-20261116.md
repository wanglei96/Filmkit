# 0.14.21：PC3D 六分量累加候选与真实无短帧回归

## 结论

0.14.21 / 818 是性能实验候选，**不能记为全面性能优化已完成**。
有接受短帧的局部协方差路径，App 三张样本的 PC3D 中位耗时减少约 273ms；
但无有效短帧的真实照片回放，PC3D 中位耗时增加 **126.1165ms / 33.36%**，
六组双向配对全部同方向。质量回归中的输出相同，不等于性能没有退化。

用户选择“先测该分支真实照片，不拆程序”。本次未拆 shader/program，未新增生产改动、
未出 0.14.22 包。手机保留已安装的 0.14.21 实验候选，不能据此默认为用户已接受取舍。
出片 3--5s、最好不超过 4s、取景器几乎不掉帧的目标仍未达到。

## 唯一生产算法表达改动

`FrameRenderer.cpp::kFsPc3d` 将两个对称协方差矩阵的累加器从各九个分量改为各六个
独立分量，输出前重建完整对称矩阵。仍保留六个分量、完整逐样本矩阵更新表达式、
原累加顺序与输出 Jacobian 噪声传播。没有减少帧数、核尺寸、采样或精度，
没有改短帧准入、RAW/降噪/色彩/高光政策，也没有复用前一张统计。
本项目成像链显式不采用 ponytail 方法论。预览与 `drawStriped` 没有最终代码改动。

独立工具尝试过常量 local-noise、成对距离求解、中心协方差外提、固定核尺寸，
均没有证明局部协方差主路径加速，因此未进入生产。程序 binary 长度不是寄存器
spill 证据，当前也没有用计时器 disjoint 样本声称纯 GPU 指令成本。

- 真实采集时间：2026-11-16 14:48:56.709，原诊断照片对应四帧 RAW，长焦镜头 3。

- 原日志实测 EV 为 `[0, 0, 2.2, 0.662]`；最后一帧并非更短曝光，未修改元数据伪造分支。
- 使用原留存 replay 标定，含 black/neutral/CCM/noise/17x13 LSC。
  部分标定和 EV 原本来自日志舍入值，不声称逐位复现原理光预设成片。

  不运行实时预览、不启用阶段 dump。实际加载 SO 的 SHA256 与 20/21 APK 内 SO 分别一致。

## 独立 GPU 用例与计时口径纠正

最初 local0 工具仍绑定三个 MRT，而生产 local0 只写一个颜色目标。
早期约 3ms 差值、1024/反向顺序/首份 3072 的 local0 结果都不能作为生产匹配结论。
用户质疑成立。工具现将计时 FBO 区分为 local0 单颜色、local1 三附件；
原生字节校验仍单独覆盖 RGBA16F 与两个 RGBA32F 附件。

纠正后 3072 平方、核 11、16 条带、三组 ABBA，每版每条件六样本：
moire0 为 126.842496 -> 174.320192ms，moire1.5 为 127.882048 -> 176.205120ms。
这只是独立合成 shader 每趟耗时，不能直接换算整张照片；上述真实全链已经另测。
GPU timer 配对样本均 disjoint，只使用含 glFinish 的墙钟，不报告纯 GPU 时间。

local1 的三附件配置原本正确。1536 平方、五组 ABBA：
moire0 175.586 -> 155.132ms，moire1.5 214.944 -> 184.345ms，全部原生附件字节相同。
直接使用最终候选源码的 512 平方矩阵覆盖核 7/11/21、local0/1、两种 moire，
72 项原生附件比较通过，144 次读回。这是覆盖范围内的验证，不是全输入数学证明。
