# 徕卡一瞬 0.12.90：真机"艳俗 / 不油润"诊断与重标记录

日期：2026-10-26。触发：用户 4 张成片（`test_temp/FILMKIT_20261026-*_徕卡M9CCD.jpg`）反馈——
"观感很艳俗，没有油润厚重感，彩噪有变好"。

## 1. 先说一个会让验收失真的硬问题（已修）

日志 `filmkit-engine-20261026.log`：4 张里只有第 1 张（095908）跑在 0.12.89 的影调上。

| 张 | 名字 | raw.render blackEv/whiteEv | 结论 |
|---|---|---|---|
| 1 | 095908 | **−4.879 / 4.0** | 预设生效 |
| 2 | 100003 | −7.801684 / 4.564171 | **掉回代码默认** |
| 3 | 100030 | −7.801684 / 4.564171 | 同上 |
| 4 | 101130 | −7.801684 / 4.564171 | 同上 |

根因：`setFilmParams` 写入预设 `[37]/[38]` 后，同一调用链里的 `applyZebraPref()` →
`applyFilmicRangePrefs()` 首次从设置页 prefs 读值并把预设值**无条件冲掉**。只在冷启动
（相机/Activity 重建）后第一次 `setFilmParams` 触发——用户拍完第 1 张看相册再回相机，后
3 张就都用了默认黑白点。修复：`setFilmParams(..., presetFilmicEv)` 显式携带预设黑白点，
`applyFilmicRangePrefs` 让预设优先（用户改设置页滑杆时再让 prefs 赢）。

样张 = `docs/research/leica-m9-samples/`（Xiaomi 17 Ultra by Leica 水印；**是否全部

## 7. 0.12.92：M9 的"适度压暗"复核

用户 2026-10-27 质疑"M9 不是应该适度压暗吗"，复核三条独立依据：

1. **爱范儿 M9 配方拆解**（1650532，2026-01-04）：亮度 −50、光感 −25、白色色阶 −20、
   黑色色阶 +15、褪色 +15、晕影 −15 —— **压暗 + 压高光 + 提黑位**是"德味"的前两步。
2. **19 号调研 M9 指纹**（11 张样张）：黑位 p25≈21（紧）、高光 p95=165（压缩狠）、
   ≥240 仅 0.1% —— 整体亮度偏低。
3. **本机样张库 20 张（小米徕卡一瞬）L\\* 中位**：p5=4 / p25=7 / p50=28 / p75=52 / p95=80。
   我们的徕卡成片：阳台 p50=33（接近）、楼顶 44、室内 71~（偏亮）。
4. 同机位对照：徕卡比标准暗 3~6 LSB，但**压暗量不足以覆盖室内/中性场景**。

结论：M9 的观感是"偏暗 + 高光低 + 暗部紧而不死"，我们的预设此前主要动饱和/曲线，
**没有把整体曝光压下来**。0.12.92 增加预设曝光偏移 **−0.3 EV**（`[0]`，叠加在用户 EV 上），
并把高光饱和收到 **0.65**、LUT 强度回到 **0.82**、暖调 **+1.5 mired**。

高反光紫边/灰块（14:24 室内橱窗）定性：LUT 的 M9 矩阵在高亮饱和色**过冲**
（实测：输入粉红 sRGB (1, .55, .72) → 矩阵输出 R=1.47 / G=−0.02），裸 clip 把 G
钉到 0 ⇒ 荧光品红 + 高光紫边。这是**资产层问题**，只在强反光高饱和区出现。

## 8. 0.12.93：LUT 重烘（保色相色域压缩 + 128³）

用户 15:15 两张室内图仍反馈"莫名其妙的紫红观感"。检查确认：中性区不偏色
（a≈2.3 / −0.6），偏品红的是**高饱和红/粉物体**（色相直方图 270–330° 占 22–32%），
即 LUT 的色相过冲，不是白平衡。

修法：`tools/bake-m9-lut.py` 在矩阵输出后、落界前插入 `gamut_clip_linear`
（darktable gamut_mapping 同型：保亮度/色相，把色度向 luma 收敛到刚好入界）。
**必须先 gamut 后 clip** —— 先 clip 会把过冲信息丢掉，压缩无从谈起。

- 64³ 装不下压缩后的陡斜率（判据 1 max 20 → **87 LSB**，会出现色带）⇒ 升到 **128³**：
  判据 1 max **45.03** / mean **0.12** LSB，灰轴 1.58，端点保黑保白；
- 采样对比（LUT 输出 sRGB）：

| 输入 | 旧 64³（裸 clip） | **新 128³（gamut 压缩）** |
|---|---|---|
| 粉红 (1,.55,.72) | 255, 0, 207（荧光品红） | **255, 102, 189**（正常粉） |
| 绿高光 (0.2,1,0.35) | 0, 255, 0（荧光绿） | **247, 255, 247**（高光去饱和） |
| 肤色 (0.85,.62,.55) | 247, 143, 122 | 248, 143, 122（不变） |

- 预设 LUT 强度 0.82 → **0.75**（矩阵对红/粉的品红倾向是 M9 配方固有，用强度控制混合）；
- 资产 786 KB → 6.3 MB，APK +5.5 MB（引擎 MAX_SIZE=128 支持，显存 128³×8=16.8 MB）。

## 10. 0.12.96：细小灰斑 —— 0.12.14 的历史同型坑在 LUT 层重演

用户提示"查历史，做 sigmoid / 曝光重做时解决过一次灰斑"。查到
`docs/reports/highlight-chain-CHECKLIST.md:30`：**0.12.14（2026-10-22）"镜面反光 / 灯面 /
窗帘反光的灰块"**，用户当时原话"灰块应该是彻底解决了"。根因（`FrameRenderer.cpp`
v0.12.14 注释）：RAW 域 allSat 重建拿**满阱亮度 lc**（与场景无关的常数）当锚，把真实
亮度远高于此的像素钉死在 lc ⇒ 压成灰；修法是改用**实测 lv**。

这次是完全同型的坑，只是发生在 LUT 层：gamut 压缩用 `Yc = clip(Y, 0, 1)` 当锚，
Y>1 的高光被钉死在 1.0、色度压到 0 ⇒ 输出 (1,1,1) 灰白斑（用户 0.12.93 起观察，
亮度 L* 94–96、RGB≈240 的细小灰点，就在黄/粉高光处）。

**0.12.96 修法**：高光**去饱和**而不是压到边界 —— 越界量 `t = max(RGB) − 1`，色度只
收 `t × 70%`（最多 70%），不推到 0。不钉死亮度、也不硬压色度：

| 指标 | 0.12.95（压到边界） | **0.12.96（去饱和）** | 0.12.92（64³ 无压缩） |
|---|---|---|---|
| 判据 1 max | 45.03 LSB | **18.46** | 20.20 |
| 格点跳变 | 142.6 | **54.5** | 56.7 |
| 粉红高光 (1,.55,.72) | 255,102,189 | **255,89,193** | 255,0,207（品红） |
| 红 (1,.15,.2) | 227,0,93 | **252,0,84** | 255,0,38 |

预设参数**一个没动**（曝光 −0.3、白点 4.2、sat 0.76/0.76/0.65、halation 0.05、暗角 −0.24
全部保留），只换 LUT 资产；拍照链残差 3.26（0.12.95 为 3.26）。
