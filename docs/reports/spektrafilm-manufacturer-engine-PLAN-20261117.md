# Spektrafilm 基础引擎与厂商直出风格方案

初稿：2026-11-17。执行修订：2026-11-18。**Spektrafilm 作为独立、可选的风格引擎接入；不再逐预设排名画质收益，也不以胜过现有引擎为准入条件。** Filmic V7 优先开工，不依赖本方案过门。未决定默认切换、旧配方迁移或发布范围。

总体设计见 `docs/reports/filmic-v7-spektrafilm-roadmap-DESIGN-20261117.md`；本方案保留原有算法和产品接入技术设计。§7 的旧厂商比较方法留作历史研究资料，不列入接入排期；有明确命名或复刻目标时才补相应证据，不为 S 重新标定所有现有配方。

本次在原结构内补齐随机复现、桌面与真机两道决策门、输入和评分冻结及分发前置检查；保留既有研究和算法路线，不另起一份 Spektrafilm 方案。待确认项集中在 §16，不能把设计建议写成用户已拍板。

## 1. 目标与建议

目标是提供可选的胶片、印相与扫描风格。引擎负责场景到成片响应；如特定配方另外组合厂商 LUT，明确其域和作用阶段。没有证据不宣称复刻厂商静态直出。

保留 Filmic / sigmoid 及旧配方原样，新增独立 Spektrafilm 风格及私有配置；不要求给每套旧配方找替代。

- 引擎按上游完整模型实现，注册为 slot=2；不烘焙成替代引擎的一张或两张 3D 外观 LUT。
- 原版 Portra 400 + Portra Endura 用于正确性基准，不预先指定为所有厂商风格的底座。
- 厂商配方由“引擎配置 + LUT + 有明确作用域的后处理”共同构成，并一起版本化。
- 先用原版完整运行结果建立证据，再选择参数；不根据成本预删显影、空间作用或光谱计算。
- 首批按上游 stock、相纸/扫描路径与资产可分发性定义风格；不以富士、理光等厂商教师收集作为接入前置条件。
- 保留上游一致性、完整链路、真机缺陷和资源验收；不做感知收益排名。

已经明确的方向：性能专项暂停，参考权威改为 Spektrafilm 原版，产品目标是厂商成片风格。本文其余具体技术选择是建议，不冒充用户已拍板。

当前可推进的论证层级分开记录：原版完整实现是否正确、某预设是否更接近目标、手机能力是否足够、承诺的产品范围是否闭环。四者分别验收；“跑通原版”“桌面更好看”“设备能出一张图”都不能单独证明可发布。完整参考包含固定提交的正式拓扑与相关有效参数分支，不仅跑默认配置；产品允许按已验证配方选择参数，不预删原版能力。

用户没有厂商相机或自备样片。公开数据搜集、核验、下载与标注由实施方完成，购买/借用相机和用户补拍都不是前置条件。

### 保留的研究边界

1. 产品定位是新增风格，不把风格差异当成画质收益。
2. 非配对 JPEG 不能反推出唯一场景响应；全图直方图/平均饱和差异不作为定量标定目标。
3. 原样保留现有 LUT 与引擎绑定；新风格使用明确且版本化的配套资产。
4. 官方 Log→成片 LUT 是参考渲染，不一定是可叠加的显示域风格层，禁止重复 tonemap。
5. RAW 预览、新线性底片和 HDR 双 view 分别评估，不作为离线收益验证的前置条件；既有模式的安全边界仍须接通。

## 2. 已核对的依据与边界

FilmKit 基线为 `dev@debf304`，最近生产代码提交为 `9613b51` / 0.14.25(822)。本次开始时工作区干净。

以上是原方案编写时的历史基线。总体设计复核时为 `dev@fc8e5547e681064fd7b4f4d06c3fea6dc44eca46`，0.14.27 / 824，`FilmParams::kCount=105`，工作区有未提交 CS/CM 等改动。后续实验须固定实际 diff、资产和输入 hash，不能按原历史基线复现当前行为；当前 CS/CM 边界见 `purple-lampshade-20261117.md` §18。

Spektrafilm 上游检出固定为 `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`。来源：`https://github.com/andreavolpato/spektrafilm`。方案中的“原版”均指该固定提交，升级须单独回归。

需要修正旧交接中的几项限定：

| 旧假设 | 本方案口径 |
|---|---|
| 65³ film/print LUT 是既定实现 | 不采用作为引擎实现的前提，保留完整运行阶段 |
| 引擎必须输入和输出线性 ProPhoto | 上游支持指定 RGB 色域；FilmKit 可直接配置线性 Rec.2020 输入，输出适配目标 LUT 的域 |
| 首个产品目标是 Portra 400 | Portra 是正确性基准，首个产品目标建议为理光负片 |
| 新引擎只需注入 GLSL 字符串 | 原版有邻域和随机运算，需要独立的多阶段资源与执行入口 |
| 跟随 PC 默认加 +0.7 EV | 不照搬；设备曝光基准、虚拟胶片曝光和相纸曝光分别定义、只应用一次 |

Spektrafilm 的输入仍是三通道相机图像。光谱重建是模型推断，不会恢复传感器没有记录的真实场景光谱，也不等于掌握厂商私有 ISP。其优点是否能转化为厂商风格相似度，需要验证。上游也明确说明部分染料吸收采用通用数据，部分 coupler 参数属于模型标定；“基于物理”不等于所有参数都来自完整实测。

## 3. 目标链路

```text
RAW 采集 / 多帧融合 / 高光恢复 / 去马赛克 / WB / CCM / 降噪
    -> 场景线性 Rec.2020，保留真实 >1 高光
    -> 所选基础引擎（以下展开完整 Spektrafilm 分支）
    -> Spektrafilm 胶片曝光
    -> 胶片显影、层间作用、空间扩散、密度颗粒
    -> 放大与相纸曝光
    -> 相纸显影
    -> 扫描、色适应、输出色域处理
    -> 厂商 LUT 指定的色域与编码
    -> 厂商风格 LUT
    -> 配方明确规定的末端处理与交付
```

前端 RAW 质量链继续承担正确的重建、色准和噪声处理。Spektrafilm 替换 filmic/sigmoid 所在的基础渲染职责，不叠在已完成 filmic 的画面之后。

原版默认完整模型包括以下阶段：

| 阶段 | 必须保留的内容 | 不可替代为 |
|---|---|---|
| 输入与曝光 | Hanatos 光谱重建、stock 灵敏度适配、输入色域压缩、曝光语义 | 一个饱和度或色温标量 |
| 光学传播 | 原版散射、卤光、启用的扩散与镜头模型及其物理尺度 | 显示域泛红模糊 |
| 胶片显影 | 完整密度曲线、DIR 自层/层间作用、空间扩散、子层颗粒 | 三条独立 S 曲线 + 末端噪声 |
| 放大/相纸曝光 | 光源与 C/M/Y 滤色、底基与染料吸收、光谱透射、相纸灵敏度、中灰归一、启用的预闪 | 对负片 RGB 逐通道乘 gain |
| 相纸显影 | 相纸曲线模型、启用的曲线 morph | 简单反相 |
| 扫描 | 观察光源、CMF 积分、黑白参考、glare、色适应、原版 gamut、启用的扫描锐化 | 套现有 filmic gamut |

上游还有正片直接扫描等正式分支，按对应 stock 类型使用，不能把负片扫描图直接当作正常正像。首个正确性基准走负片到相纸的完整路线；支持范围和每个分支的验收单独列清。

### 3.1 原版拓扑与完整性清单

固定提交的正式 tap 为 `rgb_in -> rgb_pre -> log_e_film -> cmy_film -> log_e_print -> cmy_print -> rgb_out`；`scan_film=true` 分支由 `cmy_film` 直接进入扫描。后者的 film/paper、观察光源和黑白校正语义不同，不把任意负片密度直接扫描当作正片成片。

实施须生成 `spektrafilm-coverage.json`：逐参考函数/参数分支列原路径、移植位置、默认/有效配置、依赖资产、测试 ID 和通过状态。完整参考阶段覆盖曝光/显影/印相/扫描及各阶段有效分支；设备完整移植验收沿用这份清单，不留“未消费但已经下发”的参数。某正式路径只作内部验证而不提供产品配方时明确标记，不能将未验证路径暴露为可用功能。

| 边界 | 除主图以外必须固定/观测的内容 |
|---|---|
| preprocess / film expose | 原版自动曝光结果、crop/rescale 与物理像素尺度、光谱重建、胶片曝光、用于印相平衡的中灰参考 |
| film develop | 原始/消化后的密度曲线、coupler 作用顺序、空间扩散、颗粒子层与随机状态 |
| print expose | 滤色光源、底基、相纸灵敏度、印相曝光/补偿/归一的独立开关、预闪和扩散 |
| print develop | 原版 curve morph、profile 类型与插值/端点 |
| scanning | 密度到光谱/XYZ、黑白参考校正、glare、观察白点、输出 RGB、原版 gamut、blur/unsharp 和 CCTF |

主 tap 不包含扫描内部全部观察点，需用仅研究的被动 instrumentation 补齐，不能把额外观察点误称原版自带接口。打印中灰参考等 service 状态由前级生成，阶段不是相互独立的纯函数；不得向中间 tap 注入图像、漏掉这些状态后仍称完整参考。

“不做 LUT 引擎”不等于删除原版算法的数据表。Hanatos 本身使用光谱/色度采样表，密度曲线、CMF 和原版 gamut 边界数据也须保留其定义和插值方式。它们是算法内部数据，不是把整条模拟链压成外观 LUT。参考基准关闭可选的 enlarger/scanner 3D LUT 快捷路径。

### 3.2 可复现 oracle 的执行规则

锁定原版 checkout、Python/原生依赖、profile digest、随机源和 dtype。对 oracle 使用原版 `SimulationPipeline`，采集从一次完整执行中被动复制的 tap 和阶段内部数据；调试观测不改变运算顺序、随机流、数组布局或处理尺度。若为一个阶段重跑参考，必须恢复相同配置、前级 service 状态和随机场。

明确断言 `settings.preview_mode=false`、`debug.lut_mode=false`、`settings.use_enlarger_lut=false`、`settings.use_scanner_lut=false`；保留原版算法内部必要表。默认参考自动曝光也需独立验证，固定曝光对照则使用原版公开开关关闭并记录，不把两种运行混成同一配置。

每次输出包含原始参数、digest 后参数、阶段执行清单、tap 的尺寸/单位/空间/编码/dtype、资产 hash 和随机策略。先用同一随机输入和前级状态证明无观测/有观测的最终输出一致，并用完整原版多次运行核查观测不改变统计行为，再将其作为移植 oracle；不只保存一张外观 JPEG。

不能只记一个 `seed` 就声明可复现。G1 按实际配置列出 NumPy/SciPy 与 Numba 随机调用、线程/调度设置、调用顺序、颗粒子层与微结构的坐标/尺度。保留以下三种相互独立的验证，不用任一项替代另外两项：

1. **同随机场逐点对照**：在真实抽样边界记录和重放同一随机输入，记录场的 hash、形状、子层、坐标与对应前级状态；原版与移植使用相同实现输入，定位显影、滤波和扫描误差。仪表化路径不冒充未改动的原版随机执行。
2. **原生随机路径统计**：完整原版与完整候选各自运行多个独立样本，按曝光、片幅尺度、通道及启用分支比较粒度分布、均值/方差、空间功率谱与跨通道相关。预先冻结样本策略及统计容差，不要求不同 RNG 的原生输出逐像素一致。
3. **单次捕获可重放**：设备冻结随机实现版本、坐标约定、输入/配方身份和可验证的生成状态，重试（含 renderer 重建）应复现同一颗粒实现；双 view 优先共享实际生成的密度/空间状态，不能分别抽样。做不到时视为对应重试或 HDR 能力未通过，不以额外永久存片掩盖。

## 4. 先忠实实现，再标定产品配方

需要两套有明确名称的配置，防止参考实现和产品参数混为一谈：

1. **原版参考配置**：原版 stock、参数 digest、曝光与默认效果全部记录，完整运行，无厂商 LUT。用于逐阶段验证移植正确性。
2. **厂商配方配置**：在完整实现之上，用原版参数选择目标响应；关闭或调整某个效果属于明确记录的配方选择，必须有样片验证。

原版参考配置中的自动曝光也要跑通。但接入相机后的推荐策略是由 FilmKit 统一管理场景曝光，Spektrafilm 接收明确的曝光输入，不再同时自动测光。此选择在参考配置对齐后，以原版公开参数配置并核验，不从实现中删除该能力。

曝光至少区分：实际采集曝光、设备基准校正、虚拟胶片曝光、相纸曝光。用户曝光滑杆和配方曝光分别记录，不能先在公共段乘一次、进入 Spektrafilm 再乘一次。相纸曝光补偿与中灰归一应按原版共同计算，不能把结果误当作简单的整体亮度变化。

胶片曝光变化会影响印相平衡参考，滤色和密度曲线变化也有其派生依赖。按完整不可变配置构建参考/设备状态；若以后增加增量更新，必须对照完整重新初始化验证缓存失效，不能直接共享上游 mutable service 或只更新一项 uniform。

原版完整效果不等于所有厂商预设都必须明显带颗粒和卤光。先验证实现，再按目标决定效果强度；不能为了“胶片感”破坏目标厂商的肤色、暗部或清晰度。

## 5. 色域与输出契约

推荐主输入契约：场景线性 Rec.2020(D65)，`input_cctf_decoding=false`，带曝光/WB/CCM 来源和内容版本。直接使用上游输入色域能力，避免为照搬 PC 额外绕行 ProPhoto。

原版胶片参考光源的适应由原版路径完成。输入光谱重建使用的 CAT16 与现有传感器到公共工作空间的色适应属于不同边界，应逐段核对，不重复适应，也不为了统一矩阵擅自替换原版算法。

厂商 LUT 前必须有明确契约：

- LUT 输入原色、白点、传递函数、数值范围和预期基准影调。
- LUT 输出原色、白点、传递函数和范围。
- LUT 资产 hash、插值方式、strength 的混合域及原始来源。
- 输入/输出未知的资产先诊断并标记证据等级，不能靠名称认定为标准 sRGB。

对已确认是显示 sRGB 输入的 LUT，推荐让 Spektrafilm 完成目标 sRGB 的原版 gamut 与扫描处理，再且仅再做一次 sRGB 编码，交给该 LUT。若内部目标纹理继续使用 Rec.2020，桥接矩阵必须显式存在；线性 sRGB 不能写进被下游当作 Rec.2020 的纹理。

参考中间量完整保留浮点范围。不得为了符合 LUT [0,1] 输入提前钳掉场景高光，也不得在 Spektrafilm 出口再无条件加一套旧引擎的肩部、gamut 或外观补偿。

LUT/domain 缺口是明确阻断项：先建立灰阶/基色/高饱和/曝光扫描证据；不能通过“套上看起来对”给未知 LUT 认定 sRGB。富士官方教师支路只有在 F-Gamut/F-Log2、曝光基准、输出 transfer/range 均有依据后才用于定量比较；尚未确认时仅作受限观察，不能默认 BT.709 等于 sRGB。源文件不是 runtime LUT 时不直接装进 App。

输入边界同时保存主图及 alpha/有效性语义。无效像素不能作为有效曝光样本；具体排除/填充策略须与完整前链和原版输入契约一起验证。引擎不能为掩盖坏输入自行增加未记录的去色、裁切或修复。

## 6. 引擎与后处理的职责

| 功能 | 推荐归属与处理 |
|---|---|
| 胶片/相纸响应、显影耦合、光谱变换 | Spektrafilm 私有引擎阶段 |
| Spektrafilm 颗粒、卤光、扩散、扫描锐化 | 原版位置与算法；用私有参数配置 |
| 现有 filmic 自动黑白点、曲线、gamut | slot=2 不消费，且排查 CPU 成员变量副作用 |
| 现有 look 饱和补偿、局部提亮、额外滚降 | 新配方先明确设定，不能默默继承旧值 |
| 现有显示域颗粒/卤光/锐化 | 基础标定时与原版同类作用避免重复；额外创作效果需明确独立语义 |
| 厂商风格 LUT | 独立的后置资产，保留自身颜色与亮度作用 |
| 用户后期调节 | 在已声明的处理阶段应用，避免引擎切换后旋钮仍可见却不生效 |

不要求把厂商 LUT 改成“只改色、不改亮度”。实际资产可能同时承担影调和色彩；先量出它的响应，再配套引擎。也不通过强行中性化 Spektrafilm 来保留旧参数，因为那可能抹掉引入它的价值。

## 7. 厂商配方与 LUT 标定

§7.1 的配方数据契约继续适用；§7.2–§7.5 的跨引擎比较、教师收集和逐预设排名仅保留为历史研究设计，不是现行 G0–G5 验收项。

### 7.1 每套配方保存什么

建议新增有版本的引擎私有配置，至少包含：

- `engine_id`、引擎算法版本、上游提交和资产 manifest hash。
- film/paper profile ID 与 hash、光源、原版 digest 后的参数快照。
- 胶片曝光、相纸曝光/归一、滤色、显影和空间效果参数。
- 输入输出域、虚拟片幅/像素尺度、随机种子策略。
- 厂商 LUT ID/hash/domain/strength、配套后处理及标定数据版本。

不把这些参数逐个塞入 `FilmParams` 或逐个增加 Room 列。原方案为 104 槽，当前 `FilmParams::kCount=105`，已有 `[98]` 引擎槽可复用；新增私有配置通道与预设版本字段须有完整持久化、导入导出、快照和消费链，不能只实现 JNI setter。与完整 V7 共用的版本化配置封套、稳定槽身份和 v2/v3 兼容设计见总体设计 §6；Spektrafilm 仍使用 slot=2，不因此重写本节算法参数。

私有配置使用固定提交可校验的 schema 和原版单位，原始参数与 digest 后值同时可追踪；每个公开参数有唯一消费者。`FilmParams[4]`、旧 auto-tone/端点、旧颗粒/卤光和输出滚降逐项绑定/旁路，不沿用 `slot != 0` 或 `slot >= 0.5` 的粗分支。预设切换、设置覆盖、JNI、渲染、快照、导出与重新读取须对拍同一 `resolvedRecipeHash`。

### 7.2 推荐标定顺序

1. 固定前端 RAW 重建、WB、CCM 和曝光；先验证输入基准，不用风格参数补传感器偏色。
2. 对现有 LUT 做灰阶、色卡、色相/饱和度切片和端点诊断，记录输入域证据。
3. 同一场景线性输入、曝光和现有 LUT 下比较旧 Filmic、完整官方 V7、sigmoid 和完整 Spektrafilm；此轮衡量兼容性，不宣布最终优劣。
4. 在候选中调整原版公开参数，优先匹配整体灰阶、肤色与主要色域，再处理空间质感。
5. 四条路线分别重新配套：同等证据、评估预算和校正复杂度约束；都可调各自公开参数、LUT strength 和受约束残余校正，不能只给 Spektrafilm 多一层拟合。改 LUT 要新资产 ID；不强制剥离源 LUT 影调。V7 不以旧 per-channel latitude 的平均数作所谓等价迁移，旧配方原样保留。
6. 在未用于调参的场景上验证。参数、LUT、评分门槛固定后，G2 只判断是否进入手机验证；是否升级由 G5 真机结果及用户确认决定。

引擎与 LUT 同时任意拟合容易互相抵消。标定时分步固定变量，限制自由度，不对每张图单独换曲线或加曝光来获得好看的平均分。

上述第一轮比较先在桌面用完整上游运行，不等待手机移植。先证明在现有资产和目标数据上存在有价值的候选，再移植同一配置到设备。桌面阶段不为加速启用 `lut_mode`、`preview_mode` 或删去空间效果；原图完整运行，区域裁剪只用于结果观察和测量。

控制组包括：现有原样完整配方、固定 LUT 换引擎、各引擎独立调优、无风格 LUT，以及可用时的官方参考变换。联合四路按总体设计 §4 使用同一份经生产路径导出的固定 EV 输入，冻结 LUT 前后的公共处理与色域/编码顺序；旧配方生产回归独立保留曝光闭环和所有效果。按场景/作者批次留出，不逐张调 EV/WB 刷分；同输入曝光扫描单列。

`tools/engine-shader-offline.py` 省略真实高光恢复等阶段且使用半精度 FBO，只能辅助分析。扩展 `tools/check-renderer-device.cpp` 从当前生产 renderer 导出真实引擎前浮点图、完整快照和 LUT；现有 `--film-params` 不上传 LUT，需补齐。历史 `tools/preset-exp/recipe-fit.py` 的硬编码目标不是厂商真值，禁止直接套用其 `--apply`。

### 7.3 目标证据等级

| 数据 | 可支持的结论 | 不可支持的结论 |
|---|---|---|
| 官方有域说明的可执行 LUT | 正确场景线性→Log/色域桥接后的同输入参考比较 | 等于该品牌所有机型静态 JPEG 或私有 ISP |
| 目标相机 RAW + 同次直出 JPEG，设置完整 | 同输入的端到端渲染比较；仍须控制 RAW 解码与 WB | 跨传感器光谱完全一致 |
| 同一目标相机 Standard/目标风格配对 | 该机型上风格相对变化 | 我方 RAW 到目标 JPEG 的绝对映射 |
| 受控双机同场景拍摄 | 跨机实际观感与系统误差评估 | 把传感器/镜头/曝光差全算为风格差 |
| 非配对官方样片 | 风格方向、语义区域和视觉验收 | 用全图直方图差当逐像素风格误差 |

现有样片研究记录了理光配对图、官方样片和 M9 设置序列，但不等于当前已经具备多场景目标 RAW+JPEG。先核验文件与设置；不能把 dcraw/ACR 转换版当作唯一绝对中性基准。

建议首轮覆盖日光人像、绿植、蓝天云层、室内暖光、混合光、暗部、逆光、彩灯及高饱和物体。按场景/拍摄批次划分调参、验证和最终留出集，禁止将同场景裁剪分到两侧。

肤色与中性色、绿植、蓝天、灰阶和高光分别统计；非配对照片只用于方向约束和盲评。没有足够配对数据时，结论应是“目标风格候选”，不能写“精确复刻”。

## 8. Android / C++ 接入

建议在现有渲染器旁增加独立 `SpektrafilmEngine` 模块，负责私有程序、表、纹理和多阶段调度；FrameRenderer 负责公共输入和输出衔接。

只为原版完整执行扩展引擎入口，不先建设通用节点编辑器或重写整个渲染框架。现有 filmic/sigmoid 继续原路径。slot=2 分派到多阶段入口，不能为了维持“引擎只能一个 pass”而合并或删除邻域运算。

| 拟改范围 | 职责 |
|---|---|
| `core/engine/src/film/EngineRegistry.*` | 注册 slot=2，声明实际域、能力与可用状态 |
| 新增 `core/engine/src/film/spektrafilm/` | 参数/资产、原版数学、光谱与空间阶段 |
| `FrameRenderer.*` | 接入场景线性源、输出域桥接、独立多阶段资源生命周期 |
| `core/engine/src/jni/Bridge.cpp` / `EngineBridge.kt` | 有版本的配置快照下发与返回实际生效状态 |
| `camera/EngineScope.kt` | 按引擎能力限定参数；不直接复制“非 0 全部归零”策略 |
| 预设模型、资产、设置与 UI | 配方持久化、选择、导出、错误状态和可用控制 |
| 编辑器与保存元数据 | 区分场景底片和显示图像，记录已应用的处理 |

一次快门应固定同一份曝光/WB/引擎配置/LUT/效果快照；异步渲染和编码不能读到用户随后切换的配方。预览与成片 EGL context 的资源独立拥有，只共享不可变 CPU 资产，不共享未经同步的纹理句柄。

资产须校验 schema、尺寸、布局、有限值、源 hash 与 payload hash。预设只有在全部资源和程序可用后才激活。失败不能静默输出 identity 或另一种风格并标成 Spektrafilm；保留已有成片/底片，显示和记录失败。若提供回退，必须明确标明实际引擎并按完整回退配方重跑。

原 profile 若使用带定义的缺测值/NaN，须按原版的掩码与处理规则转换；不能一律清零，也不能因一句“有限值校验”擅自丢失原语义。设备 payload 的有限数和有效性掩码分别校验并一同计入 hash；输出的非预期 NaN/Inf 为失败。

激活状态按 `UNAVAILABLE -> LOADING -> VALIDATED -> READY` 管理，失败进入 FAILED；context/尺寸/资产变化显式失效。配置完整校验后在所属渲染线程原子提交，返回实际引擎、配置和资源版本。缺资产/编译失败时新设置不生效，不将旧配置的输出标成新配方。

资源清单逐阶段记录读/写纹理、格式、尺寸、物理域、最后消费者和峰值活跃集。先确认输入不再被 HDR、统计、后处理或其他在途任务使用，才释放/复用；不直接假设 PC3D 协方差或旧 FBO 可供新引擎覆盖。预览/静拍资源上限分别实测，不预分配所有 profile 和最大分辨率组合。

`StillRenderClient` 及 native 既有失败重试路径须保持同一不可变配方；重建 renderer 后重新提交完整配置和资产。不得因新引擎失败转进旧 YUV/identity 路径后仍称成功。是否允许回退由明确产品策略决定；本轮不新增永久 RAW 保存或改变用户 DNG 偏好来掩盖失败。

所有 release 路径同时清零 GL 句柄、尺寸、program/FBO、ready/valid 状态，覆盖切镜头、尺寸变化、切引擎和重复 start/stop。

## 9. 预览与拍摄闭环

当前取景器来自经 ISP 处理的 YUV。逆 sRGB 编码和一个中灰倍率不能恢复其局部 tonemap、裁切高光和色彩变换，不能据此声称已获得原版要求的场景线性输入。

推荐把**可验证的场景线性预览源**作为最终目标，先检查并实测当前镜头/分辨率下连续 RAW、预览与静拍组合的能力和代价。RAW 预览可使用当前帧的完整色彩/引擎模型；空间尺度随输入分辨率明确换算，不能直接照搬上游会关掉部分效果的 `preview_mode` 当最终一致性证明。

范围修正：连续 RAW 预览另立验证任务，不阻塞桌面收益比较；不在本轮擅自重写采集端。设备接入必须实测现有预览的能力边界并明确显示，不能把错误输入当完整同源一致性证明。

如果硬件组合暂时不能提供该输入：现有 YUV 只能作为已标明限制的构图/风格预估。通过多曝光、多照明配对数据评估误差，并继续解决采集或预览源，不能把未验证的单标量反变换包装成正确接入。是否接受这种预览能力边界，是发布讨论项。

曝光闭环要分开“让成片正确”与“让预览接近成片”。新引擎的风格标定先固定场景曝光和配方，避免现有显示域中灰闭环为追赶 ISP 画面而补 EV，改变胶片工作点、推白天空。之后验证闭环是否保留、调整作用端或由可验证的 RAW 预览替代；不得沿用旧护栏数值就宣布适配完成。

最终检查同场景的预览与成片中灰、肤色、天空、裁切和高光，不只比较全图均值。若需要预览降档或关闭某类效果，必须先完整实现、实测误差和速度，再由用户决定。

预览/曝光验收单独交付：固定手动曝光先测输入域误差，再接自动闭环测试收敛、往返切引擎和亮暗跳变；所有 EV 的施加点有 trace。检查闭环是否把模型固有影调误当曝光错误而来回补偿。报告各实际镜头的 RAW/YUV 组合、分辨率、帧间隔、静拍干扰与超时，不把单镜头能力推广到全机。

发布能力表分开填写“拍摄输入”“预览输入”“风格预览精确性”和“曝光控制依据”。若仅 YUV 构图估计，标为受限能力并等待 §16 决定；不同意受限预览时继续验证真实输入，不偷偷沿用一个校正倍率。

## 10. 编辑器与底片

当前 `EditorEngineSession` 的主要入口是显示域 RGBA8，不能直接进入场景线性 Spektrafilm。编辑器按输入能力提供两种明确行为：

| 输入 | 可做的处理 |
|---|---|
| 有场景线性底片与完整快照 | 从引擎前重跑 Spektrafilm、厂商 LUT 和后处理，可真正切换基础配方 |
| 只有 JPEG/显示域图像 | 做显示域后期；不重复执行已烘入的引擎和 LUT，不显示无法兑现的基础引擎切换 |

建议为需要完整重显影的照片保留**引擎前的处理后场景线性底片**及元数据。仅保存一个参考帧 DNG，不能复现已完成的多帧融合与高光恢复；显示域反编码也无法替代。

范围修正：此为可选后续重显影项目，不是本轮必须增加的存储功能。当前 JPEG 编辑继续按显示域工作，不将成片伪装成线性输入重跑基础引擎；不增加不能兑现的切换入口，不自动保存大体积底片。

保存格式建议先验证无损浮点主图和版本化 sidecar；不擅自量化到半精度或有损压缩。4096×3072 的 RGB float32 未压缩约 144 MiB，存储影响需要明确讨论。推荐提供显式“保留可重显影底片”选择，普通照片仍支持显示域编辑，不暗中永久保存整套 burst。

底片保存、配方重载、预览、导出和无改动直通必须一起接通。LUT 与引擎参数分别跟踪已应用状态；反复打开/保存不能越来越浓。不得为了重显影而擅自打开用户关闭的相册 DNG 输出。

参考执行遵循原版 preprocess 的 crop/rescale 和物理像素尺度，不擅自调整其顺序；原尺寸对照固定完整输入与配置，不以裁剪小图省略模型支持域。用户后期裁切同一底片时，应先按已固定的完整处理画幅重显影，再做显示裁切，避免裁切改变既有颗粒/扩散；这与原版相机画幅设置分开记录。导出同一底片与配方时随机种子稳定，预览不能每帧重新生成闪动颗粒。

当前显示图编辑将拍摄时已烘入的 engine/LUT 与本次显示域 delta 分开记录。无修改保存应验证直通或既定编码行为，不重复基础引擎和 LUT；有修改时只应用本次 delta。未来启用底片重显影时，配置/资产缺失必须报缺失，不拿新版同名 profile 或当前全局设置替代旧快照。

## 11. HDR / gainmap

推荐优先级：**厂商 SDR 风格忠实，然后在同一风格基础上设计 HDR 显示。** 不以 HDR 越亮越好作为目标。

相纸/正片扫描响应不是无限场景动态范围。上游支持 PQ/HLG 编码和反射率到输出亮度的尺度约定，但这不自动等于 FilmKit 的场景高光保留、JPEG/R 双图或现有 CurveExtension 语义。

HDR 方案建议从同一份扫描结果及其输出压缩前数据建立显式 SDR/HDR view。两者共享胶片/相纸显影、配方和空间效果，HDR view 的参考白、显示亮度及 gamut/高光策略单独定义、验证；这是适配层设计，不标成原版默认已有能力。

必须处理三个问题：

1. 单纯把最终纸面图像乘亮会整体抬高中灰；不能当作保留场景高光的完成方案。
2. 不能直接复用 filmic 的一维中性曲线延伸去代表 Spektrafilm 的彩色层间响应，也不能从已压平或已裁切像素中宣称恢复真实细节。
3. 显示域厂商 LUT 不能直接套在 PQ 或 >1 的 HDR RGB 上。HDR 风格迁移需有明确域和完整 RGB 验证；单标量亮度补偿不保证保留该 LUT 的色相/色度行为。

gainmap 必须由同曝光、同几何且风格对应的最终 HDR/SDR 图计算。先量出单通道 gainmap 的 RGB 重建残差；若实际需要颜色差异，评估 RGB gainmap 与现有编码器支持，不强行压成亮度比。颗粒和 glare 在两幅图中共用同一随机实现，防止随机差成为 HDR 增益纹理。

本节不能提前承诺某个 HDR 延伸公式已经正确。实施时先交付独立的双 view 数学与同 RAW 图像证据，再接发布链；HDR 未验收前，slot=2 不宣称支持 HDR，不留一个看似可用却套旧逻辑的开关。若讨论后选择先发明确的 SDR 范围，须显式批准该交付边界。

### 11.1 双 view 的研究门槛

先被动导出扫描校正/色适应、输出 gamut 压缩前后的完整 RGB，确认上游默认哪一步已经限制亮度/色度。最终 `rgb_out` 或 PQ/HLG 重新编码本身不构成 HDR 信息源；不可逆压缩前也未必含有所需场景层次，需用彩色曝光扫描和真实高光核验。

再单独提出 SDR/HDR view 的输入、参考白/峰值、gamut、LUT 适配和共享空间/随机状态公式，标为 FilmKit 新适配而非原版默认。没有验证这些公式之前不预设一个延伸函数。验收含不同显示亮度、RGB gainmap 重建误差、肤色/彩灯/花瓣/灰阶和完全相同几何；不以“有 gainmap 文件”当 HDR 成功。

若没有足够模型信息或无法证明双 view 风格一致，HDR 能力维持不可用并交用户决定下一步；不得悄悄退成全局乘亮或强迫选择 SDR 发布。

## 12. 数值、空间尺度与性能

参考 oracle 使用原版及其依赖锁定环境；原版 `380..780 nm / 5 nm` 共 81 个光谱采样点保持不变。原版已有的近似、插值和边界条件也属于参考行为，不能用“理论更物理”的自研替代后仍声称逐段对齐。

手机实现优先沿用项目 GLES/compute 能力，具体阶段采用 GPU 或精确 CPU 实现，由完整模型和测量决定。FP32 计算及 RGBA32F 中间资源作为设备精度评估起点，与原版实际 dtype 路径逐段比较；原版 preprocess 将输入转 double，但不能据此声称所有依赖内部一律 float64。不预设 FP16 足够，不保证 FP32 无条件通过。若不通过，定位敏感阶段并提高精度或换执行位置。

不常驻每像素 81 通道光谱图。可在像素计算中按原版所有波长累加，或预计算仅依赖固定 profile/光源的原版数据；对参数与数据 hash 完整失效。这不允许合并成外观 LUT、减少波长或复用上一张统计。

物理半径由虚拟片幅、完整原图尺寸和缩放映射换算。原版 Gaussian/IIR、指数尾部、高光传播、边界延拓、随机分布与子层顺序逐项对照，不用旧金字塔模糊替换。分块计算必须包含正确 halo/边界；递归滤波不得将每个 tile 当独立图像。

`camera.film_format_mm`、原版 crop/rescale、最终裁切和旋转的关系必须固定；同一个效果不能在预览和静拍分别以“当前纹理像素半径”随意解释。参考原图完整运行；测试 crop 是观察，不改变滤波支持域。随机源先记录原版算法/流顺序，逐点 parity 可注入同随机场；无法匹配时采用 §13 的统计验证，不换成廉价 hash 噪声后宣称等价。每张成片冻结种子与坐标约定，HDR/SDR 两图共享实现；预览的随机稳定性独立验证。

完整原模型跑通之前不以内存预算为由预裁阶段。资源峰值同时考虑当前 CS/CM 约 382.5 MiB 名义新增量、前端与新引擎重叠；它不是已测 RSS。超出设备能力时先提交资源实测和不改数学的生命周期方案，不降低精度/光谱/空间效果来给“完整移植”造结果。

记录每阶段 CPU/GPU 时长、显存峰值、全保存时间、预览到达间隔、温度和失败率。现有性能专项虽暂停，新引擎仍需基本性能验收；任何会改动质量的优化都在完整模型跑通和真机测量之后讨论。

## 13. 验收：正确性与目标相似度分开

以下是建议判据，不是已经达到的结果。数值阈值在建立 oracle 与量化噪声底后冻结；不能看完候选结果再放宽。

形成机器可读 `numeric-budget.json` 与 `coverage.json` 后再评候选：逐阶段写绝对/相对容差、近零规则、编码/颜色误差预算、极端值和统计样本策略，附参考重复性与量化来源。无预算/无覆盖清单不通过 G1/G3，超预算必须定位，不事后放宽。确定性测试与随机测试分开，原版对齐与目标风格优劣也分开。

| 类别 | 核心检查 |
|---|---|
| 原版阶段对齐 | `log_e_film`、`cmy_film`、`log_e_print`、`cmy_print`、扫描 XYZ/RGB 分段 dump；查绝对/相对误差和异常值 |
| 确定性颜色误差 | 同配置/随机输入统计逐阶段绝对/相对误差、最终编码域误差与色差；先测原版重跑及编码量化噪声底，再在看候选排名前冻结容差，不沿用未经验证的 0.25/255 等任意门槛 |
| 随机/空间效果 | 按 §3.2 分别交付同随机场逐点对照、完整执行的原生抽样统计、同次捕获重试与双 view 一致性；另核对空间边缘响应，不把随机噪声当实现误差 |
| 曝光/灰阶 | 扫描真实 RAW 覆盖的全曝光范围，检查中灰、肩趾、连续性、有效层次；不要求所有彩色通道机械单调 |
| 风格与域 | 核对配置产生预期的胶片/印相/扫描响应，检查中性、高光、肤色等区域是否有非预期伪影；不与其他引擎排收益名次 |
| 前端质量 | 噪声放大、细节、假色、色偏、光晕、运动重影；与同 RAW 的现有完整配方比较 |
| 生命周期 | 同 renderer 连续切引擎/镜头/尺寸、前后台、编辑器返回、资产损坏与异步快照一致性 |
| 产品闭环 | 承诺范围内预览、拍照、相册重开、显示编辑、导出、无修改直通；重显影/HDR 仅在单独批准并完整验收后启用 |

联合回归额外覆盖：CS/CM 四组合、PC3D 0/1/2、单帧/burst、短帧接受/拒绝、跨镜头/尺寸/旋转；一次快门后切 LUT/引擎/配置、context 重建和失败重试。默认标定固定前端状态，不能把四组合混成同输入；所有组记录完整前端 hash。旧 Filmic/sigmoid 在未选择新引擎时同 RAW 保持原输出，用户保存的 CS 关闭偏好不被覆盖。

两类结论独立记录：“忠于上游”不能代替“更像厂商”，某组厂商样片更像也不能掩盖错误的模型移植。没有目标配对时不报告绝对复刻误差；没有完整尺寸与真机证据时不称成片验收通过。

| LUT 调整原则 | 先保留原资产联合标定，必要时生成有版本的派生资产 | 防止无依据拆掉 LUT 影调，也允许修正已证明的不匹配 |
| 完整重显影底片 | 另立可选任务；本轮不强加格式/存储改造 | 当前显示域编辑不伪装基础重显影 |
| 预览目标 | 当前输入边界先验清，RAW 来源另行实测 | 不以单倍率宣称物理等价，不把采集重写变成离线比较前置条件 |
| HDR 目标 | 厂商 SDR 忠实优先，HDR 作为有独立证据的显示适配 | 不保证沿用旧延伸能正确，也不承诺第一实验包即支持 HDR |

定版前的阻断决策按发生顺序记录，不把未知问题藏成实现 TODO：

1. **已定定位**：优先开发 V7；Spektrafilm 作为独立可选风格引擎，不做四路排名。
2. **首批风格**：由 G2 冻结 stock、相纸/扫描路径、用法与资产，不依赖厂商复刻评分。
3. **首个手机交付边界**：若真实场景线性预览/HDR 尚未过门，选择继续补齐，或显式接受限制后的完整 SDR 范围；没有答复不擅自选后者。桌面实验不受此阻塞。
4. **实际成本**：G3 完整模型后再讨论保存速度、内存、热和预览成本；质量取舍让实测与用户决定，不预批简化。
5. **分发权利**：G0 初审，生产集成/面向分发移植前确认可行路径，G5 按实际发布内容复核；研究可执行不等于资产可进入 APK。

定版记录至少包含 decision ID、确认范围、依据材料、未支持能力和回退方式。任一选择改变算法/数据/发布能力，更新相应配方/配置/测试版本，不能只改标题“已定版”。
