## 样本代表性（0.12.84 融合改造前的样片是否有效）

**对结论一（gainmap 指纹）有效，对结论三（base 账目）无效**：

- `ratioFromScene` 全历史仅 2 个提交（0.11.76 建、0.12.21 定型）；
  `git diff 29f7480^..29f7480` 对 kFsGainmap/gainPc/passGainmap **零改动**。
- ratio 只依赖 sceneY（融合线性域）：中灰归一 0.18 不随融合改造变；高光 sceneY
  是场景真实线性亮度（新旧采集都是短帧归一接管，物理值一致）⇒ 三大指纹
  （1.1 平台 / 2.5 封顶 / 码值分布）在 0.12.84 上预期复现。
- 结论三的曝光数字（>=240 等）受渲染端 AE 删除（0.12.71）与白点/teq 收口影响，
  0.12.6x 样本不能代表 0.12.84 —— **需 0.12.84 重拍确认**。
- 另：0.12.82 时 per-frame σ 未修、长帧整帧回退 ⇒ 样本（含 10-24 17:06）的融合
  参考暗部并无长帧数据；0.12.83+ 起长帧才真参与 —— 这恰好意味着 **P4 所需的
  "真实跨曝光 HDR 参考"从 0.12.84 起才第一次完整存在**。

## 结论一：gainmap 的真实现状（P4 的准确靶子）

`kFsGainmap` 的 ratio **不是** HDR/SDR 比值，而是 sceneY 的纯函数
（`FrameRenderer.cpp:7291`，SDR 侧参数声明了但未使用）：

```
ratio = clamp(max(1.1, sceneY * 1.6), 1.1, 2.5)
```

实测指纹（18 张一致）：

| 证据 | 实测值 | 含义 |
|---|---|---|
| gainmap p90 恒 0.533（boost 1.10x） | 全部 18 张 | 中灰 1.1 平台支配全图 |
| 码值 136 占 **96.5%**（303 万/314 万 px） | 170612 那张 | 1.1 平台针；8bit 码值空间浪费 ~70% |
| 码值 212 针（3.3 万 px，JPEG ringing 211~219） | 强光样本 | clamp 2.5 封顶；boost 永远到不了元数据声称的 4.0 |
| max 恒 ≈0.847（2.62x，L 通道 219） | 全部 18 张 | 同上 |

历史（git -L）：0.11.74 直接 hdr/sdr 比值（中灰 0.39 → 整张发灰事故）→
0.11.76 中灰 1.1 + t²→4x → 0.11.90 sceneY×1.6 → **0.12.21（c9d46ce）封顶 2.5**
（5619"SDR 天空开 HDR 变灰白"的修复）。即三轮真机事故后的人为塑形。

## 结论二：PC 对照 —— "HDR 输出几乎相同"的旧结论已过时

| 同场景 | gain_p90 | boost p99/max | HDR luma ≥1.0 占比 |
|---|---|---|---|
| 10-24 逆光 我们 | 0.533 | 2.51x / 2.62x | 2.12% |
| 10-24 逆光 PC | **1.000** | 4.00x / 4.00x | **12.29%** |
| 10-23 白天 我们 | 0.533 | 1.10x / 1.44x | 0.00% |
| 10-23 白天 PC | **1.000** | 4.00x / 4.00x | **53.12%** |

PC gainmap = 真实比值、大片顶格 4x；我们 = 1.1 平台 + 2.5 天花板。
10-20 记录的"HDR 输出几乎相同（P90 0.714 vs 0.697）"在当前版本不成立
（当时 HDR 源/口径不同）。

## 结论三：base 账目翻转

10-20 的"我们 base 平均亮度 85.2/98.4 vs PC 50.7（1.7~1.9×）"**已不存在**
（0.12.7x 渲染端 AE 全删 + 白点 4.8 + teq 收口后整体账反转）：

- 10-23 15:24 同刻对照：我们 mean 102.7 / p50 98.7 vs PC mean 148.0 / p50 171.4
  ——我们反而**更暗**。
- 现在的 base 问题 = 强光场景高光区大片 ≥240：我们最高 **11.14%**（102756）、
  9.38%（105359）、6.29%（170907）；PC 0.41%/1.73%。

即高光信息两头丢：SDR base 里 ≥240 顶死（无层次），gainmap 又被 2.5 封顶
（HDR 屏也救不回）。

## P4 的行动项（据此修正）

1. `ratioFromScene` 换成真实跨曝光比值：P3 融合参考（含 +2.2EV 长帧）反 OETF 对齐
   base 显示域后相除——中灰锚定到 1（避免 0.11.74 复发：融合参考中灰 = base 中灰）。
2. 真实比值 → 8bit 码值 [0.25,4.0] 全范围恢复使用（现浪费 70%）。
3. headroom 映射重标定（teq/曲线部分）：真实比值可能 > 屏幕可用 headroom
   （0.11.90 的教训：天空 4x 超出 headroom 被系统 tonemap 压出色度）——映射曲线
   要按目标屏 headroom 设计，而不是简单钳 2.5。
4. SDR base 高光 ≥240 大片问题与 1~3 联动解（base 让位 + gainmap 补）。

三大旧指纹**全部消失**：

| 判据 | 旧版（18 张基线） | 0.12.85 实测（5 张） |

| gain p90 | 恒 0.533 | 0.561~1.000（随场景连续变化） |
