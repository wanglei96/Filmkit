# FilmKit 自研印相风格：离线首样

2026-11-19；独立 SDR 研究原型，不修改 FilmKit 的 APK、RAW 前链、预览、HDR、默认引擎或预设。

## 模型

`tools/filmkit-print-study.py` 从完整 `base_engine_input` 读入场景线性 Rec.2020/D65；不重做白平衡、测光或曝光补偿，保留大于 1 的输入。64 行一批，FP64 计算：

1. 用非负且各行和为 1 的受体矩阵计算三通道曝光，用 `log1p` 曲线生成相对底片密度。对有负受体曝光的输入，沿该空间的等亮度中性轴收缩；非正亮度且越界时退到黑。
2. 以负密度的加权和定义相纸对数曝光，等价于透射率的加权几何平均；归一化纸面响应使零输入为黑、0.18 输入对应 0.18 线性灰，亮端渐近到 1。矩阵和曲线均为自写的风格参数，不是实测乳剂数据，也不拟合本次灯罩图。
3. 转换到线性 sRGB，沿同亮度中性轴解析求 RGB 色域边界，软拐点压缩相对色度，最后做标准 sRGB 编码。这不是 CAM16-UCS，不承诺感知色相恒定。输出带 ICC 的 16 位 RGB TIFF。

仅借用负片密度调制相纸曝光的处理关系；不使用上游 profile、光谱或随机资产，不模拟颗粒、卤光、DIR 和扫描眩光，不以缺省这些功能换来的时间冒称原版提速。它是独立风格实验，不是原版兼容、厂牌复刻或物理验证。

## 已验证

- 同一真实 RAW 派生 D0（SHA-256 `0452d6f65a738cc5908ab97036bc6f688697201d6255e4f65ce5768dbb86d450`），3072 × 4080。保留的原型 TIFF 回读验证了全部 37,601,280 个通道值与 ICC；64 行和 127 行两遍回读像素哈希完全相同（`30da94349284efa2245ebc3ae1f7c34d43edd6eeaffe2716b793549e23ec3ba7`）。自测覆盖黑点/灰点、单调灰阶、中性、目标色域边界、等亮度及分条一致性。
- Mac 单线程 BLAS，64 行计算累计 2.97 s（不含输入检查、量化、导出和回读），进程总墙钟 4.72 s，最大 RSS 523,370,496 B，系统报告峰值 footprint 108,464,256 B；127 行计算 3.01 s。不是 Android 计时，不能直接加到拍摄延迟上。
- 同源三方对照：FilmKit sigmoid JPEG 与 D0 真机 runner 基线哈希完全一致（`84b903114732dfe6712b6ecfb26c091dc19ad3344cc0b2a47395fa81dd056526`）；Spektrafilm Portra 400 + Endura 为该 D0 的已验证真机 TIFF。三方用 sRGB 展示，不做亮度或白平衡匹配。当前观察仅限观感：原型开暗部，主灯依然接近白色；未显示足以替换 sigmoid 的优势。不同编码、参考随机颗粒、缩略图和单一低饱和场景不支持细节、噪声、肤色或饱和色的比较结论。
- 成片、对照图和两份清单保存在 `test_temp/filmkit-print-study-20261119/`，约 81 MiB。127 行的重复 TIFF 已删除；未改原始输入和其余参考文件。

## 补拍四组 DNG：同解码 A/B

- 用户提供人像、室内绿植、室外楼群与亮云、紫红花四组 DNG/JPEG。四组全尺寸跑完；按明确文件配对，核对方向、尺寸及画面内容，哈希见 `test_temp/filmkit-print-dng-ab-20261119/manifest.json`。
- `tools/filmkit-print-dng-ab.py` 用 RawPy 0.26.1 / LibRaw 0.22.0，AHD、拍摄白平衡、关闭自动提亮，解码为线性 Rec.2020 uint16。两条离线路径吃同一份数组：一条用 FilmKit 默认 sigmoid 影调与通道色相/能量保持的 CPU 复现，一条用原型纸面响应，之后共用原型输出色域和 sRGB 编码。这个隔离 A/B 不是生产 sigmoid 全链复现。右栏使用原成片的嵌入 ICC 转换到 sRGB，仅作观感参照；不使用它来回推 DNG 的增益，不做逐像素质量差分。
- 四组整图平均线性输出亮度均略升或上升。对解码输入 Y ≥ 0.60 的像素，人像、楼群、花的原型平均输出亮度分别为 0.516 / 0.534 / 0.601，sigmoid 为 0.589 / 0.611 / 0.681；绿植组没有达到该输入阈值的像素。说明亮部被压暗，不等于层次或细节增加。可见人像的肤色和暗衣对比更柔，楼群亮云没有明确新增层次，紫红花与绿叶的饱和观感下降。原型未显示足以替换 sigmoid 的收益。
- 单张 DNG 解码不包含 FilmKit 的多帧融合与 D0 曝光准备，uint16 输入也不能检验 D0 中 >1 高光；花图解码后 9,555 个像素至少一通道到达 65535，因此不据此评价花瓣高光恢复或其他引擎的上限。只留四张对照图与清单，共约 0.9 MiB，未写整帧中间文件或改动原片。

## 下一道门

保留本轮输入作固定对照，不在且仅在一张图上调参。先令原型与 sigmoid 的中性灰阶匹配，在同 DNG 上分别关闭/开启受体和密度混色，检查肤色及高饱和色变化究竟来自反差还是混色；有潜在收益后，再补真 D0 的跨场景确认，尤其是 >1 高光。这个版本不替换 sigmoid，也不在相机内追加第二道 tonemap。画质有明确收益后，才写原生原型并在 X300 取景与多帧保存负载下测**相对现有引擎**的 P50/P95 新增耗时、峰值内存和掉帧。

复现：用已有 Spektrafilm 研究虚拟环境中的 Python（只用 NumPy、Pillow、tifffile，不导入 Spektrafilm），执行 `OPENBLAS_NUM_THREADS=1 python tools/filmkit-print-study.py <D0.json> <新文件.tif>`；不带文件参数只跑自测。
