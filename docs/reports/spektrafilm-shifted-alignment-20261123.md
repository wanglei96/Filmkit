# Spektrafilm：有位移的 RAW 对齐

2026-11-23，vivo V2509A，基线 0.14.42 / 839。未出包或覆盖安装。

## 保留的改动

ARM64 SAD 对参考帧和目标帧都在界内的连续区间使用原 NEON 整数归约，两端仍按原规则逐点 clamp。步长 2 对齐到原 tile 起点的采样相位，向量读入含交错的第二个字节也不得跨行。这补上了 L4 全宽粗搜在横移非零时回退整行标量的缺口。搜索范围、平手规则、亚像素结果、位移置信度和融合没有改变。

- 对比 0.14.42 的原 NEON，不是对比全标量。2048×1536 首层独立对齐，真机 O3 同进程交替，各 8 次，中位 17.9895 → 13.728 ms（−23.7%，每对约 −4.3 ms）。
- macOS ASan/UBSan、Android ARM64 O3：12,000 个随机 SAD、1,134 个横移与奇偶宽度用例、72 组完整位移/置信度/残差全部精确相等。ARM64 分别链接强制标量与旧 NEON 参考。
- 3072×4080 的四帧真实 HDR RAW 回放，Gold 200 / Endura 和 Provia 100F 直扫分别测试。六次对照的 RGBA、HDR 增益图、JPEG 逐字节一致，短帧高光准入和匹配结果一致。
- 扩展真机回归：高光准入状态切换、尺寸/旋转变化、两条路径的等曝光 10 位以及预览重建，保存的对应输出逐字节一致。Release JVM 共 851 项，0 失败、2 跳过。
- 同组回放至 RGBA 的观测中位：Gold 5.440 → 4.963 s，Provia 4.365 → 4.146 s。Gold 的相纸与扫描代码没有变、单这几段却波动约 260 ms；短帧准入对齐也未同步变快。不能把这些总时长的差归因于本轮改动，更不是快门至保存或活动预览测试。

## 撤回的实验

- 相纸曝光、显影、光谱扫描按像素块连跑：六次交替 Gold 回放输出一致，三段合计中位 969.60 → 960.62 ms，但完整回放中位 5.131 → 5.170 s。没有稳定净收益，保留原来的分段计时和实现。
- 半精度纹理读回后的 NEON 扩宽：覆盖全部 65,536 个 half 编码，原 Inf/NaN 映射、符号零、次正规数、颜色通道和尾部均逐位一致。单独的转换基准反而比现有查表慢；整链候选同时改了线程复用，不能据整链波动声称转换变快，已撤回。
- 单独复用 512 行读回分块的转换线程：每路径旧/新各三次，读回阶段中位 Gold 194.61 → 199.05 ms、Provia 226.49 → 217.97 ms，未观察到一致收益，已撤回。上述回放的 Android thermal status 均为 0，但没有锁频。

## 下一步验证方向

PhotonCamera 的分阶段 GPU 查表、混合精度和降采样不是当前 Spektrafilm FP64 路径的等价实现。可先借鉴它减少中间同步的策略：分开测 RAW 金字塔读回、GPU 队列等待和 CPU 扩宽成本。保留金字塔每一层、量化和现有对齐，比较一次批量读回与现有逐层同步；不直接替换求解器。

取景需要把快门采集与后台处理分开测。0.14.40 的一张 Gold 历史实拍中，采集期间相邻预览纹理时间戳最大间隔 535.869 ms；进入后台成片后，有一次 `preview.slow_draw` 的 `histReadWaitMs` 为 122.392448。前者不能归为成片线程，后者也不是 122 ms 的直方图计算开销。继续跟踪当前帧直方图的 GPU 等待与成片提交边界，不能用上一帧统计换流畅度。
