## 0. 一句话结论

v0.10.173 的门有**三个"全图性"来源**，逐个修掉后色渗回到基线量级：

| # | 旧（v0.10.173） | 新（v0.10.174） | 量化 |
|---|---|---|---|
| ① | 上限 = **绝对** `0.2`（相对 σc 是 20~40×） | 上限 = **16·σc**（相对，暗部自动收紧） | 门控覆盖率 **73.7% → 1.6%**（152207） |

## 1. 根因确认（不是重新论证，是把"全局"落到可测的数字上）

任务书给的根因是"把 wy 的放宽做成了全图统一生效"。**离线把这句话拆成了 4 条可测项**，
并发现"全图性"有**两个**独立来源（旧版报告只提到 wy 那一条）：

### 1.1 来源 ①：绝对 cap 0.2 ⇒ 73.7% 的像素被放宽

`FrameRenderer.cpp:898`（旧）：`float cg = min(uCgK * gmag, kCgCap); scEff = max(scEff0, cg);`

σc 是**真实噪声**（`sc = sqrt(ay·y0 + by·glY²)`，中灰 ≈0.01、暗部 ≈0.005），而 cap 是
**绝对 0.2** ⇒ `|∇L| ≥ 0.1` 就吃满 ⇒ 离线四张样片的 `p4scEff+`（scEff 比 sc 大 1% 以上的
像素占比）实测 **34.4% / 70.8% / 73.7% / 87.2%**。真机同源读数（上一版报告 §5）也是这个量级。

### 1.2 来源 ②：门没有下阈 ⇒ 亮部平坦区也开门

sRGB OETF 的斜率 `d(lin)/d(disp)` 在纯白处是 2.46、在中灰是 0.93。所以**显示域 ∇<10
的"平坦区"在亮部对应线性域 `|∇L|` 高达 0.0965** —— 旧的 `min(κ·|∇L|, 0.2)` 在这些
像素上照样给出非零放大。离线证据：新方案在**最终输出**上的严格平坦区 `mean|R−G|`
只降 0.5~1.1%（旧版 13.6~27.5%），而 **P4 直接输出**上是**逐位不变**（§4.3）。

### 1.3 来源 ③：D-1 的门在 5 级全部生效（这是"片"量级的唯一来源）

`kFsChromaAtrous` 的 à trous 是 5 级、`step = 1,2,4,8,16`（半分辨率）⇒ 等效全分辨率
**2/4/8/16/32 px**。旧版的门不限级别，离线实测 **d1gate = [100, 100, 100, 100, 100]**。

**归因实验**（152207，同一条链，只切换门的位置）：

| 配置 | fr60（紫边） | hue15blk（块状色相偏移） | flatRG |
|---|---|---|---|
| base（门全关 = v0.10.172） | 13.635 | 0% | 8.938 |
| **只 P4 的门**（D-1 关） | 8.894 (0.652×) | 3.20% | 8.858 (−0.9%) |
| **只 D-1 的门**（P4 关） | 9.602 (0.704×) | **12.65%** | 6.821 (**−23.7%**) |
| 两者都开（= v0.10.173 现状） | 6.505 (0.477×) | **11.90%** | 6.779 (**−24.2%**) |

⇒ **色渗 ≈ 100% 来自 D-1 的多尺度门**（只 D-1 的 hue15blk 12.65% ≈ 现状 11.90%），
而 P4 的 7×7 核只有 3 px 尺度、单独只贡献 3.20%。**"一片"只能由 32 px 级产生。**

## 2. 修复方案与依据

### 2.1 PC 原文（读了 `/tmp/pc`，不凭记忆）

`app/src/main/assets/shaders/denoise/esd3d2.glsl:78-82`（= `esd3d2_steered.glsl:94-98`，逐字相同）：

```glsl
vec3 chromaDiff = (abs(cavg-cinX)+abs(cavg-cinY)+abs(cavg-cinXY)+abs(cavg-cin))/4.0;
chromaDiff *= max(abs(xDelta),abs(yDelta));                 // ← 结构门（梯度）
float chromaNoise = max(chromaDiff.r,max(chromaDiff.g,chromaDiff.b))
                  - min(chromaDiff.r,min(chromaDiff.g,chromaDiff.b));
float sigZ = max(sigY, min(abs(chromaNoise)*MOIRE, 0.2));   // ← 只增强 + 封顶 0.2
vec4 w  = (1.0-d*d/(d*d + sigY));      // 亮度路：sigY = max(NOISES·noisefactor+NOISEO, 1e-7)
vec4 w2 = (1.0-d*d/(d*d + sigZ));      // 色度路：**只有 sigZ 一个阈值，无独立亮度项**
```

`app/src/main/assets/shaders/utils/convdiff.glsl:33-37`（`sum3` = Rec.601 luma）：

```glsl
Output.r = sum3(fetch(xy-ivec2(1,i))) - sum3(fetch(xy+ivec2(1,i)));
Output.g = sum3(fetch(xy-ivec2(i,1))) - sum3(fetch(xy+ivec2(i,1)));
Output=(Output)/2.0;                       // ← 标准中心差分（1 px 间隔）
```

`esd3d2.glsl:64-71` 再对 GradBuffer 做 3×3 方向加权和 /3 得到 `xDelta/yDelta`。

**关键**：PC 的 `sigZ` 是 `chromaDiff × 梯度` —— **既要求有色度起伏、又要求有梯度**；
而我们的旧门是**纯梯度**门。这就是"亮部平坦区被误开"的机理（§1.2）。

### 2.2 落码形态（三条修正）

**P4（`FrameRenderer.cpp:929-935`）**：

```glsl
float cgGate  = (uCgK > 0.0) ? smoothstep(kCgG0, kCgG1, gmag) : 0.0;
float cgRelax = min(uCgK * gmag, kCgRel * sc) * cgGate;   // ← 有界 + 门控（关键）
float scEff   = max(scEff0, cgRelax);
float pcGate  = (uCgScope > 0.5) ? cgGate : 0.0;
```

`p4Accum`（:837-855）里：

```glsl
float wy = (y - y0) / (sc * 1.2);                    // ← wy 恒用 σc：**放弃放宽 wy**
float w  = exp(-0.5*(wy*wy + wc*wc) - 0.5*float(dx*dx+dy*dy)/9.68);
if (pcGate > 0.0) {                                  // ← PC 的 w2，按 gate 混合
    vec3 dv = c - (cd0 + y0);
    float d2 = dot(dv, dv);
    float w2 = 1.0 - d2 / (d2 + scEff);
    w = w + (w2 - w) * pcGate;
}
```

**`cgRelax` 必须乘 `cgGate`** —— 这是本次落码中途抓到的一个真实漏洞：只把"权重分支"
门控、不把 `scEff` 的放大门控，`wc` 的阈值仍会被全局放大 ⇒ 平坦区不再逐位等于改动前。
离线 CPU 复算先犯了这个错（`mask 内 1583959 个像素不同`），修正后 **mask 内 0 个不同**
（`strictRGp4` 逐位相同，§4.3）。

**D-1（`FrameRenderer.cpp:1328-1337`）**：

```glsl
if (uCgK > 0.0 && uStep <= 2) {                      // ← 只最细两级（2/4 px）
    float gmag = 0.5 * length(vec2(yR - yL, yD - yU));
    float cgGate = smoothstep(kCgG0, kCgG1, gmag);
    sig = max(sig, min(vec2(uCgK * gmag), kCgRel * sig) * cgGate);
}
```

### 2.3 参数依据（都可复算，不是拍的）

| 常量 | 值 | 依据 |
|---|---|---|
| `kCgG0` | **0.10** | 本链红线判据的"平坦区"= 显示域（sRGB 8-bit）中心差分 **∇ ≤ 10**。线性域 `\|∇L\| = (∇/255)·d(lin)/d(disp)`，而 `d(lin)/d(disp) = (2.4/1.055)·((v+0.055)/1.055)^1.4` 在 `v = 1.0`（纯白）取最大值 **2.46** ⇒ ∇=10 对应 `\|∇L\| ≤ 0.0965 < 0.10` ⇒ **∇≤10 的像素在数学上必然 gate = 0**（不依赖场景亮度） |
| `kCgG1` | **0.30** | = 3×下阈（与 PC `min(chromaNoise·MOIRE, 0.2)` 的"饱和"语义同构：过阈即吃满）。扫描 (0.02,0.08)/(0.05,0.15)/(0.08,0.24)/(0.10,0.30)/(0.20,0.60) 后取收益/色渗拐点：更松的门**不再增加收益**（0.05 与 0.02 的 fr60 差 < 0.5%）只增加色渗 |
| `kCgRel` | **16.0** | 相对 σc 的上限。扫描 4/8/16：4 → fr60 0.695×、8 → 0.603×、16 → 0.563×（152207），而 flatRG（−0.26/−0.59/−0.59%）与 hue15blk（1.86/2.08/2.08%）几乎不动 ⇒ 取 16。旧版的绝对 0.2 在中灰是 ≈20σc、暗部 ≈40σc；16σc 在暗部只有 0.08 |
| 中心差分算子 | 1 px | 与 PC `convdiff.glsl:34-36` 同式（PC 用 Rec.601 luma，本链全链统一 Rec.709；同一梯度上差 < 3%，见 `FrameRenderer.cpp:884` 的档 A 注释） |

**`cg_scope` 作为 A/B 反证保留**（任务要求）：
`=1`（默认）= PC 的 `w2` 形式 + 逐像素门；`=0` = 字面版（只放大 `wc` 的阈值、权重仍是
gauss，`pcGate` 恒 0）。离线：字面版 0.957×（152207，P4-only 口径）⇒ 与上一版结论一致。

## 3. 色渗判据（**本次新增，权重最高**）

三条判据都实现在 `/tmp/chromagate2/eval2.py:seep_metrics()`，在**显示域**上算：

| 判据 | 定义 | 为什么能抓色渗 |
|---|---|---|

## 4. 原有三条红线

### 4.1 红线 ①：亮度线性域逐位不变

P4 的输出亮度**恒为** `y0`（`oColor = vec4(y0 + mix(cd0, acc/wsum, uMix), ...)`，而
`cd = c − dot(c,LUMA)` 的 LUMA 加权恒为 0）；D-1 只搬运 Cb/Cr、Y 原样传（`oNext.b = p0.b`）。
⇒ **线性域亮度逐位不变**，本次改动没有触碰这条路径。

显示域 Laplacian（∇>60，`lap60`）的抖动（来自逐通道 sRGB OETF 的非线性，Jensen）：

| 151502 | 73.17 | 71.13 (−2.79%) | 71.58 (−2.17%) |

> 这里踩过 v0.10.173 的同一个坑（旧版注释也记了）：**必须显式判 `uCgK`，不能只判
> `uCgScope`** —— 档 A 开着时 `scEff0 ≠ sc`，只判 scope 会把档 A 的 σc 放大泄漏到
> 亮度项。本次落码同样在 CPU 复算里先犯了一次（`scEff` 的放宽量忘了乘 gate），
> 修正后才拿到"mask 内 0 个像素不同"。

## 7. 真机判据（同场景开/关各一张）

1. **字段**（`diag.stats`）：`cgK = 2.0000`、`cgCap = 16.0000`（**注意：v0.10.173 这里是
   0.2000，值变了就是新版**）、`cgScope = 1.000`、`dfG = 0.0000`。
   `cgMean / cgP95 / cgCov` = **门控覆盖率**的 mean / P95 / 开度>0.5 的面积比。
   **健康区间：`cgMean ≤ 0.15`、`cgCov ≤ 0.05`**（离线四张样片的 gate 覆盖是 0.41~2.32%；
   v0.10.173 的旧口径下这个数是 100%）。若真机 `cgCov > 0.10` ⇒ 门铺得太开，把
   `kCgG0/kCgG1` 往上调（或关开关）。
2. **关掉开关**（设置页「强边缘色度门」关 / prefs `chroma_gate=false`）⇒ `cgK = 0.0000`，
   输出应与 `v0.10.172` **逐位一致**（离线已验证 2350080/2350080）。
3. **数值**：`diag.stats` 的 `D5-out-u8` / `FILM-out` 两级看 ∇>60 紫边 —— 期望降
   **15~60%**（不是旧版的 50~80%）；亮度锐度不变。
4. **目视（三条一起看）**：① 窗外树枝/墙沿的紫边是否减轻；② **红色/彩色物体边缘是否
   发灰**（旧版最明显的问题，新版应基本消失）；③ **有没有"一片红/黄/紫"的大色块**
   （看墙面、天空、暗部这些平坦区）。
5. **如果真机仍见色块**：先关开关确认逐位回退（应 100% 回到 v0.10.172），再考虑
   把 `kCgRel` 降到 4.0 / 把 `kCgG0` 提到 0.15（都在 shader 常量里，一行）。

## 8. 无法判定的部分（明确声明）

1. **离线不能复现真机的"彩色块"**。离线输入是**已成片**（彩噪已被上游降噪 + JPEG 抹掉），
   而真机 P4 的输入是**带彩噪的场景线性域**。同一个"跨亮度搬运"机制在无彩噪输入上
   表现为**褪色 + 色相偏移**，在有彩噪输入上才表现为**彩色块**。⇒ 本报告能证明
   "**机制被限制在 0.4~2.3% 的像素 × 2 个最细尺度上**"（门控覆盖率 + `hue15blk` +
   `corr` + `flatRG`），**不能证明真机的色块消失**。**这一条只能靠真机 A/B 照片判定。**
2. **`kCgG0 = 0.10` 在真机域（场景线性）的等效强度未直接验证**。离线的"线性域"是
   "成片 → sRGB EOTF"，而真机是 CCM 后的场景线性（局部对比度不同：filmic 会压缩高光、
   提升暗部）。⇒ 真机的 `gate+` 覆盖率可能高于离线的 0.4~2.3%。**`cgMean/cgCov` 就是
   为这个校准准备的旋钮**（见 §7.1）。
3. **平坦区 `mean|R−G|` 仍有 −0.01~−1.23% 的下降**（D-1 细级的 2/4 px 空间传播）。
   若要求"严格不下降"，唯一的办法是**D-1 完全不开门**（只 P4 门）—— 离线数据：
   152207 0.681× / 151502 0.799× / 153558 0.659× / 195630 0.984×，`strictRG` −0.17~−0.44%
   （仍不是 0，因为 D-1 会把 P4 的变化传播开）。**这是"收益 vs 平坦区"的取舍点，
   留给真机数据拍板**（当前默认取"开 D-1 细级门"）。
4. **195630 这张样片的基线异常**：`base`（门关）的 fr60 = 1.117 而输入是 0.469
   （`2.381×`）—— D-1 在没有门时反而把这张图的紫边度量抬高了 138%。这张图的倍数
   因此不可与其他三张并列读，本报告只在"同口径相对差"的意义上引用它。
5. **未做真机验证**（本任务只到"离线 + 构建 + APK"）。
6. **`cg_scope = 0`（字面版）在新形态下的行为未做四张全测**（只测了 152207：
   0.957×，与上一版"近乎无效"的结论一致）。
