# Vulkan：RAW 场景纹理直接交给 Hanatos

2026-11-26 · vivo V2509A / Mali-G1-Ultra MC12 · 手机 FilmKit 0.14.56（853）。本轮只改变完整 RAW 前链与 Vulkan Hanatos 间的存储和交接，不改变重建、六级色度降噪、光谱后段精度或 HDR 算法。

## 实现和近黑图根因

上一轮的共享目标能作为 FBO 渲染，但绑定为 GLES 纹理后没有设置单层纹理所需的 min filter。默认 min filter 要求 mipmaps；FBO 完整不代表它能被后续着色器采样。绑定 EGLImage 后补齐普通场景纹理的 NEAREST min/mag 和 CLAMP_TO_EDGE S/T 后，GLES 投影前中心样本由 [0,0,0] 恢复为 [0.21862,0.20397,0.18335]，GL error 为 0。两张诊断回放与分带对照输出完全一致；不计入计时。

正式计时比较同一实验库里的三条路径：2 为现版 GLES 分带读回到 Vulkan；3 为整图 blit 到 AHardwareBuffer、每张导入 Vulkan；5 为 GLES 直接写入同一 AHardwareBuffer、Vulkan 原地采样，且同尺寸第二张复用导入。5 仍保留生产者 fence、Vulkan 队列所有权交接、投影输出到 CPU 和用于 HDR/回退的 GLES 访问。没有把这条路径称作整链零拷贝。

## 真机 A/B

固定室内四帧，共 40 张。3072×4080，8 位、HDR、颗粒关、PC3D 关、30 Hz 合成取景。两配方各按 2/3/5/5/3/2/5/2/2/5 交错，单进程两张。起止热状态均 0、屏幕均亮。每格是同张次中位数，单位 ms：

| 配方、指标 | 2 分带 首／二 | 3 blit 首／二 | 5 直接 首／二 |
|---|---:|---:|---:|
| Gold 200 / Endura：交接＋Hanatos | 125.8／99.7 | 118.7／72.0 | 93.9／52.0 |
| Gold：RAW 引擎 | 2460／2702 | 2397／2165 | 2337／2215 |
| Gold：合成取景间隔 P95 | 44.3／50.6 | 45.5／44.1 | 42.6／42.1 |
| Gold：合成取景最长间隔 | 63.8／105.5 | 63.5／60.0 | 63.9／56.8 |
| Provia 100F：交接＋Hanatos | 115.1／80.6 | 122.3／90.8 | 96.2／49.8 |
| Provia：RAW 引擎 | 2040／1953 | 2084／1853 | 2005／1846 |
| Provia：合成取景间隔 P95 | 46.5／46.4 | 47.1／43.3 | 46.2／44.3 |
| Provia：合成取景最长间隔 | 64.6／78.9 | 64.6／53.3 | 56.8／78.2 |

- 相较现版 Vulkan，直接路径局部节省 Gold **32／48 ms**、Provia **19／31 ms**。同尺寸第二张 Vulkan 导入设置约 **0.15–0.17 ms**，仍有 **28–31 ms** 的投影结果 CPU 读回与转宽。相较每张 blit 的路线，直接路径局部省约 20–41 ms，其中也有资源复用贡献，不能全部归给 blit。
- 整链观察到 Provia **2.04→2.00 s／1.95→1.85 s**。Gold 第二张分带对照有两次 DIR 达 813、980 ms，直接路径为 325–407 ms；代码未改变 DIR，因此不把中位数差 487 ms 当成 Vulkan 的因果收益。相较 blit，Gold 第二张整链反而慢约 50 ms、Provia 快约 8 ms。合成取景直接对现版未见一致性退化；这不是实际相机预览验收。
- RAW 引擎含 HDR 增益图，不含相机采集、App JPEG/R 封装和 MediaStore。暂无足够证据将此局部提升作为明显、可交付的整链收益；跨尺寸、互操作失败回退和实际取景仍未验收。

## 回归和留存

指定单帧 DNG：人像 110832、室内绿植 110846、室外建筑 110904、鲜花 110936。两配方、8 位和 RGB10_A2，共 16 组。每组 Vulkan 直接路径均完成全部 12,533,760 像素并生成 HDR 增益图；RGBA、HDR 增益图、回放 JPEG 共 **48/48** 与 0.14.56 Vulkan 归档逐字节相同。四帧性能回放的 40 张也按配方验证，三类输出跨三路径全部一致；单帧 DNG 不替代四帧多帧融合验证。

实验补丁、日志、压缩实验库、哈希和清理审计见 `test_temp/spektrafilm-vulkan-direct-d1-20261126/`。未安装或发包；常规 ARM64 构建恢复，SHA-256 与开工前一致，Vulkan 支持及 Ultra HDR JNI 都在。清理了四份可再生 Bayer 和冗余库，保留四张 DNG；手机临时回放目录已清理，充电常亮恢复为 0。复跑可解压实验库，再用 `tools/prepare-spektrafilm-regression-dng.py` 生成 fixtures；`replay.sh` 以 `LIBRARY` 指定解压后的库，以 `FIXTURES` 指定生成目录。

下一候选不是再搬一个 API，也不是照搬整条成片。优先验证从 D1 色度滤波到场景线性 RGB 再到 Hanatos 的连续 GPU 段：将六级 RG32F 水平中间值留在 workgroup，垂直轴在同一个 dispatch 中原序计算，避免中间纹理写回，同时保留每级原有 taps、逐通道协方差、门控、浮点精度和 halo。需计入产生最终场景和 Hanatos 输出的实际墙钟，并测合成取景尾延迟；还未实现，不计入收益。

> 后续复核：旧回放脚本即使未请求诊断，也会将 `FILMKIT_RAW_HANDOFF_DIAG` 传为空字符串；旧补丁只检查该变量是否存在。原 40 张性能回放中，直接共享路径的 8 个进程（16 张）因此实际含额外 `glFinish` 和 1×1 读回。上文计时保留作历史观测，不代表关闭诊断的对照；画质哈希结论不变。无读回复测见 [D1 到 Hanatos 连续路径](spektrafilm-vulkan-d1-fused-20261126.md)。
