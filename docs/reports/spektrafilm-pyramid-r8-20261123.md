# RAW 金字塔单通道读回

2026-11-23，vivo V2509A / Mali-G1-Ultra。对比含横移 SAD 优化的 `libfilmengine-align.so`；未出包，未覆盖安装 0.14.42。

## 保留 R8

对齐金字塔 L1 至 L4 只消费红通道。改存单通道 R8，保留原着色器、逐层 8 位量化、尺寸、对齐及曝光归一。读回使用紧密行排列，退出时恢复 pack 状态。驱动支持 RED/UNSIGNED_BYTE 时直接读回，否则从 RGBA/UNSIGNED_BYTE 取 R；读回失败时不会拿空缓存继续对齐。关闭 L1 只影响时域对齐，高光准入仍读自己的 L1。

同一 4080×3072 四帧 RAW，按旧、新、新、旧交错运行：

| 配方 | 四帧金字塔读回 RGBA8 → R8 | 完整 RAW 回放到 RGBA |
| --- | ---: | ---: |
| Gold 200 / Endura | 52.26 → 13.19 ms | 5.264 → 5.083 s |
| Provia 100F 直扫 | 53.69 → 13.31 ms | 4.264 → 4.315 s |

约 40 ms 的阶段收益可重复，旧实现每组 16 次 RGBA 回退，新实现为零；不能把 Gold 回放的 181 ms 差值归给 R8。以上不是快门至保存时间，也没有证明活动取景更流畅。

## 验证

- 同一二进制分别生成两种格式的完整金字塔，逐字节比较每帧每层，包括宽 255 的粗层；另跑 L1 关闭、高光 L1 按需读取的分支，数据与准入结果一致。
- 最终实现用真实 RAW 复验 Gold 200 / Endura、Provia 100F 直扫。等曝光 10 位、短帧有无及 L1 开关、旋转与尺寸变化、预览销毁重建的真机回归也通过，对应输出逐字节相同。预览回归验证输出，不是帧间隔测试。
- ARM64 Release 构建、GLSL 校验和 `git diff --check` 通过。

## 撤回批量 PBO

RGBA8 四层提交到一个 PBO、每帧一次映射，输出一致，但四帧读回变成约 0.80–0.84 s。其中映射约 22–32 ms，直接对映射内存抽取 R 约 0.77–0.80 s。批量 CPU 等待没有消掉四通道搬运，候选已移除。

后续优先分清后台成片期间，预览当前帧直方图究竟在等哪段共享 GPU 工作；用并发回放或实拍记录最差帧间隔，再试调整提交边界。不要把历史的直方图等待当成直方图计算成本，也不要用旧帧统计绕开等待。
