## 0. 结论摘要（先看这段）

1. **原版确实有我们没有的部分**：P2 梯度四项式、P2/P3 的"中心 vs 四对角"判别细化、G@RB 输出 `LIM(0,1)`、4.2/4.3 输出 `LIM(0,1)`、边界 `border_interpolate`。但——**没有任何一项能解释淡紫线**：在用户标注区域量化后全部 ≤ 0.77/8bit（p99.9）、max 3.2（§3.4）。
2. **发现一个此前所有对照实验都没抓到的原版 bug**：原版 `rgb` 是 `float(*)[3]`，而初始化写 `rgb[indx][FC(row,col)]`，GRBG 相位下 **FC=3（第二绿位）越界**写到下一像素的 R 槽位，且 **G2 位的 `rgb[·][1]` 永远保持 0**。这使原版 G 段有一半的邻居输入是 0（R/B 位的四正邻恰好 50.1% 是 G2 位）。**RawTherapee 已修正**（`rgb[c0][i] = rgb[c1][i] = LIM01(v)`），我方也与 RT 一致。⇒ "逐行对齐原版"若字面执行会引入 dcraw 级绿色塌陷，**这一项不应追随**。
3. **我方 RCD 段已经很接近当代最优实现**：与 RawTherapee 官方版相比，`p50 0.02 / p90 0.25 / p99 1.5 / p99.9 7.7`（R 通道，/8bit 线性域），差异集中在高梯度区（高梯度区 |Δ| 均值 0.59 vs 其余 0.11）。**唯一系统性差异是 P2 梯度两项式 vs 四项式**（§2 表 D1）。
4. **淡紫线不在 RCD 段（决定性数据）**：在用户标注淡紫线的"管道/窗框"区域，RCD 段（我方 vs RawTherapee 官方版）的 B−G 差异 **p99.9 仅 0.77、max 3.2/8bit**；即使把原版 dcraw 的全部差异（含 G2 bug）都对齐也只有 max 11.3/8bit，而成片该区域实际品红量级为 **mag 峰值 43~99/8bit**（§3.4）。⇒ 淡紫线只能来自去马赛克之后的链路（P0 边缘抹宽 / 锐化 / `[54]` pc3d 旁路 / filmic），**不是 RCD 缺失导致**。RCD 段可动的只有 P2 梯度口径一项，见 §5 排序。
5. **文档修正**：`FrameRenderer.cpp:813` 注释写"原版 STEP 4.3 逐行（RawTherapee rcd_demosaicing.c 173-206 行）"——实际上我方 3b 对齐的是 **RT 修正版**，不是 dcraw 原版；原版在这一步读的是 G 位的 0（越界后果）。建议改注释（本轮未改代码）。

## 1. 关键发现：原版 G2 越界（本轮最重要）

### 1.1 证据链（代码级）

| # | 位置 | 事实 |
|---|------|------|
| 1 | `rcd_demosaicing.c:34` | `rgb = (float (*)[3]) calloc(width*height, sizeof *rgb)` ⇒ **3 通道** |
| 2 | `rcd_demosaicing.c:41` | `cfa[indx] = rgb[indx][FC(row,col)] = image[indx][FC(row,col)]/65535.f` |
| 3 | dcraw `FC` 宏（`dcraw.c:219`） | `filters >> ((((row<<1 & 14) + (col & 1)) << 1) & 3)` ⇒ GRBG 下第二绿位返回 **3** |
| 4 | 内存后果 | `rgb[indx][3]` = `*(rgb + indx*3 + 3)` = `rgb[indx+1][0]`（下一像素的 R 槽位）；G2 位 `rgb[·][1]` 保持 calloc 的 0 |
| 5 | dcraw 宿主（`dcraw.c:10140`） | `image = (ushort (*)[4]) calloc(...)` ⇒ 宿主是 4 通道（`[3]` 合法），**越界只发生在 RCD 内部的 `rgb`** |
| 6 | dcraw 收尾（`dcraw.c:10209-10211`） | `if (mix_green) image[i][1] = (image[i][1]+image[i][3])>>1`（`mix_green` 默认 1，见 `dcraw.c:1835`）⇒ 若 G2 的插值 G 为 0，成片绿色被系统性拉低 |
| 7 | **RT 已修正** | `rcd_demosaic.cc` 用 `float (*const rgb)[tileSize*tileSize]`（3×N 布局，不越界）+ 初始化 `cfa[indx] = rgb[c0][indx] = rgb[c1][indx] = LIM01(rawData/scale)` ⇒ G1/G2 都写实测值 |

### 1.2 影响量化（真实样片 142415，ROI y1900-2450 / x2000-2700）

| 口径 | 说明 |
|------|------|
| G2 位 `rgb[1]` 全 0 | ✅ 复现（G2 占 25.0% 像素） |
| R/B 位的四正邻是 G2 的比例 | **50.1%**（STEP 3 的 `N_Est/S_Est/W_Est/E_Est` 一半输入是 0） |
| 越界覆盖落点 | GRBG 下 G2 位右邻是 B 位 ⇒ **B 位 `rgb[0]`（R 槽）被 G2 实测值污染** |
| 输出影响（G2=0 vs G2=实测） | p50 2.9 / p90 100.7 / **p99 183.8 / max 255**（/8bit） |
| 三方对照（R 通道，p99.9 / max） | dcraw vs RT **29.8 / 148**；dcraw vs 我们 **31.8 / 148**；RT vs 我们 **7.7 / 36** |

**含义**：`/tmp/rcd_ab.py`、`/tmp/rcd_ab_nolim.py` 以及 `docs/research/11` §8 的全部结论，其"原版"实为**修正版原版**（G2 保留实测值），不是 dcraw 里跑的真原版。§8 的"原版品红峰 +43.8"应重新标注为"修正版口径"。

### 3.6 合成场景（`rcd-linecompare-synth.py`）的教训

## 4. 特别核查结论（对应任务 a/b/c/d）

**a) 3b 是否真正逐行等价于原版 STEP 4.3？**
数学结构等价（三项梯度、四正邻色差、反比交叉加权、V/H 双轴混合），但**不是 dcraw 原版**：
- 原版 `C(p∓3d)` 在 G 位读到 **0**（越界后果）；我方 3b 读到 **G 值**（3a 占位）。
- 我方 3b ≡ **RawTherapee 修正版**（RT 的 `rgb[c][indx-w3]` 在 G 位同样是已初始化的 G 值）。
- 换 arr_mode 的输出差 max 147/8bit ⇒ 若字面"对齐原版"会引入显著伪影，**不建议**。

**b) 原版 STEP 4.2 我方是否完整？**
✅ 完整。`uCdFix=1` 下三项梯度（`|C(NW)−C(SE)| + |C(NW)−C(∓3)| + |G₀−G(∓2)|`）与无限幅均与 `rcd:150-159` 逐项对应；`uCdFix=0`（旧）的两项梯度 + clamp 已被取代。
未覆盖：判别细化的**平滑口径**（原版四对角 vs 我方十字 5-tap）与输出钳位域（原版 `LIM(0,1)` vs 我方 `uSatClip`）。

**c) STEP 2/3 的方向加权与置信度差异？**
- 方向统计：原版 40 项二次型 vs 我方五点高通（≡ RT）——方向场 p50 0.17 / p99 0.91。
- 置信度细化：原版四对角 vs 我方 P2 用 3×3、P3 用十字 5-tap。
- 梯度项数：**P2 两项 vs 原版/RT 四项**——这是唯一系统性、可量化的实现差异（B−G p99 1.44 / max 38.3）。
- 对 G 边缘陡度的影响：我方 P2 缺的两项在平坦区接近 0（故 p99 差异仅 0.90），但**跨边界处四项会大幅增大梯度**（原版设计意图），我方两项在跨边界时权重分配不同 ⇒ 边缘过渡形状略有差异。**这是"淡紫线"在 RCD 段唯一可动的旋钮**。

**d) 原版去马赛克后是否有收尾/修正段？**
- 原版：**没有**（只有 `CLIP` 转 ushort + `border_interpolate(4)`）。dcraw 宿主另有 `median_filter()`（默认关，需 `--med`）。
- RT：`border_interpolate(9)` + tile 边界重叠；无伪彩抑制。
- 我方：**有**（P4 色度平滑 / defringe / D-1 / ESD3D2 / 强边缘色度门 / P2 四邻限幅 / 色差限幅）——**"我方多"而非"我方少"**。
