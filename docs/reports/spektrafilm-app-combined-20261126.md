# FilmKit：同一前台 App 测 RAW/DIR 与 Vulkan 连续交接四路组合

2026-11-26 · vivo V2509A / Mali-G1-Ultra MC12 · 基线 **0.14.56（853）**。
独立测试包不是交付版本。正式源码、构建库、装机 APK 均不改。

## 对照口径

- **A（0）**：现版 Vulkan Hanatos 开、GLES RAW 前链、CPU 扫描。
- **B（3）**：A＋RAW 六分量紧凑存储＋CPU FP64 DIR 平面化。
- **C（4）**：A＋RAW 末端 AHardwareBuffer 共享入口＋扫描颜色、完整滤波、打包和 HDR 底图走 Vulkan。
- **D（7）**：B 与 C 一起开。曝光、DIR、印相和扫描光谱没有迁出 CPU FP64；RAW MFNR、配方、粒度、核和 HDR 规则不变。

同一测试 APK、同一原生库、固定室内四帧 RAW 及其曝光/白平衡/CCM/阴影校正，
完整四帧 MFNR，HDR 开、8 位，关颗粒、PC3D、CS、CM。Gold 200 / Endura 和
Provia 100F 直扫各在「做／不做 GLES still 预热」下交错运行。每个条件四个块，
每块四臂各一张，四个位置均衡；每张均启动独立的 Android 前台进程，CPU 掩码 0–7。
两种条件都不提前初始化 Vulkan；「未预热」也已经启动了 EGL still context、
校验输入并读入配方，不是从点击启动 App 开始计时。只统计提交 RAW 至 JPEG/R
返回，不含预热本身、相机采集、真实取景、EXIF 或 MediaStore。慢帧仅报告每组四张
最慢样本，不称为 P95 或实拍长尾。

## 结果：Vulkan 段确实更快，但组合没稳定省半秒

单位 ms；每组四个完整块。正值是更快，负值是更慢。配对节省先在同块相减再取
中位数，因此不是直接用两列独立中位数相减。64 张均通过，另两张 pilot 不计入。
系统热状态始终为 0；每个采样点取所报两路皮温的较高值，提交前 34.0–38.0 °C，
回放后 34.1–37.7 °C，不能把它当作时钟频率恒定。

D 相对 A 的 16 个块里，14 个更快，一个近似持平（预热 Provia 慢 0.35 ms），
一个回退（未预热 Gold 慢 165 ms）。预热 Gold 最快的一组省 688 ms，但四组为
688／422／173／321 ms。把 Vulkan 两端加到已启用内存改动的 B 上，D 相对 B
配对节省为预热 Gold／Provia **216／17 ms**、未预热 **−81／134 ms**；不能把前两轮
独立探针收益相加。

C/D 确实使用 AHardwareBuffer 共享入口，GLES 场景读回时间从 A 的约 19–21 ms
变成 0；仍有同步等开销。仅比较 C 与 A，实际读回＋投影合计配对省 6–49 ms，
连续扫描（扫描输出＋RGBA 打包＋HDR 底图）省 24–64 ms。局部工作省下来不保证
整链更快：预热 Provia 在 C 还是慢 81 ms。D 的前台进程 VmHWM 相对 A 的配对中位
下降约 176–300 MiB，不等于 GPU 实际释放的量，也不证明某个分配导致缺页。

**不合入、不发 APK、不安排手拍。** 有局部和整链收益，但两条配方、两种首张条件
没有稳定接近 0.5 秒，且真实取景未验收。现有 Vulkan 开关及 0.14.56 均保留。

## 后续只追一个更大的杠杆：按实际拍摄路径预热

本轮没做「关闭预热」的产品结论。同为 A，预热的 RAW 到光谱入口中位约
711–745 ms，未预热约 967–1049 ms；但预热组的曝光＋DIR 反而更长，进程
VmHWM 约高 0.83–0.89 GiB，且主缺页计数相差很大。这是不同组下的现象，
不是因果。现版源码还明确无条件分配并清零 PC3D、CS、CM 图像目标，即使当次
夹具关了它们；12.53 MP 时，这几组未用目标合计约 **622 MiB 逻辑容量**。
所以若再做一轮，应只试「按实际已启用的路径分配／触页」，仍保留每个分支
实际使用时的完整分配、算法与质量。需要把开取景到首张、RAW 前链到 JPEG/R、
内存/缺页和取景帧间隔一起测，不能只把预热时间从计时器里挪出去。

## 画质口径

每次逐帧验固定 RAW 及元数据 SHA-256，确认 Hanatos 完整处理 12,533,760 像素
且无 CPU 投影回退，全量 MFNR、FP64 光谱、增益图和 JPEG/R 都成功。逐配方：
A/B 的全尺寸 RGBA、HDR 增益图和 JPEG/R 全部逐字节一致；C/D 同样逐字节一致；
A/B 与 C/D 的增益图一致，但 RGBA/JPEG 不使用同一哈希。扫描路线以前在四张
指定原始 DNG 上与 CPU 对照的 RGB 最大偏差为 1 码；该历史结果不能替代本组合的
人像、绿植、建筑、鲜花四原片发版验收。本轮记录固定四帧的哈希，不宣称已做
四原片或真实取景回归。
