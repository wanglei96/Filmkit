# Spektrafilm CPU 路线：曝光与 DIR 全尺寸拆测

2026-11-25，vivo V2509A，手机保留 0.14.50（847）。目标是查清两条配方共用的 CPU 开销，筛掉只能省几十毫秒的改动；不再尝试 RAW 前链和光谱分支重叠。

## 结果

用同一库的临时计时插桩对 3072×4080 的完整四帧 RAW 回放细分计时：无高光每路线 3 次；含高光每路线以一对原库／插桩库回放验证输出。所有 10 次回放始末 Thermal Status 均为 0，关闭回放额外阶段同步，合成取景并发，PC3D 和颗粒关闭。6 次输出比较的 RGBA、HDR 增益图、JPEG 和诊断统计逐字节相同；其中 2 次比较直接对生产代码基线。只收集 3072×4080 样本，不把 HDR 中性探针的 1×1 调用计入。分项与外层计时差最大 4.93 ms（包括计时输出、外层调度与阶段边界）；Hanatos 与 `filmExposureMs` 是相邻阶段，不是父子计时。

| DIR 第二次显影 | 43 | 44 | 41 | 40 |

这些是 CPU 阶段墙钟，不是线程 CPU 时间。无高光 Provia 的首次显影/抑制矩阵为 118–446 ms，同一配方的尾部/反射合计为 313–500 ms，其慢样本伴随进程记录 156,642 次 major faults。两者只是同次出现：统计涵盖整个回放进程和驱动，不能定位到该阶段，也不能归因于 FP64 缓冲本身。Gold 同一插桩库、同 RAW 的引擎墙钟也有 2.993–3.401 s 波动，不能把少数跨进程样本的差当成提速。

结论：核心 FIR 一共约 57–77 ms，单改这一项不可能产生数百毫秒净收益；数据搬运组包含必要的曝光修正，不存在把表中耗时全部删掉的候选。以含高光样本作预算，即使把所有长尾/反射滤波提速到两倍，也只分别少约 167/171 ms，且还没有这样的候选；不按比例外推到实拍。要做大的 CPU 优化，优先查实际拍照负载中全尺寸工作集、缺页和调度等待的归因，再决定是否值得跨曝光／DIR 一起重排缓冲与访问。不改核、采样、边界、浮点精度或 HDR 流程，不再为单项小改跑发布矩阵。

## CAM16 快筛及恢复

同进程、同输入、预热后交错 8 旧 + 8 新：固定 FP64 除数移出循环，CAM16 中位数 **305.263 → 286.057 ms**，包含滤波与 sRGB 编码的扫描输出 **352.532 → 334.529 ms**。最大 FP64 差 `8.99e-14`，8/10 位码值变化数均为零。这是隔离测量，无整链提速结论；候选和曝光/DIR 临时插桩均撤回。ARM64 重编与试验前的库逐字节一致，SHA-256 `0816e980316f749329e42b859b95a6965dd6741ffb83d1ed1fa64209b3bc4f41`。没有出包、安装或提交。
