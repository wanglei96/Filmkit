# FilmKit：RAW 全尺寸协方差的分配与数据布局

2026-11-26，vivo V2509A / Mali-G1-Ultra MC12，现版 0.14.56（853）。从上轮实拍现成日志和完整 Perfetto 继续，不再要求手拍。以下测试不改成片 Vulkan 开关、取景程序、曝光、DIR、MediaStore 或图像算法。

## 从实拍定位分配成本

实拍 Gold 200 / Vision 2383 的第一张之前（19:51:23）日志确认预热完成，首张没在快门后重新分配原始协方差。后两张则释放后重建，`rgb_cov.allocate` 分别为 **337.2 / 285.6 ms**。第三张用生产日志推定分配结束，再按日志中的分配耗时反推出起点；边界约毫秒精度。Perfetto 在这 285.6 ms 内观测到 FilmStill **263.9 ms 上核、20.9 ms 可运行未上核、0.7 ms 睡眠**。同期 `kswapd0` 用了约 217 CPU-ms；分配后至协方差释放的另一段中，FilmStill 约 154 ms 处于睡眠。没有驱动调用栈或 GPU fence 归因，不能断言具体在驱动的哪个子动作，也不把另段睡眠全归为 GPU 等待。可以排除「这 286 ms 大多只是睡眠等 GPU」的解释。

## 三个 A/B 候选

- **B，原格式换分配方式**：原协方差仍是两个 RGBA32F，仍在原位置申请、释放，只把这一对从可变 `glTexImage2D` 换为不可变 `glTexStorage2D`。
- **C，保留原协方差存储**：只跨张保留原始两个 RGBA32F 对象；每张重写所有像素、复位有效性、其他滤波库照旧释放。不复用上张协方差数值。此模式却将原来有意错开的 **382.50 MiB 逻辑容量**留到 Vulkan 和 FP64 工作区生命周期内，不能仅凭热态更快上线。0.14.39 已有真实低内存进程退出历史；0.14.40 开始在光谱前主动释放协方差。这里只作对照，不改回生产内存策略。
- **D，只存六分量**：方差／协方差是完整对称矩阵。原布局 `(RR,GG,BB,1) + (RG,RB,GB,1)`，改为 `(RR,GG,BB,RG) + (RB,GB)`，格式 RGBA32F + RG32F。全部六个分量维持原 FP32，不改公式、边界、tap 或跨尺度/PC3D 传播。初始协方差、CS、CM、PC3D 各级、P4 和多尺度色度消费按同布局读写；原始 RAW 融合噪声纹理的四个字段保持不动。单个 3072×4080 协方差库从 401,080,320 到 300,810,240 字节，**少 95.63 MiB（25%）**；不是实测物理 RSS。

## 固定四帧实测

室内 3072×4080 四帧 RAW，8 位、HDR、PC3D 和颗粒关、合成预览并发。两边都跑现版全帧 Vulkan Hanatos、原 CPU FP64 光谱，无附加阶段同步。每个独立进程连续出两张，热状态 0→0。引擎时间止于成片和 HDR 输出，不含相机采集、App JPEG/R 封装或 MediaStore；不是实际取景测试。

- B **无 GLES 预热**交错 ABBA，分配确实发生在首张：Gold 分配 77.3→77.8 ms、总引擎 2961→2909 ms；Provia 分配 83.0→77.7 ms、总引擎 2497→2555 ms。未复现实拍的 285–337 ms，也未出现两配方都快。在 GLES 已预热的同批暖态对照中，第二张分配只少约 7–13 ms，整引擎反而慢约 8–25 ms。
- C **有 GLES 预热**，ABCCBA 后追加 CAAC 反序，计每格四进程：Gold 首张 2388→2465 ms，第二张 2309→2214 ms；Provia 首张 1970→2032 ms，第二张 1908→1830 ms。首张原本已从预热拿到分配，C 没有移除首张分配。第二张直接省去一次 61–65 ms 左右的前链分配，RAW 到光谱入口缩短约 70–83 ms，确实有局部及连拍净收益；但并未改善首张，且把大纹理留进光谱内存峰值，保留原策略。

### D：紧凑布局，保持释放时机

GLES 已预热；ABBA、BAAB 两批，每格四个独立进程中位数，单位 ms，现版布局 → 六分量布局。

| 指标 | Gold / Vision 2383 首张 | Gold 第二张 | Provia 首张 | Provia 第二张 |
|---|---:|---:|---:|---:|
| RAW 全引擎 | 2615 → 2569 | 2486 → 2403 | 2173 → 2173 | 2075 → 1997 |
| RAW 到光谱入口 | 995 → 966 | 856 → 801 | 979 → 976 | 873 → 839 |
| 协方差分配 | 预热时 | 63.5 → 13.7 | 预热时 | 49.5 → 13.3 |
| 合成预览交付间隔 P95 | 48.6 → 45.5 | 43.1 → 41.9 | 45.2 → 43.6 | 45.2 → 40.0 |
| 合成预览最长交付间隔 | 65.0 → 61.7 | 95.6 → 55.9 | 57.9 → 55.6 | 76.8 → 55.6 |

第二张 RAW 引擎两批均有正收益，Gold 约 126 / 54 ms，Provia 约 81 / 99 ms；其中相当一部分在所改分配和前链。但首张 Gold 两批只少约 44 / 23 ms，Provia 一批慢约 23 ms、一批快约 24 ms。首次在预热里的协方差分配也变短：Gold 中位约 85→58 ms、Provia 82→59 ms。这不等于同量快门后收益。不把取景代理数据当真人取景验收。

### 无 GLES 预热：本批不计入性能结论

最初一批在 DNG 回放后受热状态变化中断。冷却门槛重跑后，Gold／Vision 2383 的四个进程均完成，确认首张确实重新分配，Vulkan 全帧、HDR、输出 SHA-256 均通过。探索性数据中，首张分配中位数为 244.2→59.6 ms、整引擎为 4772→3446 ms；但 A 两次检查手机前台都是其他应用，D 两次都是桌面，**前台负载与实验组重合，整段差值不能归因给布局**。重跑尚未开始 Provia 时发现 FilmKit 回到前台，终止回放，恢复充电常亮设置，不抢占相机。两批暖态 A/D 全部在桌面，仍可独立分析。后续性能脚本已改成在冷却等待、送帧前和回放后校验系统 Launcher，离开即停止。

## 四张指定 DNG 的画质回归

使用原始 DNG 人像 **110832**、室内绿植 **110846**、室外建筑 **110904**、鲜花 **110936**。Gold 200 / Endura 与 Provia 100F 直扫，各测 8 位和 10 位，共 **16 组**。两侧都开 Vulkan 和 HDR；显式打开标准单 RAW 降噪，确保命中协方差生产与消费；主矩阵关闭 PC3D、CS、CM。A/D 的原尺寸 RGBA、HDR 增益图、回放 JPEG **48/48 逐字节一致**。追加的人像 Gold／Endura 8 位样本在 **PC3D 叠加、CS、CM 全开**时三项也一致；这不是全配方/全开关矩阵。追加 10 位试跑曾因热状态变化在 A 侧后停止，未组成对，不计入结论。没有把灯罩或固定室内四帧当作四张原片的替代。

## 证据与决定

**本轮不合入、不发包。** 保留 D 作为后续整链候选中可复用的等价布局，不单独交付这约 0.08 s 的第二张回放改善。B 没有跨配方提速；C 有第二张收益，但不能用额外常驻几百 MiB 来换。不要把某张实拍 285–337 ms 的分配墙钟当作可直接回收的预算，受控回放的原样本分配只约 50–83 ms，也没有真实取景下的候选 A/B。

## 下一步：用同一次 App 回放验证跨阶段的内存收益

实拍 6.026 s 样本，协方差释放之前已用 2.163 s（含 0.466 s 四帧到齐），随后 Vulkan 交接＋Hanatos 约 0.164 s，曝光＋DIR 则为 1.738 s。Vulkan shader 本身 9.5 ms，继续只磨 shader 不可能省半秒。已经试过的 AHB 直连＋Vulkan 扫描尾段在同四帧相对现版开的首张配对差为 66／95 ms，不能与本轮后续张次的收益相加。

下一套同 RAW App 对照要同时记前链 FBO 分配／降噪提交尾部、进程缺页／换页、FP64 曝光／DIR 和完整交付耗时，分别控制预热和内存压力。布局 D 减少前链全帧分配；光谱侧可检验 DIR 的抑制场是否能直接生成到三个 FP64 平面，由完整尾核和核心核直接消费，避免目前把每个通道从交错 Triplet 另拷进一个全尺寸工作平面。必须先生成完整抑制场再改写曝光：抑制矩阵需要原像素三个通道，不能边生成下一通道边覆盖源曝光。这个设想保留完整公式、顺序和边界，逻辑上可少一个 95.63 MiB 工作平面；没有实现或测得速度，不计入收益。新的 Vulkan 连续前链同理，必须能少一次全帧写回、读回或大资源分配，再用同一套首张整链对照验证；本轮没有新 Vulkan shader 贡献。
