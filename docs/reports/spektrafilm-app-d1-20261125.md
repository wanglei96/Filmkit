# Spektrafilm：0.14.53 D1 分带真机实拍

2026-11-25，vivo V2509A。0.14.53（850）安装后由用户手拍，反馈「预览卡顿变好了，Provia 100F 会卡一点点」。与 [0.14.52 实拍](spektrafilm-app-cam16-20261125.md) 各路线一张比较。四张均为 cameraId 2、3072×4080、四帧 MFNR、颗粒关、8 位及 HDR JPEG/R Q100 4:4:4。热状态快照为 0；RAW 曝光/ISO、文件大小和预览工作分辨率（旧 590×786、新 608×811）不同，不作算法因果对照。

## 曝光后到保存

单位 ms；起止为 `capture.begin` / `photo.saved`。RAW 引擎包含光谱分支；`frontSubmitMs` 是调用方前链提交墙钟，不是 GPU 执行时间，也不能与各行相加。

| 观测 | Gold 200 / Endura：0.14.52 → 0.14.53 | Provia 100F 直扫：0.14.52 → 0.14.53 |
| --- | ---: | ---: |
| 快门到保存 | 6479 → 7005 (+526) | 6580 → 5993 (−587) |
| 四帧采集（`mfnr.capture.ms`） | 444 → 425 | 442 → 435 |
| RAW 引擎整段 | 5446 → 5559 | 4799 → 4923 |

| 其中光谱分支（含读回及 HDR） | 3245 → 3547 | 3134 → 2895 |

Provia 提早保存来自保存段少 661 ms，入保存队列反而晚 74 ms，不能把 −587 ms 记成 D1 提速。Gold 的 +526 ms 分别来自入队前 +208 ms、入队后 +318 ms。新版编码墙钟/线程 CPU 是 Gold 166/152 ms、Provia 144/132 ms；发布 367/1 ms、280/0 ms。发布耗时没有主要落在调用线程 CPU 上，不能仅凭该计时断言是磁盘、Binder 服务还是调度。新版没有复现 Provia 659 ms 编码尾部，不等于长尾已修。

## 预览分窗口

- 快门初期峰值交付间隔：Gold 362 → 383 ms，Provia 370 → 363 ms；两版两条路线均有约 369 ms 纹理时间戳间隔。0.14.53 对应事件的取景渲染提交仅 31 和 14 ms；主要间隔已出现在采集输入侧，不把这段归为 D1/光谱。
- 排除包含快门初期停顿的首个统计窗口后，快门到保存期间后续窗口最长交付间隔：Gold **345 → 145 ms**，Provia **326 → 218 ms**，与体感方向一致，不等于持续帧率或重复测量的中位数。Gold 后续未触发 ≥150 ms 逐帧记录。
- 本次 Provia 余留长帧在快门后 **4.420 s**；同一帧纹理间隔 **33.333 ms**、排队 **4.586 ms**、纹理更新 **1.600 ms**、渲染提交 **190.425 ms**，其中当前帧直方图读回等待 **183.922 ms**，交换缓冲约 **0.580 ms**。D1 冷分配在快门后 2.337 s 已记完，按光谱 `branchMs` 倒推此长帧落在光谱分支时间窗，且在 JPEG/R 保存之前。读回是已定位的阻塞点，上游等待原因未定；不能把它直接归为某个光谱算法、D1 分配或传感器断流。

结论：这轮实拍验证了处理期预览体感改善，未验证关颗粒双路线整链都提速。若继续排查，先在固定 RAW 环境尝试复现 Provia 后段的读回阻塞，并区分线程调度与 GPU 同步；另跟踪保存尾部，不复用旧帧统计。画质以先前 [同 RAW 字节级回归](spektrafilm-d1-tiled-preview-20261125.md) 为准，不用这四张不同 RAW 做像素比较。设备未再次触发快门，也未改动相机设置。
