## 胶片曝光与 DIR：局部有收益，候选未交付

候选将光晕合成、FP64 `log10` 与通道写回放进同一遍遍历；让 DIR 扩散后的修正样本直接经过原第二次显影曲线。核、精度与运算未删减。ARM64 合同覆盖 96 个正／负片用例，显影输入及 DIR 密度中间值逐字节一致。真机用两组固定四帧 RAW（室内／白灯罩）、3072×4080、关颗粒、HDR 8 位、30 Hz 合成预览做 32 次平衡交错回放；RGBA、增益图和回放 JPEG 的 SHA-256 一致。另有 USB 中断前 3 次，不并入平衡组。

## JPEG/R：并行底图编码已交付

3072×4080 的 4:4:4 底图分为三段 MCU 对齐的输入，由同一 libjpeg-turbo 编码成一个带 restart markers 的 baseline scan；量化、Huffman、DCT、质量和采样不变。尺寸不合适或分段失败则走原单流，之后仍有原 stb 回退。增益图、EXIF、JPEG/R 容器校验、媒体库发布顺序和线程优先级均保持。新增 `hdr.jpegr_encode` 拆出底图、增益图、封装、校验及 JNI 拷贝；`photo.encode` 单列 EXIF。

在手机用固定 RGBA／HDR 增益图／EXIF 做 JNI ABBA 对照，每配方、亲和组和版本 16 个热样本。起止热状态 0；`0f` 为固定小核簇的压力对照，不是实拍调度方式。

| 路线 | 不限制核：全 JPEG/R 中位 | 仅小核簇：全 JPEG/R 中位 |
| --- | ---: | ---: |
| Provia 100F 直扫 | 154.5 → 99.2 ms | 271.5 → 129.8 ms |
| Gold 200 / Portra Endura | 164.3 → 104.1 ms | 299.6 → 138.9 ms |

Provia 最大值分别为 160.8→109.2 和 298.3→144.5 ms。两配方的解码底图 RGB、SOF0、DQT、DHT、APP1 相同；辅助 HDR JPEG 整段逐字节一致，Android 均能解码 gainmap。容器 SHA 不同是 restart markers、熵流和 MPF 偏移的预期变化。宿主测试通过 60 项 RGB/RGBA、12 项完整量化系数对照及小图旁路。测试的 JPEG/R A/B 图是固定输入派生产物，非相机原片。

最终 ARM64 与 0.14.54 的另一组 8 次 A/B，用独立 30 Hz 合成取景并发 Provia JPEG/R，热样本编码中位 145.95→89.88 ms。编码重叠期合并 P95 56.21→55.49 ms、单轮最大值中位 60.56→62.86 ms、最坏 62.52→66.89 ms；全窗 P95 56.45→55.49 ms，最坏 68.31→66.89 ms。未测到明显退步，不能替代真实取景。另将最终 APK 中同字节的 ARM64 库与旧版在白灯罩固定 RAW 上回放，Gold／Provia、8 位／10 位共 4 组 A/B 的 RGBA、增益图及普通回放 JPEG 全部逐字节一致。普通回放 JPEG 不经过 JPEG/R helper；新 helper 的等价性由上一项独立对照证明。
