# Spektrafilm：RAW 多尺度降噪分带，保留完整邻域

2026-11-25，vivo V2509A，0.14.52（849）CAM16 库为基线。目标是处理期取景长帧和关颗粒成像时间，不动快门采集、预览的当前帧直方图、保存链，亦不降 MFNR 或降噪规格。全程使用已有 RAW，无新实拍。

## 从预览长帧到 RAW 临时缓冲

- [JPEG/R 长尾复核](spektrafilm-jpegr-tail-20261125.md) 记录了实拍 Provia **292.8 ms** 的同步直方图读回，在光谱分支前。固定 RAW 回放独立复现了 **292.6 ms** 的读回等待（室内 Gold，对照组），CPU 提交窗与 D1 多尺度色度降噪重叠。更细的无同步提交标记下，同一场景另一对照的合成取景 GPU 完成间隔达 **356.0 ms**，该帧直方图读回 **248.4 ms**，D1 首次分配墙钟 **352.6 ms**。这些不是逐 GPU pass 的执行计时，但能把异常与 D1 的冷分配窗口对齐。
- D1 原来持有六张全幅 RG32F 临时图，3072×4080 合计 **601.6 MB**。候选每带提交 1024 个有效行，两侧保留最多 **126 行** 邻域，六级空洞 B3 的完整纵向支撑是 `2×(1+2+4+8+16+32)`。在内部边界重算邻域、只回写带中央；图像真实边界仍按原规则钳制。全图引导、噪声和饱和掩膜保持原始坐标。固定带缓冲最大 **188.2 MB**，减少 **413.5 MB / 68.7%（标称纹理容量）**。每个采样、收缩公式、六级频带和 FP32 存储不变，不把未完成的零初值或旧帧统计拿来用。
- 对照试验：协方差纹理换不可变存储在交错回放未同时改善两条路线和取景，撤回。去掉 D1 首带前全幅零累积图的写读，Provia 的 8 位成片与 JPEG 哈希变化、HDR 增益图没变；未继续计时或合入，不能说差异已通过画质验收。

## 真机时延

两份 3072×4080 四帧实拍 RAW：室内原始 burst 与真实裁切白灯罩；Gold 200 / Endura 印相、Provia 100F 直扫；颗粒关、HDR 开，PC3D / CS / CM 关。8 位按 ABBA 各跑四次，共 16 次，均使用已安装 APK 的同一 CAM16 表；RAW 和设置校验一致，有 30 Hz 合成取景，各轮开始和结束 Thermal Status 0。表中为各版两次的中位数。引擎计时不含相机采集、JPEG/R 和 MediaStore。取景是合成预览 GPU 完成间隔，不是屏幕帧率或触感验收。

| 场景／路线 | D1 首次分配墙钟（ms） | RAW 到光谱前，`chain` 以后（ms） | RAW 引擎（s） | 前链最长取景间隔（ms） |
|---|---:|---:|---:|---:|
| 室内 Gold 印相 | 232.0 → 34.6 | 761.5 → 551.5 | 3.068 → 2.714 | 217.2 → 57.1 |
| 室内 Provia 直扫 | 124.6 → 49.1 | 591.0 → 555.5 | 2.228 → 2.088 | 84.2 → 47.8 |
| 白灯罩 Gold 印相 | 124.0 → 35.8 | 600.5 → 543.0 | 2.821 → 2.678 | 87.7 → 58.3 |
| 白灯罩 Provia 直扫 | 104.9 → 36.3 | 603.5 → 536.0 | 2.420 → 2.285 | 85.0 → 57.4 |

分配墙钟记录的是调用方时间；不把等待归为 GPU kernel 执行。四组冷回放引擎均更快约 **135–353 ms**，但局部因果证据以 D1 分配、前链时间和取景窗口为主，不把后续未改阶段的波动算成 D1 算法提速。回放进程峰值 RSS 中位减少约 **241–436 MiB**；不是 App 实拍 PSS。后续纯光谱窗口仍可见更长间隔，不能声称全程不卡。

### 反序复核：不带探针日志的候选库

室内 8 位 BAAB 各两次，仍用原来的当前帧取景与 30 Hz 合成负载。Gold RAW 引擎 **3.150 → 2.955 s**、Provia **2.428 → 2.254 s**；每次全程最长合成取景间隔的中位数分别 **213 → 118 ms、80 → 60 ms**。D1 首次分配 **122 → 94 ms、118 → 50 ms**。局部收益未复现到同一幅度，但两个路线的方向相同。该组候选 Gold 仍有一次 155.4 ms 的全程长帧。

### 同进程第二张

同一 still renderer 每版每配方连跑两次，第二张不重新分配 D1。间隔降温，四批开始／结束 Thermal Status 均为 0。第二张 Gold 引擎 **2.728 → 2.692 s**（全程取景最长间隔 **85.0 → 76.3 ms**），Provia **2.203 → 2.192 s**（**55.9 → 52.9 ms**）。每路线每版只有一张热样本，没有观察到明显的热拍成本转移，也不据此宣称稳态提速。第一、第二张的 RGBA、HDR 增益图和 JPEG 均逐字节一致。更早的三张连跑候选单批结束 Thermal Status 1，未用作对照性能证据。

## 画质和验证

- ABBA 16 次逐次对照：两场景、两路线的 **RGBA、HDR 增益图、JPEG** 均与既有 0.14.52 回放哈希完全一致。白灯罩为原始真实场景，灯面没有新增偏色；全图逐字节比较也覆盖原尺寸灯面和分带接缝，不是缩略图替代。上一轮灯面数值和回放口径见 [CAM16 实拍报告](spektrafilm-app-cam16-20261125.md)。
- 去掉探针日志后重新用候选 Release ARM64 库对照：8 位 BAAB 8 次和 10 位两场景×两配方 8 次，均与各自既有 0.14.52 全尺寸哈希完全一致。10 位比较的是原生 `RGB10_A2`，并另比 HDR 增益图和由回放生成的 JPEG（10 位回放 JPEG 仅用作对照，不是 HEIF 交付）。
- 原始裁切灯罩额外打开 PC3D 叠加、CS 和 CM，两路线各做一对；所有输出逐字节一致，日志确认三项确实执行且仍进入 D1。
- 独立纵向支撑检查：14 个图高（包含带边界及最后一带很短），在内部边界加入不连续强阶跃，所有行与整幅累积 FP32 逐位一致。此检查针对带邻域，不替代生产链真机像素比较。

保留分带实现，未保留逐阶段探针日志，仅保留 D1 分配计时。双 ABI Release 构建、Release JVM 测试任务和 `git diff --check` 通过；生成的本地构建没有签名或安装。手机仍在 0.14.52，本次未重新测快门到 MediaStore 保存，也未复验真实移动取景体感。
