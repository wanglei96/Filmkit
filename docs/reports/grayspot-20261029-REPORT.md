## 2. 天空白块已定案：它是 RAW 真实饱和，短帧信息没有进成片

- 把 144536.dng 的 RAW（黑阶 64 / 白阶 1023）按 G 通道 ≥1000 叠到成片上：白色平台**逐块与 RAW 饱和区重合**（天空区饱和 10.1%，全图 4.7%，150/4032 个 64×48 块）。
- 采集端实测 `bracket.actual sat = 0.0687,0.0689,0.1461,0.0002` ⇒ **−1.5EV 短帧几乎不饱和（0.02%）**，信息是有的。
- 但融合层没有把它接回来：
  - `kFsMfnrFft`（DFT 频域收缩）为**等曝光 burst** 设计。跨曝光时 `a = d²/(d²+cσ²)` 里 d² 是长短帧归一后的整档差 ⇒ a→1 ⇒ 输出退回参考帧。代码注释自认：「多曝光下长短帧在高光处相差整档 ⇒ 收缩只能判成不一致并退回参考帧，短帧真值没有出口」（FrameRenderer.cpp:2879）。
  - 唯一的短帧高光出口 `kFsHlInpaint` 被 **`kHlInpaintOn = false` 硬关**（0.12.135，因灯面台阶/色块问题）。
- 结果：饱和区 = 长帧满阱亮度 + `kFsHlApply` 的 allSat「中性白/参考比 × 满阱 luma」⇒ **平白平台**，与周围天空的渐变脱节。
- 不是 tone 曲线：两根天空日志 `teqHl=-0.0`、`teqSh=0`（高光滚降没触发）。

## 3. 粉蘑菇灰斑：高光只有 G 饱和，落在 HL 的「普通 G 分支」，但仍有降噪干扰

`kFsHlApply` 的分支（FrameRenderer.cpp:4996-5195）：

- 判据 = `v >= 0.987 × 满阱[c]`（0.12.105，逐通道满阱归一）。
- `nsat >= 2` ⇒ allSat（参考比/中性白 × luma 锚）；`nsat == 1` ⇒ 只对 c==1（G）走「普通 G 重建」，`outv = max(v, mix(v, gest, smoothstep(satFrac)))`。
- 粉蘑菇高光 **R 未饱和、B 只 190 个** ⇒ 绝大多数像素 `nsat=1` ⇒ 走普通 G 分支；`gest = 0.5·(Rv/rg + Bv/bg)`，0.12.160 起小面积镜面高光 `rg=bg=1`（中性白）⇒ `gest < v=1.0` ⇒ **max 兜底后 G 不变**，R/B 也不动 ⇒ 该像素输出就是「满阱比例的色比」。
- 与 libraw 同区域对比（**注意：libraw 无 LSC，只作定性**）：高光区 R/G 我们 1.24 vs libraw 1.54 —— 我们的高光更中性/更灰。

真正把灰「抹开」的是降噪链：
- `dn=0` 那一张 `pc3dOn=0 / dfG=0 / csOn` 全关（dn 与它们联动），灰斑消失；
- `dn=0.3` 那一张 `p0w=5.01`（P0 在饱和边界大量拒绝采样后靠邻域权重）、`pc3dOn=1`；
- 0.12.140 注释自认：「用膨胀版会把光晕也算成核心，于是光晕拿到核心的处理（G 封顶）而混不到背景色（139 的绿/灰就是这个原因）」——PC3D 的饱和掩码口径会制造绿/灰。

⇒ **灰斑 = HL 的「满阱色比」底子 + 降噪链在饱和边界的抹开**，两者叠加。要通过 A/B 把权重分开。

## 4. 本轮改了什么（0.12.168 / 619）

1. **恢复 `FilmParams[49] hl_grecon` 受设置控制**（0.12.132 曾强制 =1，使设置页「高光重建·自创 allSat 档」变成死开关，名不副实第三例）。默认值不变（prefs 默认 true ⇒ 与 167 逐位相同）。
2. **`d4Y`/`fmY` 剖面移到 `if (c.dn)` 块外**：降噪关时也能拿到 D4/film 两层剖面（10-29 两张 dn=0 全缺，无法判断平台层）。
3. 版本 0.12.167(618) → 0.12.168(619)。

## 5. 0.12.169：按原版 1:1 复位（本轮的正式修复）

判断 = **代码缺陷**（自创分支覆盖原版），修复 = 把 HL 链按 darktable `hlreconstruct/opposed.c` 复位：

- `FilmParams[49] hl_grecon` 默认 **0**（原版 opposed）：`out = (v >= 0.987×满阱[c]) ? MAX(v, refavg + chrominance[c]) : v`，**只抬不压** + 加性 chrominance。
- 引擎侧不再强制 `grecon_on=true`，设置页开关恢复有效（A/B 用；开 = 自创 allSat 档）。
- chrominance 补偿恢复（原版的一部分；统计口径沿用 0.12.121 的逐通道满阱对齐 + 0.12.127 的 sat-fix 标记过滤）。
- 顺手修 0.12.167 的契约缺陷：`kCount` 99 → 101、`FilmParamKeys.bySlot` 补 [99] `hl_rolloff` / [100] `d4_usm`（`check-filmparams-contract.py` 由 FAIL 转 PASS）。

保留的**机制缺失**（本轮不动，等实测）：跨曝光融合无饱和感知（DFT 对长短帧整档差判"不一致"、退回参考帧）；`kHlInpaintOn=false` ⇒ 大面积饱和区拿不到短帧真值，只能是"满阱 + 重建"的平色。

包：`filmkit-0.12.169-OPPOSED.apk`（53.2MB，已验签 + dex 版本 + JNI/uhdr 符号）。

## 6. 验证方法（同一构图，粉蘑菇高光 + 窗外天空 + 灯面各一张）

- 默认即原版档，日志应为 `hlGRecon=0`、`hlChroma` 非零（chroma 补偿生效）。
- 若灰斑/白平台**消失或明显减轻** ⇒ 缺陷即自创档，收口。
- 若**仍在** ⇒ 是机制缺失（短帧高光没进成片），下一步查融合层，不再动 HL。
- 想看自创档复现：设置页开「高光重建·自创 allSat 档」（`hlGRecon=1`）。

原版已知代价（darktable 源码注释自认的失效条件 a）：WB 系数与 D65 差距大时，三通道全饱和的灯面会在 WB 域偏暖米色。这是原版行为，若用户判定不可接受，再按"归一化域 opposed"（PC `raw/whitePoint[c]` 口径）做**改进**，而不是回到自创分支。

## 6. 修复路线（按定案结果二选一，不预删）

- **HL 侧**：把 opposed 做到**归一化域**（每通道 ÷ 满阱，三通道满阱同为 1，再做 refavg 立方均值，最后 × 满阱）——这是 PC `hlVal = raw/whitePoint[c]` 与 darktable（RAW 域满阱相同）的原义；现实现只归一化了**判据**，重建值仍在 WB 域。allSat 的「中性白」插值（0.12.159）在归一化域要重估。
- **融合侧**：重开短帧高光出口（`kHlInpaintOn`），但要治 0.12.135 的灯面台阶：短帧值只作「亮度引导」走低频/中值，不逐点注入；或把跨曝光帧并入 DFT 的归一化域 + per-frame σ（0.12.83 已有 `uGainRatio`，但 d² 未做饱和感知）。
