# 取景器 / 成片亮度对齐（显示域闭环）

- 版本：0.12.232
- 触发问题：点测抬亮取景器后，成片中灰比取景器低 **0.9 EV**（实测 15:02:23 截图 P50 128.5 / 成片 94.8）

## 1. 根因：用一个标量顶替了参考实现的完整度量

PC（PhotonCamera）的做法是**同一把尺量两张图**：

```
MeteringSystem.analyzeSrgbThumbnail()
  → midToneDisplayLuma（显示域鲁棒中灰）
  口径：截尾四分位 0.25/0.75 + 中心高斯 sigma 0.32 + 中位权重 0.55
  目标：DISPLAY_TARGET_LUMA = 0.18
```

我们这边：

| 环节 | 状态 |
|---|---|
| 显示域鲁棒中灰统计 | 0.12.51 建了（`FrameRenderer.cpp` 预览路径，逐行照抄 PC 口径） |
| 积分 / 消费端 | 0.12.56 删掉，注释说"交给 Kotlin 外环" |
| Kotlin 外环 | **从未实现**（`displayP50` / `setAeDisplay` 零调用） |
| 实际替代品 | `g_domain_ratio` 一个标量（HAL 域 / RAW 域中位比） |

`g_domain_ratio` 的初值是 **2.0**，而 15:02 那次拍摄的真实比值是 **3.49**：

```
预览 linMid 0.3371 / 成片 linMid 0.0965 = 3.49
0.3371 / 3.49 = 0.09659  ← 与成片 0.09650 只差 0.1%
```

两条链的 RAW 等效中灰**完全一致**，取景器那 0.9 EV 纯粹是域比用错导致的显示误差。
而且域比只有静拍后才 EMA 更新（步长 0.3、clamp 上限 4.5），实测有 6.71 的帧被截断。

## 2. 方案：成片出片时对齐取景器的显示域中灰

不做标量估算，直接量：

1. 预览每 10 帧读**画面中心 1/2**，用 `robustMidToneDisplayRgba8()` 算显示域鲁棒中灰 → `g_pv_disp_p50`（EMA 0.7/0.3，只统计不改 EV）
2. 成片 `passOutput` 之后，用**同一函数、同一区域**量 `tex_cap_` → `still_disp_mid_`
3. `d = log2(g_pv_disp_p50 / still_disp_mid_)`，死区 0.10 EV
4. `pe.exposure_ev += d` → 重跑 `passFilm` + `passOutput`（**只这两个 pass**，场景线性纹理已就绪）
5. `g_domain_ratio` 降级为纯诊断，不再参与任何亮度计算

为什么只重跑两个 pass：`tex_scene_`（去马赛克/降噪/融合的结果）与曝光无关，
filmic + output 是纯显示域映射。全分辨率 2 个 pass ≈ 几十毫秒，不是整条链。

## 3. 关键约束（防止又变成半成品）

- 预览与成片**必须**调同一个函数、取同一区域，否则闭环对齐的是两把不同的尺
- 闭环只做一次迭代（第二次的残差记进日志，不递归）
- 10bit 档暂不参与（`GL_RGB10_A2` 不能按 RGBA8 读回），日志里 `dispMid=0` 即表示未触发
- 诊断字段：`preview.filmic.pvDispMid`、`raw.render.dispMid` / `dispEv`

## 4. 预期

| | 改前 | 改后 |
|---|---|---|
| 同场景 | 0.9 EV | < 0.1 EV（死区内） |
| 换场景 | 0.5~0.9 EV | 一次闭环到 < 0.1 EV |
| 真实域比 6.7 的场景 | 偏 0.6 EV（clamp 截断） | 不存在该问题 |
| 换设备 | 需重新标定 | 无需标定 |

代价：成片多 2 个全分辨率 pass；预览每 10 帧一次 ~2MB 读回。

## 4.1 真机验证结果（2026-11-04 15:29~15:30）

实测（成片 JPG 中心 1/2，同一口径复算） vs 同一时刻预览读数：

| 成片 | 实测显示域中灰 | 日志 `dispMid` | 取景器 `pvDispMid` | 实测 − 取景器 |
|---|---|---|---|---|
| 15:29:30（白点开） | 0.1375 | 0.130 | 0.126 | **+0.13 EV** |
| 15:30:04（白点开） | 0.0997 | 0.093 | 0.092 | **+0.12 EV** |
| 15:30:44（**白点关**） | 0.0344 | 0.032 | 0.034 | **+0.02 EV** |

- 改动前（0.12.231，同机位 15:02）：取景器 128.5 / 成片 94.8 ⇒ **差 0.9 EV**
- 改动后：差 0.02~0.13 EV（剩余 0.1 EV 是 JPEG 压缩 + 采样权重差，恒定偏置）
- 15:30:44 那张 `dispAdd≈0.12` 触发了一次重渲染 —— **白点关掉时闭环自己拉回来**，
  证明它不依赖白点上探兜底

## 5. 验证方法

装 0.12.232 后拍一张，看 `raw.render`：

```json
"dispMid":0.16xx,   // 成片最终的显示域鲁棒中灰
"dispEv":0.0xxx,    // 闭环追加的 EV（0 = 已在死区内）
```

判据：`dispMid` ≈ 同一时刻 `preview.filmic` 的 `pvDispMid`（差 < 0.1 EV）。

0.12.233 起字段语义拆开（旧 `dispEv` 语义有歧义，记的是残差不是补偿量）：

- `dispAdd` = 实际加到 `exposure_ev` 的量（0 = 未触发）
- `dispErr` = 重渲染后的残差（收敛精度）

两个都不应长期贴近 ±2.0（那是限幅，说明方向反了）。
