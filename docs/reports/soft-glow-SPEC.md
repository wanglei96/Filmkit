> 前置：`editor-E4-film-params-DESIGN.md` §3.2（halation，正在实现）、§1.3（引擎里 bloom **不存在**）

---

## 1. 是什么，与光晕的区别

| | **光晕 halation**（E4-5，在做） | **柔光 soft glow**（本规格） |
|---|---|---|
| 物理来源 | 胶片**乳剂背反射**：高光穿过乳剂→片基→反射回乳剂层再次曝光 | **镜头/滤镜**：Black Pro-Mist、Softar 一类柔光镜；以及 Orton 效应（暗房叠印） |
| 通道行为 | **通道相关**（红扩散最远）⇒ 点光源"白→橙→红" | **通道无关**（三通道同半径）⇒ 高光"发白、外扩" |
| 混合方式 | **加法**（能量叠加，过曝区更亮） | **Screen blend**（`1-(1-a)(1-b)`，保高光不过曝） |
| 观感 | 夜景点光源的红色光晕 | 高光柔化、对比略降、整体"梦幻/朦胧" |
| 参考实现 | emulsion（规格 §3.2.1） | darktable `src/iop/bloom.c`（Orton 效应）+ X half 的 `SOFT GLOW` |

**判据（怎么确认两者都对）**：同一条含"光晕 + 柔光"的预设，夜景点光源应同时看到
**红色外晕（halation）**与**白色柔光（glow）**，且关掉任一项另一项仍在。

## 2. 算法（对齐 darktable `bloom.c` 的 Orton 支）

```
① 高光提取   h = max(0, luma - threshold) / (1 - threshold)      // 0..1，threshold 默认 0.70
② 模糊       b = gaussian_blur(h, radius)                        // 通道无关，单半径
③ Screen 混合 out = 1 - (1 - c) * (1 - b * strength)             // 保高光不过曝
```

- **域**：**显示域**（sRGB 编码之后），与 `[90..94]` / 清晰度 `[78]` 同段 ——
  理由：柔光是"成片观感"层，且暗房 Orton 效应本身就是正片叠印（显示域操作）。
- **落点**：`kFsOut` 与 `kFsStyle` 的**显示域段**（`passOutput` / `kFsStyle`），
  与 `[90..94]` 相邻。**两条链路都要**（用户 2026-10-11 指令"不统一的要统一掉"）。
- **顺序**：影调分区/褪色 → **柔光** → 暗角 → 颗粒 → LUT → dither
  （柔光在颗粒之前：颗粒是胶片纹理，叠在含柔光的画面上；与暗角/颗粒的相对顺序见 §4）
- ⚠️ **不做通道扩散**（那是 halation 的事）—— 若做，两者会视觉重叠、用户无法分辨。

## 3. 槽位分配（**需要扩契约**）

`[95]` 是 `reserved`（恒等 0、shader 零引用）⇒ 可用。柔光需要 3 个 ⇒ **扩契约 `kCount` 96 → 98**：

| 槽 | 名称 | 单位 | 范围 | 默认 | 说明 |
|---|---|---|---|---|---|
| `[95]` | `glow_strength` | 0..1 | 0..1 | **0.0** | 0 = 整链旁路（A/B 通路，零成本） |
| `[96]` | `glow_radius` | 0..1 归一 | 0..1 | **0.35** | 模糊半径（相对短边，分辨率无关） |
| `[97]` | `glow_threshold` | 显示域 0..1 | 0..1 | **0.70** | 高光触发阈值 |

**契约扩展是三处同改 + 第四处下发点的危险操作**（`editor-E4-film-params-DESIGN.md` §2.1/§2.1.1，
2026-10-08 有真实事故：漏一处 = 装包即崩）。必须：
1. `FilmParams.h::kCount`
2. `CameraPresets.neutral()` 的 `DoubleArray(N)` + 三个新默认值
3. `fromDoubles` 的 `if (n > idx)` 解析
4. `CameraController` 的按索引下发点有 `size` 兜底
5. 槽位注释同步（哪个版本、什么语义、默认值为什么是这个值）
6. **护栏单测**：照 E4-1 的做法（"全槽位非零默认值"清单 + 长度一致性）

## 4. 与既有参数的正交性

| 参数 | 关系 |
|---|---|
| `[78]` 清晰度 | **相反方向**：清晰度增强局部对比（USM），柔光降低局部对比。两者同时开不冲突（一个加、一个减），但**要真机确认不打架** |
| `[90..93]` 影调分区 | 柔光作用在**高光提取**上（阈值以上），影调分区作用在**亮度分区增益**上 ⇒ 正交 |
| `[94]` 褪色 | 褪色抬黑场、柔光提亮高光 ⇒ 正交 |
| `[66..68]` 暗角 | 暗角压四角、柔光外扩高光 ⇒ 正交；**顺序**：柔光 → 暗角（柔光的高光外扩不该被暗角再次衰减） |
| `[26..27]` 颗粒 | 柔光在颗粒**之前**（颗粒叠在最上层） |
| `[34]` LUT | LUT 在**最后**（显示域风格化的终点）—— 与暗角/颗粒同段 |

## 5. ★ 与光晕共享基础设施（**为什么本卡要等 E4-5**）

两者都需要"**高光提取 → 降采样金字塔 → 模糊 → 上采样合成**"，区别只在：
- halation：**per-channel 半径**（3 套）+ 加法混合
- 柔光：**单半径** + screen 混合

⇒ **共享同一个金字塔**可以省下大量 GPU 成本（halation 的 5 级金字塔 16 pass 已经很重）。
实现时：
- 若 E4-5 已把金字塔做成**可复用的资源/函数** ⇒ 柔光只加"单通道采样 + screen 混合"几个 pass
- 若 E4-5 把它写死在 halation 流程里 ⇒ 先重构出共享层，再加柔光
  （**重构要单独提交**，不要与柔光功能混在一个改动里）

## 6. 性能与验收

**成本预期**：比 halation 低（单半径、无通道扩散）—— 静态估算与**真机实测**要求同 halation
（项目铁律：性能取舍不许拍脑袋替用户决定，实测数据交用户拍板）。

**验收判据**：
1. `[95]=0` **逐位零回归** + **零 pass 零纹理**（资源分配证据）
2. 高光区"发白外扩"（给出半径-亮度曲线）；**三通道同半径**（通道差 = 0，与 halation 的判据相反）
3. 三个参数各自**单调可控**
4. **两条链路逐位相同**（`kFsOut(srgbDecode(D))` vs `kFsStyle(D)`，U-4 已证明这是本项目的验收口径）
5. 与 `[78]` 清晰度同时开不打架（给出实测）
6. **静态性能估算** + 真机实测步骤与判据
7. **目视判据只能真机**（"像不像柔光"是观感问题，不接受"数据好看"代替目视）
