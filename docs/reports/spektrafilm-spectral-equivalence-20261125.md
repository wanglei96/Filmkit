# Spektrafilm CPU：等价替换感光投影与光谱插值

2026-11-25，vivo V2509A，基线为 0.14.50（847）的渲染逻辑 + 既有计时。试验只替换光谱分支的采样实现，不更改 RAW 前链调度，不减帧、波段、采样点、滤波核或浮点精度。参考了固定版本 `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc` 的 Hanatos 投影、Mitchell 反射边界、印相/扫描投影及 PCHIP 插值源码。

## 实现与隔离测试

1. **Hanatos 逐行三次多项式。** 将 Y 方向四个 Mitchell tap 展开为同一个三次多项式；每个原 X 行、Y 单元预计算一次系数。每像素用 FP64 Horner 求值，再按原 X 权重组合。保留 16 个 tap 的贡献、反射、CAT16 后 XYZ 到色度坐标、权重归一化和曝光增益。数学模型相同；计算次序与 FP64 FMA 不同，不要求中间值逐位相等。另一候选将 X/Y 两轴都预展开为每单元 16 个系数；计入建表后反而不如逐行版本。192×192 响应表的额外系数内存约 3.36 MiB（逐行）或 13.36 MiB（两轴）。
2. **光谱 PCHIP 向量核。** 保留 49³ 网格、全部 81 个波段的建表模型、三轴单调斜率、8 个角及其原 FP64 累加顺序。ARM64 两个颜色分量向量化，第三个分量标量；把同一 8 角的极值移到建表时求一次，再在每个像素原位限幅。没有更换为三线性/四面体插值；超出网格仍走完整光谱积分。额外 48³ × 6 个 FP64 极值约 5.06 MiB。

每组在同进程对真实配方资产使用 3072×4080 的合成输入，预热后同序交错 6 旧 + 6 新。PCHIP 输入覆盖每个格点、边界及格点间密度，另检查超界和 NaN 拒绝；Hanatos 输入覆盖通道边界/负值、高亮与宽色度。所有组始末 Thermal Status 0。以下为含建表的隔离阶段中位数：

| 候选与输入 | 旧 → 新 | 减少 | FP64 对照 |
| --- | ---: | ---: | --- |
| Hanatos 逐行，Gold 连贯输入 | 91.57 → 63.14 ms | 28.43 ms | 最大绝对差 `4.26e-14` |
| Hanatos 逐行，Provia 宽动态散布输入 | 100.09 → 80.49 ms | 19.60 ms | 最大绝对差 `4.55e-12`，按 `max(1, abs(旧值))` 缩放后 `9.70e-16` |
| Hanatos 两轴展开，Gold 连贯输入 | 89.91 → 65.72 ms | 24.19 ms | 最大绝对差 `4.97e-14` |
| PCHIP，Gold 印相 | 122.92 → 98.81 ms | 24.11 ms | 37,601,280 个值逐位相同 |
| PCHIP，Gold 扫描 | 117.28 → 98.09 ms | 19.20 ms | 37,601,280 个值逐位相同 |
| PCHIP，Provia 直扫 | 119.09 → 100.06 ms | 19.03 ms | 37,601,280 个值逐位相同 |

## 真实四帧 RAW 对照与结论

选逐行 Hanatos + PCHIP 组成一版，仅做一对旧/新／配方的真机回放。3072×4080，同一组真实四帧 RAW、两版本均通过高光准入、颗粒及 PC3D 关闭，8 位 HDR、合成取景并发、关闭回放额外同步。两对的 RGBA、HDR 增益图、JPEG 及诊断统计均逐字节一致。这不是全配方、颗粒、10 位或实拍取景验收。

| 路线 | 替换目标合计¹ | 光谱分支墙钟 | RAW 引擎墙钟 |
| --- | ---: | ---: | ---: |
| Gold / Endura | 416.4 → 306.8 ms | 2102.5 → 1993.3 ms | 3567.9 → 3052.2 ms |
| Provia 直扫 | 245.0 → 188.6 ms | 1578.6 → 1458.7 ms | 2684.0 → 2619.5 ms |

¹ `hanatosMs + paperExposureMs + scanSpectralMs`。后两项包含原有解码/收尾，不能把全部墙钟差归给插值。Gold 的整引擎差约 516 ms，但这对样本中分支以外也少了约 407 ms，而试验未改前链；Provia 原库/候选进程的 major faults 为 7035/792。始末热状态 0 不代表资源和调度相同。可信的因果证据是同进程交错快筛：按两个配方各自经过的调用次数，粗略预算为 Gold 约 72 ms、Provia 约 39 ms，不把合成输入数据当成实拍时间。没有验证从快门到保存的净收益。

决定：等价实现可复现，局部确实省时，但不足以作为本轮提速版本，不扩大测试矩阵或发包。试验原型与可复跑证据保留，生产源码恢复到试验前（既有计时改动不动）。重编 ARM64 库与基线逐字节一致，SHA-256 `0816e980316f749329e42b859b95a6965dd6741ffb83d1ed1fa64209b3bc4f41`。手机仍是 0.14.50（847）。若继续寻找大收益，优先比较散射、光晕与 DIR 共用的 FP64 递归滤波实现，尝试减少全尺寸中间数据的搬运，同时保留每个 tap、整行整列递推和原边界状态；本轮没有测试该方案。
