# Filmic V7 升级、Spektrafilm 风格引擎与性能工作的总体设计

初稿：2026-11-17。执行修订：2026-11-18。用户已确认优先启动 Filmic V7；Spektrafilm 仅作可选风格引擎，取消联合四路质量排名。未批准替换默认、迁移旧配方或发布。

## 1. 文档边界与建议结论

本设计补齐完整官方 V7 的实现、兼容与验收，并编排三条工作的依赖；**不重写已有 Spektrafilm 方案**。Spektrafilm 的接入以正确性、稳定性和实际设备成本为准，不以优于 Filmic 或 sigmoid 为门槛。

Spektrafilm 的完整算法、厂商证据、Android 移植、预览、编辑器、HDR 和许可设计，继续以 `docs/reports/spektrafilm-manufacturer-engine-PLAN-20261117.md` 为主文档，下文简称 S 方案。本文以 `S §章节` 引用，不复制其技术正文。本文补充的引擎身份、私有配置和联合对照适用于两份文档；若发现其他冲突，实施前记录差异并解决，不默默改口径。

按以下顺序推进：

| 优先级 | 工作 | 依赖与产物 |
|---|---|---|
| P0，共用基础 | 冻结引擎输入与旧配方生产回归；启动分发可行性核对 | 固定 EV 引擎验证与完整生产回归分开；不恢复性能专项 |
| P1-A | 完整官方 V7 桌面参考 | 保留旧 Filmic，先证明参考一致性，不直接覆盖预设 |

先建可信 V7 参考，不先重标全部旧预设。Spektrafilm 首批选择明确的胶片/相纸风格，优先闭合实际使用路径，不逐一替旧厂商预设争排名。

### 1.1 继承的硬约束

- 质量优先；完整参考实现跑通后才评估偏离。成像链不采用 ponytail 方法论。
- 不缩核、不减帧、不减样本/波长、不预降精度、不用上一帧统计换速度。
- 不恢复已失败或被移除的高光/inpaint 通路；V7 不是紫边根因修复。
- 不以换一张外观 LUT 代替 Spektrafilm，不以补一个 clamp 或滑杆代替完整 V7。
- 不按模型复杂度决定胜负；允许所有预设保留现有引擎，也允许只有部分迁移。
- 本阶段先完成隔离的 V7 参考验证；未经分发可行性与设备验收，不出包、不安装、不改默认或旧配方。

## 3. 参考权威与版本冻结

### 3.1 Filmic 参考范围

本次观察到的 darktable 上游 HEAD 为 `395aa7d5156b68a69d8f2d25a3e6fc66c525a3c2`。它作为候选参考提交，不冒称已验证稳定发布版；正式实现前固定完整 checkout、依赖和构建选项，并验证其可构建性。换提交即新实验版本。

V7 的 UI 年份名为 v7 (2023)，内部枚举为 `DT_FILMIC_COLORSCIENCE_V5`；spline v3 是另一套版本编号。来源 R1/R2。

darktable 的可选高光重建、旧版保色 norm、GTK 交互、其他像素模块，不属于本次 tone/gamut 升级。参考测试显式关闭其高光重建，不擅自重新启用 FilmKit `[41]`。若未来需要这些能力，另立完整参考与质量评估，不在本轮以“官方升级”名义夹带恢复。

### 3.2 Spektrafilm 参考范围

沿用 S §2/§3/§12：`3bb2c2d2801ff68b92019cf1dbcbb133d60832bc` 的完整原版和锁定依赖。不能以其他项目的同名移植替代 oracle。桌面/GPU 移植只能提供实现借鉴，须核对阶段、配置、精度与空间效果，未经 parity 不采用其结果作为真值。

两类引擎均保存 reference manifest：提交、源文件 hash、依赖、编译器、数学选项、profile/表、参数 digest、输入输出域、参考输出 hash。临时 `/tmp` 检出不是持久复现方案，参考代码和大体积数据按许可存入受控研究目录或由 manifest 精确恢复，不随意加入 APK。

## 4. 共用输入、对照组与色彩契约

### 4.1 两个固定观察点

扩展生产 `tools/check-renderer-device.cpp`，明确导出：

- `reconstruction_output`：实际融合/高光/去马赛克/CCM/CS/CM/降噪等前链结束后的信号，用于确认前端一致。
- `base_engine_input`：真正调用基础引擎前的像素。RAW 路径已过适用的 TEQ、输入准备、线性 EV 和局部补光；当前 `kFsFilm` 在 `uHdrProbeMode == 2` 的返回处可作为观察点定位。导出必须核对与正常渲染使用相同的输入、uniform、公式与像素精度，不能把 `film-src-pre-TEQ`、HAL 域或中性曲线探针当成等价输入。

D0 输出两种独立基准：

| 基准 | 冻结内容 | 用途与放行条件 |
|---|---|---|
| 固定 EV 引擎验证 | 同 RAW 与前端、同一份 `base_engine_input` hash；固定采集基准、用户 EV 和所有产生该输入的局部处理；关闭实验支路的显示中灰反馈与候选自动测光，不允许候选重复乘已施加的 EV | 用于 V7 与旧链的可归因比较；S 使用该输入做风格接入测试，不做胜负排名。E0 另用原版输入契约与数值夹具 |
| 旧配方生产回归 | 按现有路径保留 AE/TEQ、预览统计、显示中灰反馈及全部效果；记录统计来源与快照、每次重绘的 EV、输入 hash、天空护栏回退、最终被采用的那一次和最终配方 | 用同上下文重放旧 L/G；真实设备静拍另验。从未走反馈的单次引擎回放不能作为旧链零回归证据 |

输入采用无损 FP32 RGB(A) dump 与结构化 sidecar，保存尺寸、步长、方向、原色/白点、scene-referred/transfer、有限值范围、alpha/有效性语义、曝光/WB/CCM、前端开关、噪声状态和输入 hash。RGBA16F 生产输入导出为 FP32 不等于恢复丢失精度，必须记录生产纹理格式。

### 4.2 参考与对照身份

| 对照 ID | 内容 | 用途 |
|---|---|---|
| L | 当前 Filmic 完整原样配方及公平调优版 | 兼容与保留基线，不冒称官方 V7 |
| V | 完整官方 V7 | 标准实现和新配方候选 |
| G | 当前 sigmoid 完整原样配方及公平调优版 | 中性、肤色与风格竞争基线 |
| S | S 方案完整 Spektrafilm | 独立的可选风格引擎；仅与自身原版做实现对照 |

V 与 S 独立验收，互不阻塞。L/G 仍用于保留旧配方和回归。

### 4.3 输出与 LUT

每次渲染明确工作域、引擎 view 目标、LUT 输入/输出和最终交付域，域桥接为显式步骤。矩阵同时记录原色和白点，不能仅改字符串。

E1 的共同处理按有序清单冻结：引擎后、LUT 前的末端滚降/对比度/锐化等公共效果，每次矩阵/色域处理、裁切、编码、LUT 插值与强度混合域，以及 LUT 后处理。记录各边界和 `lut_input` dump。不同引擎输出须显式对齐到同一公共输入域；V/S 原版内部 gamut 仍属引擎，不能为统一外观删掉它。旧专属控制不跨引擎冒充同义参数；生产原样 L/G 不为凑 E1 公共链而改写。有未证实的 LUT 域，或无法构成等价外部处理时，标明该组不可比较，不用隐含适配混进 E1 结论。

V7 在场景线性 Rec.2020 输入上执行；其 view 输出以参考确认的输出参考 RGB 数值承接，继续保留工作空间表示。输出 profile 感知 gamut 由 V7 内部完成；随后仅做必要的表示转换与正确 OETF，不再无条件执行旧工作域 gamut 造成二次去色。非线性 tone 运算不等于已经套了 sRGB OETF；灰阶和基色夹具验证编码恰好一次。

S 的完整契约沿用 S §5/§6。厂商 LUT 不是引擎，不能直接套在未知空间、Log、PQ 或 HDR >1 RGB 上。profile-aware gamut 的目标是实际 view/LUT 边界；LUT 后如仍有越界，按已声明输出意图另行处理并纳入比较，不悄悄多套旧肩部。

参考 gamut 支持边界遵循上游；不为宣称支持任意 ICC 而将 LUT-profile 近似成矩阵。首轮覆盖项目实际交付 profile，其他 profile 的不可用状态明确返回。

## 5. 完整 V7 设计

### 5.1 模块与完整性清单

建议新增 `core/engine/src/film/filmic_v7/`，与旧实现隔离；内部按 reference math、参数准备、profile/gamut、GPU 执行分工，不先建设通用图编辑器。

实施产物必须有 `filmic-v7-coverage.json`：参考函数/分支、参数单位与默认、移植位置、消费者、测试 ID、支持状态。会影响选定 V7 路径的分支不能标作“以后补”后宣称完整。

| 子系统 | 必须实现/核对 | 验证产物 |
|---|---|---|
| 参数准备 | 官方默认、参数单位、范围、派生量及自动 hardness/custom grey 的相互作用 | 原始参数与 derived 参数 dump |
| spline | 完整有效曲线模式、节点、系数与边界，阴影/高光可独立选模式 | 3x3 曲线组合、边界/退化输入与过冲用例 |
| tone | 官方 V7 两分支、norm 边界、混合与输出幂 | 分支与最终 RGB dump；mix 两端/中间及边界 |
| gamut | 工作/输出 profile 矩阵、Ych/LMS 等完整转换、色度/色相与合法域处理 | profile 与转换夹具、逐段误差 |
| host 到 GPU | 派生参数布局、矩阵方向、精度、FBO 格式与能力检查 | host oracle、设备 shader 对照 |
| 产品消费 | 私有参数、能力门控、快照、预设、导入导出和实际引擎身份 | 往返测试、并发/生命周期与实拍验收 |

完整清单以 R1 的选定路径及其传递依赖审计为准，不以这张概括表替代逐函数阅读。R3/R4 提供 GPU 公式与颜色转换的一手交叉核对。

### 5.2 参数模型与生效规则

保存上游原始单位，统一在 typed 配置边界处理；禁止把官方百分比 latitude 与项目 0..1 per-channel 值直接互拷。

配置覆盖 source/target gray、source/target black/white、contrast、latitude、balance、shadow/highlight curve、highlights saturation mix、auto/manual hardness 和会影响已选路径的其他有效选项。动态范围缩放等 GUI 辅助若只修改其他参数，则保存其解析后的真实参数及来源，不造一个未消费的 uniform。旧 preserve-chrominance norm 不作为 V7 新功能暴露。

曝光只应用一次：现有采集曝光与用户线性 EV 的职责分开，输入注明用户 EV 是否已施加；V7 不自动再补默认 EV。V7 私有 contrast 是曲线控制；旧 `[4]` 不能因为 slot 非零又在输出重复施加。

参考自动端点/取样功能与项目 AE 是不同边界。本轮固定端点和输入曝光建立 oracle；如开放自动端点，须实现其当前图像统计/消费闭环、单列覆盖率并先验收，不沿用旧成员变量副作用。没有接通的自动控制不显示为可用，固定端点也不声称包含整套 darktable 自动取样 UI。

### 5.3 两套配置，分离算法与标定

- `official-reference`：上游默认与参数语义，外部风格处理置恒等；用于正确性。
- `filmkit-recipe`：同一完整算法，按官方公开参数标定；与 LUT、公共处理共同版本化；用于产品质量。

不把旧 M9/黑白的三通道肩趾平均成官方参数，也不往 V7 偷加旧扩展后称官方。无法等价表达的旧配方保留 L；新 V 配方独立调优后以新 revision 提供。

### 5.4 V7 HDR 适配与能力门控

V7 的官方 tone/gamut 对齐只证明选定参考输出，不证明 FilmKit JPEG/R。D3 开始 HDR 接入前，从同一张 RAW 和同一次最终确认的曝光取得两类同几何信号：真正的 `base_engine_input`（仍有有效场景高光）及 V7 的两分支混合后、目标 gamut/亮度限制前的完整 RGB。将这些 tap 与官方 V7 输出、最终 SDR base 一起对拍，实证哪里尚有颜色与高光信息。不能把已压平的 SDR 反编码当作高光信号；高光已在前链裁切的区域不得宣称恢复细节。

SDR view 继续用完整官方 V7 与明确的 SDR 配方；HDR view 从上述未丢失信号单独构建，两者在 SDR 编码和显示域 LUT 之前分支，不改变 SDR base。HDR 适配设计须先锁定完整 RGB 的亮度/色度映射、参考白、目标峰值、gamut 和输出编码；若有风格 LUT，以同风格的显式 HDR 变换验证，禁止把 SDR LUT 直接套到 >1 线性 RGB 或 PQ 数值。旧 `computeHdrCurveExtension` 及中性探针仅作对照，不作为 V7 的默认 HDR 路径。适配公式待原始信号实证后单独审查，不把它算作官方 V7。

两路共享最终曝光、几何与适用的空间/随机状态；从最终 SDR/HDR 图生成 gainmap，验证实际编码/解码重建、RGB 残差及各显示亮度下的灰阶、肤色和彩色高光，并确认 SDR 不因启用 HDR 而改变。没有证明时，V7+HDR 标为不可用，设置与快门前均检查能力；不静默换引擎、不在保存时偷偷落成 SDR。接受 SDR-only 或受限预览是独立发布决策，不是桌面参考的先决条件。

## 6. 引擎身份、配置与接线

### 6.1 注册与兼容身份

建议固定槽 0=`filmic`（当前算法）、1=`sigmoid`、2=`spektrafilm`（沿用 S 方案）、3=`filmic_v7`。不复用或重排已保存槽，不把旧 0 在升级后静默解释成 V7。三类算法包含两个 Filmic 版本，因此实验有四条路线。

注册表扩展最少必要能力：实际输入/输出域、执行类型（原有注入/独立多阶段）、配置 schema、参数绑定、可用的预览输入与 SDR/HDR view。Kotlin 与 C++ 表项对拍；不再用 `slot != 0` 代表“所有参数归零”，也不以 `slot >= 0.5` 决定输出对比度。

旧 0/1 在新功能未选择时保持原像素路径。未知旧槽的历史容错与明确请求新引擎失败分开：新 schema 中不支持的引擎/配置不得静默降级。

### 6.2 有版本的配方快照

新增有版本配置封套，不把大量新私有参数加入 105 槽数组。拟用 `EngineConfigEnvelope`，包含：

```text
schemaVersion, engineId, algorithmRevision, upstreamCommit
recipeId, recipeRevision, configHash, assetManifestHash
typedConfig: FilmicV7Config | SpektrafilmConfig
inputDomain, viewTarget, outputDomain
```

封套和 `FilmParams`、LUT payload/hash/strength/混合域、公共后处理、前端快照，组成一次不可变 `ResolvedRenderRecipe`。schema 结构仅为设计名，实施时生成正式 schema 与正反例，不复制未验证数值默认。

每个控制只有一个权威消费者：旧 Filmic 专属槽仍只归旧 Filmic；V7 与 S 私有参数由 typedConfig 消费；公共效果按明确阶段绑定。用户曝光、曲线 contrast 和显示编辑 contrast 不能因为名字相近同时下发两处。

规范化后再计算内容 hash：固定键序、显式默认、有限数、资产身份与版本。JNI 收到完整封套/二进制参数包后先完整解析与校验，再在同一渲染线程原子激活。返回 requested/resolved engine、配置 hash、资源版本和状态；不能只有 setter 返回成功而消费仍读旧配置。

### 6.3 预设与存储迁移

当前预设为 schema 2、语义名参数、prefs JSON，`StillSnapshot` 主要保存数组与 LUT。新方案增加整体预设 schema 3 和版本化引擎字段，不逐私有参数增加 Room 列。

新版本同时读取 v2/v3：v2 进入旧规则，不推断 V7；v3 显式验证 engine 配置和引用资产。原 v1 拒绝策略不顺带改变。旧预设首次读取不自动覆盖存储；用户保存新字段时才写 v3。新配置导出必须带完整身份与依赖清单，不伪装 v2；旧版本不能正确读取时明确不兼容。

`StillSnapshot` 增加可选 schema、resolved recipe 和 baked-stages；缺字段旧照片走历史解释，不能因全局引擎变化重新套一次。CS/CM 仍为现有全局/捕获快照策略，CM 不借本次迁移进入预设。

全局 override 保留旧 -1/0/1 语义，新增选择仅在引擎与完整基础配置可用时生效。强制新引擎不把旧私有参数当新配置；按“该预设已标定配置，否则显式新引擎默认配置”的规则解析，并记录属于用户覆盖而非厂商已标定默认。

### 6.4 状态与失败

```text
UNAVAILABLE -> LOADING -> VALIDATED -> READY
                    \-> FAILED
READY -> INVALIDATED（context、尺寸或资产变化）-> LOADING
```

激活前校验配置、资源、程序及 view 能力；失败保留上一份可用设置并显示失败，新请求不得借用旧资源却标成新引擎。异步任务始终持有其快门时刻快照，切预设不能污染在途照片。

执行中失败不静默 identity 或切风格。保留已有底片/结果，反馈失败；如提供回退，必须是明确选择的完整回退配方及实际身份。现有 `render.still_fallback` 等重试路径逐一审计，重试只能重放同一配方，不能绕过新引擎。

## 8. 实验与逐预设决策

### 8.1 数据与分组

沿用 S §7.3/§7.4，由实施方取得公开数据、标注设置与权利；不把用户购买相机或补拍作为前置条件。优先完善富士官方教师与理光证据，哈苏做中性检查，5219 验证完整 film/paper/scan 配方；其余逐套推进。

数据至少覆盖日光肤色、绿植、天空、暖光/混合光、夜景彩灯、逆光与裁切高光、暗部纹理、运动及细彩线。每个发布候选必须覆盖其目标场景；缺证据写“证据不足”，不能用非配对照片填出精确复刻结论。

按场景/拍摄批次锁定调参、验证、最终留出集；同图裁剪不得跨集合。冻结 manifest 后再调候选，新增数据形成新版本，不能看结果后挑留出。

### 8.2 桌面验证与真机放行

| 轮次 | 固定项 | 比较与结论边界 |
|---|---|---|
| E0 正确性 | 同输入、原版配置、无厂商 LUT | V/S 对各自上游 oracle；不是风格比赛 |
| E1 兼容性 | §4 固定 EV 输入、现有 LUT/strength/公共处理 | 仅对拟适配 V7 的配方作固定输入比较；不替换旧槽 |
| E2 配方能力 | 同输入与完整处理合同 | 分离 V7 算法对齐和风格配套；S 仅核对自有风格配置与明确的域 |
| E3 桌面留出 | 预先冻结配方、观察项和留出集 | 验证 V7 新配方及不可退化项；不运行 S 的细粒度收益排名 |
| E4 真机放行 | 同一候选配方；真实 RAW、产品范围和已锁定的回归基线 | 设备 parity、同 RAW 整链质量/资源与产品回归；才决定是否按预设迁移或发布 |

E1 只能判断旧资产的适配性。前端 RAW 质量检查使用设备完整链，桌面 engine-only 结果不替代融合、高光或细节验收。

### 8.3 评分与迁移规则

先排除实现错误、严重色偏、灰带、细节/肤色失败和不稳定，再比较目标风格。配对数据使用明确 ICC/view 下的分区色差、灰阶和高光响应；非配对数据只做方向约束和盲评，不算逐像素误差。真实肤色/绿植与紫边抑制分别报告，不能用总体平均分掩盖局部失败。

在打开最终留出结果前，逐预设冻结评分表：目标机型/模式和可支持的结论、必须通过的场景/ROI 与不可退化项、指标方向/聚合方法、相对现有原样配方的最小有意义收益、对同等调优 L/G 的判胜和持平规则、有效样本/评审分歧的处理。阈值来自参考噪声底与验证集的感知校准，不能以算法 parity 容差充当风格优势，也不能看完留出再改。盲评打乱显示顺序、隐藏身份，按场景/拍摄批次汇总，不把同图多个裁剪当独立证据。未过硬约束、持平或结论不稳，默认保留旧配方；证据只支持观感偏好时，不宣称目标复刻胜出。

仅对实际提出适配 V7 的配方记录 E3/E4 决策，包含配置与 hash、原尺寸全图/ROI、实现误差、桌面结论、真机成本及用户确认。S 记录自身参考一致性、风格身份、接入能力与真机成本，不填写收益或胜负决策卡。

默认不一次替换全部预设；迁移采用新 recipe revision，保留旧配方可回退，不覆盖用户自定义值。算法正确不等于值得迁移；未证实收益不迁移，也不因证据不足声称模型失败。

## 9. 数值与回归验收

### 9.1 误差预算的冻结方法

先测参考自身重复性、参考 CPU/GPU 差异、输入/中间格式量化及高低值数值稳定性，形成 `numeric-budget.json`。分别定义各阶段绝对/相对容差、近零处理、最终显示域色差和极端值限制；在查看移植候选排名前冻结并审查。

没有预算文件不通过正确性门；超预算定位源头，不事后抬门槛。不能把原版 float32 参考吹成全 float64，也不把 Spektrafilm 的不同 dtype 混称同一精度。按实际参考路径逐阶段记录 dtype；设备默认以 FP32/RGBA32F 验证敏感中间量，不预设 FP16 足够。

旧 L/G 在同设备、同输入和同旧快照下要求完整输出及阶段合同零回归；无法逐字节一致必须解释来源并经质量评审，不把“看不出区别”当兼容证明。

| 类别 | 必测内容 |

## 10. 资源、性能与稳定性

### 10.1 不恢复专项，但保留测量基础

P0 记录当前完整链的墙钟时间、帧到达/显示间隔、应用与 GPU 可见内存、温度、失败率，按配置 hash 关联。新增引擎的基本资源验收是质量交付的一部分，不等于擅自恢复历史性能专项。

GPU/CPU 提交、执行和等待时间分开。诊断强同步模式用于定位，不把它与正常模式的速度直接混比；不把删除等待后的 CPU 提交耗时称为 GPU 完成。没有有效 timer query 时只报可确认的墙钟区间。

资源由对应 EGL context 拥有；快照和只读 CPU 资产可共享，未经同步的 GL 句柄不跨线程共用。新 S 中间图按阶段精确释放；同尺寸复用只在格式、域、生命周期和参数身份一致时允许。不预热所有引擎全部最大尺寸，先完整实现后量峰值与预览干扰。

### 10.2 恢复性能专项后的候选次序

| 顺序 | 候选 | 正确性先决条件 |
|---|---|---|
| F1 | 诊断计时延迟收集、非功能统计异步化 | 列清功能/诊断统计消费者；同帧功能统计不删不陈旧 |
| F2 | 当前帧 histogram GPU 归约与读回 | bin 边界、权重、分位与完整度量等价；不拿标量替代分布 |
| F3 | CPU 高光 guides 与 GPU 金字塔重叠 | 原始输入快照、写入集合、生命周期与有界 worker 明确 |
| F4 | 跨帧金字塔/CPU 对齐流水、延迟 PBO 消费 | 双缓冲与 fence 完成关系、generation、最终完成、取消/失败清理完整 |
| F5 | RAW producer 缓冲与固定 worker、阶段资源复用、warmup/程序缓存 | RAW 数据不丢不串，缓存完整失效，热启动/切镜头实测 |
| F6 | PC3D 布局/tile 完整原型；替代模型独立研究 | 保留完整算法/精度，先审计旧 NN 否决；PMRID 不是 PC3D 替代 |

不把 fence 本身等同提速；只在有独立工作可重叠时测收益。历史全局六分量 PC3D 与 mask-cache 的退化结论保持，不能换名字直接重上。JPEG/R 直编、SAD NEON、现有 still/preview 分线程和编码队列不重复计功。

### 10.3 实测方案与放行

先以相同 RAW 回放做交替 ABBA/BAAB 对照，再做获准的 App 实拍，分开冷启动、预热后、稳定温度与持续连拍；记录手机、驱动、温度/频率状态、实际核/尺度与全部开关。各条件初始至少四个交替区组，尾部延迟与热稳定性需额外样本，不能用八次回放宣称可靠 p95。

报告保存时间分布、最大值、预览帧间隔分布/最大停顿、峰值内存与失败；样本少时原值全列，不只报平均。`快门到保存 <5s` 为既有目标，不能把 5.005s 四舍五入为通过；“稳定达标”的采样时长/比例须在恢复专项时事先冻结。无实测不预估可省几百毫秒，也不相加独立微基准收益。

若完整新模型更慢，提交实际质量收益、时间/内存/预览成本及可选范围，由用户决定；不以超时为由预删颗粒、波长、空间核或减精度。资源失败、死锁、黑图和错误照片为阻断项，不能用质量优先作为带错发布的理由。

## 13. 发布、回退与待确认边界

开发候选不改变旧默认；最终按预设发布新 revision，保存旧配方入口。回退不删除用户新配置；旧程序无法解析的新配置保留为不支持，不能强制扔掉字段后覆盖原件。
