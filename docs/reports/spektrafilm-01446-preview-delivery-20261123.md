# Spektrafilm 0.14.46：成像期间的取景与 JPEG/R 保存

对比 0.14.45（842）；新版为 0.14.46（843）。

## 改动

- 多尺度色度降噪在各波段结束时检查既有 GPU 队列深度，最终应用分 16 条提交。六个波段的采样、着色器、精度和像素运算不变。快门采集和取景统计未改。
- 4:4:4 JPEG/R 由 libultrahdr 在封装时直接加入 EXIF。避免 AndroidX 在发布后重写全尺寸成片；4:2:0 和 SDR 仍用原 EXIF 写法，但在发布前完成。新增媒体库插入、写入、发布和 EXIF 分段计时。

## vivo V2509A 受控实测

3072×4080、同一组四帧 RAW、HDR 开、颗粒关，合成取景并发。旧、新、新、旧交错；各次 Thermal Status 为 0，未锁频。表内 RAW 回放不含快门采集或 MediaStore。

| 路径 | RAW 回放，旧 → 新（秒，各两次） | 每次回放最长取景 GPU 完成间隔，旧 → 新（毫秒） | 本地编码、写入及 EXIF 中位数（毫秒） |
| --- | --- | --- | --- |
| Gold 200 / Endura | 4.763 / 3.541 → 3.665 / 3.619 | 162 / 110 → 59 / 56 | 152.6 → 132.4 |
| Provia 100F 直扫 | 3.180 / 3.160 → 3.421 / 3.172 | 145 / 132 → 114 / 72 | 145.6 → 128.2 |

合成取景长帧缩短，但不代表相机实拍已更跟手；RAW 回放没有证实两路都提速。保存探针固定 RGBA 和增益图，去除第 0 次后各版本 8 次，省 17–20 ms，不能解释基线全部保存耗时。0.14.45 最近的两张实拍从快门到保存为 8.674 / 7.740 s；新版该指标待实拍。

## 画质与封装

- 回放的 RGBA、增益图和 JPEG 在每条路径的新旧四个样本间逐字节一致。另用 Release DEX/JNI 比较固定输入的保存结果：11 个 EXIF 标签、尺寸、平台解码底图及增益图 CRC、色域和增益参数一致；原生 SDR/部分 HDR/全 HDR 解码探针通过。
- 保存探针的新旧文件都是 4:4:4。去掉 EXIF 和 MPF 段后，各路径文件 SHA-256 相同。两个旧样本与问题月亮原片的 MPF 主图长度均比实际 JPEG 边界少 372 字节；新增益图起点、终点和主图长度均匹配实际文件边界。Android 和 libultrahdr 仍能正常解码旧文件，不能据此断言这就是系统相册偶发整图变暗的原因。
- Release 构建和 JVM 测试通过（851 项，0 失败，2 跳过）。已核验 APK v2/v3 签名、版本、DEX 和五个 JNI 符号。APK SHA-256：`ad7a02c3ed9bfd6d27e57a94aaa326bbcb7d82ab51e9278586507343bec06ed3`。
- 证据：`test_temp/spektrafilm-delivery-01446/`。实拍验收只用 Gold 200 / Endura 和 Provia 100F 直扫，检查移动取景、成片颜色曝光、快门到 `photo.saved` 及保存分段。

## 移动实拍验收

用户确认两张颜色、曝光和保存正常，预览仍有少许卡顿。日志和实际文件确认均使用四帧 RAW MFNR、3072×4080、4:4:4 JPEG/R，且内嵌 EXIF 生效。
