# FilmKit：把 RAW 和 DIR 的内存改动放进一次 App 成片回放

2026-11-26 · vivo V2509A / Mali-G1-Ultra MC12。正式 0.14.56（853）不变。两侧均使用现版 Vulkan Hanatos，现版的 RAW 去马赛克、降噪、颗粒设定、FP64 光谱、预览和 HDR 公式均未改。

## 处理链和候选

- **A**：现版 RAW 协方差布局和 CPU DIR。
- **B**：只把 RAW 协方差的两张 RGBA32F 改为 RGBA32F＋RG32F；同样存放全部六个 FP32 分量，保留释放时机，逻辑容量少 **95.63 MiB**。这个阶段仍在 GLES；不是 Vulkan 着色器变化。
- **C**：只改 CPU DIR 布局。先按原曲线完整显影，在每工人的 256 像素临时条带中计算三通道抑制矩阵，直接写成三个 FP64 平面。三个抑制平面全部就绪后才允许覆盖原曝光；各通道仍走原来的完整三项尾核、完整核心核、原运算次序和边界，再完成第二次显影。不再创建 3×FP64 全帧交错输出并逐通道拷到滤波工作平面，改成额外两个 FP64 平面，常用空间扩散配置下峰值再少一个 **95.63 MiB** 的逻辑工作平面。DIR 无扩散／关闭仍计算完整原语义。颗粒开启时仍为后续颗粒保留独立输出，不做颗粒性能结论。
- **D**：B 和 C 同时启用。这两次逻辑容量减少发生在不同阶段，不能说是同一时刻省下 191 MiB 物理内存。

## App 前台固定四帧、首张 JPEG/R

独立签名测试包使用相同原生成片 JNI、Bitmap 拷贝和 JPEG/R 编码（质量 100），每个样本使用新进程和原 GLES 预热，Vulkan 不提前初始化。空白测试页面让进程真正位于前台，全部同为 CPU 掩码 0–7，不打开相机、不启用真实取景及其负载。不走 EXIF、相机采集、相册写入或 MediaStore。固定 3072×4080 室内四帧，完整 MFNR，8 位，HDR 开，颗粒/PC3D/CS/CM 关。每次前后温控等级 0、桌面受控；测试页获得并保有前台焦点。

开始时一个后台尝试在 DIR 后被 vivo 系统 RMS force-stop，不能说是 native crash；另一个 pilot 因把 Shell 模式 2 当 App Vulkan 编码槽的布尔值而被参数校验拒绝。两者均未计时。已验证正式测试 Vulkan 全帧 12,533,760 像素、HDR 增益图与 JPEG/R 均真实运行。

### DIR 单独复测

另跑 Gold C/A/A/C、Provia A/C/C/A，仍是新进程首张（每格两个）。Gold 提交到 JPEG/R **2860→2742 ms**，DIR **509→403 ms**，两对整链均有小幅正收益（212／25 ms）。Provia 提交到 JPEG/R **2215→2242 ms**，DIR **418→452 ms**，一对反慢约 152 ms，一对快约 98 ms。Provia 初测的正向幅度没有被 DIR 单独复现；不能据此承诺 DIR 单独跨配方便能省 0.2 s。也不能把组合总差全部归因于 DIR。

## 画质回归

使用用户指定的四张原始 DNG：110832 人像、110846 室内绿植、110904 室外建筑、110936 鲜花。Gold / Endura 与 Provia，每配方测 8／10 位，单 RAW 降噪打开以覆盖 RAW 协方差，Vulkan 和 HDR 保持开启。16 组 A/D 的全尺寸 RGBA、HDR 增益图、回放 JPEG 逐字节一致；人像 Gold 8 位另做 PC3D 叠加、CS、CM 全开对照，三项也一致。

App 四帧回放逐次对照 RGBA、HDR 增益图和实际 JPEG/R SHA-256，均一致；RGBA 和增益图还匹配历史安装版同四帧基准。另有 40 组 CPU FP64 逐字节对照，覆盖正片／负片、对齐／奇数尺寸、DIR 关闭／局部／完整空间扩散、1／8 线程，测试前把工作平面填入不同旧值，验证不读取旧像素。

## 决定与留存

**只保留实验，不发布。** 现在有真实 Android 前台进程的首张可量化证据，但没有真实预览或快门到保存同 RAW A/B，更没有跨配方稳定的 0.5 s。不能把 RAW 内存、DIR、已有 Vulkan 直连和扫描的单次差值相加。若再追整链，优先在这里的同一回放夹具用完整组合做开关对照，并补带真实取景的回归；还要分别记录设备是否预热、缺页、GPU 同步和完整保存耗时。不要用 MediaStore 偶发差异解释引擎收益。
