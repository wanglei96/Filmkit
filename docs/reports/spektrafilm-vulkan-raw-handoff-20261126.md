# Vulkan：RAW 融合到 Hanatos 的驻留、交接与同步

2026-11-26 · vivo V2509A / Mali-G1-Ultra MC12 · FilmKit 0.14.56（853）。此次不改重建、降噪、光谱算法或精度。目标是验证 RAW 前链尾部与现有 Vulkan 投影之间，能否去掉整图搬运和同步，并且不使取景变差。

## 验证了什么

- **去掉整图拷贝**：让最终 GLES 场景 pass 直接写 RGBA16F AHardwareBuffer，由 Vulkan Hanatos 消费，省掉原纹理到 AHB 的 blit。Provia 试跑的 8 位成片 RGB 均值约 2.333，对照为 159.589；诊断在 Vulkan 投影前从 GLES 目标中心读到 RGB [0,0,0]，GL error 为 0。问题已可在 GLES 生产端观察到，不能归因于 Hanatos，也不足以判定是驱动还是附件/状态问题。直接写入路线撤回；它的耗时不纳入提速结论。
- **复用资源，保持已验证的整图拷贝**：保留 GLES 内部场景目标与原 glBlit，跨张复用同尺寸 AHB、EGL 图像及 Vulkan 导入。仍等生产者结果就绪，不减少任何输出像素。在同一实验库中独立测试每张重新导入、复用、现有分带读回三种路径。
- **独立验证融合后的等待**：把选定光谱分支融合后的 glFinish 改为 glFlush；原 GLES 上下文继续按命令顺序采样，后续 CPU 读回和跨 API 依赖不删。分别在现有读回和共享复用上做对照，不能把提前返回等同于工作消失。

## 真机计时

使用同一组 3072×4080 室内四帧 RAW，8 位、HDR、颗粒关、PC3D 关、30 Hz 合成取景。每配方五路线，先后反向交错；每路线两独立进程、每进程两张，共 40 张，起止热状态均为 0。引擎总时取日志的 raw.render.totalMs，含 HDR 增益图生成，不含快门采集等待、App JPEG/R 封装和 MediaStore。取景统计为引擎回放期间相邻两次交付的最长间隔，不是实拍取景。

第二张中位数，单位 ms：

| 配方、指标 | 2 当前 Vulkan 分带 | 3 共享每张创建 | 6 共享复用 | 2a 分带＋融合异步 | 6a 复用＋融合异步 |
|---|---:|---:|---:|---:|---:|
| Gold 200 / Endura：交接＋Hanatos | 88.8 | 73.4 | 65.5 | 92.3 | 62.0 |
| Gold 200 / Endura：RAW 引擎 | 2276 | 2201 | 2175 | 2330 | 2338 |
| Gold 200 / Endura：取景最长间隔 | 71.5 | 53.1 | 57.5 | 80.2 | 95.0 |
| Provia 100F：交接＋Hanatos | 82.4 | 81.9 | 61.0 | 82.5 | 61.1 |
| Provia 100F：RAW 引擎 | 1914 | 1878 | 1881 | 1886 | 1800 |
| Provia 100F：取景最长间隔 | 54.8 | 61.9 | 58.2 | 81.5 | 51.6 |

- 共享复用比每张共享导入，第二张设置时间 Gold **12.0→0.3 ms**，Provia **9.8→0.2 ms**。同时相对当前分带模式，第二张的交接＋Hanatos 合计少 **23.4 / 21.4 ms**。这是局部路径结果，不把全部差值归给导入设置。
- 相对当前模式，第二张整链复用路线的中位数差约 **102 / 33 ms**；首次是 Gold **2547→2344 ms**、Provia **2244→2031 ms**。每格只有两进程，基线首张两样本相差约半秒，且第一张尚没有跨张复用；不能将首张或整链差归成约 0.2 s 的可交付提速。
- 异步使融合后的主机同步墙钟从约 **16–17 ms** 降到接近 0；Gold 组合路线反而变慢，且合成取景最长间隔从 **71.5 到 95.0 ms**。Provia 组合路线有正向观测，但不足以通过两个配方的引擎和取景门槛。热状态相同也不意味着 GPU 调度或频率相同。

## 哪个整体方案更值得测

另用同组四帧在不开额外同步的情况下取 GLES 查询，重连后完成 8 张。重建到色度起点的 4 个有效 GPU 时间区间为 **93–103 ms**；色度这一段的 7 个有效区间为 **175–184 ms**。有 4 个重建查询和 1 个色度查询无效（disjoint），未统计。两段区间都可能包含同 GPU 的调度，不等于独占 kernel 时间；也不能把它们相加后承诺同量加速。

这组数据支持优先验证的不是再省一次 20 ms 的交接，也不是换掉整个成片栈。**候选边界应从融合输出延续到色度处理、场景线性 RGB 和 Hanatos 的连续驻留段**。要证明其价值，应让相邻 pass 共用中间图像、减少全尺寸中间写回，在真实消费者处同步；不能把单个 RCD shader 搬去 Vulkan 后再搬回。先用同画幅同算法统计中间图像读写与整段输入就绪到 Hanatos 输出的耗时；如果拿不出可删除的整图写回和同步，不能仅依靠改变 API 预期提速。曝光、DIR 的现有 FP64 路径和拍照取景不在这个候选改动范围。连续方案尚未实测，这份报告不把它算作收益。

- **按指定四张原始 DNG 回归**：110832 人像、110846 室内绿植、110904 室外建筑、110936 鲜花；Gold 200 / Endura、Provia 100F 各跑 8 位与 RGB10_A2。共享复用在 16 组均处理 12,533,760 个像素，设备输入哈希与原始 DNG 派生的 Bayer 一致。与 [0.14.56 Vulkan 同四原片历史归档](spektrafilm-vulkan-01456-20261126.md) 比较，**16 组、48 个 RGBA、HDR 增益图和回放 JPEG 的 SHA-256 全部一致**。
- 四帧性能回放的 40 张按配方比较，各配方五路线的三个输出也全部逐字节一致。融合异步的画质证据来自这组实际运行融合的四帧回放，而不是单帧 DNG。不外推为其他机型、真实取景或独立 HDR 高光专项验收。
- 证据在 `test_temp/spektrafilm-vulkan-raw-handoff-20261126/`。保留 `perf-summary.json`、`verified-hashes.json`、`verify-evidence.py`、`replay.sh`、两份补丁、三份压缩实验库和设备日志。复用实验可从压缩库解出 `libfilmengine-reuse.so`，用 `LIBRARY` 指向该文件；`MODES` 对应表格模式，`SCENES=indoor` 为四帧，`REPEATS=2`。四张 DNG 的完整 Bayer 可用 `tools/prepare-spektrafilm-regression-dng.py` 再生，重放需将 `FIXTURES` 指向再生目录。
