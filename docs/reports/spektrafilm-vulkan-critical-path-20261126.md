# FilmKit 的 Vulkan 成片关键路径

2026-11-26，vivo V2509A，Mali-G1-Ultra MC12。以同 RAW 因果对照评估 Vulkan 分工。前两轮单独迁移 RCD、连续扫描尾段的原始数据保留在对应报告。

## 用时从哪里来

四帧回放的生产顺序为上传、金字塔与配准、高光准入与融合、RAW 重建及降噪、线性 RGB 交接、Hanatos、胶片曝光、DIR 显影、印相或直扫、扫描输出及 HDR。相机采集与应用 JPEG/R、EXIF、系统保存在该计时区间外。

| 基线热态同 RAW 引擎，ms | Gold 200 / Endura | Provia 100F 直扫 |
|---|---:|---:|
| RAW 到光谱入口，含 CPU 与 GLES | 875 | 853 |
| 交接与 Hanatos | 123 | 114 |
| 胶片曝光与 DIR | 674 | 637 |
| 印相、扫描光谱与眩光 | 485 | 134 |
| 扫描颜色、滤波、量化、HDR、其余 | 213 | 210 |
| 引擎总时间 | 2370 | 1948 |

室内 3072×4080 固定四帧，PC3D 与颗粒关，30 Hz 合成预览并发。阶段取各自中位数，再进行组内相加和取整。其余包括精确的本张 HDR 中性响应和输出资源成本。基线使用 0.14.56 的现有 Vulkan Hanatos 和现有 FP64 CPU 曝光、DIR。生产 RAW 仍部分依赖 CPU，高光回退与 AMaZE 路径也必须计入全链迁移设计。

## 整体候选如何选

| 路线 | 潜在收益及可验证边界 |
|---|---|
| 整条成片改 Vulkan | 能减少中间 API 交接，但仍有相机输入、上传、FP64 运算及编码出口。Mali 缺 shaderFloat64，直接搬全部光谱无法保留原 FP64；串行递归同搬亦保留完整长链。 |
| RAW 连续驻留 | 必须连起来量最终线性 RGB 到 Hanatos 或下一真实消费者。前次只搬 P1/P2，GLES 热态约 48 ms，因此即使这两段变成 0 ms，整个约 2 秒的热态引擎也只省这 48 ms。全 RAW 约 0.85 秒含上传、CPU、融合等，其余整段上限尚无同口径 Vulkan 替代数据。 |
| 扫描尾段连续驻留 | 前次扫描颜色、FIR/USM、打包、HDR 底图合段已验证热态局部省 42–50 ms，金额小于两次回放间部分波动，合成取景未在两配方同时受益。 |
| 曝光＋DIR 由 CPU/GPU 并行 | 两配方共用，而且该段约占热态引擎 28% / 33%。以通道为分工边界，CPU 做另外两个通道，GPU 做整段滤波，运算时间以先后完成时间的最大值决定，外加收口与共同串行阶段。两路共享 DRAM，实际并行窗口由真机测量。 |
| Vulkan 块边界递归 | Nehab 等 2011 的方法利用每块边界状态保持完整正反递归，并合并行列处理来减少全图中间写入（DOI 10.1145/2024156.2024210）。这是可评估的 Vulkan 算法候选。需证明现有 Young–van Vliet 边缘初值、完整多半径混合和原顺序可复现，并将搬运、合并和取景计入多通道整段预算。 |

合成预览与成片计算共用 Mali。Khronos 的 Mali 样例说明排队与同步可影响 GPU 并发，独立队列本身不度量取景改善。实测只在真实数据依赖处等待，额外阶段同步关闭。GPU 命令时间是两个 Vulkan 时间戳之差，含命令区间的 GPU 调度影响。

## 验证 CPU/GPU 分工

曝光阶段把 R 通道的镜头模糊（启用时）、散射全部半径、光晕全部反射项放在同一个 Vulkan 提交里，CPU 同时算 G、B。FP64 对数曝光等三个通道就绪后按原逻辑计算。DIR 的初次显影及抑制矩阵保持 CPU FP64；GPU 接手 R 通道完整扩散与混合，CPU 算 G、B，最后减自原曝光并执行 CPU FP64 修正显影。每个 GPU 支路上传一次、读回一次，无逐 tap CPU 同步。常量与缓冲可跨同进程两张使用。FIR 原半样本反射与 IIR 全行、全列正反扫保留。IIR 使用同传递函数的单实极点加共轭对，GPU 空间中间值为 FP32。

A/B 各为两次进程，每进程连跑两张，每配方 ABBA，均热状态 0→0。两边使用同一个实验库，环境变量切换分工。同一配方的各路线内，所有重复 RGBA、增益图、回放 JPEG 都逐字节复现。

| 真机同 RAW，ms | Gold 首张 / 第二张 | Provia 首张 / 第二张 |
|---|---:|---:|
| 曝光与 DIR，A → B | 762 / 674 → 1116 / 679 | 658 / 637 → 888 / 679 |
| RAW 引擎，A → B | 2695 / 2370 → 2994 / 2359 | 2095 / 1948 → 2392 / 1961 |
| 合成预览最长交付间隔，A → B | 79 / 61 → 70 / 69 | 68 / 60 → 64 / 68 |
| B 曝光路径 GPU 命令区间 | 278 / 267 | 297 / 261 |
| B DIR 路径 GPU 命令区间 | 178 / 183 | 188 / 186 |
| B 曝光 CPU 两通道完成后的 join | 332 / 75 | 299 / 77 |
| B DIR CPU 两通道完成后的 join | 16 / 18 | 24 / 24 |

首张曝光 GPU 管线及缓冲初始化占 Gold 248 ms / Provia 167 ms。第二张初始化小于 0.01 ms，说明预热可针对首张开销，但第二张合流仍有约 93 ms / 101 ms 的等待。GPU 结果回写另占合计约 34 ms / 33 ms。曝光 GPU 支路热态墙钟 298 / 292 ms，CPU 给它的重叠窗口约 220 ms。DIR GPU 支路热态墙钟均约 221–222 ms，重叠窗口约 200 ms。

即使把这两个 join 理想化降到零、其余耗时固定，该结构相对基线也只省约 88 / 59 ms。这是单一情景估算，不将其外推为其他算法的理论上限。若以额外省 250 ms 作为一项讨论用的整链量级，且全部从曝光＋DIR 单独取得，现有 674 / 637 ms 须降至约 424 / 387 ms，包含所有交接与曲线。接近该量级要对多个通道并行、减少整尺寸中间平面读写，或同时从其他驻留阶段拿到经过整链 A/B 确认的收益。单个通道继续减少 join，仍有两条 CPU 通道和共同 FP64 阶段留在关键路径。

## 画质和留存

指定 DNG 人像 110832、室内绿植 110846、建筑 110904、鲜花 110936，两配方、两色深共 16 组。A 端与既有 0.14.56 Vulkan 四原片回归的 48 个输出哈希完全一致。B 端保持曝光与 DIR 末端精确曲线，所有 8/10 位原尺寸 RGB 最大差 1 码，最多 799 / 37,601,280 通道改变，全图平均绝对差最大 0.00002125 码。16 张增益图逐字节一致。回放 JPEG 解码最大差 6 码、最坏全图平均差 0.000130 码。两条配方的整图和肤色、叶片、建筑、花瓣 1:1 裁块目视未见明显变化。实拍 JPEG/R、真实取景和其他机型未纳入本轮回放验收。

候选未过性能门槛，已撤回成像代码，仅保留可重放的补丁。常规 ARM64 native 构建完成，Vulkan 支持和 Ultra HDR JNI 均在，实验入口不存在。手机仍为 0.14.56（853）。证据与复现在 `test_temp/spektrafilm-vulkan-spatial-chain-20261126/`，含 `spatial-chain.patch`、`replay.sh`、`perf.json`、`quality.json`、全尺寸无损归档、裁块和清理审计。两边的实际手机输入、输出 SHA-256 均已校验。
