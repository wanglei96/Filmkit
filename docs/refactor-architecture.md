**验收方法学修订（重要）**：设计 v1/v2 多处写"成片 SHA256 逐位一致"，但**引擎没有
"同一张 DNG 重渲染"的入口**，跨版本连拍又受光照/AWB/时刻影响（实测同一会话相隔 40 秒
两帧的 `linMid` 差 10.3%）——**该承诺在真机上无法执行**。实际采用的判据：
1. **静态证明为主**（调用图 / `.o` 反汇编 / section 级比对 / token 级 diff）；
2. **日志对拍兜底**（`tools/log-ab-diff.py`：42 项不变量 + 字段冻结清单 + 场景指纹门控；
   指纹不匹配时判"无法判定"而非误报回归）；
3. **真机视觉收口**（静态证明覆盖不到运行时 GL 状态机与绑定顺序）。

⚠ 数值项跨版本对比**要求场景指纹匹配**——`iso` 与 `ns`/`nzS`/`nsHal`/`nzO`/`nzG`
**随 ISO 变化，不是不变量**（已从工具的 `INVARIANT_KEYS` 移入 `ISO_DEPENDENT_KEYS`）。
实测例证：0.10.152 vs 0.10.153 场景指纹差 10.3%、ISO 493 vs 445，13 项超阈值**全部**

### 4b 期：离线预验证**否决**（2026-10-04，四张真机样片）

**结论：换域没有收益，且核心动机不成立。** 决定性实验是**强度匹配**（扫描 σ 乘子，
在"同一张图的共同残余噪声区间"内插值比较细节保留）：

| 对比 | 结果 |
|---|---|
| 换域后等效强度变化 | D3 的色度差幅度只有 D4 的一半（rms\|Δcd\| 0.0373→0.0150）而 σ 不变 ⇒ **σ/rms 从 0.443 翻到 0.906** |
| **强度匹配后的细节保留**（决定性） | D3 比 D4 平均 **−2.4%**（逐图 −4.0 / +0.1 / −5.3 / −0.2%）⇒ **换域无收益，还略差** |
| 品红过冲（4b 的**核心动机**） | 平均 P99 −1.5%、**P90 +23.6%**；四张里**三张变差** ⇒ **动机不成立** |
| 唯一收益（彩噪 −23.4%） | 强度匹配后**归零** —— 它是"拧大旋钮"换来的，在 D4 上同样能做到 |
| 细节损失分层 | **强细节区 −22.3% > 噪声区 −11.2%** ⇒ 压掉的是真实细节，不是噪声 |

理论侧一致：CCM 行和 = 1（信号不变）但行范数 1.32–1.85，**同时**放大色度信号 1.85× 与噪声 1.60×，
线性变换不改变可达的色度 SNR —— **换域不产生净收益是数学上的必然**，不是参数问题。

> ⚠ **子代理自己勘误了一条**：它第一版报"同等细节下 D3 彩噪 −12.2%"，是**跨图平均时两条曲线
> 取了不同图子集**的方法论错误，已修正为 −2.4%。**旧的 −12% 不得再被引用。**

**⚠ 由此得到一个可用的副产品（未排期）**：报告量化了当前 D4 域 σ 形式的**真实偏差** ——
`Var(R−G)=Var(R)+Var(G)` 是在 WB 前（三通道量纲相同处）推导的；含增益的正确形式是
`Var(cd_i) = (1−2w_i)σ_i² + Σ_j w_j²σ_j²`（对称均值下 `(2/3)σ_i² + (1/9)Σσ_j²`）。
旧式 **σ̂ 对 R 低估 19.8–25.3%、对 G 高估 49.8–119.1%**；权重偏差 u=1 时 G +36%/R −27%、
u=3 时 G +1538%/R −94%，而**偏差集中在色度边缘**（平坦区实测权重比仅 0.95–1.09×）。
这与 §3.5 的 **S4/S5 同根因**，且证明了一件事：**不改域也能拿到这部分收益** ——
直接在 D4 域按正确形式重标定 σ。**候选为独立小项：离线可验、不动链路结构、无 4a 的 19.2ms 成本。**

**方法学教训（记入验收纪律）**：**相关系数判据对 CFA/WB 相位与增益错位近乎全盲** ——
子代理把 R 增益乘进了 G1 位后，三个相关系数判据（C1/C1b/C2）**全部通过**
（R/B 交换的负对照与正确假设仅差 0.0042），是导出图片肉眼看出紫色调才暴露；
另有一个 Malvar 绿核中心系数误写 0 的独立 bug。**后续任何 CFA/WB 改动必须加
"WB 后子网格均值离散度"自检**（正确 1.7–15.2% vs 错误 23–130%），不能只靠相关系数。

### σ 口径核实结论（2026-10-04，离线，**决定不改**）

独立核实了 P4/D-1 的噪声尺度口径（报告 `/tmp/phase-sigma/REPORT-sigma.md`，20 个可重跑脚本）。
**发现**：P4 用 luma 权重合并三通道方差（`dot(uNoiseA, LUMA)` = `Σwᵢσᵢ²`），而色差向量
`cd = c−y` 的正确尺度是 `Σⱼσⱼ²(1−2wⱼ+‖w‖²)` —— **G 的权重 0.715 vs 正确 0.132**。
偏差量级 `sc_正确/sc_引擎` = **2.0~2.3×**（解析口径）/ 1.7~1.8×（含实测空间相关），
方向 = 现状降噪偏**弱**。

**但决定不改**，四条理由：

1. **标定已吸收偏差**：实际系数 `2.25 = 1.5²`，等噪声下的正确因子是 **2.686** —— **差 9%**。
   即当年真机标定出的 1.5 几乎精确补偿了公式误差。该公式**只在 WB 把三通道噪声拉开时
   才失效**，这解释了它为何长期未暴露。
2. **直接改形式与历史被否决的修正同型**：σ 会 ×2.0~2.3，与 `:788-790` 记录的 v0.10.119
   （"A 项乘 glY"：σ×1.7~2.2 → 降噪 21~32%→43~62%、发糊、色块无改善，**已回退**）
   **同向且同量级**。
3. **离线双跑证实有害**：修正后彩噪确实大降（σ(B−G) −65%），但**真实色度边缘梯度保留
   0.870→0.782（下降）、边缘 ΔC RMSE +68%（变差）**。
4. **最大不确定性指向抵消**：σ 是"融合后未再降噪"的理论值，而 P4 输入**已过 P0+MFNR**
   ⇒ 真机 σ 可能本就偏大，与"偏小 2×"相互抵消（**离线无法验证**）。

**唯一残留的真实问题**（标定吸收不掉、且是纯解析结论不依赖滤波复现）：**D-1 的 Cb/Cr
共用同一个 σ**，而 `var(B−Y)` 与 `var(R−Y)` 本不相等 —— 不对称偏差 **1.71× vs 1.06×**，
与"彩噪偏蓝紫"吻合（`fig_wall.png` 的 eng 面板可见）。**候选为独立小项，需真机 A/B。**

**两条附带发现（记录在案，未排期）**：
- **N1**：`p4A` 含 MFNR 的 `1/Neff`（日志 `p0A/(nzS·nzG) = 0.25` 精确）—— σ 是"融合后**未再**
  降噪"的值。
- **N2**：噪声模型的通道映射实为 **[R, Gr, Gb]，B plane 未被使用**（ISO445 下 S 差 1.6%、
  O 差 6.7%）—— 可修的小项，影响面 <7%。

### 第 5e 期（S5）：D-1 色度降噪 σ 双路修正（2026-10-04，已实施）

σ 核实顺带挖出的**唯一可辩护的问题**，已实施 + 离线验证 + 真机验证。

**根因**：D-1 给 `(B−Y)` 与 `(R−Y)` 两条路径**共用同一个标量 σ** = `Σᵢwᵢσᵢ²`（luma 合并 = 1.0）。
但两路的噪声投影行不同，权重平方和为 **1.4175**（Cb）vs **1.1367**（Cr）⇒ **Cb 路径被系统性
欠降噪**，这是"彩噪偏蓝紫"的算术来源。

**改动**（只动两个 shader，不碰 CPU 侧与纹理格式）：
- `kFsChromaDown`：σ 改逐路 —— 先算逐通道方差 `σᵢ² = Aᵢcᵢ + Bᵢgᵢ²`（**顺带修掉把 shot/read
  两项都折成 luma 的近似**），再按正确投影得 `(σ_Cb, σ_Cr)`
- `kFsChromaAtrous`：σ 取 `.rg` 逐分量收缩

**离线验证**（`/tmp/phase-d1/REPORT.md`，复现完整 5 级 à trous）：
- **四重独立口径互证**现状的不对称：解析 1.61 / 实测 σ 中位数 1.65 / 实测 `d/σ` 1.70 /
  **实测平坦区彩噪比 1.61**（现状给两路比值 1.00）
- **"σ 因 P0/MFNR 整体偏大"这一最强反方被实测否掉**：平坦区实测 `d/σ` 在 **Cb 路 1.62、
  Cr 路 0.95**（独立噪声下应 ≈0.891）⇒ **同一标量 σ 下 Cr 标定几乎正确（差 7%）而 Cb 差
  82%**；要让"σ 偏大"救回现状，P0+MFNR 必须把 Cb 压 45% 而只压 Cr 7% —— 但两者都在
  **demosaic 之前、逐 plane 同样处理、通道无关**，做不到。σ 尺度扫描 ×0.25→×2 方向不反转
- **效果**（203843，ISO445 / 极端 WB `g_B=3.24`）：彩噪 σ **Cb −25.7% / Cr −0.2%**
  ⇒ 目标达成且**风险隔离干净**
- **代价**：Cb 的 **4–32px 色度结构保留率 0.441→0.346（−21.5%）**。⚠ 报告自我澄清：该掩码
  在"σ→0"时保留率也只有 0.81 ⇒ 它测的是"4–32px 色度结构"而非"真实物体边缘"，其中含彩噪
  成分。**A2 不是"单纯变强"，而是"把降噪预算从 Cr 挪到 Cb"**（同总量对照臂 A4：Cb −15.6% /
  Cr −12.9%，总量几乎相同 −13.0% vs −14.3%，分配相反）
- 附带：Cb 全图均值漂移 ×3.2（相对该图 mean Cb 仅 0.77%，绝对值可忽略）；推广到 P4 时要查积累
- **不做"只修比例、总量不变"**（A5 臂）：会把 Cr 彩噪推高 14% —— 现状 σ 在**两路都偏小**，
  总量本身也要抬

**真机（0.10.156）**：用户场景 ISO 360 / `g_B=3.08`（属"能修得动"类），判定**肉眼无可见差异**。
与离线一致 —— 该 ISO 下 Cb 彩噪绝对量仅 ~0.3–1 个 8bit 级，25% 改善约合 0.1–0.25 级。
**收益应在弱光/高 ISO 下显现**（本版按"修正结构性错误 + 无可见副作用"定版，用户 2026-10-04 拍板）。

**P4 的同类偏差（×1.639）明确不改** —— 与 v0.10.119 被真机否决的修正同向同量级（见上文 σ 结论）。

## 0. 一句话诊断

**链路的"域"从未被建模**：12 个不同的域（各自的 transfer、primaries、白点、饱和含义）
同时存在，全靠注释约定；**白点没有管线级载体**，于是每个判据各自现场重算；
**色度处理被放在唯一不成立的域里**（CCM 之后）；**缺两个前置环节**（G1/G2 均衡、伪彩引导图）。
每一个真机症状都是这三条的必然投影，而不是独立 bug。

## 1. 诊断（每条都有代码/实测证据）

### 1.1 域未被建模 —— 12 个域混用，一个 target 承载 3 个

域审计实测：链路同时使用 **D0 sensor RAW / D1 归一化 RAW / D2 WB 后 mosaic /
D3 WB+LSC / D4 相机 RGB / D5 Lab / D6 显示域 / D7 sRGB 编码 / D8 sqrt 灰度 /
D9 色差 / D10 Ych / D11 HAL 显示域 / D12 对数统计域**。

结构性来源：**`fbo_scene_` 一个 target 承载 3 个域**
（`:4710` D11、`:4726` D11、`:5661` D4、`:5078` D4+G 反推）。
pass 之间靠"谁先谁后"隐式约定域，读代码的人（包括三次独立审查的子代理）只能靠注释猜。

**实证代价**：本次重构前，作者在数小时内连续三次踩"CFA 相位/域"错误
（`rot90` 后相位互换、rawpy pattern 编码、WB 域当 RAW 域），中间两组数据报废、
两个结论公开发错。这不是疏忽，是**结构问题的人格化**。

### 1.2 白点没有管线级载体 —— 每处判据各自重算

**标准做法**（两家一致）：
- darktable：`processed_maximum[4]` 是管线级白点字段，WB 时更新
  （`/tmp/dt/src/iop/temperature.c:524-525`），被 **五处**消费：
  `highlights.c:508-510`、`demosaic.c:766`（→`rcd_demosaic(..., procmax)`）、
  `denoiseprofile.c:1246`（`wb[i] = weights[i] * processed_maximum[i]`）、
  `colorin.c:675,1222`（CCM 后更新白点）、`cacorrect.c:295`。
- PhotonCamera：`RawDemosaicProcessor.kt:1680-1711 demosaicCalculationWbGains()`，
  一个函数让去马赛克 / 高光重建 / 噪声标定**三处共享**。

**我们的做法**：`prepareRawCommon:5826-5841` 的归一化**是对的**（中性乘成 (1,1,1)、G 归一），
但白点没有载体 —— `clips[3] = {gains[0],gains[1],gains[2]}`（`:5247`）在 A 处现场取，
`runHighlightReconstruct:7514-7535` 在 B 处**手工把 RAW 白点换算到 WB+CCM 域**并乘离线常数
`kMaskGain = 1.13f`（`:7524`）。

**已经出过两类事故，代码里有原始记录**：
1. 阈值写死 1.0 或用 RAW 域白点 ⇒ `whiteEv 5.494 → threshold 6.75`，而 G 饱和像素
   pixMax 中位仅 `2.355` ⇒ 阈值是实际值 **2.9 倍、命中率 0%**，
   注释原文："**这条链在真机上从未重建过任何像素**"（`:7511-7513`）。
2. 写死 1.0 那版误触发 8.7% 的块、高权重落在白墙 / 电视屏（`:7503-7504`）。

**后果**：换 CCM / 换镜头即失效，只能重标定。A、B 两处锚点语义不同源，
"① 修不到、② 也不敢修"的缝隙是**结构性的**，不是参数问题。

### 1.3 色度处理在唯一不成立的域里（最严重）

**标准做法**（两家在"CCM 之前"一致，但**在 WB 上相反**）：
- 位置：都落在 **CCM 之前** ✓
  darktable `denoiseprofile` 在 iop_order 的 **9.0**、`colorin`（CCM）在 **28.0**
  （`/tmp/dt/src/common/iop_order.c:192,194,223`）—— 但它在 `temperature`（WB）**3.0 之后**。
  PhotonCamera 注释原文：*"RAW input is filtered in linear camera RGB opponent space
  **before white balance and color conversion**"*（`ChromaDenoiseAlgorithm.kt:9-16`）—— **WB 之前**。
- **【v2 更正】** v1 称两家"高度一致"并据此选 D3（WB 后），但两家在 WB 位置上**相反**：
  darktable 在 WB 后、PC 在 WB 前。**选 D3 是跟随 darktable，不能再引 PC 的 "before WB" 作论证**；
  且 PC 的 `(r+g+b)/3` 与 `Var(R−G)=Var(R)+Var(G)` 是在 **WB 前**、三通道量纲相同处推导的
  —— 迁到 D3 后**方差形式必须重新推导含增益的版本**（已写入 §5 第 4b 期）。
- 亮度基准（两家一致）：**`(R+G+B)/3` 对称均值**。
  darktable `toY0U0V0 = {{1/3,1/3,1/3,0},...}`（`denoiseprofile.c:1499-1500`）；
  PC `guideSignal` 在 camera RGB 路径用 `(r+g+b)/3`（`ChromaDenoiseAlgorithm.kt:27-32`）。
- 理由（PC 注释写明，两条）：① 解耦后保边判据只作用于亮度，色度可更激进平滑而不损细节；
  ② **camera RGB 各通道增益不同，Rec709 权重在该域无意义**。

**我们的做法（三方中唯一孤例）**：
`kFsChromaDenoise`（`:697-773`）输入 `tex_scene_`，是 **WB + LSC + CCM 之后**的 sRGB 线性域
（CCM 在 `kFsRcdChroma:621` 已施加）；亮度基准 `LUMA = vec3(0.2126,0.7152,0.0722)`（`:711`）。

**连带后果（我们自己已经记录）**：
- CCM 后 R/B 饱和点 ≠ G，`c - y` 在近饱和处被截断污染，而 P4 判据把它当"真实色度边缘"保护
  —— `:777-778` 原文："**P4/D-1 的保边判据恰好保护它（品红边缘），整链近零压制**"。
- 缺 PC 的**曝光不变性回缩**（`ChromaDenoiseAlgorithm.kt:195-203` 的
  `signalScale = centerSignal/averageSignal`，注释："ratio-of-means … exactly preserves
  a constant camera chromaticity across an exposure gradient"）。
- 噪声模型混域（S4）：`:749-756` 的 `uNoiseA/B` 是 D2 系数（WB 后，`:5902 afterWb`），
  而 `y0` 是 D4 的 luma；shot 项未乘 LSC、read 项乘了。CCM G 行
  `|−0.141|+|1.343|+|−0.202| = 1.686` ⇒ **判据偏小约 1.7×** ⇒ `w=exp(−0.5d²)` 塌陷
  ⇒ 色度降噪不足（与 `:627` 记录的"彩噪是短板"一致）。

### 1.4 缺两个前置环节（不是缺一个滤波器）

**(a) G1/G2 均衡缺失** —— 对症实测的"1–2 px 镜面高光线、RAW 域 G1 与 G2 相差 35%"。
darktable 有 `green equilibration`：枚举 `DT_IOP_GREEN_EQ_NO/LOCAL/FULL/BOTH`
（`/tmp/dt/src/iop/demosaic.c:118-121`）、触发 `:764,1102`、
实现 `green_equilibration_favg`（`:871`）/`_lavg`（`:874`），
**位置在去马赛克之前、RAW mosaic 域**。作用：消掉 G1/G2 比例失配，
否则 RCD 会把交替失配当真实信号 → G 位高频交替 → 与 R/B 插值耦合 → **品红/绿交替**。

⚠ **【v2 更正】两条必须同时记住**：
1. **darktable 默认关闭它**（`demosaic.c:145` `$DEFAULT: DT_IOP_GREEN_EQ_NO`），
   且它位于 demosaic **内部**、`temperature`（WB）**之后** —— 它不是"默认开启的标准做法"。
2. **35% 的失配异常大**（正常传感器只有数个百分点）。本次调查中作者连续三次踩过
   CFA 相位 / pattern / 域错误 ⇒ **必须先排除数据 bug（相位、pattern、LSC 网格错位），
   再谈实现均衡器**。用默认关闭的可选滤波器去掩盖一个可能是数据 bug 的 35% 异常，
   风险不是 v1 所评的"低"。

我们：`kFsRaw(244)` / `kFsRawDenoise(636)` / `kFsRawDenoiseFused(1430)` 全无 G1/G2 匹配。

> **✅ 2026-10-04 实测结论：不需要 G1/G2 均衡。**
> 样片：`FILMKIT_20261004-182547.dng`（窄高光）、`1000021658.dng`（瓶子高光）、
> `FILMKIT_20261004-180318.dng`（室内窄高光）。方法：按局部相对梯度分层 + 仅平坦块统计。
>
> | 指标 | 实测 |

> | 分层均值比（平坦→高频） | 1.00022 / 1.00026 / 1.00316 / **1.00559** |

> （G1 与 G2 空间上差一个像素对角），**不是通道失配**。
> darktable 的 green equilibration 针对的是**几个百分点**的失配 —— 我们连 1% 都不到。
> **评审"35% 异常大、应先排除数据 bug"的警告是对的；原第 3 期计划据此取消（见 §5）。**

**(b) 伪彩引导图缺失** —— PC 的 `MeasureMoire`：
- 输入是 **RawToYuv 之后的线性 Y 平面**（不是 Bayer mosaic）；

（算法本体是 Halide AOT 汇编，不可读 —— 我们只需对齐 I/O 契约与位置。）

### 1.5 反推通道无闸 —— 全链唯一一个"裸除法"

`D-1` 收口（`:1096-1097`）：`o.g = (y + dyn - 0.2126*o.r - 0.0722*o.b) / 0.7152`

**标准实现的四~五道闸**：
- PC（`ChromaDenoiseAlgorithm.kt:103-117`）：`green = m − (u+v)/3`（**对称组合，不给任何通道
  特权亮度角色**，注释 `:105-107`）+ `max(..., vec3(0.0))`（`:109-116`）
  + ratio-of-means 曝光不变性（`:195-203`）+ `Var(R−G)=Var(R)+Var(G)`（`:121-133`）
  + 中心锚定（`:157` 注释）。
- darktable（`hlreconstruct/opposed.c`）：`fmaxf(0,…)`（`:51`）
  + **`MAX(inval, ref + chrominance)` 只增不减**（`:229,418,447`）
  + 裁剪邻域统计（`:184,355-370`）+ 100 样本闸。

**我们：一条闸都没有**。放大系数 `1/0.7152 = 1.398`；`y+ch.x<0` 在暗部常见，
而 G 恰好是**无 WB 增益放大、Bayer 上 2× 采样、SNR 最高**的通道 ——
我们在最后一步把最干净的观测量丢掉，换成含噪派生量；之后全链**再无第二次 G 观测**。

## 2. 设计原则（重构的验收标准）

1. **域是一等公民**：每个 render target 携带 `{primaries, transfer, white_point, reference}`；
   每个 pass 显式声明 in/out 域；跨域必须在代码里看得见。
2. **白点单一真相源**：`white_point[3]` 由 WB 建立、随 CCM/曝光更新，**判据只从它取，禁止现场算**。
   **【v2 补充】但"只从它取"不等于"删掉下限"**：自动白点已被三次真机证伪
   （v0.10.16-19 默认关；v0.10.17 阈值随白点掉到 0.5 ⇒ 47% 的块进重建；v0.10.111 加白点下限自适应），
   且 `:7509-7521` 记录的下限语义与 `kMaskGain` 标定证据必须保留 ——
   **物理下限与标定证据本身是元数据的一部分**，与白点并列，而不是被它取代。
3. **判据与作用量同域**：阈值、掩码、σ、权重全部在它作用的那个域里定义。
4. **禁止跨域 mix**：跨域只能通过显式的域转换函数。
5. **通道对称性台账**：任何对 R/B/G 不对称的阈值/clamp/掩码/权重，必须在台账里登记理由。
6. **禁止隐式反推通道**：若某通道由另两个反推，必须带闸（下限 + 只增不减 + σ 建模），
   或改用不丢该通道的对称组合。
7. **统计域 = 渲染域 = 判据域**（同 EV 基准）。
8. **删除优先**：能删的补丁与死码先删，不保留"以防万一"的分支。

**已有正面模板**：`runHighlightReconstruct:7509-7536`（v0.10.145）的阈值
`1.13·‖CCM·(0,gain_G,0)‖` 是**全仓库唯一做对"跨域判据显式换算"**的地方 ——
重构时把它的一般形式（白点随域变换）推广到全链。

### 3.4 两个新增环节的实施规格（已从对标源码落到可执行）

#### ~~阶段 2 · G1/G2 均衡~~ —— **已取消**（实测无系统性失配，见 §1.4a）

> **本节保留作参考存档**：若将来换传感器/换镜头后实测出现**几个百分点**的 G1/G2 失配，
> 可直接照此规格实现。**当前不实施**（实测偏离 0.08%，低于噪声量级）。

**参考实现**（源码已补全到 `/tmp/dt/src/iop/demosaicing/`）：
`basics.c:149-197`（`green_equilibration_lavg`）、`basics.c:200-233`（`_favg`）；
调用与阈值 `demosaic.c:860-890`。

**算法（两支）**：
1. **favg（全图）**：累加 G1、G2 位置各自的总和 → `gr_ratio = ΣG2/ΣG1` →
   **只缩放 G1 位置**（`out[G1] = in[G1] × gr_ratio`），G2 不动。
2. **lavg（局部）**：对每个 G1 位置，取**对角邻居**（另一 G 相位，4 个）均值 `m1`、
   **十字邻居**（同 G 相位，4 个）均值 `m2` → `out = in × m1/m2`。
   **三重保护必须照搬**：
   - `m1 > 0 && m2 > 0 && m1/m2 < 2.0` —— 防 `m2` 过小造成 hot pixel；
   - **`in < 0.95` —— 排除近饱和像素**（正对我们实测的"1–2px 窄高光线"）；
   - `c1 < thr && c2 < thr` —— 局部对比度门槛，`c1`/`c2` = 各自 4 邻居两两绝对差的均值（6 对），
     **只在平坦区校正**，避免在真实边缘上误缩放。
3. **阈值 `thr = 1e-4 × ISO`**（`demosaic.c:862`）—— 与噪声水平挂钩，ISO 越高放行越多。
4. 模式：`FULL`(仅 favg) / `LOCAL`(仅 lavg) / `BOTH`(favg→lavg)；**darktable 默认 NO（关闭）**。
   → 我们应按 `BOTH` 实现，但**保留独立开关**便于 A/B。

**对我们的适配**：
- **位置**：P0 降噪之后、RCD 之前（与 darktable `rawdenoise 7.0 → demosaic 8.0` 的顺序一致）。
- **域**：D2（WB 域）。G1/G2 增益相同（`gains[1] ≡ 1`），所以失配不是 WB 引入的，不需要域换算。
- **成本**：一个全分辨率 pass，每像素 8 次同色采样（4 对角 + 4 十字）+ 2 次对比度计算。
- **验收**：实测的窄高光"G1/G2 相对差 35%"回落到全图基线（3.6%）量级；
  窄高光场景的品红 `mag` 下降。

#### 阶段 6 · 伪彩强度图

**参考**：PC `mgc_full_resolution_denoise_jni.cpp:1021-1048` +
`mgc_denoise_static.cpp:1666-1715`。**算法本体是 Halide AOT 汇编，不可读** ——
只能对齐 I/O 契约；若要复刻行为需另找 MGC 文档或论文（**这一点在排期时要计入风险**）。

**契约（严格一致）**：
- 输入：**线性 Y 平面**（不是 Bayer mosaic）、S16/Q14；
- 输出：**1/4 分辨率 × 3 通道**、uint16 定点（Q8）；
- 用途：**只替换色度降噪的强度图**；luma 降噪的强度图不变 —— 它是**引导图生成器，不是滤波器**。

**对我们的适配**：
- 输入用阶段 7 之前的线性 Y，且**基准同为 `(R+G+B)/3`**（与阶段 7 对齐，避免又一次白点分裂）；
- 输出强度图调制阶段 7 的色度平滑强度 —— 我们的 P4 已有 per-pixel σ 与强度概念，接口天然契合。

## 5. 迁移路径（每期独立可验证、可回滚）

- **第 0 期 · 生效性审计**（前置，必须先做）

  `hr_wavelet` 在 v0.10.145 之前命中率 0%（阈值是实际范数的 2.9 倍），却占 **597 行

  产出：**「环节 → 生效判据 → 当前实测值」基线表**，作为后续所有删除与改动的依据。
  已核实部分见 §7.1。

  | 环节 | 生效判据 | 实测值 | 判定 |

## 6. 验证体系（重构期间必须同时建立）

> **【v2 更正】** v1 只覆盖了项目铁律"质量四维"（噪声、细节、色准、影调）中的**一项半**。
> 本节按对抗性评审补齐。**原则：每一项都要有基线、有门槛、有样本口径。**

**6.1 三方对拍基线（v1 完全缺失）**
AGENTS.md 明确"目标是全面超越 PC（PhotonCamera）"。每个验收必须三方对拍：
**本引擎 / PC 同机位样片 / 厂商直出或 libraw**。只有本引擎的前后对比**不算验收**。

**6.2 色度指标：P90 + 撞顶率（v1 有，需补定义）**
中位数会**掩盖右尾**（实测：改 `uGCap` 后中位纹丝不动 `1.3330→1.3322`，
而 P90 从 `1.3203→1.0948`）⇒ 所有色度验收用 **P90**。
**"撞顶率"必须定义**：撞的是哪个上限（`uGCap`／`clips`／显示域 1.0）、在哪个域统计、样本口径 ——
定义为：*在 WB 域统计 `raw_gest > uGCap` 的像素占 G 饱和像素的比例*。

**6.3 细节／纹理指标（v1 完全缺失）**
历史上多次因降噪抹纹理翻车（v0.10.55 实测 8px 尺度纹理能量 **3.17 vs PC 3.59 = −12%**；
v0.10.57"只优化 σC 没看色度纹理"）。必须测：**2/4/8/16px 带通能量、Laplacian 保留率、

**6.5 跨场景回归门槛（v1 缺失 —— 这是"改一个场景坏另一个"的唯一防线）**
固定**锚点样张集**（≥4 场景 × ≥3 张 × ≥2 种 ISO/曝光），版本间做**差分回归**：
任一场景任一指标退化超阈值即失败。建议初值：色度 P90 ≤ **+5%**、
纹理带通能量 ≥ **−3%**、撞顶率 ≤ **+1pp**。

**6.6 同帧 A/B 能力（复用 v0.10.74 范式）**
每个改动必须能在**同一帧数据**上双跑，避免跨帧混杂（MFNR 帧选择、对齐抖动、曝光 EMA）。
