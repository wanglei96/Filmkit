## 1. 根因（三条，均已进入设计文档）

1. **WB 后三个通道白点不同**（实测 `gains = 2.07 / 1.00 / 1.68`），而下游判据一律假设"1.0 是白"。
   一个三通道全过曝的白，经 WB + CCM 后必然得到 `(2.69, 0.71, 2.08)` = 强品红 ——
   **物理上的白在这条链上必然品红**，只能靠上游高光重建救回。
2. **色度处理在唯一不成立的域**：PC 与 darktable 都在 CCM 之前 + 用 `(R+G+B)/3` 对称均值；
   我们唯一在 CCM 之后 + Rec709 luma。代码注释 `:777-778` 早已记录后果：
   *"P4/D-1 的保边判据恰好保护它（品红边缘），整链近零压制"*。
3. **缺两个前置环节**：G1/G2 均衡、伪彩引导图（PC 的 MeasureMoire / darktable 的
   color smoothing + pre_median）。

## 2. CFA 相位口径（**本次调查连续踩了三次，务必照抄**）

**原始传感器坐标**（`raw_image_visible`，pattern `[[1,0],[2,3]]`）：

```
G1 = nv[0::2, 0::2]     # pattern 值 1
R  = nv[0::2, 1::2]     # pattern 值 0
B  = nv[1::2, 0::2]     # pattern 值 2
G2 = nv[1::2, 1::2]     # pattern 值 3
```

**`np.rot90(cfa, 3)` 之后**（与 JPG 同向，corr≈0.82–0.89）：

```
B  = nv[0::2, 0::2]     # 旋转后 (0,0) = 原 (1,0)
G1 = nv[0::2, 1::2]     # 旋转后 (0,1) = 原 (0,0)
G2 = nv[1::2, 0::2]     # 旋转后 (1,0) = 原 (1,1)
R  = nv[1::2, 1::2]     # 旋转后 (1,1) = 原 (0,1)
```

**三个踩过的坑**：
- 用 `rot90` 后却按**未旋转的相位名**取通道 ⇒ R/G 互换（两次）；
- 把 rawpy 的 `raw_pattern` 编码 `(y&1)*2+(x&1)` 当成通道号（实际不是）；
- 忘记归一化（`(cfa-bl)/(wl-bl)`）⇒ 值是 233 这种原始码值。

**防御**：任何 CFA 脚本必须内置 `corr(JPG降采样, RAW重建)` 自检并打印
（见 `tools/hl-ref-chroma-check.py` 与设计文档 §6）。

## 3. 各场景实测基线（真机 DNG，用于回归对照）

| 场景 | 文件 | WB 增益 R/B | G 饱和 | `raw_gest` P50/max | 修复前 R/G | 修复后 R/G（目标） |
|---|---|---|---|---|---|---|
| 逆光窗 | `FILMKIT_20261004-162411.dng` | 2.092 / 1.441 | 4.58% | 1.17 / **1.79** | 1.0887 | 0.9535（0.9311） |
| 台灯 | `FILMKIT_20261004-155309.dng` | 1.908 / 1.568 | — | 1.37 / **1.76** | — | 1.0740（0.8600） |
| 室内窄高光 | `FILMKIT_20261004-180318.dng` | 2.066 / 1.682 | 0.027% | 1.48 / **1.89** | 1.3330 | 1.3322→（cap 2.0） |

**关键教训（已进设计文档 §6.2）**：**中位数会掩盖右尾** —— 改 `uGCap` 后中位纹丝不动
（`1.3330→1.3322`），而 P90 从 `1.3203→1.0948`。所有色度验收用 **P90**。

**窄高光的形态**（室内场景那条紫线）：RAW 域 **G 饱和（1.0）而 R 只有 0.365**，
G1 与 G2 相对差 **35.3%**（全图基线仅 3.6%）—— 亚像素级窄亮线的采样错位。
`gest` 需要抬到 **1.74**，而当时 `uGCap=1.5` 把它削平（69.9% 撞顶）。

**⚠ 2026-10-04 19:56 复测（0.10.151，窗户+瓶子场景，判据 `excess=min(R−G, B−G)>0.05`）**：

| 来源 | 像素数 | 占检出 | 判定 |
|---|---|---|---|
| 瓶身标签彩色图案 | 533 | 72.9% | **判据误判**（真实彩色内容） |
| **窗框高光的亚像素反光点** | **~135** | 20.2% | **真实伪彩**（1–2px 孤立点，全图 0.0011%） |
| **瓶子镜面高光点** | 46+ | 6.9% | **确有紫晕 —— 用户 2026-10-04 亲自放大确认**：亮白核 + 紫蓝色晕（我此前归入"待查"是核得不够） |

全图 `excess>0.05` 占比从早期场景的 **0.187%（客厅）降到 0.009%**（不同场景，仅作量级参考）。
最强残留点在 `(1648, 803)`：窗框竖条镜面高光上的 1–2px 反光点，
5×5 邻域全为品红（`excess` 0.05–0.22）⇒ 是一处小"晕"，不是孤立单像素。
**结论**：窄高光品红已从"成片可见"降到"孤立微点"，**剩余部分是 CFA 在亚像素镜面反光上的物理极限**；
用 `color_smoothing` 类全局方法消除它需付出全图色度带通 −28% 的代价 ⇒ **不值得**（见设计文档 §5 第 3 期）。
**判据注意**：`min(R−G, B−G)` 会把**彩色印刷图案/红色物体**误判为品红，统计前须按区域排除。

## 4. 关键参数（真机实测）

- **WB 增益**：随时随地变化（同场景 6 分钟内 R/B 比可从 1.094 跳到 1.451）——
  这是 AWB 正常反应，**不是 bug**；未饱和区 WB 后 `R/G=0.976 / B/G=1.012`（AWB 准确）。
- **CCM**（真机日志 `raw.meta`）：`1.622,-0.554,-0.068, -0.141,1.343,-0.202, 0.008,-0.576,1.568`
  —— **G 行两个系数都是负的**，因此把任何 G 缺口**放大 1.34×**。
- **日志诊断字段**（`raw.render` 的 kv 共 **113 项**，字段集合已冻结）：
  `hlOk`/`hlCnt`/`hlCnt3`/`hlRefW`/`hlRgG`/`hlBgG`/`hlRef2Hit`/`hlRefGHit`/`hlChroma`/`hlSum`/
  `hrThr`/`hrWhiteEv`/`hrMs`/`hrStatRaw`/`dfCavg`/`nzG`/`nzPre*`/`nzPost*`/`linMid`/`pLo`/`pHi`/`ev`。
  **⚠ 三个踩过的坑（2026-10-04 实测更正）**：
  - `avgLuma`、`cfa` **在真实 `raw.render` 里不存在** —— 别引用；
  - **`blackEv`/`whiteEv` 不是场景指标**：两份**不同场景**的日志里它们逐位相同
    （`-7.654144` / `5.551635`），是设备/标定常量，用它们判"是否同场景"会永远判"同场景"；
  - **真正的场景信号是 `linMid` / `pLo` / `pHi` + `ev`**（见 `tools/log-ab-diff.py` 的场景指纹）。

## 5. 已试过且**无效或被否**的方案（避免重复劳动）

| 方案 | 结论 | 原因 |
|---|---|---|
| 提高高光重建的参考范围（块 8→32→64） | 单独无效 | 真正的问题是**样本选择口径**（通道间不对称），不是范围 |
| 池化口径（v0.10.148） | 单独几乎无效 | 只在全局兜底那 5% 上生效；真正的病在参考样本选取 |
| `uGCap` 1.5→2.0（v0.10.150） | **有效**（右尾） | 室内窄高光需要 G 抬到 1.89，1.5 削掉了 48.4% 的像素 |
| 去饱和（E 方案） | **用户否决** | 不想牺牲颜色 |
| Laplacian 高光重建（darktable 移植） | 离线否决 | 单帧无法恢复被截断的绝对亮度（归一化会压暗 40%） |
| 参考色度改中尺度/三级兜底（v0.10.139） | 部分有效 | 方向对，但样本口径未修 |
| defringe 的 `gate` 修法 | **暂不修** | 实测只影响约 3% 的贴边紫边（a>30 占比 2.6–3.3%），且改法会把真实红色物体的权重也归零 |
| 锐化関連 | **用户明确排除** | "干锐化鸟事" |
