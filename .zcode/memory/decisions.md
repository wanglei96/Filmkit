## 平台与成像内核

- [2026-09-22] **饱和/外观类改动只能用"有边界"的手段**；**色度增强判据=亮度相对饱和**；**DNG 对照只定位缺口不当绝对标尺**

## 色彩链、管线与 MFNR
- [2026-09-24] **色彩基准**：先定为同机位 PC 成片 → **后改为"色准对标基准 = 实物本身"**（用户拍板），PC 降级为参照
- [2026-09-24] **方向链路三定案** — `orientationStep`=设备物理旋转步进（**绝不能喂 Display.getRotation()**，语义相反）；成片裁切跟设备姿态、与窗口解耦；相机页不转窗口（正解=GL 预览收设备旋转 + UI autoRotate）

## 质量铁律与方法论
- [2026-09-28] **项目大前提（用户拍板，写入 AGENTS.md）**：质量 > 成本/工期；严禁简化关键质量管线（论文一手 + 成熟开源实现逐行对照）；**性能取舍必须实测、不替用户决定**；**对标口径 = 标准做法，非 PC**
- [2026-09-28] **OETF 改真 sRGB**（`pow(c,1/2.2)` 不是 sRGB；kFsOut/kFsHist/measureSceneStats 三处同步）
- [2026-09-30] **出包前两件必做**：新增 GPU 路径必跑 `tools/check-diag-fields.py`；**同刻 100% 裁剪目视**（定量指标只作辅证）。配套两条判据纪律：判据必须先在已知正/负样本上验证（"相邻像素相同占比"在 PC 纯黑区 77%，不成立）；纹理保真必须覆盖 2–4px 细纹尺度且 σ 分解（亮度分层 + 色度 1–32px）

## C / A / D 专项
- [2026-09-30] **P0 亚像素默认开**（用户拍板：+43.7%/+46.5%、细节无损失）；**两个杠杆必须一起看**（整数采样会把对齐精度的差别整个抹平）；**D-2 收线**：颗粒 = 胶片感、是风格不是缺陷

## 拍照线程与 LUT（10-01）
- [2026-10-01] **拍照独立线程/context 重做必须带开关**（0.10.83 那次失败丢了用户的照片）；**"只启动不销毁"**从根上消除竞态；**空闲释放要连 context 一起销毁**（只销 FrameRenderer 会让 Mali 分配不出全分辨率纹理）；**进程级设置必须能被后建实例补齐**（LUT/YUV 矩阵走进程快照）；**largeHeap 兜底连拍内存**；**OOM 时「这张失败」优于「进程 abort」**（用户红线：失败不以丢照片为代价）

## NN 判死与曝光决策（10-02）
- [2026-10-02] **判死：跨域模型不可直接用 + 微调需数据量 → 转 HDR+**：口径全修对后真机观感仍无改善（文字区梯度 −24%、平坦区斑块状伪影），**不如 P0**；四次微调留出集**全过拟合**（官方 3 万+ 对 vs 我们 4 场景）；代码与开关保留（`nn_dn` 默认关）

- [2026-10-02] **曝光 ×N + ISO ÷N = 亮度与高光裁切完全不变，纯赚 SNR**：离线解析收益 √N 与物理上限逐位吻合（N=8.66 → 2.95×）；约束三条 = ISO 下限/快门上限/运动预算
- [2026-10-02] **运动判据 = 1s 窗口矢量平均角速度**（Night Sight §2.3，不用 RMS——帧内模糊是角度积分）；**纹理预算维持细节优先 2.2px**（放宽 4.5px 属误读用户意见，已撤回）；曝光上限交用户拍板
- [2026-10-02] **σ 恒为真实噪声；强度 <1 走输出 mix、>1 才作 σ 乘子**：σ 被压小 ⇒ bilateral 的 `exp(−0.5d²)` 指数塌陷 ⇒ 降噪近似归零，且散粒噪声 ∝√x 使**亮部受害最重**；`nzPostP90 ≈ nzPreP90` 是失效指纹
- [2026-10-02] **三摄噪声模型改用 GCam 生态标定**：HAL 的 cam2 profile 其 G 通道比 R/B 低一半（物理上不合理）；优先级 = 用户选定 > 内置 > Camera2，**手动选定是全局的**

## 影调与曝光判据（10-03）
- [2026-10-03] **曝光目标 = "刚好不烧高光"（HDR+ §4），但用户优先噪声 ⇒ 默认曝光给足**：实测该场景渲染域高光 3.02 > 白点 2.438 达 0.58EV，两者**物理上不可兼得**；用户拍板：先压噪声，高光交给影调层
- [2026-10-03] **影调层固定、曝光层自适应**（标准做法）：darktable/AgX/ACES 的影调映射都是一套固定参数，场景差异由曝光吸收；我们做反了（曝光固定、影调每场景自适应）才是设置爆炸与"修一个坏一个"的根源
- [2026-10-03] **横拍方向与画幅必须快门瞬间快照**：MFNR 渲染 3~4s，凡"拍照时刻的状态"被数秒后的链路读取，一律快照
- [2026-10-03] **超广畸变只能自校正**（HAL 无能力、无标定）；裁边取舍待拍板：完整校正（视场窄 5~10%）/ 部分校正 / 不校正

## 高光重建、品红与紫边（10-03 → 10-06）
- [2026-10-03] **filmic HR 的 `threshold` = 曝光前域白点**（旧实现写死 1.0 致大面积误重建，真机 clipB 523→2）；**opposed chrominance 置 0**（输入已 P0 降噪使补偿方向反了，四张 DNG 验证安全）；**inpaint 噪声取 0**（相对幅度 3× 致彩色颗粒）。**伪彩判据被真实样片否决**："色度高亮度平坦"前提反向（品红亮度带通 = 全图 14×、56~66% 贴轮廓）⇒ 品红 = 逆光边缘紫边渐晕，正解 = defringe（RT 同形态，0.10.134 落地）+ 低频噪声另治

## 相册与预设（10-11 → 10-13）
- [2026-10-13] **白点取方案 A（不死白优先）**：`[38]` 2.5~2.7 → 4.0，死白起点 2.40~2.60 → 3.55 EV；代价亮部变暗 −15.9~−18.0 LSB、拟合残差 8~10 → 12.7~17.4。等真机验收后与方案 B（回滚）定档

## 设置页、图标与编辑器立项（10-04）

- [2026-10-06/07] **紫边两类分治 + 品红带机理闭环 + [56]/[57]/[58] 三开关默认关存档**：A = 4px 窄峰（红笔场景锐化是主放大器，仅该场景成立）；B = 逆光窗框品红窄峰。色散 = 管线产生（RAW 域三通道对齐、成片 dRG +0.9~1.0px，非光学非 [51]）。**品红带 = 白区左边缘 B 通道 ~8px 缓爬 vs G ~2px 陡跳的错位带**（RAW 域 G/B 形状重合 = 光学干净；单帧 ≈ 4 帧 ⇒ 融合赦免；P0 是缓解者）；**B 缓 G 陡错位 = RCD 类算法固有**。三开关 `[56]/[57]/[58]` 默认关存档（v0.10.178~180，三轮真机 A/B 均未证明收益：[57] 目标态命中率仅 0.1% —— X300 场景 G 先饱和 32%>R 19%），代码保留作 A/B 通路与机理记录

## 引擎插槽与影调架构（10-13）
- [2026-10-13] **引擎切换要做，第 2 步直接对齐 PC**（公共管线 + 引擎插槽）：对齐 PC `RawEngineTonePass` 形态 —— **引擎 = 1 pass**、shader 字符串注入公共模板、**输出契约线性 sRGB**（OETF 只做一次）。**切口 = gamut 归引擎、外观层归公共**：gamut 是 darktable filmic v5 的一部分，留公共会让 ACES 被套双份色域处理；方案见 `docs/engine-slots-design.md`。
- [2026-10-13] **参数面：`FilmParams` 只加 1 槽 `[98] engine_slot`**（0 = 内置 filmic ⇒ 旧预设行为不变）；引擎私有参数走**独立有序 KV 通道**；加/删引擎**不改槽位布局、不改 Room DB schema**（PC 的 Fuji 下线 = 33 文件 + DB v49→v50 的教训）。阶段 0–1 硬判据 = **`[98]=0` 时同帧 CRC32 逐字节等价**。
- [2026-10-13] **影调判据改用可分辨跨度** 作主判据（从白纸起每 0.1 EV ≥1 LSB 能持续多远；死白起点换阈值即翻转排序，若保留则必须写明阈值）；**公共工作空间推荐 Rec.2020 线性**（PC 的 sigmoid/AgX/filmic 即在 BT2020 域，可直接对照）但**必须单独一期** —— 换工作空间 = 整链处理域定义变化 + 所有预设重标，与插槽重构同期会毁掉零回归判据。
- [2026-10-13] **阶段 1 用"单真源 + 运行时切片"**（`ef1f50e`）：切片是连续区间划分 ⇒ 逐字节恒等由构造保证（物理拆三段只能靠人眼比对）；锚点缺失时退回整体字面量 + kError（不崩、不伪装）。
- [2026-10-13] **离线链缺口优先开工**（`f098ba8`）：`tools/engine-shader-offline.py` 当时只跑到 CCM/D4、头注释声称的 FILM pass 不存在 ⇒ 补 FILM 段 + PC3D，用旁路档逐位恒等自证。**离线基线只证明"拆 `kFsFilm` 没改变它的输出"，不证明"成片没变"**。

## 引擎插槽阶段 2/3 与全局开关（10-14）
- [2026-10-14] **`[35]` auto_tone 必须旁路 —— 它"不走 uniform"**：`updateFilmicEV` 在 `passFilm` 里**无条件调用**（`:14014`，只有 program 重建在 `if` 里）⇒ 成员变量 `last_still_w999_`（`:13865`，由 `auto_on` 门控）逃出引擎边界 → `sw999` → `sceneHighlightEv()` → `ExposurePlanner` 欠曝量 → **成片 `[0]`**。原判"由 shader 结构自动旁路"**错误**。（另一条候选"HR 白点泄漏"**不成立**，见 lessons 10-14。）
- [2026-10-14] **`[28]` 的旁路值是 1.0，不是 0.0**：引擎 1 的 `kFsSigmoidMain`（`:6603`）**复用 `uToneK` 作为 sigmoid 整条曲线的应用权重**（`if (uToneK > 0.0) { toned = sigmoidTone(out3); … }`）⇒ 置 0 = **引擎 1 完全空转**（指纹 `0x189e4126`）。我原推理 `mix(lin,toned,0)=lin` **只在引擎 0 成立**（引擎 0 的 `toned` 才是"基准影调"）。**`[22] sat_high` 亦须入表**（一个「饱和度」滑杆同写 `[20][21][22]`，只钉两槽留半旁路）。
- [2026-10-14] **新增判据 0：引擎 1 必须真的改变画面**（`0x8fdb4e38` ≠ 空转 `0x189e4126`；日志 `tone=1.0`）。原六条**全是负向判据**（"filmic 不该影响引擎 1"），一个"把引擎 1 关掉"的实现能让它们**全部通过** ⇒ **今后任何新引擎上线都必须配正向判据。**
- [2026-10-14] **设置页全局引擎开关 = 三档（用户拍板方案 C）**：`-1` 跟随预设〔默认〕/ `0` 强制 filmic / `1` 强制 sigmoid，prefs `engine_override`；**只作用于拍照链路** —— **编辑器不参与 override**（编辑旧照片应按**拍摄时**的引擎，否则改个设置页开关旧照片会突然变样）。「完整参数」页的预设级入口**保留**（强制档下仍可编辑 + 一行"被设置页覆盖"提示）。

## 期 B 域空间（10-19）

- [2026-10-19] **交付域保持 sRGB**（期 A R1 不变）：内部大盘子、输出转回小盘子。实读 PC 佐证：AgX/Sigmoid/Filmic 跑 BT2020，输出统一 `computeWorkingToOutputTransform(…, SRGB)` 存 8bit JPEG；且 PC 的**实时预览用另一套简化实现**（它在"预览 vs 成片"上比我们更不一致）。
- [2026-10-19] **预设不重标**（沿用用户 10-14"预设先不动"）：本期只保证**链路正确**，观感变化留到"域完成后重估"。理由：重标的目的是恢复旧观感，与本期目的（改善高饱和色）方向相反。待重标 7 项见归档 §7。

## 色相路线与 HDR（10-19）

- [2026-10-19] **ACES 与 Oklab L-only 都不做**：D5 域口径修正后 ACES 2.0 重锚 Δh 1.58° 与 filmic 1.50° 持平而 ΔE 4.69 更差，且需 Rec.2020→AP0 + 中灰重锚；Oklab L-only 能把 sigmoid Δh 4.43°→1.83° 但 ΔE 3.69→5.42，试遍 a/b 缩放与混合权重都没同时达标 ⇒ 回滚，不在 sigmoid 上继续加复杂度。

## HDR 交付（10-20）

- [2026-10-20] **"高光顶白"归因自动曝光策略，单独开期**：同场景实测 SDR base 平均亮度我们 **85.2/98.4** vs PC **50.7**，`>=240` 占比 **3.38%/2.22%** vs PC **0.37%**，而 **HDR 输出几乎相同**（P90 0.714 vs 0.697）⇒ PC = 暗 base + 大增益、我们 = 亮 base + 小增益，高光在 8bit 截断已丢信息。**gainmap 链路本身没问题**，不在此期改曝光（回归风险大，需用户拍板方向）。

## 自动曝光（10-20，已落地）

- [2026-10-20] **自动曝光放渲染端，用本张 RAW 统计**：`AeMetering` 按本张 P50/P99.5 决定 film pass 的 EV（中灰锚定 18.45% + 高光优先），**光子全保留、会话第一张也有效**；采集端的高光保护（只能拿上一张预测）在 `ae_auto` 开时**旁路** —— 两层同时压同一件事 = 双重欠曝（真机：第二张采集欠 1.98EV + 渲染再压 2EV）。
- [2026-10-20] **高光判据 = P99.5 + 限幅 ±2EV**：P99.9 会为 0.1% 像素压全图约 2EV（台灯场景实测）；改 P99.5 让 0.5% 像素可裁切（PC legacy matcher `maximumClippedFraction=0.005` 同口径），压暗量从 −1.74 收到 −1.11。欠曝上限 2EV = gainmap `[0.25,4.0]` 的表达上限，更大的动态范围交给 bracket。
- [2026-10-20] **bracket 方向拍板**（用户 2026-10-20 确认）：1 短 3 长、短帧放**帧 0 作参考帧**、`k=2` 初值；短帧先 ×ratio 归一后对齐，σ 按 ratio² 缩放，饱和像素权重 0；两条融合路径（`kFsMfnrFuse` / `kFsMfnrFft`）都要改。设计 `docs/engine-bracket-design.md`。
- [2026-10-22] **sigmoid contrast 定案 1.5（tag `contrast1.5`）**：两次想提到 1.7/1.8 补暗部对比度均回退 —— 引擎真实代码实测白纸 218.84→226.52（+7.7 LSB）而 PC 白纸 219.24，+4EV 247.4→250.4 高光更早 clip；中灰恒 119.01 不动 ⇒ 只有高光端受损。**用户决定不在引擎改，留到预设里调对比度**。
- [2026-10-22] **teq 的职责边界**：只做“按 AE 的取舍做局部分区补偿”，不承担“塑造对比感”。整体/暗部对比度该由曲线负责，压深放对 EV 分区（云 q≈−0.5 落白点档、天空 q≈−2.0 落第 6 档），**不要用事后权重函数去否决 gain**（wTop 改了四轮都没稳定）。
- [2026-10-22] **频域合并默认开**（推翻本窗口早前“净损失、勿开”的结论）：那个判断只量了噪声没量细节。噪声确实高（亮部 σ 5.99 vs 3.05），但用户实拍确认**细节明显更好**。按“质量优先”取细节。**量化单一指标不足以判优劣**。

## AE 定性、鲁棒测光与编辑器（10-23）

- [2026-10-23] **带天空偏暗不是测光/曝光问题**：EXIF 对拍 PC 2.02ms/ISO50 与我们 2.20ms/ISO50 ⇒ 采集一致；成片 p50 98.7 vs 171.4、p25 34.3 vs 65.6 ⇒ 差距全在 tone mapping。此后再不动"补光/测光"方向。
- [2026-10-23] **渲染端 AE 只做两件事：补暗 + 压高光**；中灰交给 HAL（它有场景判断）。三条不做：固定目标闭环（暗场景必爆）、用上一张统计（换场景必错）、在预览链上做第二套 AE（与 HAL 互相激发，室内忽暗忽亮）。
- [2026-10-23] **鲁棒测光不接**（186 样本）：`rob/geo` 中位 +0.16EV、68% 场景更高、散布 −0.60~+0.51 ⇒ 会让画面更暗且更散，不是"更稳"。留在 `aePRobust` 诊断位。
- [2026-10-23] **提亮与保天空饱和在同一条固定曲线上互斥**：C* 随 L* 下降是曲线性质（PC 同样，L* 91 时 C* 2.2）。要两全只能动色彩科学（darktable `preserve_chrominance` 三模式），属独立专项；当前方案 = 用户自调 `baseEv`，全场景一致。
- [2026-10-23] **`applyEngineScope` 是拍照链的兼容策略，编辑器不能复用**：它把公共段 `[20]/[21]/[22]` 归零（切引擎观感不跳），编辑器照搬 ⇒ 相册饱和度旋钮失效。编辑器改用 `applyEngineScopeForEditor`（跳过公共段，filmic 专属槽照旧旁路）。

- [2026-10-23] **bracket 短帧取 −2.6EV（ratio 6），不用 −3EV**：−3EV 虽能把日落天空收进范围，但短帧归一化 ×8 ⇒ 高光区噪点 ×8；−2.6EV 是"天空略好 + 噪点可接受"的平衡点。
- [2026-10-23] **AE 白点固定 4.8EV（≈243 LSB），不用曲线死白点 6.22**：6.22 等于允许 AE 把天空推到无层次区（真机夕阳窗景 8.6% 平顶）。理想白点只该是"还能分辨"的位置。
- [2026-10-24] **不许为单个场景加采集规则**：长帧 +2EV 专为日落楼暗而加，却在阴天（ISO 同样贴底）把长帧推到 41% 饱和。**采集端的规则必须对所有场景安全，否则一律不做**。
- [2026-10-24] **不引入跨张统计**（用户明确否决）：任何"看上一张的 p50/p999 决定这一张"的方案都不做 —— 用户不会停在一个场景里。

## 交付裁剪、删除与 ISZ（10-22 晚）

- [2026-10-22] **删除不做恢复（用户拍板）**：`createTrashRequest` 在 vivo 上直接落成真删（日志 `gone:true` 但系统「最近删除」为空）；系统回收站目录是 MediaProvider 内部实现、第三方不可写。**不自建回收站**，防误删只靠闸门 + 删后核实（`RESULT_OK` ≠ 已删）。
- [2026-10-22] **"保持原分辨率"不做**：PC 的 `Restore digital zoom resolution` = 拍摄记物理尺寸 + 渲染时 Lanczos3 / MGC RAISR / guided upsample 放大回该尺寸，纯插值且**默认关**。我们 2x 成片是 3.4MP 真实像素；补到 12.5MP 只花 4× 存储换 0 信息、同屏观感更软。要真清晰只能多帧超分（另开一期）。
- [2026-10-22] **ISZ 判定：标准版主摄不可达**：MTK tag 支持、remosaic key 全在 `availableCaptureRequestKeys` 且 set 成功，但 RAW 尺寸与 crop 不变；`vsdofFeatureOpticalZoomSets=0` ⇒ 没有任何变焦档位暴露给第三方。不再深挖。
- [2026-10-22] **镜头表按等效焦距去重、物理相机优先**：逻辑相机只是"能自动切镜头"的包装，而 `setZoomEquiv` 自己会物理切；保留逻辑相机会让同焦段在不同会话落到不同 id（zoomRange 0.67–10 vs 0.6–100），行为漂移。

## 测光、AE 架构与 HDR（10-24）

- [2026-10-24] **渲染端 AE 全删，回到 PC 架构（用户拍板）**：曝光 = HAL AE + planner + baseEv + 用户 EV；`g_still_ae_ema` 与 `pe.exposure_ev += ae` 一起删除，`decideAe` 只留诊断。理由：渲染端 AE 是自研的第二套，与 HAL 打架（点测光下把成片补回统一亮度），且跨张 EMA 违反"每张独立"。
- [2026-10-24] **测光三档 + 对焦/测光分离**：系统默认 / 点测（6% 框，PC `SPOT_AE_REGION_FRACTION`）/ 高光优先（PC 的最亮簇 + 16% 框）；`AF_REGIONS` 与 `AE_REGIONS` 分离，点按永远只对焦；长按 = 对焦+曝光一起锁 + 黄框，点按对焦自动解锁。
- [2026-10-24] **测光算法不许自创**（用户明确）：高光优先第一版"固定顶部中央"被否决；正解 = 逐像素/网格找最亮簇（PC `calculateMeteringResults`），点测区域大小也必须用 PC 常量。
- [2026-10-24] **DCP 生态不做，AdobeCurve 降 P2**：DCP 是相机原厂色彩身份、不是胶片 stock；跨相机套 HueSatMap = 二次校正；破坏 D8/D9"基准中性 + 风格 LUT"分工；Adobe camera matching 版权不可随包分发。AdobeCurve 的价值在 hue-preserving + over-range，与 DCP 无关，只作可选实验。
- [2026-10-24] **HDR 曝光融合立项（独立专项）**：采集 0/0/+2.2/−1.5 + Mertens 逐像素融合（`highlightValidity` >0.96 拒绝、deghost 黑白门、census mismatch）；4 帧起步、6 帧封顶，不抄 PC 的 20 帧（它是 YUV 路径、我们是 RAW burst）；开关默认关，关掉必须与 0.12.74 逐字节一致。
