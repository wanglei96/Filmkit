## 基础与平台

- [2026-09-17] **首发 Android、vivo X300 专项 Tier-0** — raw/YUV 对应 Camera2；**全 GPU 路线**（RCD/降噪，CPU 路径删除）；需求基线 v2.0（D1–D13）：爱好者向、「M 档」、DNG 开关默认关、RAW binned 4080×3072、接受预览/成片差异、**基准色彩科学 + 理光 LUT 风格层**
- [2026-09-18] **采集/媒体基础** — 预览走 SurfaceTexture 系统路径；手动对焦默认 10D 试值；镜头按 ID 启停；FILMKIT_*/tools/bin 不入库
- [2026-09-18] **版本与出包** — 远端 `wanglei96/Filmkit` main，附注标签 `v<versionName>`；出包 `filmkit-<versionName>.apk` 单文件覆盖制；**每轮对话只打一个 tag**（本轮又违反一次：打了 6 个，已清理）
- [2026-09-30] **CI 只手动触发**（`workflow_dispatch`，用户拍板）——push 自动构建顶爆 500MB Actions 配额；出包在本地做
- [2026-09-18] **相机 UI 走专项** — PhotonCamera 结构骨架 + DAZZ 胶片质感；**主动审计约定**：UI 改动先按规范+交互清单自查再报用户
- [2026-09-18] **焦段条按发现镜头生成**（X300=15/24/70，等效焦段去重升序）；**变焦画质优先**（到长焦即切镜头，±3% 迟滞）
- [2026-09-19] **参数 A/手动模型** — EV、AE(Tv+ISO)、WB 三组独立默认 A；范围/步进取自 HAL（evInfo）
- [2026-09-19] **手动 WB = HAL 恒 AWB AUTO + 引擎侧补偿**（HAL 三路径 X300 全证伪）；**作用点 = raw 域**（黑阶后 CCM 前、G 归一相乘），预览/YUV/RAW 三链同语义，DNG 不动

## 成像内核

- [2026-09-20] **RCD 单趟三段 fragment 管线** — 研读 PC 结构+论文自写（GPL 不抄码）；质量档 prefs `demosaic_quality` 默认 RCD，bilinear 保留 A/B；**性能取向=中间量预计算全图复用**（12MP 1969→417ms）
- [2026-09-20] **降噪两段式** — P0 RAW 域同色 bilateral + P4 色度平滑（色差域、Y 零损失）；只接 RCD 质量档
- [2026-09-21] **LSC 接在去马赛克后、CCM 前**（网格低频单元≈240px；关闭档绑 1×1 全 1 网格）
- [2026-09-21] **P2 标准色彩链自建** — ColorMatrix/ForwardMatrix 双光源 + Bradford → camera→sRGB；默认开、可 A/B、缺失回退 HAL CCM
- [2026-09-21] **斑马纹只进预览**；**FilmParams 契约按实际长度读取（下限 26）**
- [2026-09-21] **影调/色彩类改动必须自带可关闭 A/B 通路**（无开关致跨时刻无法归因）；**离线调参只在"同一时刻 A/B 对"上成立**
- [2026-09-22] **提亮用线性域曝光不用幂提亮**（三旋钮正交：ev/p/blk）；**自适应影调判据 = 中间调锚定**（职责=提中间调以提色彩，非校正曝光；**提亮上限才是控制量**）；高光软肩 knee 必须与目标白点对齐
- [2026-09-22] **饱和/外观类改动只能用"有边界"手段**；**色度增强判据=亮度相对饱和**；**DNG 对照只定位缺口不当绝对标尺**
- [2026-09-22] **LUT 插在输出 OETF 之后**（display 域）、kFsHist 必须同源；**④ 纹素中心校正废弃**（恒等 LUT 实测与硬件等价）
- [2026-09-22] **不做"理光/徕卡引擎"、不照搬 RawProfile**（PC 8 引擎无理光/徕卡；RawProfile 是未接线代码）

## 色彩链重构与对标

- [2026-09-23] **P4 降噪职责归空间半径**（σc 只保真实色度边缘）；**关降噪也走 P0**（k=0 与 P1 直读数学等价且更快）
- [2026-09-23] **局部色调映射低频图尺寸随渲染分辨率**（固定尺寸致预览/成片提亮尺度差 3.4×）；预览流上限 2160
- [2026-09-23] **MFNR 对彩噪特别有效且让大尺度空间降噪变得不必要**（彩噪跨帧独立；HDR+ 原话 "making aggressive spatial denoising unnecessary"）
- [2026-09-24] **色彩基准**：先定为同机位 PC 成片 → **后改为"色准对标基准 = 实物本身"**（用户拍板），PC 降级为参照
- [2026-09-24] **高光去饱和判据用 max 通道**（旧区间 (0.85,1.30) 实拍从未触发）；改区间前必须反推判据点在真实成片的取值
- [2026-09-24] **方向链路三定案** — `orientationStep`=设备物理旋转步进（**绝不能喂 Display.getRotation()**，语义相反）；成片裁切跟设备姿态、与窗口解耦；相机页不转窗口
- [2026-09-24] **基础影调换哈苏形状 Reinhard 曲线** → 后由 filmic 原生件接管（不复制专有 .hcurve 资产）
- [2026-09-24] **`docs/research/90-…原始转储.txt` 不可删**；**"打包可切换渲染引擎"待办**（filmic / 哈苏式 / AgX）

## 管线定稿与 MFNR

- [2026-09-27] **管线顺序定稿**：多帧融合(Bayer)→黑阶+WB→去拜耳→LSC→高光重建→CCM→局部色调映射(可选)→filmic/AgX→基准曝光+EV→高光滚降→锐化→OETF→3D LUT→颗粒→JPEG；硬约束 LUT 必须 OETF 后
- [2026-09-27] **EV = 单一来源**（`FilmParams[0]=base_ev+用户EV`）+ 撤 HAL AE 补偿；**v0.10.22 更新：EV = filmic 前线性域**（BaselineExposure 语义）；**基准曝光设置项**（±2EV）
- [2026-09-27] **删旧 log 域胶片链与色彩外观层设置项**（域外延展非恒等 = 篡改 filmic 输入）；**ccm_std 保留**；**局部色调映射保留**（去留不再议）
- [2026-09-27] **MFNR 立 P0 优先于 AgX**（用户拍板）；管线加**轻度锐化**层（线性显示域 luma USM、OETF 前）
- [2026-09-27] **MFNR 阶段一三定案** — ① 对齐 tile 直接进阶段一（手持全局位移不成立）② **融合=等权均值**（置信度加权被否定）③ **tile 64 + 每通道网格亚像素双线性**（同相位 4-tap、零色度污染）
- [2026-09-27] **MFNR 设置三档**（mfnr 0/1 自动暗光/2 强制）；**采集 = maxImages 4 + 帧 1-3 拷贝即 close**（maxImages 5+4 全程持有致 HAL 预配 125MB 闪退）
- [2026-09-27] **空间降噪 σ 融合后 ÷√N**；**噪声测量必须用与噪声水平无关的选块判据**
- [2026-09-28] **轻度锐化 = 线性显示域 luma USM**（乘法式零色度污染、邻域 tap 各自过 rolloff 防暗 halo、gain 限幅 ±0.4）
- [2026-09-28] **手部验收标准（用户定义）**：允许自然拖影、不容重叠错误 → 权重分段（m≤0.10 全融合、m≥0.35 硬清零）
- [2026-09-28] **MFNR 运动判据 = 残差 + 位移幅度双判据**；**诊断插桩先于修改**的方法论确立

## C / A 专项

- [2026-09-29] **C 落地 = 逐通道 (A,B) 方差系数 + 强度滑杆即 σ 乘子**（1.0 = 真实 σ；k_p0=s、k_p4=1.5s）；mismatch/tile-RMS 用 k=1；**噪声模型优先级**：用户导入 > 内置实测（型号+焦距）> Camera2 > ISO 估算
- [2026-09-29] **多摄标定方法学**：DNG 水平差分横向比值 × HAL 主摄模型；**设备内自动标定（拍平场向导）用户拍板暂不做**
- [2026-09-30] **A 落地形态**：按 CFA 平面独立合并（HDR+ 语义）、16×16 平面 tile 半重叠 + 修改升余弦窗；位移 tile 中心 round 偶数；c=256；输出 4×RGBA16F image2D（相位组静态分支）；**neff 恒 4**、**不叠 mismatch/conf 权重**
- [2026-09-30] **compute program 现场创建、用完删除**（init 创建的在该 Mali 上写入全丢）；**实验路径严禁进 init 阻塞检查**（失败仅日志 + 运行时回退）；**imageStore 目标纹理一律 `glTexStorage2D`**
- [2026-09-30] **对标口径修正（用户指正）**：PC 对照样片同为 **4 帧** → 加帧数不是追平 PC 的正当路径

## D 专项：收线与性能（09-30）

- [2026-09-30] **降噪分级职责**：P4（半径 3）管 1–3px 彩点；D-1（à trous 5 级）管 4–32px 色斑；**单帧后段空间核路线否决**（两次真机证明保纹理与强降噪不可兼得，0.10.56 起 `uL=0`）
- [2026-09-30] **亮度杠杆在 merge 阶段**：加样本而不加大空间模糊；0.10.58 落地时域×空间联合 P0（4 帧 × 24 同相位邻域 = 96 样本）
- [2026-09-30] **对齐精度定案保留**：最细精化层 = **1/2 域**（HDR+ §4 原版 2×2 平均灰度），真机 5 帧同帧 A/B 全胜（均值 +2.9%），成本整机 +0.1s
- [2026-09-30] **P0 亚像素采样默认开**（用户拍板）：同帧实测 **+43.7% / +46.5%**、纹理无损失、dnMs 未见上升
- [2026-09-30] **两个杠杆必须一起看**：整数采样把 0.27px 与 4px 的差别抹平——只换层 +2.5%，加上亚像素才 +45%；任何"提高对齐精度"的改动都要同时确认采样没把它吃掉
- [2026-09-30] **D-2 收线**（用户拍板）：颗粒 = 胶片感，是风格不是缺陷；**降噪对标 PC 暂缓**，归到成品 app 优化阶段
- [2026-09-30] **性能收口优先于运动补偿**（用户拍板）：参考帧已是最短曝光帧（"回最锐帧"待办实际已满足）；NS §3.3 的价值随"颗粒=风格"下降
- [2026-09-30] **在飞上限 2 张**（1 渲染 + 1 排队），第 3 张记 `capture.busy` 并忽略
- [2026-09-30] **拍照独立线程/context 重做必须带开关（默认关）**：0.10.83 那次失败丢了用户的照片（只留 DNG）并闪退——架构改动不能以照片为代价

## 拍照线程与内存（10-01）

- [2026-10-01] **拍照侧实例「只启动不销毁」**：0.10.83 的根因是 stop 时旧线程仍在跑合成、新线程复用同一实例；本版取消整条销毁路径（线程 + context + 实例常驻），从根上消除竞态
- [2026-10-01] **空闲释放要连 context 一起销毁**：只销毁 FrameRenderer（保留 context）会让 Mali 在建/销后分配不出全分辨率纹理（`raw.upload_failed`）；整条重建才与"首次启动"同构（首次 59ms / 重建 67~98ms，代价相同）
- [2026-10-01] **进程级设置必须能被后建实例补齐**：LUT / YUV 矩阵走进程快照，在 `nativeStillStart` 与 `nativeEngineStart` 里下发——否则独立线程拍出的照片会静默丢风格层（画质红线）
- [2026-10-01] **largeHeap 作为连拍内存兜底**：MFNR 每张在飞持 4 帧 direct buffer（100MB），而 `ByteBuffer.allocateDirect` 走 `trackExternalAllocation` **计入 ART 的 OOM 额度**；在飞 2 张 200MB + 成片回传 50MB 撞默认 256MB
- [2026-10-01] **OOM 时「这张失败」优于「进程 abort」**：JNI 回传加 `ExceptionCheck` 防护 + 失败自愈重试一次，仍失败才回退预览线程（用户红线：失败不以丢照片为代价）
- [2026-10-01] **调度类优化在本平台不再投入**：DFT 分片 / glFlush / 真 sleep / 线程降优先级四种手段实测**全部无效**（Mali 不在 context 间轮转），sleep 还拉长卡顿窗口 → 帧率定性为 GPU 算力·带宽硬约束，改走"用现成开关定位主因，再按主因优化或降预览负载"

## LUT 资产互通与预览降载（10-01）

- [2026-10-01] **LUT 无损口径（对照 PC）**：.cube float 解析不重采样不量化、DOMAIN 原样保留（shader 按 dmin/dinv 归一）、原文件字节存档；PC 的 >65→33 重采样是有损点不学；唯一妥协 = 超引擎上限（Hald L12=144³）三线性重采样到 128³
- [2026-10-01] **预览降载落点 = 引擎中间纹理**（非 Camera2 流）：帧级切换无需重建 session；16F 无线性过滤 → 输出 pass 渲到小尺寸 RGBA8（OETF 后）再 blitFramebuffer(GL_LINEAR)；成片链零改动
- [2026-10-01] **单帧 RAW/YUV 迁独立线程用 buffer 语义**（拷贝后 close Image）——回退重放的前提；nativeStillStart 必须补齐 YUV 矩阵快照（曾漏，BT.709 被按 601 解码）
- [2026-10-01] **LUT 强度滑杆 = 相对拖动**（按下不跳、增量累加）：M3 Slider 按下即 snap，拇指微调必误跳；专业相机 App 标准交互
- [2026-10-01] **拖动中不写 prefs**：setLutStrength 直通渲染线程写 filmParams[34]，prefs 只在松手写一次；lutStrengthFromPrefs 哨兵防每帧同步拉回直通值
- [2026-10-01] **用户 LUT 存档原文件**（字节级，导出可取回原样）；id 加 u_ 前缀防与内置冲突

## NN 路线与集成（10-02，已判死）

- [2026-10-02] **中频归因与集成形态**：P0 空间核在合焦布纹上净 4px 损失 ≈0；MFNR 融合无损中频；锐化只盖 1–3px；强度滑杆不是纹理杠杆；失焦只衰减信号不衰减噪声。集成 = Java TFLite + JNI 逐 tile 回调 + NnInfer 常驻线程；MFNR+单帧都接；任何失败**整张回退 P0**（照片优先）；NN 开 = P0 空域降噪被替代
- [2026-10-02] **cvt_k 定案（推翻 0.10.104 的 S_anchor/S_iso + 本机 anchor）**：`inp = img01 × cvt_k × 256`，`cvt_k = S_train·neff/S_input`。S_train = 官方 K(1600)/V = **1.0093e-3**（img01 域，**训练数据的噪声水平**；用本机 S(ISO1600)=4.5e-4 会让输入噪声只剩 1/2.24）；**× neff 必须**（NN 输入是 tex_fused_、方差已 ÷4；P0/P4 早已 ÷neff，唯独 NN pass 漏了）—— 两层合计差 ~9×，是"细节全糊"的根因。通道序 = 官方语义 **(R,Gr,Gb,B)**（bggr2rggb 的 rot180 只是"把 BGGR 摆成 RGGB"的手段，等价于不翻转、按语义取相位）。真机 nnGain 181.9→963/1018/1073 全与公式吻合
- [2026-10-02] **判死：跨域模型不可直接用 + 微调需数据量 → 转 HDR+**：口径全修对后真机观感仍无改善（文字区强边缘占比 -36%、梯度 -24%、平坦区斑块状伪影而非白噪），**不如 P0**；根因 = PMRID 官方权重在 SIDD 上训练、与 X300 域不匹配。四次微调（监督×3 + Noise2Noise）留出集**全部过拟合**（+12.0/+9.9/+11.7/+5.06%），官方 3 万+ 对 vs 我们 4 场景差 3~4 个数量级。下一步转 HDR+ bracketing（后处理造不出被噪声淹没的信息，FX 的 +3.6EV 属采集端差距）
