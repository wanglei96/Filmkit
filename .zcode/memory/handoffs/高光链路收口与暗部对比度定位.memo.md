# 高光链路收口与暗部对比度定位

## Summary

0.12.4→0.12.33 把"自动局部压高光"这条自创链路按"压深放对 EV 分区"重做，删掉四轮迭代堆起来的事后开关；顺手定位并修掉相册闪退（ThumbCache 并发）。高光侧全部场景真机通过。暗部"发灰/发亮"最终查明是**局部对比度低**（不是亮度），来源未定，用户决定留到预设里调。

## Done

- **高光压深放对分区**（核心）：9 档曲线第 i 档对应 q=i−8。云/镜面反光 q≈−0.5（白点档）、天空主体 q≈−2.0（第 6 档）。旧版把压深放第 8 档 ⇒ 云被压 2.2EV 成乌云、天空只拿 +0.06 顶死成灰白。现 `curve[6] += hl`、`curve[7] = hl*0.30`、`curve[8] = 0`。
- **删掉三层 wTop 事后开关**（v0.12.13/17/19）：它们都在补上面的错位，每补一次弄坏另一类高光（反光点→绿植背景→白云）。
- **高光只压超出白点的部分**：旧式普通场景 `-0.60-0.50*t` 不管超没超白点先压 0.6EV ⇒ 室外有天空就整体偏暗（成片 p95 199 vs rawpy 243）。现 `hl = -max(0, p95_rel_white)`。
- **判据改用 AE 之后**的 P95（域错位）：`ae_p95_` 是融合后 AE 前的值，而 teq 作用在 `exposure_ev += ae` 之后。同一天空三张（2456 正好/2426 偏淡/4609 偏灰）验证：提亮前都在 1.8EV，提亮后 1.76/3.23/3.51。尾部比值门 1.5→2.2。
- **去掉暗部无条件的 +0.30**：`sh = 0.30+0.55*t` → `sh = 0.55*t`（与高光同型毛病）。
- **sat-fix 进入条件 0.98→0.94**（与它内部的软过渡起点对齐）：0.94~0.98 的像素原本根本不进分支（保持 0.878），而 ≥0.98 的按 w 注入短帧真值（≈3.6）⇒ 相邻差 2EV。真机 RAW 实测：过曝块内 94.8% 饱和但 **p5=0.878**，灰块就在亮区内部。
- **sat-fix 的 sVal 改连续插值**：`smoothstep(0.95,1.0,s/wl)` 在 sNorm 与保守值之间插值，替掉 `no_info ? 保守值 : sNorm` 的 1 LSB 硬跳。
- **HL 的 allSat 亮度锚用实测 luma**：原式 `lc=luma(满阱)` 是与场景无关的常数 1.237，把 sat-fix 救回的真值又压回 1.237。改 `lv=luma(Rv,Gv,Bv)`。
- **MFNR 频域合并修好并转默认开**：`const float cs2_base = uC*sig2` 非法（uniform 不是常量表达式）⇒ 整个 shader 编译失败、一直静默走空域。去掉 const 后首次真正跑起来。
- **相册闪退根因 = ThumbCache 并发**：`LinkedHashMap(accessOrder=true)` 连 `get` 都改结构，而 `put` 的淘汰循环持有 `entries.iterator()`。相册并发加载缩略图 ⇒ `NoSuchElementException`（真机两次，主线程）。全部方法 `@Synchronized`。
- **native 崩溃取证**：`sigaction(SIGSEGV/ABRT/BUS/ILL/FPE)` + async-signal-safe 的 `open/write` 写 `<logs>/native-crash.txt`（信号号+故障地址）。不取堆栈：NDK 没有 `execinfo.h`，`_Unwind_Backtrace` 不是 async-signal-safe。
- **诊断字段补齐**：`raw.render` 增 `lt`（local_tone 实际值）、`baseEv`（基础曝光补偿，全局设置默认 0.7，此前日志完全不可见）。

## Decisions

- **sigmoid contrast 保持 1.5**（tag `contrast1.5`）。两次想调到 1.7/1.8 补暗部对比度，均回退：实测副作用白纸 218.84→226.52（+7.7 LSB）而 PC 白纸 219.24，且 +4EV 247.4→250.4 高光更早 clip；中灰恒 119.01 不动 ⇒ 只有高光端受损。**用户决定不在引擎改，留到预设里调对比度**。
- **频域合并默认开**：此前注释写"净损失、勿开"是**片面的**（只量了噪声没量细节）。噪声确实高（亮部 σ 5.99 vs 3.05），但用户实拍确认**细节明显更好**。按"质量优先"取细节。
- **teq 的职责边界**：它只做"按 AE 的取舍做局部分区补偿"，不承担"塑造对比感"。暗部/整体对比度该由曲线负责。
- **`local_tone` 是标定旋钮不是 bug**：设置页开关移除是**有意设计**（预设/编辑器可外推，如 0.475），默认 0.25 必须保留（`Stage3EngineScopeAuditTest` 有断言）。曾把三处默认改 0，被单测抓出后全部回退。

## Pitfalls

- **`脚本 | tail -2 && build` 会吞掉脚本退出码**：`tail` 成功即 `&&` 放行。0.12.20 的黑屏就是这么漏出去的（`validate-shaders.sh` 明明报了"禁止发版"）。改用 `脚本 > log 2>&1; RC=$?`。
- **替换注释段时误删代码**：0.12.20 换 teq 注释时把夹在两段注释中间的 `float g = curveAt(q);` 一起清掉了 ⇒ shader 编译失败 ⇒ 预览黑屏。换注释必须用"只删注释行"的方式，不能按起止锚点整段切片。
- **全图分位 ≠ 同区域对比**：拿 p1/p5 比两张图，得出"暗部差 2EV"的结论是**假象**（各自最暗 1% 不是同一个东西）。同区域实测只差 0.1~0.3EV。**跨图比较必须同区域**。
- **测试是设计意图的文档**：`local_tone` 那条断言（"默认值必须仍是 0.25（标定旋钮）"）比任何注释都直接。改默认值前先搜测试。
- **"参数相同"不等于"输出相同"**：核对 PC 源码后确认两边 sigmoid 参数逐位相同（0.3544/0.00143/1.5 vs 0.3597/0.00138/1.491），但 PC 的局部对比度仍高 6.5 个百分点 ⇒ 差异在链路别处（demosaic/锐化），不在曲线。
- **别问日志里已有的信息**：`base_ev`、`local_tone` 这类值此前不在日志里，导致反复推断；补齐字段比来回问用户快。
- **`git checkout HEAD~1 -- <files>` 用于回退错误改动**，比手改更可靠（尤其多文件同时改错）。

## Next

- **暗部局部对比度**（未定论）：同区域相对局部对比度 rawpy 单帧 19.4% / 我们 17.6% / **PC 25.9%**。我们只比"完全不处理"低 1.8 个百分点（降噪/融合不是主因），**PC 反而高出 6.5 个点** ⇒ 它在链路里增加了细节。候选：去马赛克档（我们 RCD，PC 为 AMaZE 系）。**验证方法**：设置 → 画质 → 去马赛克切非 RCD 档，同场景拍，量对比度是否上来。
- **天空复验**（等晴天）：`allSat` 改实测 luma 后天空同属"大面积饱和"，需确认没被带偏。判据：天空蓝 + `hlGRecon 1` + `teqHl -2.2` + `hi240 ≤ 0.5%`。
- **PC HEIC HDR 是死链**（审查发现，未修）：`passGainmap` 只在 `!c.ten_bit` 时跑，而 HEIF 档恒 `ten_bit=true` ⇒ HEIC 永远拿不到本帧 gainmap；若此前拍过 JPEG-HDR 会读到上一张的（stale）。C++ 注释"HEIC 走平台 HeifWriter"与 Kotlin 用法矛盾。
