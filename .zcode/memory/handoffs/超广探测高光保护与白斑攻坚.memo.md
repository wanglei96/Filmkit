# 超广探测高光保护与白斑攻坚

## Summary

从"超广畸变先做能力探测"出发，AOSP 一手取证 + exp7 真机把 HAL 路线**彻底关闭**（RAW 规范上
永不校正，且 X300 连 YUV 都不校正、无标定、无 pre-correction 区）；转而在曝光专项上做出
**高光保护**（exp8：曝光目标改"刚好不烧高光"，欠曝量由成片 EV 补偿，真机 clipB 890→163）。
期间修掉一个**严重回归**：横拍成片被裁成竖幅（丢 44% 画面，根因是画幅比例没做快门瞬间快照）。
随后用户目视指出**红杯釉面密集白斑**，为此连续五轮定位（exp9~exp12）——排除了脉冲尖峰/坏点、
锐化过冲、色度噪声、真实纹理四类假设，确认是**亮区噪声**（1~2.3σ、两帧 IoU=0）；并在用户
三次严厉纠正（"老想打补丁""跟降噪没关系，看曝光策略""跟帧数有屁关系"）下把**曝光判据的域
错位**（预览 OES vs RAW 归一化域，差 0.58EV 且逐次不同）改掉，默认回到**曝光给足**。
影调层同步收敛：4 个互相干扰的白点旋钮 → 0 个（标准模式唯一，固定 darktable 默认 −8/+4）。
**白斑尚未确认解决**，等 exp12 真机复验。

## Done

- **超广畸变能力探测（exp7 / 05f865f）**：AOSP 原文取证 `DISTORTION_CORRECTION_MODE`
  —— *"The correction only applies to processed outputs such as YUV, Y8, JPEG, or DEPTH16;
  it is **not applied to any RAW output**"* + *"on by default on devices that support"*。
  真机（4 次会话 × 2 个 cameraId）：`distModes:"none"`、`lensDistortion:"0.001,0,0,0,0"`
  （AOSP 占位值）、`preCorr == active`（4080×3072 / 4080×3060）、`intrinsic` fx=2790.18（主摄）
  / 2414.06（超广）。**结论：HAL 路线全关（连 YUV 也不校正），必须 GPU 自标定 + 自校正**；
  裁边与否完全由我们自己决定。写入 `docs/x300-能力审计.md` §4。
- **高光保护（exp8 / 64a5ff2）**：`ExposurePlanner` 加第 4 项约束（高光保护，**n 可 < 1**）
  + 3 项单测；欠曝量由成片 EV 补偿（`filmParamsForStill()`）——只欠曝不补偿 = 把"高光爆"
  换成"画面暗"。真机：`hlUnder 0.85`、`altSec 0.0100→0.0055`（只缩曝光不抬 ISO）、
  **`clipB` 890→163**、降噪 P90 从 0.3% 改善到 7.9%/13.4%。
- **横拍被裁成竖幅修复（exp8 / e65b1fb）**：根因 = `captureAspect` 是实时状态，而 MFNR
  渲染要 3~4s，用户拍完立刻把手机转回竖屏 ⇒ 裁切按竖版 3:4 执行（真机日志
  `photo.crop srcA:1.328 dstA:0.750 out:2304x3072`）。修复 = **快门瞬间快照**
  `stillRot/stillAspect` + 按姿态定向（不依赖 Compose 的 `LaunchedEffect` 异步）+ 渲染、
  DNG 的 EXIF 方向、A-B 路径全部改用快照。真机复验：横拍 4080×3072、无 `photo.crop` ✓
- **影调层收敛（exp10/11 / 03be158、6424446）**：4 个互相干扰的白点旋钮（自适应影调 /
  高光自适应白点 / 白点下限边距 / 白点上探幅度）→ 收成 1 个开关 → 最终**撤掉开关**（标准
  模式成为唯一行为），固定 darktable 出厂默认黑白点 **−8 / +4 EV**（一手出处
  `docs/research/01-darktable.md`）。
- **曝光判据域修正（exp12 / 3557324）**：引擎加 `stillW999()`（**只有成片链写入**的 P99.9，
  RAW 归一化域），Bridge 暴露 `sw999`；判据从预览域 `w999` 改为 `sw999`；默认
  **曝光给足**（`hl_protect` 默认 0）；余量 0.35→0.1。
- **白斑定量（未解决）**：红杯釉面密集白点，显示域幅度 **15~56 级**、**两帧 IoU = 0**
  （随机）；白斑 RGB (211,171,168) vs 周围 (114,65,41)，通道增量 R+66% / G+126% / **B+229%**。
  排除四类假设（见 Pitfalls）。弱相关：HR 关 −40%、`dn` 0→0.45 −40%。

## Decisions

- [2026-10-03] **曝光目标 = "刚好不烧高光"（HDR+ §4 原文），但用户优先噪声 ⇒ 默认曝光给足**：
  实测该场景渲染域高光 3.02 > 白点 2.438 达 **0.58EV**，"曝光给足"与"高光不爆"**物理上
  不可兼得**（不欠曝时 `clipB` 803 = 26% 的块命中裁剪）。用户拍板方向：先压噪声，高光交给
  影调层（固定曲线肩部 + 高光重建）。
- [2026-10-03] **判据的域必须与物理过程一致**：预览链走 OES（ISP 已 tonemap），与 RAW
  归一化域**不是一个尺度**——同场景实测预览 `w999` 2.09 / 成片 2.674，差 0.58EV 且逐次不同。
  用错位的量做判据，结果必然既不准也不稳。
- [2026-10-03] **不为 0.1% 的饱和像素牺牲全图**：`w999` 是 P99.9，那 0.1% 基本就是窗/灯。
  为它们欠曝 0.35~0.85EV ⇒ 全图光子 −25%~45% ⇒ 相对噪声（1/√N）上升 ⇒ 中高亮表面冒白斑。
- [2026-10-03] **影调层固定、曝光层自适应**（标准做法）：darktable filmic / AgX / ACES 的
  影调映射都是**一套固定参数**，场景差异由曝光吸收。我们把这件事做反了（曝光固定、影调疯狂
  自适应），这正是设置爆炸与"修一个坏一个"的根源。
- [2026-10-03] **横拍方向与画幅必须快门瞬间快照**：渲染 3~4s，用户按完快门就会转手机；
  凡"拍照时刻的状态"被数秒后的链路读取，一律快照（项目既有教训同型）。
- [2026-10-03] **超广畸变只能自校正**（HAL 无能力、无标定）；裁边取舍待用户拍板：
  完整校正（视场窄 5~10%）/ 部分校正（残差与裁边同比降）/ 不校正。

## Pitfalls

- **判据域错位**（预览 OES vs RAW 归一化域）：这是我连续两轮定位失败的根源，也是白斑判据
  一直不 work 的原因。**任何"统计→判据"链路必须先核对统计域与作用域**。
- **代价与收益不成比例**：为 0.1% 的像素（且是"爆了也不可惜"的窗/灯）让全图欠曝。
- **设置项爆炸是"每场景加旋钮"的必然结果**：4 个白点旋钮互相干扰，每个都为修某个场景而加
  （白壶案 → 上探；红杯案 → 下限），最终"修一个坏一个"。**根因不是旋钮不够，是分工错了**。
- **命名撞车**：我新加的「基础影调」与既有「基准影调」（`base_tone`）名字撞车，设置页出现
  两个影调开关——**加 UI 项前必须先 grep 同类标题**。
- **排除法要排除干净再下结论**：白斑先后被误判为"脉冲尖峰/缺 DPC"（实际 RAW 域两帧位置
  重合仅 0.5%，那 1.1 万个"异常"是饱和/边缘像素被全局 σ 判据误判）与"白点过高"（exp9
  改动确实生效：`whiteEv` 3.876→2.893，但白斑没退）。**改动生效 ≠ 问题解决，两者必须分别验证**。
- **用户三次方向纠正都是对的**：① "从曝光策略解决，别老打补丁"；② "跟降噪没关系，看曝光
  策略 / 自动白点"；③ "跟帧数有屁关系"。三次我都先按自己的假设做了包，才回头验证用户的判断。

## Next

1. **exp12 真机复验（用户手上）**：默认曝光给足下拍同场景 —— 白斑**减少** ⇒ 确认根因是
   "欠曝导致光子不足"；**没变** ⇒ 转查去马赛克在红色高饱和区（R 高、G/B 极低）的色度行为。
2. **超广畸变自校正**：方案待拍板（完整 / 部分 / 不校正），实现走引擎 GPU pass（去马赛克前、
   逐 CFA 平面反向映射保相位）；`intrinsic` 的 fx 可作归一化半径起点，畸变系数需自拟合
   （直线约束或棋盘格）。
3. **固定影调的观感验收**（−8/+4 一套参数走所有场景）：亮场 / 暗场 / 光影三个场景各一张，
   确认暗部能沉、高光不闷。
