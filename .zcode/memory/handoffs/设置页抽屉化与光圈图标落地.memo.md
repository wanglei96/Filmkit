# 设置页抽屉化与光圈图标落地

## Summary

设置页 35 项平铺整理为 4 个抽屉 + 拍摄高频项,删除 NN/YUV709 死入口;应用图标经 5 版迭代
定为**光圈叶片+居中镜片 vector**(G 款),期间踩遍 adaptive 图标渲染坑后确立 **PC 同构完整

## Decisions

- [2026-10-04] 设置页信息架构:已定案的 A/B 开关归"实验与诊断"抽屉,用户可感知项归功能组;
  主页只留拍摄高频项 + 抽屉导航 + 系统
- [2026-10-04] 应用图标定稿 = G 款光圈 vector;资源结构 = PC/微信同构完整套,
  任何一层缺失都会在真机触发异常渲染
- [2026-10-04] 编辑器与预设**一体做**:同一参数源(FilmParams schema),编辑器 = 预设编辑界面,
  拍摄 = 预设实时应用;DNG 底片保留 = 编辑器自由度上限(架构分级先定)
- [2026-10-04] 顺序:品红/斑块修复 → 编辑器 E1–E3 → E4 胶片参数(halation 复用品红的高光提取设施)
- [2026-10-04] 每轮对话只打一个 tag 之执行:本轮仅 v0.10.133

## Pitfalls

- **adaptive 图标前景用 bitmap(PNG)会被某桌面非等比渲染**(三版 88%/72%/61% 全部复现"又小
  又扁");**纯 legacy 会被垫白色圆托**;换 **vector 前景后正常**——桌面对 vector 与 bitmap
  走不同渲染路径
- **照抄成熟 App 的资源结构**优于对黑盒机制试错:解包 PC 的 res/ 对比后才发现自己只给了
  "半套"资源(缺 legacy 并存 / 缺 monochrome / 前景类型不同)
- Compose M3 ModalBottomSheet 真机返回键语义不可靠(两次才关);自绘浮层 + BackHandler 是本项目
  规范的做法(拦截层先绘制 + FilmMotion 出入场)
- 删除设置项必须**同步锁死读取端**(prefs 历史值可能残留 true,如 nn_dn/yuv_709)
- AI 生成的参考图上带"豆包 AI 生成"水印,用作产品图标前必须去除
