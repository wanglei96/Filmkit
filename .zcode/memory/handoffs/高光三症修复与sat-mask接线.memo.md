# 高光三症修复与sat-mask接线

## Summary

10-29 晚到 10-30 上午（0.12.168→192）：把"天空品红 / 灯面方形色块与色斑 / 窗台方块亮斑"三症
逐个定案修掉，并把记忆里 Next #1 的**独立饱和掩码**（参考帧 RAW → 满阱−3σ → 1px 膨胀 →
2×2 聚合 → R8/RGBA8）落地、接到 P0/P4/PC3D。**但掩码至今 `satmHit=0`（判据零命中）**，
三处消费者等于没接，灰斑（粉蘑菇/空调管）未受任何影响；品红在 0.12.192 仍"没有完全修掉"。

## Done

- **[2026-10-29] 天空品红（0.12.179）**：根因 = 0.12.170 把 `refavg`/chroma 除以逐通道满阱，
  破坏 opposed 的立论前提（三通道满阱相同 ⇒ 中性白三通道相等）。WB 域中性白是 1,1,1，
  `raw/1023` 域是 0.476/1.0/0.684 ⇒ refavg_G 只剩 0.57，`MAX(1.0, 0.57)` **永不抬 G**。
  165153.dng 逐 photosite：G 饱和像素 WB 域中位 R 1.300 / G 1.000 / B 1.139（R/G 1.30、
  B/G 1.14 = 品红），参考场 0.944/1.036。回 WB 域 + 中性饱和核按"参考比 × 实测 luma"
  三通道同步重建 ⇒ 落在 0.944/1.036。真机 17:14 用户确认"品红修复了"。
- **[2026-10-29] 窗台方块亮斑（0.12.180）**：179 的 `nsat≥1` 判据太松，块内一两个
  photosite 饱和就整块改写，luma 锚含饱和 G ⇒ 整块 16×16 px 提亮，硬边方块。
  加面积门控 `satFrac = 1 − refRatiosW().z`，smoothstep(0.55,0.85)。
- **[2026-10-29] 灯面方形色块 + 大面积色斑（0.12.183）**：灯面中心 nsat≥2（中性白 1.266）、
  边缘 R/B 落 0.90~0.98 满阱被判成 nsat==1（refavg 把 G 抬到 1.76）⇒ 0.5 亮度台阶；
  `wAreaN` 混合把台阶摊成色斑。容差 0.99→0.90；**nsat≥2 无条件中性白、不做面积混合**。
  真机确认"灯已修复"。
- **[2026-10-29] 0.12.172-177 全部删除**（dump / gamut-sRGB / alpha-mask 实验），回到
  171 基线；gamut_check 回工作空间域。
- **[2026-10-29] sat mask 0.12.181→191**：GPU 版（kFsSatMask + FBO）在 X300 上"program/
  纹理/FBO 全就绪、强制输出 1.0 后读回仍 0"⇒ 改 CPU 生成（25MB 参考帧副本 + 逐 photosite
  判据 + 1px 膨胀 + 2×2 聚合 → RGBA8 上传）。P0（fused + Ts）、P4、PC3D 三处接线；
  D4 几何的掩码按 `kVertRot` 映射在 CPU 转置一次（rot 0/1/2/3 逐字对应）。
- **[2026-10-30] 品红回归（0.12.190→192）**：190 用"参考场偏粉"关掉 G 抬升（治绿边），
  但背景虚化高光点局部 32 块全饱和 ⇒ `refRatiosW` 退到**全图池化比**（hlRgG 1.108）⇒
  被误判偏粉 ⇒ 中性高光留成品红。192 改为**只在局部参考可信（rrH.z > 0.30）时门控**。

## Decisions

- **opposed 必须在 WB 域**（中性白 = 1,1,1）；"逐通道满阱归一化"（raw/1023 域）不满足
  opposed 前提，是本轮天空品红的唯一根因。revavg / chroma 统计 / 判据三者必须同域。
- **中性饱和核按饱和通道数分流**：nsat==1 → 参考比（彩色高光，天空/云）；nsat≥2 →
  中性白 × 实测 luma（色度不可知，灯面）。两条路径的亮度锚必须一致，否则出方块台阶。
- **参考比门控只在局部可信时生效**：全图池化比不能用来判断单个高光点是否"偏色"。
- **chroma 补偿保持停用**（0.12.171 结论不变）：WB 域复算会把粉云 G 顶到 1.55（R/G 0.84
  偏绿），真实缺口只有 0.08 —— 量级不对，不是"调小"能救的。
- **sat mask 走 CPU**：GPU 侧不可诊断（强制 1.0 也读回 0），且 mask 是数据变换、不含画质
  算法；25MB 副本 + ~200ms 在拍照 5s 内可接受。

## Pitfalls

- **"强制输出 1.0 也读回 0"是决定性诊断**：它把"判据错"与"绘制链路坏"分开。R8 作颜色
  附件在 X300 上"FBO 完整但不落值"，换 RGBA8 也没救 ⇒ 最终改 CPU。
- **尺寸域错配会静默吞掉整个 pass**：`passSatMask(w,h)` 传的是 dst 尺寸（旋转后 3072×4080），
  而 raw 副本/纹理是 4080×3072 ⇒ 函数第一行早退，`satmCov` 恒 0。竖拍必现、横拍偶发。
- **诊断字段自己会撒谎**：`satmP/satmTx/satmPrg` 全 1 只证明"变量被赋值"，不证明 mask 有值；
  `satmRaw=1` 只证明尺寸变量非 0，不证明副本内容非空。要判内容必须打命中数（satmHit）。
- **全图统计不能代替局部判断**：hlRgG/hlBgG 是整张场景的池化比，用在单个高光点上必然误伤。
- 0.12.181 的 PC3D shader 写成 `uSatMaskOn > 0.5`（int 比 float）⇒ 编译失败 ⇒ `pc3dOn=0`
  整条色度链回退，灯面**看起来像色块**。GLSL 报错只在 `render.shader_error` 里。
