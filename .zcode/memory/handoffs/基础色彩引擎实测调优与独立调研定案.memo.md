# 基础色彩引擎实测调优与独立调研定案

## Summary

本窗口从"用户对 LUT 效果不满意"出发，一路查到根因在**基础引擎**而非 LUT：真机实拍显示我们的无 LUT 成片对比 68.4 / 黑位 13.1 / C\* 4.14，而厂商同场景直出是 89.2 / 2.1 / 5.96。据此完成 12 个版本迭代（v0.6.9→v0.6.20），把 `baseTone` 的三个旋钮**正交化**（ev 管亮度 / p 管对比 / blk 管黑位）、加了**自适应影调**与**高光软肩滚降**，并顺带完成 42 个 LUT 资产的中文化与分类、Material3 暗色主题修复。窗口末尾又启动一轮**不受既有结论干扰的独立调研**，拿到 PhotonCamera 与多个开源项目的一手源码证据，定案：基础引擎还缺 **sRGB 分段 OETF**、**有边界的色度增强**、**区域加权 AE 与切镜头重置**三项，LUT 插桩位置（display 域、OETF 之后）**已确认正确**。

## Done

- **LUT 资产扩充（v0.6.9–v0.6.13-m4）**：6 个 .cube → **42 个 uint8 二进制 `.lut`**（`~/Downloads/LUT/滤镜.cube/` 的 64³ 源重采样到 33³，4.3MB；ASCII 要 40MB）；`LutLibrary` 改为**扫目录**不再硬编码；中文显示名 + 品牌分类写进资产头（格式扩为 `[size][titleLen][title][catLen][category][data]`）；分类可新建/删除（长按 pill 删除带二次确认，长按卡片归类）；强度上限 100%→**150%**
- **Material3 暗色主题（v0.6.11-m4）**：根因是 `MainActivity` 里一个**空的 `MaterialTheme {}`**，所有 M3 组件（AlertDialog/OutlinedTextField）吃默认浅色方案；给 `FilmTheme` 加 `colorScheme()` 并在根部传入，顺带统一 Button/Switch/FilterChip/Divider 与两个对话框的圆角字体
- **baseTone 旋钮正交化（v0.6.17-m4）**：删掉 `g` 幂提亮（它是**降对比**的旋钮），提亮改用**线性域曝光** `x*exp2(ev)`；离线（真机成片反推）验证 `ev+0.35 p1.60` 得对比 93.1 / 黑位 1.9，对齐厂商直出
- **自适应影调 + 高光滚降（v0.6.18-m4）**：新增 `histogramFrom(src,…)` + `updateAutoGain`——按**场景纹理**显示域直方图 **P95** 算线性增益（限幅 [1,4]×，只提亮不压暗，EMA 平滑），统计放在 `passFilm` 内使预览/YUV 静拍/RAW 静拍三条路径共用；`kFsOut.highlightRolloff` 把 `clamp` 换成**指数软肩 + 去饱和**；设置页加「自适应影调」开关（默认开，`FilmParams[35]`）
- **高光层次 / 噪点 / 饱和度修正（v0.6.19-m4）**：`knee` 与增益目标对齐（0.75→0.80，之前让"正常亮部"也落进压缩区）、曲线换 `t/(1+t)`→`1-exp(-u)`（l=1.0 处斜率 0.25→0.37）；P4 色度降噪 `2.60/2.20→3.25/2.75`（提亮 1.1EV 使色度 σ +84%）；`look_chroma` 1.0→1.25
- **取证包（v0.6.20-m4）**：`raw.calib` 按 **cameraId** 各记一条 + 加 `cameraId` 字段，`raw.meta` 加 `lens` 字段——此前整个会话只记一条且不带镜头号，无法判断主摄/长焦矩阵是否相同
- **独立调研（4 路并行 + ISP 补跑）**：PhotonCamera 管线逐文件核实、LUT 域与资产逐点比对、darktable/RawTherapee/Blender AgX/ACES/libplacebo/filmulator 对照、ISP 标准链与 AE/MFNR 一手论文（HDR+ / Night Sight / BT.2408-7 / libcamera）。报告落盘 `docs/research/`（11 份）
- **仓库工作**：三次分领域提交并推送成功（`d630994` / `6efc516` / `0050853`）；清理 184MB 第三方克隆 `filmulator-gui/`；调研文档从被 gitignore 的 `handoff/` 移到 `docs/research/`

## Decisions

- [2026-09-22] **提亮用线性域曝光，不用幂** — `pow(x,g)` 是"抬暗部"（降对比）的旋钮，`x*exp2(ev)` 才是亮度旋钮。三个旋钮至此正交：`ev` 亮度 / `p` 对比 / `blk` 黑位。学习自 PhotonCamera 的 `exposureCompensationDomain=Linear`
- [2026-09-22] **自适应影调默认开、可关**（`FilmParams[35]`）— 真机三场景白点（显示域 P95）普遍偏低，暗场景要 +1.2EV、亮场景只能承受 +0.3EV，**差 4 倍**，固定补偿无解；开启后输出与场景绝对亮度解耦（合成压力测试 x×1.0/1.5/2.0 下 L\* 恒定、clip 0%）
- [2026-09-22] **白点取 P95 而非 P90/P99** — P90 会把增益打满上限 4.0×（过亮），P99 被小面积高光骗（书桌笔记本屏幕 → 只给 1.15×，桌面仍暗）
- [2026-09-22] **高光软肩的 knee 必须与增益目标对齐** — knee 低于目标白点等于让"正常亮部"也进压缩区（v0.6.18 就是这么把 L\*75–85 段的梯度从 4.00 压到 0.00 的）
- [2026-09-22] **饱和/外观类改动只能用"有边界"的手段** — `look_sat`（全局乘性增益）保持 1.0；v0.6.14 用 1.5× 补 C\* 时把白平衡残余暖偏同比放大（白墙 b\* +1.63→+2.31），是**放大器不分该放大的色和该保留的误差**
- [2026-09-22] **LUT 插桩位置（display 域、输出 OETF 之后）确认正确** — 本轮调研独立核实 PhotonCamera 的两条链路（预览 `LutRenderer` / 成片 `LutImageProcessor`）都在**非线性 sRGB 显示域**，且其 `.plut`/`.cube` 的 curve 默认 SRGB、gamut 默认 SRGB，入口变换链**恒等抵消**
- [2026-09-22] **不做"理光/徕卡引擎"，也不照搬 `RawProfile`** — PhotonCamera 的 8 个引擎里没有理光/徕卡（徕卡只是 Lumix 的一个 PhotoStyle）；它的 `RawProfile`（色彩空间+log+基线 LUT）经核实**是未接线代码**（`rawLut` 指向不存在的 assets、`setColorSpace` 无调用者）
- [2026-09-22] **调研文档入库 `docs/research/`** — `handoff/` 在 gitignore 里，报告放那里不会被跟踪

## Pitfalls

- **~~纯 2.2 幂 OETF 是"发闷"的独立成因~~（2026-09-22 复核订正）** — 真实成片实测：换 sRGB 分段后**中间调仅 +1.27/255**（可忽略），差异集中在**暗部 −7.57/255**；且**方向是纯 2.2 幂在暗部更高**（0.001 处 +235%、0.005 处 +47.5%）。原"sRGB 在暗部更高"与"喂 2.2 削弱 LUT"**均不成立**（喂 2.2 时 LUT 更用力）。详见 `lessons.md` 同日订正条
- **色度 S 曲线 knee 0.25 是域错误（2026-09-22 复核订正，已修）** — 注释称"0.25 线性 ≈ 显示域 64/255"，但 **0.25 线性实为显示域 136/255**。真机 10 张成片实测 `max|cc|`：P50 **0.022** / P90 **0.057** / P99 0.179 ⇒ 旧 knee 下 **99.8% 像素在 knee 以下**，中位像素仅得 **0.5%** 增益（名义 25%），旋钮近乎惰性。修法＝按实测 P90 取 knee **0.06**（`FrameRenderer.cpp:700`）。**通用教训：注释里的域标签会骗人，必须回代码核实**
- **AE 用单点分位且不重置 → 切镜头亮度跳变** — 实测同机位主摄 luma 81.7 / 长焦 104.1；libcamera 是区域加权平均锚定 0.16，换 mode 时 `filtered_.totalExposure *= ratio; target_ = filtered_;` 丢弃历史
- **"从 PhotonCamera 导出"的资产与它的内部 `.plut` 不是同一份数据** — 内部是 v1 无元数据（`.plut`，33³ 或 UINT16），导出是 64³（Hald level 8）且**会烘进 `colorRecipeParams`**，命名规则也不同（`LEICA M9.cube` vs `Leica_M9_STD.plut`）。我一度把它误读成"来源不同"，被用户纠正
- **Gradle 构建需要工作区外的 `~/.gradle`**，且本机默认 JDK 是 8 —— 必须 `JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home`
- **改 shader 后必须跑 `tools/validate-shaders.sh`** — 引擎 shader 是设备端运行时编译，构建/单测全绿不代表 GLSL 合法
- **离线 CLI 模拟与真机实测有 5–8 个 L\* 的偏差** — 场景光随时间变化 + 反推的量化损失；离线只能判断趋势与方向，**绝对亮度必须真机**
- **在成片上二次套曲线是错的** — 成片已过 OETF，再套影调曲线等于二次压缩（对比会爆到 90）

## Next

1. **基础引擎第一批修正（2026-09-22 二次复核后订正）**：
   - ① 输出 OETF **纯 2.2 幂 → 精确 sRGB 分段**：**仍做，但理由改**。原"治发闷（viewing gamma 中间调）"**数值上可忽略**（真实成片实测中间调仅 +1.27/255）；原"喂 2.2 削弱 LUT"**被实测证伪**（喂 2.2 时 LUT 反而更用力：对比 +11.46/+14.80pp vs sRGB 的 +5.41/+12.83pp）。**真实收益 = 暗部压深**（暗部 −7.57/255）⇒ 无 LUT 时**对比 +9.87、饱和 +2.01pp**；加上**域正确性**（sRGB 是标准显示编码、也是本仓库 LUT 设计域）。⛔ 实现**三处同步**：`FrameRenderer.cpp:780`(kFsOut) / `:845`(kFsHist) / `:2013`(反解码)
   - ② 色度 S 曲线判据：**两次修正，均已实施（v0.6.21→v0.6.22）**。
     **(a) knee `0.25 → 0.06`**：原值把"线性 0.25"误当"显示域 0.25(=64/255)"，实为**显示域 136/255**；实测 **99.8%** 像素在其下、中位仅得 **0.5%** 增益（v0.6.19 的饱和度修正实际没生效）。报告建议的 0.10~0.15 **剂量不足**。
     **(b) 判据由「绝对线性色度」改「亮度相对」**（真机复验暴露）：树叶 vs 易拉罐（均 look=关）实测 `max|cc|` 树叶 P50 0.017/P90 0.043、罐体 0.032/0.184 ⇒ 旧判据树叶仅 **5.05%**、罐体 **13.70%**（差 2.7×），树叶 P90 仍在 knee 下**永远吃不满**。改 `rel = max|cc|/luma`（knee 1.0、luma 下限 0.02）后 5.05%→**12.50%**、13.70%→**22.11%**（差距 1.8×）；**相对判据天然保护近中性色**（暗部中性像素增益仅 0.06%）。**待真机 A/B 强度**（旋钮 `uLookChroma`，1.25 = 满额 +25%；开关 `uLook`/prefs `color_look`）
     **(c) 待定案**：树叶绿"准不准"缺参照 → **需该组 DNG**，用 libraw 出标准链后对比同一叶片 C\*/h\*。已排除：白平衡（四张 a\*≈b\*≈0）、色域到顶（树叶仅达上限 25%、罐体 51%）；易拉罐组 A/B **无效**（L\* 25.0 vs 32.5，曝光差 7.5）
   - ③ AE：**只做「切镜头重置 + 死区」**（`stopInternalKeepClient` 保留 RenderClient ⇒ `auto_gain_` 跨镜头存活，EMA 0.7/0.3 需 7–8 帧≈0.25s 才收敛；置 0 即可复用既有"首帧直通"分支，1 行）。「改区域加权锚定 0.16」**降级为待真机 A/B 的选项**——libcamera 的 0.16 是**区域加权平均**（rkisp1 `estimateLuminance` 实测），与我们「显示域 P95=0.80 白点」是**不同目标语义**，非可直接照搬
   - ④ LUT 采样纹素中心校正 **❌ 废弃**：已用**恒等 LUT 实测**证明现行 `t=c*(N-1)` 与硬件 `texture()` 路径**数学等价**（差 ≤2e-17）；`texelFetch` 取整数索引绕过过滤（`setLut` 的 `GL_LINEAR` 惰性）。报告公式逐字来自 PhotonCamera `BasicToneLutShader.kt:20-22` 的**纹理坐标**补偿，照搬会二次偏移（纯白只能查到 0.985）
2. **基础引擎第二批**：**局部色调映射**（手机"通透"的主因，HDR+ 用曝光融合变体、Night Sight 强调"必须保住全局对比与黑位"，强度 ≤0.2–0.3）与 **MFNR**（治噪根本解，HDR+ 按噪声模型定 2–8 帧、Night Sight `σ²/N`、参考帧取 burst 中最锐者）
3. **真机复验待办**：v0.6.19/v0.6.20 的三张实拍（阳台/卧室/书桌）用户报"噪点还是大"；主摄 vs 长焦需要**同机位只切镜头**的 A/B 才能定论（此前的对比是不同构图，全图 C\* 差 2.9 倍但只算彩色像素只差 44%）
4. **M4 后续**：.cube / Hald 导入导出、链式融合烘焙 65³、预设包（`.filmkit` zip）
5. 真机项（M3 遗留）：桌面 Lightroom 开 DNG、色温灰卡精校、MF 滑杆手感复验
