# 亮部降噪短板定位与小波重建待修

## Summary

从"exp12 复验白斑"出发，一路走到**对标定位**：用同场景 PhotonCamera 对比确认**唯一成像短板 =
亮部亮度降噪**（亮部 σY 0.82 vs PC 0.49，差 1.67×；而色度反而全面优于 PC 1.2~1.8×）。
期间经历 **5 次归因失败**（釉面真实结构 / 去马赛克 clamp / LSC / 影调白点 / σ 的 LSC 传播），
每次都是"改了 → 出包 → 实测无效或更糟"。**真正推进的全部是用户设计的开关实验**（LSC、dn、
hr_wavelet）。最终由用户切出：**杯口色块 = `hr_wavelet`（小波高光重建）误重建**，三个混合权重
参数已排除（与 darktable 默认一致 0.5/1.0/1.0），待逐行对照原版修实现。

## Done

- **RAW 域高光重建（darktable highlights "inpaint opposed"）**：4 个 fragment pass
  （mask 块级 → 膨胀 → 全图 chrominance 统计 → 对立外推应用）接在去马赛克**前**的线性
  mosaic 上，`FilmParams[45] hr_raw`；离线预告工具 `tools/hl-opposed-check.py`（在真实 DNG
  上重放同一套公式，报裁剪 photosite 数 / chrominance / 恢复幅度）
- **exp13 全画面红**：mosaic 纹理的通道约定 bug —— 值必须写在**所属 CFA 相位**的槽位里
  （R 位 = `(v,0,0)`），我一律读写 `.r` 导致 G/B 归零。已修，并在注释里写明约定
- **exp15**：RCD 色差段回归 RawTherapee 原版（去掉 `clamp(d,lo,hi)` + 梯度补第三项），
  `FilmParams[46] rcd_cdfix`；**实测对色块无改善**（中性，保留）
- **exp16**：修复 filmic 黑白点滑杆失效 —— `toneStandard()` 恒 true 把 `[37]/[38]` 硬编码成
  −8/+4.0，滑杆写了 prefs 却永远进不了引擎（一整轮 A/B 因此无效）
- **exp17 → exp18**：σ 的 "A 项乘 glY" 修正，实测降噪从 21~32% 猛增到 43~62%、**画面发糊而
  色块不变** ⇒ 已回退
- **对标数据（同场景，相隔 14 秒）**：亮部 σY 我们 0.82 / PC 0.49（1.67×）；中亮 0.66/0.49；
  中暗 0.82/0.66；**色度多尺度 1→32px 我们全面占优 1.2~1.8×**
- **白点本质**：随机涨落（同机位两帧白点重合 6.8% ≈ 随机期望 5.4%）；`whiteEv` 4.5→6.2 时
  红釉白点消失（代价：对比度降低）
- **排除项**：dn 滑杆与白点无关（0/0.45/1.0 ⇒ d>15 = 0.38/0.50/0.53%）；噪声模型准（RAW 域
  实测/模型 = 1.04~1.39）；LSC 关可改善杯体但有残留、**对杯口无效**
- **杯口色块定位（用户开关实验）**：关 `hr_wavelet` ⇒ 色块消失但高光出品红（树枝/绳子紫边）
  ⇒ **两端都不对 = 重建实现有偏差，不是开关问题**

## Decisions

- [2026-10-03] **小波高光重建保持开启**：关掉换来的高光品红比色块更难接受，且等于放弃高光
  修复能力；正确做法是修重建实现
- [2026-10-03] **影调白点是取舍不是 bug**：`whiteEv` 越大曲线越平、噪声越不明显，代价是对比
  度降低；是否把默认值从 4.0 改到 6.x 属**观感基准变更，待用户拍板**
- [2026-10-03] **停止"猜层→改→测"循环**：本窗口 5 次归因命中率为 0 且每轮消耗用户实拍；
  改用"一次只动一个开关"的对标实验
- [2026-10-03] **管线改动以对标数据为判据，不以推导自洽为判据**（exp17 的教训）

## Pitfalls

- **单张对比会骗人**：两次拿两张单张就下结论（白点"真实结构"、LSC"是根因"），都被同机位
  实验推翻。**只有同机位/同时段/单变量的对比才算证据**
- **指标会与感知背离**：σC 在 LSC 关时反而更高（10.7→13.4）而画面更干净；自动红杯定位在
  木桌场景会泄漏（杯宽算出 2700px）⇒ **目视 + 手动区域优先于自动指标**
- **`jnum(v, n)` 的 n 是字符数不是小数位**：`jnum(40077, 1)` 截成 `"4"`，据此误判"highlights
  没生效"，实际样本 4 万
- **参数写了 prefs ≠ 进了引擎**：`toneStandard()` 恒 true 让黑白点滑杆静默失效 ⇒ **改完参数必须
  核对引擎回读值**（raw.render 的 whiteEv）
- **"物理上更正确" ≠ 实测更好**：σ 的 LSC 传播推导更自洽，真机却是画面发糊、问题照旧
- **用户主导的开关实验命中率远高于我的分析**：LSC、dn、hr_wavelet 三次都由用户切中
- **木桌/红釉场景的自动红色定位必泄漏**：用限定区域 + 严格阈值，或直接目视

## Next

1. **修 `hr_wavelet` 的误重建**（当前最高优先）：逐行对照 darktable `filmicrgb.c` 的
   `reconstruct_highlights`（1278 行起）与我们的 `kFsHr*` 十个 shader。重点三处：
   ① **`threshold` 语义** —— 我们用 `1.0f`（RAW 白点绝对量），原版是 `reconstruct_threshold`
   （$MIN −6 $MAX 6 **$DEFAULT 0.0**）的相对阈值；
   ② **mask 生成与 `init_reconstruct`**（哪些像素进入重建）；注释里留着"0.10.17 阈值随 white
   掉到 0.5 曾把 47% 的块送进重建"的事故记录，说明该量一旦偏会导致**大范围误重建**；
   ③ **RGB / RATIOS 两轮的组合** —— 原版 2154/2172 行是"**先 RGB，失败才 RATIOS**"
2. **亮部亮度降噪**（根治白点且不改影调）：查 P0 bilateral 在亮部为何只降 ~30%（`σ²=A·x+B`
   在亮部更大 ⇒ 权重应更大，实测相反）；PC 对应实现是预编译 IP 核（`capsule.bin`）不可读，
   只能按标准做法推
3. **影调默认值拍板**：`whiteEv` 4.0（darktable 默认，有白点）vs 6.x（白点消失，更柔）
4. **窗户场景采集曝光只给 12ms**（客厅 100ms）：exp12 已改"曝光给足"，需查 `ExposurePlanner`
   四条约束为何在强光场景收敛到 12ms
