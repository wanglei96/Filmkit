# 0.14.20性能收线与临时清理

## Summary

本窗口从 0.14.6 的性能回归排查推进到 0.14.20，完成预览线程/门控、首拍资源预热、
协方差生命周期复用、高光 guide 当前调用行缓存，并修复无真实短帧时的云边品红。
0.14.20(817) 已提交并推送，`test_temp` 大体积临时照片与二进制已按用户授权清理；
快门到保存 3--5s、优选不超过 4s 和预览几乎不掉帧的目标仍未达成。

## Done

- **0.14.7--0.14.10**：预览回调移入专用线程，新增 `PreviewFrameGate`；修复通知竞态，
  跳过相同 SurfaceTexture 时间戳的重复绘制；PC3D 改用完整对称主元 LDLT，保留六分量协方差。
- **0.14.11--0.14.13**：诊断链改 thread-local，消除 still 诊断串入预览线程；缓存只依赖几何的
  histogram 中心权重，仍读取每帧全部像素并重算当帧完整统计；删除预览 TEQ 额外 `glFinish`。
- **0.14.14--0.14.16**：实测首拍新纹理/程序创建约 1115.884ms，把 RAW noise、RGB covariance、
  full-size PC3D slot2/3 接入 warmup；mismatch 改为既有 `drawStriped(4)`，样本与准入不变。
- **0.14.17--0.14.18**：协方差 slot3 在原始 RGB cov 最后读者完成后借用两张 RGBA32F，
  每帧完整重写，少分配约 382.5MiB；取消 capture 主动 pause/resume 和恢复时丢四帧，
  预览在拍照期间持续消费，保留快门黑闪与飞入动画。
- **0.14.19**：分离 `highlight_resolve_ready_` 与 `highlight_merge_ready_`。无真实短帧时仍按
  本张 neutral/reference scale 执行完整 RGB CameraWhite resolve，short share=0，typed dummy
  绑定本张 LSC；删除可达的旧 CFA sat-fix 回退。用户两张长焦云边实拍确认“均已达预期”。
- **0.14.20**：`highlightGenerateGuide` 只在当前调用、每个 worker 内缓存三行校准 CFA 四元组；
  保留全部九样本、RGB moments、18 green、噪声 LUT、signed variance、binary16 和累加顺序。
- **真机结果**：0.14.19 三张保存 6.894/6.671/6.220s；0.14.20 三张
  5.599/5.289/5.881s。guide 中位 486.36→330.00ms；ABBA 独立基准中位
  418.675→306.400ms（-26.8%），只代表该段，不是整张成片加速比。
- **质量回归**：主机/真机各 80 组 guide 输出逐字节一致；ASan/UBSan 通过；真实生产
  FrameRenderer 14 组连续状态共 28 份 RGBA/JPEG 与 0.14.19 逐字节一致；预览四份输出一致。
- **提交与交付**：`d6f6ede fix(camera): preserve bracket highlights and optimize capture pipeline`
  含 34 文件、2672 insertions/280 deletions，已 push `origin/dev`。0.14.20/817 已安装核验，
  根目录保留 `filmkit-0.14.20-PERF.apk` 与回退 `filmkit-0.14.19-HIGHLIGHT.apk`。
- **临时清理**：`test_temp` 从 9.1GB 降到 203MB，删除 474 个文件/8.863GiB，其中

## Decisions

- [2026-11-16] **允许当前调用内复用 guide 中间行，不允许跨张复用统计**：缓存必须在调用结束释放，
  输入、曝光域、样本、累加顺序和输出精度不变；任何前张 cov/mask/guide 都不得进入当前成片。
- [2026-11-16] **协方差纹理复用必须按完整生命周期证明**：slot3 只能在原始 RGB cov 的最后读者
  完成后借用，slot2 仍被第二趟 PC3D 读取时不得覆写；下一张 `passHighlightNoise` 必须全量重写。
- [2026-11-16] **source-white resolve 就绪与真实短帧 merge 就绪分离**：无更短曝光是有效观测约束，
  不能放宽短帧门槛伪造真值；但 CameraWhite 仍必须按本张参考执行，short share 明确为零。
- [2026-11-16] **拍照期间预览持续消费**：不得用 pause/resume 冻结预览来掩盖队列或恢复跳变；
  飞入动画只覆盖视觉，底层 SurfaceTexture 仍要 `updateTexImage`/绘制。
- [2026-11-16] **清理证据先保留可复用摘要**：大图/RAW/stage dump 只有在代码已提交、报告与
  SHA256/parity 已落盘后才能删除；删除后不得把历史样片路径继续当作可重放输入。

## Pitfalls

- **云边品红不是协方差纹理复用造成**：失败样本没有执行新局部噪声/协方差路径；真因是无短帧时
  RGB resolve 被 merge 就绪状态误门控，旧 CFA sat-fix 又重开。先看本张实际分支，不按最近改动猜。
- **“名义短帧 -1.5EV”不等于真实更短曝光**：手动快门/ISO 下限钳制后，侧帧可能实际为正 EV；
  旧日志四位小数秒会掩盖差异。准入应读纳秒曝光与硬件上下限，不靠请求标签。
- **性能样本不是锁温/锁曝光 A/B**：0.14.19/20 均 Thermal 2，SKIN、ISO、曝光和场景亮度有差；
  0.14.20 的总时长差异不能全部归给 guide 行缓存。
- **完整合成窗口最低 FPS 不等于全程流畅**：0.14.20 新三张没有 >400ms gap 告警，但全流程重叠
  窗口仍有 287--386ms 空档；启动预热 1534ms，启动窗口最低约 20.11FPS。
- **协方差少分配不等于进程峰值下降**：约 382.5MiB 是两张纹理的逻辑大小，不是 PSS 实测收益；
  噪声 scale/场景变化时必须用匹配快照验证。
- **`test_temp` 清理后历史重放材料可能不存在**：报告中的照片、RAW、RGBA/stage dump 路径只能
  证明当时证据，重放必须重新采集原始输入。
