# 快门动画与保活预热

## Summary

预览专项从"快门后冻结"推进到"生命周期保活 + 构图期预热 + 快门定格动画"：预热让第一张 3805→3129ms、与热态差距 1261→398ms；fence 窗口与时间片让路实测无收益；iPhone 味飞入动画反复 14 版仍未定稿，**0.13.40 未安装成功**（设备实际停在 0.13.38），交接时动画仍在调。

## Done

- **0.13.17**：空间域 `fuse`（单次全屏 draw）与 PC3D 平滑趟按 16 条行条带化 —— **方案错误**，用了 `glViewport`。
- **0.13.18**：条带扩展到 HL apply / defringe / CCM / TEQ apply / CA / color_smooth / color_median；预览 context 请求 HIGH、预览线程 DISPLAY、satmask 膨胀/转置并行。用户实测**预览画面重复 N 次**（每条带重复整幅图）。
- **0.13.19**：`glScissor` 修复条带（viewport 保持全屏），画面恢复；根因 = 全屏三角形 UV 按 NDC 插值，viewport 一缩每带 UV 从 0 重来。
- **0.13.20**：still 空闲释放 10s→60s；satmask 4 张 CPU 缓冲（~125MB）跨张复用。
- **0.13.21**：删掉定时释放，改生命周期驱动 —— 相机页可见+亮屏保活，不可见/`ON_PAUSE`/熄屏 `releaseNow()`；真机验证停 87s 不重建、切后台立即释放、回前台重建+预热。
- **0.13.22**：warmup 从"只分配"扩到 `ensureHlTargets`/`ensurePc3dTargets`/df/cs/cm/teq/ca + 对 35 个中间 FBO `glClear` 触页。真机：第一张 3805→3129ms，与热态差 1261→398ms；teq/hl 与热态一致；剩余 323ms 在采集侧 `upload`。
- **0.13.23**：`capture()` 入口 `cancelWarmup()`（未开始的预热不挡快门）。
- **0.13.24–26**：fence 窗口（在飞 2）实测 total 3124 vs 3121、fps 不动；时间片 sleep（10ms/30ms）total +231ms、fps 不动 ⇒ 已回退。
- **0.13.27–0.13.40 动画**：420→560ms、真实控件坐标终点（`boundsInRoot`）、相机页请求 120Hz（`preferredDisplayModeId`，实测 `appRequestBaseModeRefreshRate=120`）、draw 阶段读动画状态（零重组）、PixelCopy 抓当前预览帧、白边/阴影。**0.13.40 未装上**。
- **PC 对比实测**：PC 专业模式 RAW 拍照 tap→落盘 **6.59s**（我们 3.2–3.5s）；PC 无帧率日志、`SurfaceFlinger --latency` 对其 BLAST layer 不可用，掉帧只能靠录屏+运动场景。

## Decisions

- [2026-11-13] **条带化只能用 `glScissor`**，不能用 `glViewport`：全屏三角形 UV 按 NDC 插值，缩 viewport 会让每条带重复整幅图（0.13.18 事故）。
- [2026-11-13] **still 引擎按生命周期保活**（相机页可见+亮屏），不再定时释放：显存驻留不耗电，重建（init 135~265ms + 2.4GB 分配）才耗电且卡。
- [2026-11-13] **fence 窗口（在飞 2）与时间片让路不采用**：真机实测对预览帧率零收益，时间片纯亏 231ms。掉帧不是队列深度问题。
- [2026-11-13] **快门定格到动画结束即恢复**（不等合成 3s），处理期掉帧由用户接受的体感换时间。
- [2026-11-13] **相机页请求 120Hz**：窗口默认 60Hz 时 Compose 动画被 vsync 锁在 60fps，代码优化无效。

## Pitfalls

- [2026-11-13] **⛔ 安装必须用 `dumpsys package` 验版本**：0.13.40 的 install 命令被后续 `echo ok` 掩盖，设备实际仍是 0.13.38，排查动画"没生效"时白绕一圈。
- [2026-11-13] **暂停预览不消费 buffer = 预览永久不回**：SurfaceTexture 队列满会堵死 HAL producer；`resumePreview()` 必须先 `updateTexImage` 清 ≤4 帧。修复前 `preview_gap` 6654ms 且不恢复。
- [2026-11-13] **`boxW` 首帧为 1px**：用它算飞入图尺寸会退化成 1dp 图 + 20dp 阴影 ⇒ 屏幕上只剩"一圈阴影"。
- [2026-11-13] **飞入图与背景同内容**：不加白边/微阴影根本看不出"图被抽出来"；大尺寸 + 大阴影反而像 bug。
- [2026-11-13] **`screenrecord` 要等进程结束再 pull**，否则 moov atom 缺失、ffmpeg 打不开。
- [2026-11-13] **动画状态在组合作用域读 = 每帧重组整个相机页**，必须放 `graphicsLayer`/`drawBehind` 的绘制阶段。

## Next

1. **装 0.13.40 验动画**：`dumpsys package` 确认版本；看飞入是否是"整张预览缩小飞出 + 白边"。
2. 若仍不对：按 iOS 截屏实际形态重做（屏幕中部 ~30% 尺寸起、白边、不压暗、起点与预览框重合），不要再靠猜尺寸。
3. 采集期掉帧（快门后 0.5~1s HAL 重配）未解决；PC 处理更慢却不拖预览，差异疑在采集流（ZSL/预览流不重配），需运动场景录屏对比。
4. 旧任务延续：Spektrafilm（slot=2）、理光负片曲线重标、绿植/绿段、AE 高光保护。
