# 高光融合落地与出片回归

## Summary

本窗口把 PC/Bento 的高光融合按一手参考完整落地（0.14.5），却在交付时踩到两个**非成像**回归：
GPU 计时器手写枚举错一位（`0x8FBD` 而非 `0x8FBB`）产生 `GL_INVALID_ENUM`，被新增的硬失败检查判成
渲染失败 ⇒ 没有 JPEG；同时我早先留下的 `burst_dump` 哨兵绕过用户 DNG 开关往相册写 DNG。
修复后 **0.14.6(803) 用户验收通过**（JPEG 正常、DNG 不再出现）。
当前未解决：**拍照变慢 + 拍照时预览非常卡**，用户怀疑条带化优化被吃掉，需先实测剖面再动。

## Done

- **native CFA clipping 有效性**：`kFsMfnrMismatch` 的 off1/2/3 改用真实 `uOffTiles`（原用 4× 细网格
  `uTiles`，越界错采）；原始 u16 在扣黑/曝光归一**之前**判剪裁（逐相位黑/白阶），亚像素采样要求
  非零权重 tap 全部在图内且未剪裁；四 CFA 相位全采，逐 ALT 独立累计有效配对与噪声方差。
- **UNKNOWN 契约**：有效配对不足/缺相位 ⇒ UNKNOWN=1，普通时域保守退出；CPU 侧用独立的
  `mis==255` 判据绕开 ISO `res_fade` 与中值滤波，UNKNOWN 不再被重新赋正权重。
- **配准与几何准入**：四相位完整 RGB guide（3×3 moments + 18 green + binomial + noise LUT + clip
  sentinel）、前后向真实求解 + 完整向量 cycle、4×4 空间 RGB agreement、8 连通区 + radius4 collar
  （≥4 donors）+ confidence/距离² 插值 + 全局加权中位回退 + 无可观测支持则拒绝；highlight 分支
  强制完整 L1（原 `align_l1=false` 会静默降级）。
- **整帧接受**：最大 8 连通 hole ≥80 guide px 拒绝；short 自身剪裁只作诊断，不再二次清零；
  被拒时 selected global weight=0，不能从普通时域途径偷渡。
- **融合**：`kFsHighlightMerge` 完整 MergeBayer（roundEven、mirror、原始相位、always-dual-green、
  Gaussian/linear dual kernel、未归一累加后统一相除、按源噪声/曝光调参），删掉 Bayer 内
  CameraWhite 截顶，MRT 输出 `Vactual/Aeff/Beff/shortShare`。
- **RGB 域白界**：`kFsHighlightResolve` 在去马赛克后、CA/CCM 前做 `min(source/lsc, CameraWhite·gain·scale)·lsc`，
  独立 target + blit 回 `tex_work_`；四旋转映射与 RCD 的 `tuv` 翻转一致。
- **噪声传播**：`kFsHighlightNoise` 生成 D4 六分量 cov（LSC² + 完整 CCM 矩阵）；PC3D/P4/小波
  Cb/Cr 全部按完整矩阵配对 Mahalanobis 或投影（不再单 scalar）；gaussdown→首趟 PC3D→guided up→
  第二趟 PC3D 逐阶段 MRT 传递，P0 直接消费逐样本 V。
- **旧路径收口**：`allow_ts=!highlight_merge_ready_`；`hr_on` 加 `!highlight_merge_ready_`；快速
  bilinear 在 HDR 下显式路由 RCD 并记日志；defringe 仍下线；NN 与恢复域不兼容时明确回退并记日志。
- **失败契约**：`finishStillChain` 失败时清空输出并返回 false（不让上层复用上一张像素）。
- **验证工具**：`check-highlight-geometry`(301)/`-recovery`(4635)/`-merge`(59 GPU)/`-noise`(32)/
  `-noise-filter`(10)/`-resolve`(317520 比较)/`-temporal`(21)/`-postprocess`(106)；Mali 真实
  EGL：58 checks/16 draws、12 生产 shader link；新增 `check-renderer-device.cpp` 动态链接真实
  `libfilmengine.so` 跑完整 RAW→JPEG（256/512/2048/rotation/bilinear 全 PASS）。
- **0.14.5 事故与修复**：`GpuTimer.cpp` 手写 `GL_GPU_DISJOINT_EXT=0x8FBD`（标准 `0x8FBB`）⇒
  每次 `endMs` 出 `GL_INVALID_ENUM(1280)`，被新硬失败判死；改为 include `<GLES2/gl2ext.h>`
  并用成套 EXT 入口动态加载。`CameraController` 删除调试 RAW→MediaStore DNG 旁路，四帧诊断只写
  app-specific `burst/*.raw`。新增 `tools/check-capture-diagnostics.py` 防复发。
- **交付**：`filmkit-0.14.6-CAPTURE-FIX.apk`(803)，签名/aapt2/DEX/arm64 符号核验通过；用户真机
  验收「JPEG 正常、DNG 关闭不出 DNG」。

## Decisions

- [2026-11-15] **CameraWhite 必须在去马赛克后的完整 RGB 域执行**（undo LSC→白界→redo LSC，CA 前）：
  它是 PC 的 source-neutral 输出白上界政策，不是满阱检测；写在 Bayer 相位内会跨 CFA 相位非线性截顶、
  不满足与去马赛克可交换。代价明确：会压掉超过源中性白界的真实颜色，不宣称无损。
- [2026-11-15] **UNKNOWN ≠ 静止**：clipped reference + valid short 是可兼容的 HDR 观测而非运动；
  有效配对不足时普通时域保守退出，selected short 由准入 M 独立接管，不被该标量决定。
- [2026-11-15] **整帧拒绝优先于强行恢复**：最大 8 连通 hole ≥80 就拒绝短帧，禁止为"救回一点高光"
  放宽阈值或回退到跨 CFA 标量 inpaint。
- [2026-11-15] **噪声只能按完整度量传播**：不用 neff 标量顶替；多尺度滤波用显式冻结权重的一阶/凸上界，
  并如实标注"非精确非线性 RCD 噪声"，不写"exact"。
- [2026-11-15] **调试诊断不得改变用户可见输出**：RAW dump 只进 app-specific 目录，公共相册写入
  必须且仅由用户开关授权。
- [2026-11-15] **新增硬失败检查必须先隔离既有 GL 错误**：否则会把历史上的非致命错误放大成"出片失败"。

## Pitfalls

- **单 shader / 离线 replay 全绿 ≠ App 能出片**：`GL_GPU_DISJOINT_EXT` 的错误只在真实 host 链暴露，
  所有 fragment 级测试都看不见。判定"能出片"必须走真实 `FrameRenderer` + 真实 JPEG 编码。
- **手写 GL 常量是地雷**：`0x8FBD` 与 `0x8FBB` 差一位，症状是"融合成功但 bytes=0"，
  且会被下一层的错误检查错误归因。一律用平台头文件枚举。
- **遗留调试哨兵会污染用户输出**：`files/burst_dump` 绕过 DNG 开关写相册，用户看到"没开 DNG 却有 DNG"。
  诊断开关默认关不够，必须连"诊断路径能否写用户可见位置"一起审。
- **增量分段 GL 检查要打在正确的 pass 边界**：`after_RCD_direction` 里同时包着 `gpu_dir.endMs()` 与
  `gpu_g.begin()`，先怀疑 shader 会白查一轮；把检查插在 timer 前后才能分离。
- **同场景对照必须同口径**：`--plain` 在修复前也走同一条错误计时器路径，只是旧链吞掉了错误，
  所以"plain 能出片"不能证明 HDR 独有的问题。
- **工具装载 app so 会撞 libc++ 全局析构**（Scudo invalid chunk）：测试进程里先完整析构
  `FrameRenderer`/EGL 再 `_Exit(status)`；这是 CLI 装载问题，不是成像管线缺陷。

## Next

1. **性能回归优先（用户最新反馈）**：拍照变慢 + 拍照时预览卡。先实测，不要先重写：
   - 取 `raw.render` 的 `p0Ms/dirMs/gMs/hlMs/dnMs/fuseMs/preMs/totalMs` 与 `preview_arrive_gap`、
     `preview_gap`、fps，和 0.14.0 同场景基线对比（基线：DFT 不用、P0 300–352、RCD 39–66、
     P4+PC3D 542–1131、总 5.2–6.5s）。
   - 重点怀疑新链：每次拍照多出 1 张原生 RAW RGBA32F noise（4080×3072×16B ≈ 200MB）、
     D4 两份 RGBA32F cov（≈200MB）、PC3D 每趟 3 attachment（含 2 张全分辨率 RGBA32F）、
     逐阶段 `glGetError()`/`glCheckFramebufferStatus` 同步点、`passHighlightNoise` 与
     `passHighlightResolve` 的额外全屏 draw、`drawStriped` 是否被新 pass 绕过。
   - 确认条带化仍在：`runPc3d`/P0/P4 的 `drawStriped(16)` 未被新分支替换；`glScissor` 语义未被改。
   - 预览卡属于 still context 与预览 context 的 GPU 争用：检查 LOW 优先级 context 是否仍生效、
     新增大纹理分配是否落在预览线程、`warmup` 是否覆盖新 FBO。
2. 日光待验：极高光品红、云朵灰斑、花瓣灰斑/绿边、栏杆紫边、灯边灰带、运动重影、跨镜头/预设、
   降噪开关直通。CameraWhite 与保守 cov 的观感风险见 `docs/reports/highlight-fusion-0.14.5.md`。
3. 应用单测仍有 1 个既有失败 `Pv3StaleFrameTest`（`under` 层归属校验），与本轮无关但未修。
