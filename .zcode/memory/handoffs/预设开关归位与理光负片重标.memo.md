# 预设开关归位与理光负片重标

## Summary

从「HDR 增益归属」快照接续。先说结论：本窗口修掉的是**一类** bug——预设展开时把"基线里的管线开关值"带进成片，而 prefs 覆盖层因为"值没变就不写"的缓存判断静默失效（027 的 local_tone=0.25 / color_smooth=0 / sat=0.76 全是这么来的）。修法 = 换数组后把 21 个 guard 缓存全部置哨兵。顺带按用户拍板删了设置页「饱和补偿」、三段饱和拆成三条滑杆、ESD3D2 回替换档。后半程做理光负片：从 GR 官方博客抓 19 张标准样片 + 2 组同场景配对，重烘 64³ LUT、把预设从旧自创配方压到「三段饱和 + 黑白点 + LUT」。0.12.208→214 共 7 个包，828 单测全绿。

## Decisions

- **管线开关不进预设**（用户 2026-11-01）：预设只承载风格（对比/曲线/分区饱和/色温/颗粒/暗角/LUT）；开关的唯一事实源是设置页。后续若明确要求某个开关进预设，再单独放行。
- **饱和度听预设**：设置页的「饱和补偿」删除，`[20..22]` 由预设决定，不再有第二个写入者。
- **ESD3D2 默认 = 替换档**（用户定档）：与 `FilmParams.h` 的 `pc3d = 1.0f` 一致；两处 getInt 兜底曾写 2，属"代码说替换、实际跑叠加"的偏差。
- **三段饱和拆三条**（方案 B）：UI 能力 == 引擎能力；要复刻机内直出就把三条拉成同值。不选"按色相 8 段"（A）：M9/GR 的味道不是色相分区，且 LUT 已能承担色相相关调整。
- **未标定的预设不锁 engine_slot**：只有曲线/黑白点已按 filmic 标定的徕卡一瞬锁 `[98]=0`；理光/黑白待重新标定后再定。
- **LUT 只做色彩、不做影调**：旧 `ricoh_negative.lut` 自带"中灰 127→150、白压 237"，代码里又把它的提亮和 contrast 1.2 互抵 ⇒ 观感来源不可归因，已弃用。
- **理光标定方法论**：GR 无固件配方、JPEG 无法分离曲线 ⇒ 曲线用"配对亮度传递"判定不动，色彩用"配对色相 delta + 多张样片灰轴统计"定，不做无数据的拟合。

## Pitfalls

- **预设数组 vs prefs 的脱钩是复发性结构缺陷**：`setFilmParams` 换数组 + `applyXxxPref` 的"值没变不写"，只要基线值 ≠ prefs 默认就会静默生效。新增 applier 时必须同步在 `setFilmParams` 里置哨兵（`[49]` 0.12.99 已踩过，`[36]/[54]/[59]` 又踩）。
- **用 custom 样片定目标会骗方向**：第一版 12 张里 5 张是作者自定义 `+B5`（加蓝），据此把"负片"定成"全图偏蓝"，与官方语义（暗暖亮冷）相反。必须先读图注、排除非默认参数。
- **`test_temp` 的 DNG 不能做影调标定**：12 张里中性像素 L* 中位 7.5（GR 样片 45.1，差 6 倍），全是粉云/夜景/暗角等 bug 现场。拿它反推对比度等于拿阳台夕阳对街头阴天。
- **LUT 轴序是 `a[b][g][r]`**（.cube 的 R 变化最快 ⇒ 线性索引 x 轴 = R）：按 `a[r][g][b]` 采样会得出"红→蓝"的假象，进而误判"引擎 R/B 通道交换"。引擎上传路径（`setLut` → `glTexImage3D`）无转置，是对的。
- **`fit/builtin-curves.json` 的 `editor` 是历史实测值**：换 LUT / 改配方后必须重算（本轮用 Kotlin 复刻 `measure()` 重算并标注"待 recipe-fit 重跑"），否则 `kotlinReimplementationMatchesEngineShaderWithinOneLsb` 会红。
- **改 assets 后单测要 `--rerun-tasks`**：`testDebugUnitTest` 会命中 up-to-date 缓存，报"1 秒成功"的假绿。
