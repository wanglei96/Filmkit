# 紫边归因闭环与对标基准修正

## Summary

本窗口从"高光下物体边缘品红"出发，逐层排除后把紫边锁定到**高频环节（去马赛克伪彩/小尺度色度处理）**，
并发现**项目长期使用的对标数字 3.684 把 PhotonCamera 高估约 2.2 倍**。本窗口产出 APK **v0.10.163~0.10.176**（v0.10.162 未留包；仓库现存 14 个包含更早基线），修掉三个真实缺陷，排除两条错误路径，修正了测量口径本身。

## Done

- [2026-10-05] **小波 HR 阈值域不匹配修复（0.10.168）**：threshold 按"RAW 满阱"算（1.511）却用在场景线性域
  （中性白范数 √3=1.732）⇒ 正常亮部被判裁剪。真机 Y 加权和之差 **+2.03% → +0.03%**，clipB 289→60。
- [2026-10-05] **`uStat` 接线 + HR 前置到 P0 之前（0.10.167）**：`uStat` 原是死参数
  （`texelFetch(uStat` 全文件 0 命中），统计/mask/apply 共用 `uMos` ⇒ 这是历史 exp21"改 src 即全改"的结构性根因。
- [2026-10-05] **档位 2 硬限回退 + `hr_wavelet` 默认关（0.10.162）**：移除 `w=(w>0.9)?w*w:0`（+29% 梯度来源）；
  默认关后省 **≈752MB 纹理 + ≈103 个全分辨率 pass/张**。
- [2026-10-05] **`uGRecon` 开关（0.10.169）**：关掉自创的 G 三级池化比 ⇒ 高光区 B/G **1.087→1.025**。
- [2026-10-05] **4:4:4 JPEG 编码（0.10.171）**：实测生效（SOF0 变为 4:4:4、ms=293）**但紫边未解决**；
  **反证：PC 成片本身也是 4:2:0** ⇒ 排除编码路径。
- [2026-10-05] **AMaZE 去马赛克（0.10.172）**：完整实现（CPU 多线程，247ms@12MP）+ 设置三档可选；
  离线六项指标**五项为负**（∇>60 伪彩 AMAZE 30.0 vs DCB 19.2）⇒ 排除去马赛克路径。
- [2026-10-05] **强边缘色度门（0.10.173→174）**：0.173 全局放宽 `wy` ⇒ 真机"一片红一片黄一片紫"；
  0.174 改逐像素门控（门覆盖率 73.7%→1.6%），色渗判据全绿。
- [2026-10-05] **ESD3D2 完整移植（0.10.175）+ 设置页入口（0.10.176）**：核尺寸由噪声模型算（我们=11）、
  两趟 + 引导上采样；**关键发现：`cap=0.2` 在 PC 里从不触发（实测吃满率 0.00%）**，0.173 把 cap 当放宽量 ⇒ 大 27×。
- [2026-10-05] **紫边审计闭环（`/tmp/pcfix/REPORT.md` 578 行）**：口径自证复现 PC 的 **3.68413/0.44607%**；
  零假设检验证明 **3.684 里只有 +1.668 与边缘有关**；剖面形状：**我们=窄峰（FWHM 4px）、PC=宽缓斜坡（20+px，无峰）**。

## Decisions

- [2026-10-05] **对标基准修正**：项目此前把 **3.684 当目标**（`CameraPresets.kt:183-186` 关 `[54]` 的理由），
  实际它把 PC 高估约 2.2×；正确目标是"**边缘局域超额 1.67 / 剖面 core 1.08**"。
- [2026-10-05] **`∇>60` 紫边均值禁止作为跨图 KPI**：同一地点相隔 7 秒的两张成片读数可差 **25.8×**；
  应改用**剖面 core** 或**零假设选择超额**（对噪声/曝光/白平衡免疫）。
- [2026-10-05] **排除三条路径**（均有实测反证）：编码 4:4:4、去马赛克算法、横向色差
  （PC 的 `CorrectingFlow` 只对 OnePlus 生效，样片 vivo 走 passthrough）。
- [2026-10-05] **`hr_wavelet` 与 RAW 域高光重建职责重叠** ⇒ 前者默认关（模块保留、可 A/B）。

## Pitfalls

- [2026-10-05] **全局放宽色度权重的亮度项 ⇒ 大面积色渗**：PC 的门是**逐像素**的（`chromaNoise` 内含梯度门），
  做成全局后平坦区也开始跨亮度搬运色度。修复 = 门控必须乘在放宽量上（`cgRelax = min(...)·cgGate`）。
- [2026-10-05] **离线验证漏判据导致真机翻车**：0.173 只测"紫边下降 + 平坦区色度"，
  **没测"色渗/大色块"**。此后新增四条色渗判据（块状色相偏移、平坦区色度-亮度相关、大色块方差、门控覆盖率）。
- [2026-10-05] **跨图对比必须同口径**：不同子代理用了三套口径（Rec.709+中心差分+降采样 / 前向差分+(R+G+B)/3），
  同一张图读出 7.39 vs 12.155 ⇒ 所有旧比值无效。**测量前先自证口径能复现已知值**。
- [2026-10-05] **`clip(x,0)` 口径对分布宽度敏感** ⇒ 噪声高的图读数天然更高；跨图比较必须做零假设校正。
- [2026-10-05] **rawpy 报告的 `black_level_per_channel` 是取整值**：曾据此误判"R 相位黑电平 63 导致暗部偏红"，
  DNG 真值是 `[63.99,64.01,64.01,64.01]`（相位极差 ≤0.03 ADU）⇒ 该假设被推翻。
- [2026-10-05] **旧诊断照片是二次传输重编码的副本**（1777×2360 ≠ 原生 3072×4080，DQT 非标准表）
  ⇒ 用户截图不能作为证据，必须取相册原图。

## Next

1. **用新 KPI（剖面 core）重估 `FilmParams[54]`（ESD3D2 移植，代码已就绪、默认关）的三个档位** ——
   它是"去马赛克后、全分辨率、核 11"，正好治这类高频窄峰。
2. **修正 `CameraPresets.kt:183-186` 的对标基准注释**（3.684 虚高 2.2×，改为"剖面 core 1.08"）。
3. **定位产生窄峰的具体 pass**：剖面显示我们=4px 窄峰、PC 无峰 ⇒ 需真机 A/B 逐个关暗环节
   （去马赛克 / 小尺度色度处理 / 色度锐化）才能点名。
4. **把"剖面 core / 零假设选择超额"沉淀为 tools 脚本**（替换现用的 `∇>60` 均值口径）。
5. 待用户真机 A/B 拍板的取舍：`[54]` 是否默认开、`[51] κ` 是否调低（高饱和彩边去饱和 25~37% 的代价）。
