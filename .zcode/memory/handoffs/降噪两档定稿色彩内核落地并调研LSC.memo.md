# 降噪两档定稿色彩内核落地并调研LSC

## Summary

从 v0.5.32 降噪调参起步，完成 M3-2 降噪两档定稿（v0.5.33–35）、基准色彩内核四轮迭代（v0.5.36–38/41）、高光重建（v0.5.39）、预览过曝斑马纹（v0.5.40–41），并以一轮深度调研（自研 DNG 解剖 + DCP/开源色彩管线）定位"直拍 RAW 没有色彩"的根因、确认 X300 的 LSC 数据可用（v0.5.42 探针）。共 10 个版本 v0.5.33–v0.5.42（versionCode 63–73）全部真机验证并推送。**下一步主线：P0 镜头阴影校正（LSC）**。

## Done

- v0.5.33-m3 降噪两档（关/标准/强）→ **真机实测失效**：标准与强无差别（σC 1.04/1.00、Lap 2.48/2.38）、细节 -59%、JPEG 体积腰斩（8.14→4.28MB）
- v0.5.34-m3 降噪重标定（P0 值域 σ 系数 标准 0.50/强 2.20、P4 1.80/2.60）+ **修静默失效**（`SENSOR_NOISE_PROFILE` 是 `Pair<Double,Double[]>[]` Java 数组，原 `as? List<Any?>` 永远失败 → σ 自适应从未生效）→ 标准档**强边缘锐度 0% 损失**（17.50 vs 关档 17.49）
- v0.5.35-m3 标准档放轻（P0 0.28 / P4 2.20）→ 体积 -26%（原 -36%）、σ(chroma) 1.21（用户接受，优先保体积与清晰度）
- v0.5.36-m3 基准色彩内核 v1：发现 pass2 在中性参数下**数学恒等**（整链无影调工程）→ 加三点锚定 S（黑 0.003→0、中灰 0.18→0.18、白 1.0→1.0，端点 rolloff 而非硬截断）+ norm-controlled；黑位 P0.1 20.4→3.9
- v0.5.37-m3 软化（枢轴 0.22 / p 1.20）+ 新增「基准影调」开关 → 同机位 A/B 实测亮度影响 **-11%~-16%**
- v0.5.38-m3 高光去饱和（修"灯泡变红"）：norm-controlled 等比压缩保色 → 过曝区过饱和；`w=smoothstep(0.85,1.30,n0)` 向峰值收敛
- v0.5.39-m3 高光重建（RCD P3 的 CCM **之前**，饱和通道用未饱和通道反推辐照度）
- v0.5.40-m3 预览过曝斑马纹（`kFsOut` + `passOutput(zebra)`，**成片路径恒 false**）；v0.5.41 开关移入快捷面板
- v0.5.41-m3 中间调提亮 `pow(f, 0.90)` → 均值回到关档 -2.5%（黑位/高光不动）；**离线校准法首次验证通过**（同一时刻 A/B 对：预测 42.22 vs 实测 42.29）
- v0.5.42-m3 LSC 探针 → **X300 提供 `STATISTICS_LENS_SHADING_CORRECTION_MAP`**：17×13、mode=1、中心 1.000、角落 **6.236**
- 深度调研（结论落 docs「色彩引擎调研结论」节）：DCP 字段分工与硬限制、开源项目源码级做法、自有 DNG 解剖（GainMap / OpcodeList2）、规划 vs 实现 gap 表

## Decisions

- [2026-09-21] **降噪两档定稿**：标准 P0 0.28/P4 2.20、强 P0 2.20/P4 2.60；只接 RCD 质量档，bilinear 保持纯净基线
- [2026-09-21] **色彩内核 = 三点锚定 S + norm-controlled + 高光去饱和 + 中间调提亮**（v0.5.41 定稿）：保留黑位与高光 rolloff，整体亮度对齐无 tone 水平
- [2026-09-21] **高光重建 v1 = 中性外推（保守）**；"局部比值法"只覆盖 0.128% 像素 → 降为低优先
- [2026-09-21] **斑马纹只进预览**（`passOutput` 显式 zebra 参数从接口上堵死进成片）；拍摄相关开关按约定放快捷面板、不放设置页
- [2026-09-21] **LSC 列为 P0**（数据已验证可得、成本一次采样、同时治暗角 + 角落色偏 + "偏暗"）；**色彩外观层（3D LUT）才是"寡淡"正解**；DCP 只解决色准（其 LUT 不能提升饱和度）
- [2026-09-21] **影调/色彩类改动必须自带可关闭 A/B 通路**（v0.5.36 无开关导致无法归因，教训）
- [2026-09-21] **离线调参只在"同一时刻 A/B 对"上成立**；跨时刻对比受场景光变化污染，不可归因
- [2026-09-21] FilmParams 契约改为**按实际长度读取**（下限 26），新增参数一律末尾追加 + 防呆

## Pitfalls

- [2026-09-21] **全图 Laplacian 判"细节损失"会系统性高估**：它把噪声当细节计（σY 2.30 时梯度 P90≈5.7 几乎全是噪声）；正确口径 = **强边缘锐度（梯度 top 0.5% 均值）**
- [2026-09-21] **降噪"过猛"的量化特征**：σY 恰降 1/2.8≈1/3（9 点平均理论值）+ 与强档无差别 ⇒ 值域权重已饱和、退化成无条件平均；JPEG 体积腰斩是同一根因
- [2026-09-21] **`SENSOR_NOISE_PROFILE` 是 Java 数组而非 List**：`as? List<Any?>` 永远失败（编译器 "This cast can never succeed"）→ σ 自适应静默失效；修好后才敢断言"X300 不回填"（noise=0、nsHal=0.03 走回退）
- [2026-09-21] **norm-controlled 保色会让过曝区过饱和**（灯泡变红）：亮度压缩与去饱和**必须成对**（Filmic/AgX 同理）；硬截断之所以看着正常，是因为它把三通道一起顶到 1
- [2026-09-21] **对称 S 曲线对"中灰以下为主"的暗光场景必然整体压暗**（P50 线性 0.11 < 中灰 0.18）；要提亮得加中间调 gamma，移枢轴几乎无效
- [2026-09-21] **RAW 饱和必须在 WB 域判定**（阈值 = black+(white−black)/gain：本例 R≥520/G≥1023/B≥747）；从 JPEG 通道反推饱和是错的（v0.5.39 提交信息的推断即此错）
- [2026-09-21] **DNG `OpcodeList2` 内部是大端、而 TIFF 头是小端 `II`**（DngCreator 产物）——Lightroom 兼容性待验
- [2026-09-21] **Android 没有 `STATISTICS_LENS_SHADING_MAP`**：正确键是 `STATISTICS_LENS_SHADING_CORRECTION_MAP`（返回 `LensShadingMap`，`getGainFactor(color,col,row)`）——凭记忆写 Camera2 键名必错，用 javap 核 SDK

## Next

- **P0 LSC（第一优先）**：`STATISTICS_LENS_SHADING_CORRECTION_MAP` → 17×13×4 增益纹理 → RAW 解码时按相位双线性采样；验收=暗角消失、角落色偏改善
- **P1 色彩外观层**（治"寡淡"）：3D LUT（自建 .cube，或按 HueSatMap 语义做 hue/sat twist），GPU `GL_TEXTURE_3D` + LINEAR 一次采样；目标参照 = 厂商直出
- **P2 补 DNG 标准矩阵链 + 感知白平衡后移**：`ForwardMatrix1/2` + `CameraCalibration1/2` 双光源 CCT 插值（DNG 内已有，引擎未用）
- 真机项：**vivo 直出同场景对标**、桌面 Lightroom 开 DNG、色温灰卡精校（WB_CAL_R/B）
- 待用户确认："直拍 RAW 没有色彩"指成片寡淡（已量化）还是 DNG 在第三方软件中无色
