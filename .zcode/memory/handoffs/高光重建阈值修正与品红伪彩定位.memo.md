# 高光重建阈值修正与品红伪彩定位

## Summary

从"修 `hr_wavelet` 误重建"出发，逐行对照 darktable `filmicrgb.c` 找到 **`threshold` 语义偏差**并修复：色块消失，真机 `clipB` 从 523~601/3072 块降到 **2**。随后五轮追品红（chrominance 偏大 3.7×、换统计源反而更红已回退、禁用 chrominance、关闭 inpaint 彩色噪声），**最后靠"把全部品红像素标出来"才发现前几轮测错了区域**——品红不在天空，而在**逆光悬挂物边缘的伪彩（紫边）**。翻 PC 源码得到答案：PC 用 `MeasureMoire` 逐像素伪彩强度图驱动色度降噪，我们没有这一环。

## Done

- **`hr_wavelet` 阈值语义修正**（`fd6fac8`，exp19=0.10.121）：逐行对照 `filmicrgb.c:3120` 后确认唯一实质偏差是 `threshold`——原版 `2^(white_source + reconstruct_threshold) × grey_source`（后者默认 0）⇒ **threshold = 白点**，我们写死 `1.0`。改后真机 `clipB` **523~601 → 2**，色块消失
- **逐行核对并排除的三处**：mask 公式/feather、`init_reconstruct`、RGB/RATIOS 两轮组合（先 RGB，`success_1` 后跑 RATIOS）；另核对 B-spline 核与边界 clamp、scales、gamma/beta/delta、HQ=1、`noise_distribution=GAUSSIAN` 全部一致
- **新诊断字段**：`hrWhiteEv`（HR 输入域白点）、`hlSum`/`hlCnt3`（chrominance 分子与分通道样本，`fedc7ca`）
- **chrominance 偏大 3.7× 定位**：同 DNG、同增益下引擎 `G −0.250` vs 原版公式 `−0.047`；`hlCnt` 接近（47269/48925）而 `hlSum` 差 4 倍 ⇒ **不是样本集合问题，是输入被降噪**（P0 空间 bilateral 把饱和像素旁的 G 压低）
- **禁用 opposed chrominance**（`d7257a1`，exp22=0.10.124）：同场景成片亮部洋红像素 **6.21% → 0.83%**、B/G 1.040→1.019
- **关闭 inpaint_noise**（`bc6e8ee`，exp23=0.10.125）：`noise_level` 0.2→0，并跳过恒等 pass
- **品红定位（本窗口最重要的一步）**：把成片里全部 `mag≥10` 像素标出色块后可见——**100% 集中在逆光悬挂物（衣服/毛巾/树枝/挂绳）边缘**，天空本体几乎没有；该区域成片 **14.74%** 品红、RAW 域（双线性+CCM）**21.14%** ⇒ **整条链只压掉 30%**
- **PC 源码对照**（`/tmp/photoncamera`，降噪已 C++ 化）：`mgc_full_resolution_denoise_jni.cpp:1021-1064` 显示 PC 在 `RawToYuv` 后跑 **`MeasureMoire`**（输入 Y 平面，输出 **1/4 分辨率 3 通道强度图**），其输出**替换**送给 `ChromaDenoise` 的强度图（注释原文 *"replaces only the strength map supplied to ChromaDenoise; Pecan keeps strength"*）；`ChromaDenoise` = **四级色度金字塔** + **4 level × 3 通道 × 2 branch** 独立 shot/quadratic/read 噪声表 + 频响参数

## Decisions

- [2026-10-03] **threshold = 曝光前域白点**，即 `max(2^(ev_white_ − exposure_ev) × 0.1845, 1.0)`；取曝光前域是因为 `kFsFilm` 内部才乘 `2^ev`。下限 1.0 = `2^2.4383EV × kGrey`，与 `kWhiteSat` 同源，防 0.10.17 的 0.5 事故重演
- [2026-10-03] **chrominance 置 0**（有数据支撑地偏离原版）：原版该补偿的前提是"输入为单帧未降噪 RAW"，我们的输入是 MFNR+P0 之后，`v−refavg` 被系统性拉负、补偿方向反了。安全性经四张 DNG 验证：另三张 `chroma_G` 仅 +0.015~+0.022，禁用前后 R/G 差 0.007
- [2026-10-03] **inpaint 噪声取边界值 0**（原版 `noise_level` 是用户可调 0~6、默认 0.2）：裁剪区纹理改由邻域 LF/HF 外推提供
- [2026-10-03] **伪彩感知的色度降噪**（用户拍板"做"）：按 PC 结构补"逐像素伪彩强度图 → 驱动 P4/D-1"，替代当前的全局统一参数

## Pitfalls

- **测量区域错一步，后面全白费**：前几轮测"窗户上部天空"得出"品红 2.1%、已修好"，而该 ROI 混入了室内白天花板把结果稀释；真正的品红在悬挂物边缘（**14.74%**）。**下结论前先把指标画成图看位置**
- **坐标尺度混用会让结论完全反向**：把全分辨率（3072×4080）坐标用在缩略图（1777×2360）上裁剪，得到"双线性 21% vs 成片 0%"的假对比
- **改一处要沿数据流检查所有受影响点**：exp21 把 mask/chroma 的输入换成 P0 前的 `tex_fused_` 时**顺手把 apply 的判定也换了**，修复面 47269→63903 样本 ⇒ 修得更多、画面**更红**；真正该改的只有统计源
- **opposed 的 chrominance 依赖"输入未被降噪"这一隐含前提**：换域/换降噪顺序后它从补偿变成放大器（引擎比原版偏大 3.7×）
- **`noise_level` 是相对白点的比例**：`sigma = pix × noise_level / threshold`，我们 `threshold`=1.0（RAW 饱和点）而 darktable 白点远高于数据最大值（本例 9.6 vs 1.4）⇒ 同等公式下相对幅度是它的约 3 倍，逐通道独立 ⇒ 彩色颗粒
- **"物理极限"不能当作结论交差**：用"三通道全饱和、信息已丢失"解释品红残留，但实测覆盖率仅 1%（去色方案几乎无效）⇒ 该解释当时就不成立；**给出解释前先用数据验证它的量级**

## Next

1. **实现伪彩感知的色度降噪**（当前最高优先）：先在 DNG 上离线验证"色度高、亮度平坦"判据在该区域成立，再改动 P4（`kFsChromaDenoise`，7×7、半径 3）与 D-1（半分辨率 à trous）的强度；PC 的 `MeasureMoire` 本体是编译好的 Halide capsule（`mgc_demoire_capsule.bin`），算法公式不可读，只能按其输入输出位置自建
2. **品红验证口径**：改完后用 `mag≥10` 占比 + `σ_HP(R-G)` 在**悬挂物边缘区域**（不是天空）验收，成片当前 14.74%
3. **亮部亮度降噪**（保留）：亮部 σY 我们 0.82 / PC 0.49（1.67×）；P0 全图只降 21~32%，亮部为何更弱待查
4. **拍板项**（保留）：影调 `whiteEv` 默认值（4.0 / 6.x）；超广畸变方案（完整 / 部分 / 不校正）
5. **窗户场景采集曝光只给 12ms**（保留）：客厅同类场景给到 100ms
