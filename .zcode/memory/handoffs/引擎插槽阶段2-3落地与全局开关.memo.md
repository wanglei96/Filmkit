## Decisions

- **[2026-10-14] `[35]` auto_tone 必须旁路**：它**不经 uniform** 生效 —— `updateFilmicEV` 在 `passFilm` 里**无条件调用**（`:14014`，只有 program 重建在 `if` 里）⇒ 成员变量 `last_still_w999_`（`:13865`，由 `auto_on` 门控）→ `sw999` → `sceneHighlightEv()` → `ExposurePlanner` 欠曝量 → 成片 `[0]`。原判"由 shader 结构自动旁路"**错误**。
- **[2026-10-14] `[28]` 的旁路值是 1.0 不是 0.0**：引擎 1 的 `kFsSigmoidMain`（`FrameRenderer.cpp:6603`）**复用 `uToneK` 作为 sigmoid 整条曲线的权重**（`if (uToneK > 0.0) { toned = sigmoidTone(out3); … }`，`sigmoidTone` 全文件只此一个调用点）⇒ 置 0 = **引擎 1 空转**。我原推理 `mix(lin,toned,0)=lin` **只在引擎 0 成立**。
- **[2026-10-14] `[22] sat_high` 必须入表**：一个「饱和度」滑杆**同写三槽** `[20][21][22]`（`writeSaturation`），只钉两槽会留"高光档仍跟用户值走"的**半旁路**。
- **[2026-10-14] 未注册 `engine_slot` ⇒ 按 0 处理、不旁路**（与 C++ `warnEngineSlotUnavailable` 降级一致），否则会出现"引擎 0 + filmic 参数被清零"的**第三态**。
- **[2026-10-14] 新增判据 0：引擎 1 必须真的改变画面**（指纹 `0x8fdb4e38` ≠ 空转 `0x189e4126`）。原六条是**纯负向**判据（"filmic 不该影响引擎 1"），一个"把引擎 1 关掉"的实现能让它们**全部通过**。
- **[2026-10-14] 设置页三档语义（用户选方案 C）**：跟随预设 = 每条预设用自己存的 `[98]`；强制 = 全局覆盖。**只作用拍照链路** —— **编辑器不参与 override**（编辑旧照片应按拍摄时的引擎，否则改个设置页开关旧照片全变样）。
- **[2026-10-14] 引擎 override 的实现要害**：**必须把 `[98]` 真的改写成 `effective`** —— 只旁路不改 `[98]` = "引擎没换、filmic 参数被清零"。渲染侧用变异检验证明该判据能红。
- **[2026-10-14] 「饱和度」在引擎 1 下整体隐藏**（用户拍板）：宁可丢掉 `[22]` 的真能力，也不留一个只调高光的半假滑杆。P1 修复后三槽全失效 ⇒ **由通用判据自动达成**，我一度加的产品级例外 `UI_HIDDEN_PARAM_KEYS` **已删**（能自动推导的判据不要显式声明）。
- **[2026-10-14] 出包放项目根目录**（用户明确纠正）：`filmkit-<versionName>.apk`，不放 `test_temp/`。

## Pitfalls

- **[2026-10-14] ⛔ P0：`[28]=0` 让引擎 1 完全空转，而六条判据全部会通过**（我引入，验证卡抓出）。实跑指纹：引擎 1@`uToneK=0` 与"引擎 0@`uToneK=0`"**逐字节相同**（`0x189e4126`）。**教训：判据集里必须有正向判据（"它真的在工作吗"），纯负向判据会集体放过"什么都没做"。**
- **[2026-10-14] 假绿陷阱：探针取值 == 恒等值**（旁路卡自查抓到）：`[20]/[21]/[22]/[28]` 的恒等值**都是 1.0**（`[35]/[36]` 是 0.0）⇒ 探针若取到恒等值，"旁路生效/没生效"给出同一数组。⚠ **契约改值会翻转既有用例的假绿面**（`[28]` 从 0→1 之后才出现）。修法 = 逐槽守卫断言 `assertTrue(v != NEUTRALIZE[slot])`。
- **[2026-10-14] "隐藏开关" ≠ "旁路"**：三条链里只有**拍照链**的引擎注入段随 `[98]` 换；`kFsStyle`（编辑器）与 `kFsOut` 不随 ⇒ `[28]/[20]/[21]/[22]/[36]` 走**公共段**、`[5..10]/[37]/[38]` 走**编辑器曲线段**，必须**在参数组装处置恒等值**才算旁路。
- **[2026-10-14] 我的一处实证错误 → 又由我复核驳回验证卡的一半结论**：验证卡报的"`[35]` 漏径 B（HR 白点）"**不成立** —— `runHighlightReconstruct` 内是 `(void)white_ev_input_domain;`，v0.10.145 起 threshold 只依赖 `CCM 第二列 + kSaturationNormCalib`，**不随白点/色温漂移**。⇒ **双重复核要双向**（我采纳它的漏径 A、驳回漏径 B）。
- **[2026-10-14] 验证卡报告的行号归属也会错**：它写"`updateFilmicEV` 四个调用点（`:8286/:8307/:8486/:11091`）"，实为 **`passFilm` 的调用点**；`updateFilmicEV` 全文件**只有 1 个调用点 `:14014`（无条件）**。这个区分是本质的 —— **只有一个且无条件 ⇒ 躲不开**，成员变量副作用才逃得出引擎边界。
- **[2026-10-14] 用户样片不能直接 A/B（两条）**：① 构图位移 —— 用户给的"同场景对比"实测中心块最优位移 **−74/−52 px**（11 秒手持），逐像素差 11.6 LSB 全是错位伪影，**必须改用直方图分位数口径或固定机位**；② 用户两次"明确改了引擎"拍的其实**都是引擎 1** —— 判引擎归属**只能读日志 `engine.film_src` 的时刻序列**，不能靠肉眼或文件名。
- **[2026-10-14] 日志陷阱：引擎 1 下 filmic 字段仍在变**（`updateFilmicEV` 无条件跑，uniform 落 −1 被丢弃）⇒ 引擎 1 期间 `raw.render` 的 `fCon/whiteEv/fPow` 有值且会变，**不能据此推断 filmic 还在影响画面**。判定引擎真工作的机器判据 = **`tone=1.0`**。
- **[2026-10-14] 并行卡的裁决必须同步给所有相关卡**：我把 `[35]` 的裁决只发给旁路卡、没发给正在写审计测试的验证卡 ⇒ 那个文件里出现两条互斥断言，全量红 3 条（假红），排查了一轮。

## Next

1. **真机验收（阶段 3 + 3b）**：清单 `docs/reports/stage3-acceptance-CHECKLIST.md`（判据 0–7）。**先验判据 0**（引擎 1 必须真的改变画面，`tone=1.0`）；判据 2/3 不能在引擎 1 下拖滑杆（控件已隐藏）⇒ 唯一路径 = 引擎 0 下改预设 → 切引擎 1 → 套用，**每步配引擎 0 的正对照**；判据 5 必须用**成片**比（预览链有 EMA 状态）。
2. **判据 ① 的真机证据仍缺**：需 ① **固定机位**（否则构图位移毁掉逐像素对比）② 画面里有**真正过曝区**（用户现有样片 `≥250` 只占 0.001%）③ 成片比。新包的设置页三档开关正好用于快速 A/B。
3. **两条已知边界（暂不动）**：① `engine_override` 键名字符串两侧各一份（渲染侧硬编码 / UI 侧常量，靠源码对拍测试守着）；② 三处 gate 不订阅 prefs 变化（每次重组读一次）⇒ 极端情况下白点行显隐晚一步，**渲染侧永远正确**。
4. **用户可能想定的产品问题**：当前切引擎"观感差异很小"（同白纸口径对齐的结果，中灰 0 LSB / 全图 p90 1.1 LSB）—— 若要"明显风格差异"，选项 = 给 sigmoid 加参数面板（contrast 可调）/ 改默认 contrast（代价：与 filmic 不再同口径）/ 保持现状。
5. **下一步大方向（既有计划）**：10bit HEIF 交付链 + 公共工作空间切 Rec.2020 线性（**必须单独一期**，与插槽重构同期会毁掉零回归判据）。
