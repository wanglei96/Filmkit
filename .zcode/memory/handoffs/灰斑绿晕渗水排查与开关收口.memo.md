# 灰斑绿晕渗水排查与开关收口

## Summary

10-28~10-29 两天围绕"高光灰斑 / 绿边 / 阴影渗水边"跑了 0.12.102→0.12.167 约 60 个包。
真正定案的只有两件：**Bento collar flow 自 0.12.122 起是 no-op**（已修），
**锐化过冲限幅 ±0.4→±0.12 让"渗水边"回到用户可接受**（167 默认画面确认）。
灰斑本体未定案；D4 大半径 USM 是错误方向（会毁画面，已默认关）。

## Done

- [2026-10-29] **Bento collar flow 修复**（0.12.161）：`uOff.w` 恒为 1.0（打包时 `pack`
  初始化 `1.f` 只写 x/y），而 `kFsCollarFlow` 首行判据 `c.w >= uMinSupp` 恒真 ⇒
  **整个 pass 自 0.12.122 上线起就是 no-op**。改法 = GPU 出 support（参考帧 RAW 的
  `clipped==0`）× CPU 做 8-连通分组/collar/全图中值（照 `BentoRegionAdmission`）。
  真机 `collarSupp=765 / collarRegions=2 / collarTiles=3` ⇒ 确实在跑，但全图只 3 个
  tile 命中，与大面积灰斑无关。自检 `tools/check-collar-flow.py`（5 用例）。
- [2026-10-29] **色差域 3×3 中值**（0.12.162）：`kFsColorMedian`（darktable
  `color_smoothing` 原版）+ `passColorMedian` 两趟。离线（地砖 D4）紫像素
  5.86%→4.15%、平均色度 −2.5%。日志 `cmOn`。
- [2026-10-29] **锐化过冲限幅 ±0.4 → ±0.12**（0.12.163）：`sharpenLuma` 的 USM 在阶跃
  处亮侧提亮/暗侧压暗，±0.4 = 最多 40% 过冲。离线量化显示域过冲 13.5→8.4 LSB。
  **用户 10-29 11:28 确认"默认设置下阴影正常了"** —— 这是本轮唯一被真机验证有效的
  改动（164 只有 dump、165 是 USM，用户跳过了 163/164 直接装 165）。
- [2026-10-29] **D4 大半径 USM**（0.12.165）：1/8 低频 + 相对增益，位置在 tone 之前。
  离线能把亮缝 25→18px、对比 5.80→7.69×（无暗环；r=6 会压暗背景 65% 故不用）。
  **但它没开关、强制进成片，用户反馈"画面毁了"** ⇒ 0.12.167 改为 FilmParams[100]，
  **默认 0 = 关**。
- [2026-10-29] **设置页三个开关**（0.12.166/167）：高光滚降 `[99]`（默认开）、
  高光重建 `[45]`（去掉 `if (!bracketOn)` 隐藏，bracket 下也能关）、D4 USM `[100]`
  （默认关）。FilmParams kCount 99→101，`neutral()` 显式写 `[99]=1.0 / [100]=0.0`。
- [2026-10-29] **剖面 dump**（0.12.164）：`raw.render` 新增 `d4Y` / `fmY`（4 条水平线
  × 64 点、3 位 hex），用于一次拍摄定位"平台在哪一层"。

## Decisions

- [2026-10-29] **D4 USM 默认关**：它是"收窄暗部软边"的实验手段，不是修复。默认开会
  改变全图观感且用户判定画面被毁。
- [2026-10-29] **锐化限幅保留 ±0.12**：边缘过冲减半且不影响正常纹理（detail/l0 在
  纹理上 <0.1，撞不到限幅）。
- [2026-10-29] **不改 tone curve 补对比**：用户明确拒绝（"改你妈影调"）。实测 RAW
  亮缝 34px、我们 D4 26px、AHD 14px，AHD 那个 14px 是去马赛克锐化伪影，不是真值。
- [2026-10-29] **Bento 只做到 PC 语义的子集**：support 是二值（缺 agreement 项，需
  反向金字塔对齐），故 collar 权重只有 1/d²。

## Pitfalls

- [2026-10-29] **跨 libraw 的坐标映射必须用亮度剖面互相关验证**：色比图对转置不敏感，
  给出了 0.94 的假相关（错映射），导致整轮 RAW 结论作废；正确做法是二维剖面搜索
  （正确映射相关 0.831，错误 −0.198）。
- [2026-10-29] **"名不副实"第二例**：`passColorSmooth` 注释写"darktable color_smoothing
  逐行移植"，实现却是判据式去饱和（梯度门 + 局部色度峰），且梯度门 `|∇L|·255 > 6`
  在暗部（L≈0.05、∇≈0.01 ⇒ glen≈2.5）**恒不打开**，实测只改 0.05% 像素。
  （第一例是 Bento support。）
- [2026-10-29] **硬编码进成片的实验改动必须有开关**：0.12.165 把 USM 无条件接进 film
  之前，用户装上后"画面毁了"且无法关闭。
- [2026-10-29] **离线链缺 LSC/HL/AMaZE 时不能用它下"某 pass 无关"的结论**：离线 P0
  on/off 的 D4 差 <1%，但真机 P0 吃的是融合 mosaic + 真 LSC。
- [2026-10-29] **用户否决过的方向要记牢**：关降噪（灰斑）、换去马赛克、改 tone curve
  都已被用户明确否定；本轮反复踩，浪费大量轮次。

## Next

1. **灰斑本体仍未定案**：需要用 `d4Y/fmY`（0.12.164 起）拍一张真机，确认"平台"在
   D4 还是 film 层；D4 平滑而 fm 有平台 ⇒ film；两者都平滑而 JPG 有 ⇒ kFsOut。
2. **锐化限幅是否再降**（±0.12 → ±0.06）待用户拍板；再降会让高反差处变软。
3. **横向色差校正从未启用**：本张 `caApplied=0`、`caKraw=[5.3e-05, 8e-06]` 低于门限，
   若阴影边缘仍有紫/绿边，这是现成的未启用路径。
4. **AMaZE + CCM 比 AHD 多产生 2.1× 紫像素**（D4 层实测 5.37% vs 2.50%），若紫晕复现，
   治本要落在 AMaZE 的色度外推约束。
