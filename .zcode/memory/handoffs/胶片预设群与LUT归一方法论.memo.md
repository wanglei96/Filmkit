# 胶片预设群与LUT归一方法论

## Summary

内置预设从 3 条扩到 7 条（理光正片 / 富士NC / 哈苏自然 / 柯达5219），每条都走完"样片证据 → 引擎 → LUT 可用性 → 配方 → 出包 → 真机迭代"全流程。过程中沉淀出三套可复用工具（LUT 亮度归一、暗部加深/压黑、官方样片统计）与一条硬结论：**预设要携带参数配方就只能锁 filmic**。5219 经历五轮真机反馈（深蓝 → 压黑 → 颗粒/高光 → 误用摄影师 LUT → 回退），徕卡暗角两轮（过渡生硬 → 直接去掉）。

## Done

- **[2026-11-01] 理光正片（0.12.215）**：19 张 GR 官方正片样片 + 3 组 Positive↔Negative 配对（亮度匹配后按色相桶）实测 delta：红 Δh −7.9°/C×1.07、绿 Δh −14.1°/C×1.11、蓝 C×1.45；灰轴暗暖→中冷→**高光回暖 +0.64**（负片是 −1.9）。新烘 `ricoh_positive_v1.lut`（64³）+ 预设 `builtin_ricoh_positive`。
- **[2026-11-01] 富士 NC（0.12.216→217）**：官方样片拿不到（SPA + Cloudflare），改验收现有 `fuji_nc.lut` —— 色彩方向对（暗部 a\* −2.8 青绿、中高光 a\* +3.1 暖品），但**白点被压到 91.8%**（filmic 白点救不回）。`normalize-lut-luma.py` 只换 L\* 保留 a\*/b\* → `fuji_nc_v2.lut`。真机拍吸顶灯出现**品红色带**：源 LUT 在 80~97% 把白染粉（a\* +2.8~+3.6），97% 处 R 先撞 255 造成 a\* 突变 ⇒ 加"高光去色"（判据用 **min(R,G,B)** 不是 L\*，否则亮黄被洗白 C\* 96.9→10.7）。
- **[2026-11-01] 哈苏自然（0.12.218）**：拿到官方一手样片（hasselblad.com X 系统 84 张，取 13 张）。**灰轴逐张散布 ±5、符号不一致 ⇒ HNCS 不系统偏色**，不能给它加冷调。复用 `hasselblad_classic.lut`（探针色相 0°、灰轴 0、肤色 C×1.23），只补饱和（我们 C\* p50 7.5 vs 哈苏 11.3，同一脚本同口径）。
- **[2026-11-01→02] 柯达 5219（0.12.219→225）**：原资产可用（暗部 b\* −4.8、高光 +1.9、压白仅 2.7%），**不归一**（归一会让纯青偏 −20°）。真机四轮：①暗部蓝偏淡（成片 −2.5 vs 目标 −4.8，因为 filmic 把暗部推到 LUT 浅蓝段）→ `adjust-lut-shadow-blue.py` 按 L\* 高斯下压；②仍嫌灰 → 提饱和（**无效**，见 Pitfalls）→ 压黑（base fog 12/255 → 0.5/255）；③外部评审指颗粒缺失/高光冷 → `grain 12/500` + `[24] split_cool −0.30`；④误用摄影师 LUT（见 Pitfalls）后回退。
- **[2026-11-02] 徕卡暗角（0.12.226→227）**：真机测径向衰减 0.7–0.8 只降 0.4、0.9–1.0 降 6.7（末端加速）—— 角落 cplen 1.252 落在余弦 t=0.73（最陡段）。改 65/70/−0.20 后末端落进平缓尾部；用户仍觉"跟噪点一样"（暗部压进 8bit 色带）⇒ **直接去掉暗角**（M9 机内 JPEG 默认开镜头暗角校正，原厂本就没有）。
- **[2026-11-02] 新工具三个**：`tools/normalize-lut-luma.py`（含 .cube 解析、高光去色、暗部端点保护、白点容差参数化）、`tools/adjust-lut-shadow-blue.py`（暗部 b\*/a\* 高斯偏移 + 压黑）、`tools/hasselblad-sample-stats.py`（官方样片灰轴/亮度/色相统计，报告数字可复跑）。
- **[2026-11-02] 四份报告**：`docs/reports/{ricoh-positive,fuji-nc,hasselblad-natural,kodak-5219}-calibration-20261101.md`，含证据表、判据、未决项。

## Decisions

- **需要"参数配方"的预设必须锁 filmic**：sigmoid 的 shader 只有 `sigmoidTone(out3)` + 7 个编译期常量 uniform，**没有任何从 FilmParams 读取的通道** ⇒ 选 sigmoid 时 [4]/[5..10]/[37][38] 全部旁路，预设退化成"换个 LUT"。7 条里 5 条锁 filmic，理光负片/徕卡黑白缺省（走 sigmoid）。
- **LUT 只做色彩、影调归 filmic**：归一 = 逐格点把输出 L\* 换回输入 L\*、保留 a\*/b\*；超域点**硬裁**（保色相缩 C 会把亮黄/青砍到 0.46~0.63，画面上更难看）。
- **摄影师调色版只能借指标、不能搬色彩**：它的中高调灰轴带绿（a\* −2.4~−3.7，调色师签名 + 扫描基底），照搬会让白墙发绿。
- **压黑可以去掉负片 base fog**：5219 的"最黑处 4.7%（L\*11.6）"是画面蒙灰的物理来源；`L_new = max(0, L − 8·(1−L/15))` 只动 L\*15 以下。
- **人工暗角不是原厂特征**：M9 机内默认开镜头暗角校正，原厂 JPEG 几乎没有暗角；我们加的 −20% 是自创，且在暗部产生 8bit 色带。
- **颗粒按胶片物理，不按"机内默认"**：DLT 是"减少暗部颗粒"不是消除；500T 加 `grain 12 / size 500`（[27] 就是 ISO 语义）。
- **外部 AI 评价只采纳"能在数据上找到位置"的条目**：三条评价里两条（绿偏亮、高光硬）数据不支持。

## Pitfalls

- **"发灰"别急着提饱和**：`C* p50` 被白墙/桌面主导（89% 像素 C≈0），`sat` 对它们零作用 —— 提 1.18 时 C\* p50 只从 3.2 变 3.1。真正的灰来自 LUT 抬黑。
- **判据基线写错会冤枉自己**：压黑/加蓝的 L\* 判据若拿"输入灰阶 vs 输出"比，会报 5.65 失败——那是源 LUT 自身的提中调（50%→56.5%），不是改动。基线必须是"改动前 vs 改动后"。
- **白点判据要按 LUT 目标参数化**：电影负片的高光本就是暖白（5219 归一后三通道差 9.23/255），硬判"中性白 ≤1.5"会误杀；富士那种数码模拟才该要求纯白。
- **单张样片的外部评价容易把场景当风格**：室内白墙 + 深色桌面天然低饱和，被读成"预设发灰"。
- **我自己的两次错判**：①"DLT 降颗粒 ⇒ 不加颗粒"（DLT 是减少不是消除）；②"摄影师 LUT 归一后可直接当资产"（色偏是签名，白墙 a\* −4.1 发绿）。
- **`.cube` 解析的 reshape 顺序**：R 变化最快 ⇒ `[b][g][r]`，按 `[r][g][b]` 建网格会得到"红→蓝"的假象。
