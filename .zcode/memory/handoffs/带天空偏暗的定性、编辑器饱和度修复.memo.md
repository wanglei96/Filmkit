# 带天空偏暗的定性、编辑器饱和度修复

## Summary

从"带天空场景偏暗"入手，先证明 HAL 的 EV 补偿在 X300 上确实生效（推翻 v0.7.8 的旧结论），再连续试了四版渲染端 AE（探测 / 闭环 / 显示域 / 一次性），全部因"固定目标闭环"或"与 HAL 打架"失败并回滚。最终用 EXIF 对拍定性：**PC 与我们的采集曝光几乎相同，差距全在渲染链**（同机位 p50 98.7 vs 171.4）。同期修掉相册编辑器饱和度旋钮失效。

## Done

- **EV 补偿实测生效**（0.12.43 诊断包）：+1EV ⇒ ISO 490→931，+2EV ⇒ sec×3 + ISO×2，−1EV ⇒ ISO 减半。v0.7.8 的"X300 不执行"是把**静拍 `AE_MODE_OFF`** 的结论错误外推到整个键。
- **渲染端 AE 四版试错后全部回滚**（0.12.44→0.12.58）：显示域闭环（读屏幕 + 积分 EV）在预览链上与 HAL 的 AE 互相激发 ⇒ 室内忽暗忽亮、成片与取景器不一致；一次性大跳 + 固定目标 0.18 ⇒ 室内过曝。0.12.59 删除全部实验开关与代码路径，`CameraController` 回滚到 0.12.42。
- **0.12.60：`ev_mid` 只提不压**（clamp ≥ 0），压暗只由高光约束做 —— 修掉"HAL 已按天空压过 + 渲染再压 −0.54EV"的双重欠曝。
- **0.12.61：修相册编辑器饱和度旋钮失效**：`applyEngineScope` 会把公共段 `[20]/[21]/[22]` 置恒等 1.0（拍照链"切引擎观感不跳"的兼容策略），编辑器照搬 ⇒ 旋钮转了但参数被抹掉。新增 `EngineScope.applyEngineScopeForEditor`（跳过公共段，filmic 专属槽照旧旁路）。
- **EXIF 对拍定性**（152436 vs PC 152446）：快门 2.2 vs 2.02ms、ISO 50 vs 50、f/1.7 vs 1.7 ⇒ **采集一致**；成片 p50 98.7 vs 171.4、p25 34.3 vs 65.6、p95 194.9 vs 231.9 ⇒ PC 是"中暗部整段提起"，属 tone mapping。
- **鲁棒测光 186 样本评估**：`rob/geo` 中位 +0.16EV、68% 场景 robust 更高、散布 −0.60~+0.51EV ⇒ 接上会让画面**更暗**且散布变大，判定不接，留在诊断位。
- **提亮对天空饱和的量化**：同机位 baseEv 0 → 0.7，天空 L* 75.1→84.0、蓝天 C* p90 9.7→7.1；PC 同 L* 84 时 p90 15.8（但 PC 的输入色度更高，无法据此断定我们压缩过强）。

## Decisions

- **带天空偏暗不是测光/曝光问题**：采集已与 PC 一致，差距在渲染链的 tone mapping。
- **渲染端 AE 只做两件事**：补暗、压高光；中灰交给 HAL（它有场景判断）。
- **三条不做**：固定目标闭环（暗场景必爆）、用上一张统计（换场景必错）、在预览链上做第二套 AE（与 HAL 互相激发）。
- **鲁棒测光不接**：186 样本显示它系统性偏暗 0.16EV 且散布 ±0.5EV，不是"更稳"。
- **提亮与保天空饱和在同一条固定曲线上互斥**（C* 随 L* 下降），PC 同样如此且更淡（L* 91 时 C* 2.2）⇒ 方案定为"用户自己调 `baseEv`"，全局偏移、全场景一致。
- **要"提亮同时保住蓝天"只能动色彩科学**（darktable filmic 的 `preserve_chrominance`），属独立专项，需离线对比后再做，不在本轮顺手改。

## Pitfalls

- **`applyEngineScope` 是拍照链的兼容策略，编辑器不能复用** —— 相册饱和度失效就是这么来的；改这类共享函数前先问"它的语义是为谁定的"。
- **预览链与 HAL 的 AE 是两条独立回路**：在预览上做 EV 闭环（哪怕 1Hz）必然互相激发；"慢速外环"不是解，方向就错了。
- **节流 + 小步长 = 可见台阶**：1s / 0.3EV 被用户当场看出"每秒抬一截"；一次性大跳在暗场景直接过曝。
- **读取滞后是振荡的根因**：测量用 0.7/0.3 EMA（滞后 3 步）却给 0.7 增益，必然过冲。
- **EXIF 对拍比任何推断都快**：PC 2.02ms vs 我们 2.20ms 这一条数据，否掉了整轮"补光/测光"假设。
- **别用单场景反推全局参数**：`kSkyLift` 这类按场景算的系数换时刻就失效，用户当场指出。

## Next

- **`baseEv` 调参**：用户自定（建议 0.4~0.7），全场景一致；收 0.4 时天空 C* p90 ≈ 8.5、地面 +0.4EV。
- **若要"提亮 + 保蓝天"**：进独立专项，先离线跑 darktable `preserve_chrominance` 三模式（max RGB / luminance / XY）在现有样片上的差异。
- **bracket 白点 6.22 保留**（逆光窗 102756/100833 有效）；若回退到 4.8 需重测那两张。
- **PC 渲染差距未定论**（p50 99 vs 171）：需要 PC 同场景 0EV 对照，或 DNG 级色彩链对拍（CCM/DCP 层）。
