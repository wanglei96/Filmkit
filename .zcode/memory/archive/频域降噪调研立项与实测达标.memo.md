# 频域降噪调研立项与实测达标

## Summary

本窗口完成频域降噪专项（AGENTS.md 队列④）的完整调研与立项：修正"PC 优势 =
GCam 功率谱维纳"旧归因（MGC 合并在空间域）、取全 HDR+/NS 式 6/7 一手原文、定位
我方六维差距；把 HDR+ 式 6/7 DFT 合并做成真机可跑内核，三轮实测（含优化版）

## Decisions

- **旧归因修正**："PC 8× 优势 = GCam 功率谱维纳（频域）"不成立——MGC 多帧合并
  在**空间域**；"功率谱"是噪声模型；PC 优势构成 = 更细合并（16px 格位移场 + RBF +
  rejection + Bento）+ 五级金字塔后处理降噪（含细节回填）+ 参数化噪声模型 + 帧数。
  hdr-plus 的合并实为 L1 距离反比空间域加权（非 DFT 实现，此前记忆有误）。
  HDR+ Fig.6 批的是"全 burst 单次 3D DFT"，pairwise DFT 恰是论文正解。
- **立项顺序（用户拍板）**：**C**（σ²=A·x+B 噪声模型 + tile RMS，底座）→ **A**
  （DFT 逐频收缩合并，v2 寄存器 FFT 架构，替换/并联 kFsMfnrFuse）→ **D**（NS §3.3
  运动区补偿性空间降噪）；**B**（PC 式五级金字塔降噪）与 **E**（细位移场+各向异性
  核）为储备，待 A/D 真机画质数据再二选一。
- **A 用 v2 架构**：twiddle 查表（uniform vec2 uTw[8]，idx=(16k)/len）+ 寄存器内
  1D FFT（每 FFT shared 访问 128→32 次）；Mali 展开常量边界循环良好（无 spill）。
- **性能储备（不立项）**：8×8 tile 变体（≈÷4）、线程利用率优化（行/列阶段
  128/256→全满）；A 替换 fuse pass 后净增 ≈165–190ms。

## Pitfalls

- **GL 错误状态污染判定**：首轮 readbackOk=false 是旧代码把测量循环累积的 GL
  错误计入判定（非 Mali readPixels 组合缺陷）；**先 glGetError() 清空再执行+判定**
  是 GL 校验标准写法。
- **"预判否掉路线"被实测双杀**：旧注释以"HDR+ Fig.6 证明 DFT 脆弱"+"GPU 成本不现
  实"预删 DFT 路线——Fig.6 批的是全 burst 单次 3D DFT；hdr-plus 非 DFT 实现不能当
  反例；实测优化版 207.5ms 达标。
- **单 tile 输出 = 参考帧×窗**：HDR+ 靠半重叠 overlap-add 恢复无窗图；读回校验
  期望值必须乘窗（首版漏乘会误判）。
- **测量学**：同配置跨轮波动 ~3%（热状态）——跨变体比较必须**同轮连跑**；判据先
  写下防事后解释。
