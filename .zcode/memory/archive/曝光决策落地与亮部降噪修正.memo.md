# 曝光决策落地与亮部降噪修正

## Summary

从"NN 判死后转 HDR+"出发，把**曝光决策专项**从离线定量一路做到真机四轮迭代
（v0.10.107-exp → exp6）。离线用真机 18 帧自建合成器证明：曝光 ×N 的噪声收益 = **√N**
（解析值与物理上限逐位吻合，N=8.66 → 2.95×），代价（帧内模糊）只与 d 有关；据此实现长曝光
规划器 + 陀螺仪 motion metering + 手动曝光上限档。真机 250ms 档拿到 **ISO167**（与 Filmix 的
ISO166 同款），RAW 域噪声降到基准 **1/3.1**。

随后用户目视指出"三家对比里只有我们的盘沿有颗粒"——定量定案为**降噪强度档被当 σ 乘子 ⇒
亮部降噪近似归零**（`nzPostP90 ≈ nzPreP90` 是失效指纹），修正为"**σ 恒真值 + 强度<1 走输出
mix**"，真机 P90 降 21~29% 确认生效。同期接入用户提供的**三份 GCam 生态噪声标定**（主摄 HPB
100 张实测 / 超广 JN1 / 长焦 LYT602），并发现 `BUILT_IN` 映射**原本没有主摄条目**（主摄一直
在用 HAL 的 cam2）。最后发现**超广角桶形畸变未校正**（实测幅度 5.7%），方案待拍板。

## Done

- **离线定量（tools/exposure-lever-eval.py，新建）**：真机 18 帧 → 15 帧对齐平均作 clean 参照
  （场景 1，ISO4781/38.46ms）；注入模型 `σ²(x,N)=(s·x+o/N)/N`；逐 CFA 平面线性拖影。
  结果：解析 σ 收益 1.42/2.00/**2.95×**（N=2/4/8.66）与 √N 逐位吻合；tex_keep 只与 d 有关
  （2px 0.956 / 4px 0.918 / 8px 0.842）；细节优先口径决策边界 **d\*≈2.2px**。
  结论文档 `test_temp/exposure_lever/findings.md`。
- **ExposurePlanner（新建，纯函数 + 7 项单测）**：`曝光 ×N + ISO ÷N` 保持亮度与高光裁切不变、
  只赚 SNR；三重约束（ISO 下限 / 快门上限 / 运动预算 `t ≤ budget·RAD_PER_PX/ω`）；输出含
  `blurPx`（预估帧内模糊）供每次拍照核对。
- **CameraController 集成**：陀螺仪 `TYPE_GYROSCOPE`（1s 环形缓冲 → **矢量平均**角速度）；
  长曝光生效时取消参考帧压短；`mfnr.burst_actual` 记录 HAL 实际曝光/ISO（防 clamp 致偏暗）；
  `capture.busy` 补日志（原来静默 return）。
- **真机四轮迭代**（全部提交）：exp（首版，运动判据用 RMS ⇒ 恒不生效）→ exp2（改矢量平均 +
  删自动交替 A/B）→ exp3（撤回纹理预算放宽，恢复细节优先 2.2px）→ exp4（曝光上限手动档
  0/100/250/500ms）。
- **250ms 档真机生效**：`expCap:"250ms" expN:"8.33" altIso:167 altSec:0.2500`，与请求逐位一致；
  RAW 域 nzPreMed 0.005219→0.001688（1/3.1）、成片域 0.002104→0.000417（1/5.0）。
- **三图对比与纹理定案**：Filmix / 我们 / PC 同场景原图（test_temp/）。跨图配准后**中频相关
  0.096/-0.019 ⇒ 纹理层不可比**（我会话中一度据此下错结论，已撤回）；改为**盘沿亮白段**
  （Y≈211–224）局部精配准（Filmix SAD 8.6）定量：σY **我们 4.48 / Filmix 1.72 / PC 0.92**；
  对照茶几中间调 我们 **1.06（最好）**。碗内壁经 lag-1 自相关判别（0.939 vs 0.938）为**真实
  纹理**非噪声。
- **σ 语义根因与修正（v0.10.108-exp5，commit 3f51579）**：`denoiseParams` 里 `p0a = S·k²`
  把强度档当 σ 乘子 ⇒ σ 报小 ⇒ `d=(c−c0)/σ` 放大 ⇒ `w=exp(−0.5d²)` **指数塌陷** ⇒ 降噪近似
  归零，且散粒噪声 ∝√x 使**亮部受害最重**。真机铁证（192226）：`dn 0.45`、`p0A/nzS=0.099`
  （σ 仅真值 0.31×）、`nzPreMed→nzPostMed` 降 2.0× 但 **`nzPreP90 0.006035→nzPostP90 0.005806`
  几乎没降**。修正：σ 恒真值、`k>1` 仍作 σ 乘子、`k<1` 走 `mix`；4 个 pass（P0/P0fused/
  P0fusedTs/P4）+ uniform 结构同步改。`validate-shaders.sh` 抓到 P0FusedTs 中心值变量名是
  `ref` 非 `c0`（已修）；native 重编已核对 `.so` md5 `529384d5→0e6a5d62`。
- **三摄 GCam 噪声标定接入（v0.10.108-exp6，commit f930e9e）**：`app/src/main/assets/noise_models/`
  三份（x300_23mm/x300_15mm/x300_70mm），`BUILT_IN` 补主摄 23mm 条目。真机验证
  `raw.noise src:"builtin"` ×3 ✓；σ 修正的效果 `nzPreP90→nzPostP90` 降 21~29% ✓。
- **超广角畸变定量**：221313 竖直边拟合直线残差中位 **50.7px**（图宽 887 = 5.7%）、两侧都偏
  ⇒ 系统性桶形畸变；代码 `grep DISTORTION|LENS_INTRINSIC` **零结果**（RAW 流 HAL 不做几何
  校正，我们也没自校正）。

## Decisions

- [2026-10-02] **曝光 ×N + ISO ÷N = 亮度与高光裁切完全不变，纯赚 SNR**：收益 √N（离线解析值
  与物理上限逐位吻合）。长曝光的约束只有三条：ISO 下限 / 快门上限 / 运动预算。
- [2026-10-02] **运动判据用"1s 窗口矢量平均角速度"（Night Sight §2.3），不用 RMS**：帧内模糊
  = 曝光窗口内的角度积分，高频在窗口内正负抵消、只有低频漂移会累积；RMS 保留高频 ⇒ 严重高估
  （真机 0.030 rad/s 把预算压到 22ms，比 AE 的 40ms 还短 ⇒ 功能等于不存在）。
- [2026-10-02] **纹理预算维持细节优先 2.2px（tex≥0.95）**：曾一度放宽到 4.5px 以让长曝光生效，
  属**误读用户意见后替用户做质量取舍**（"偏一点没关系"= 不必严格 A/B，不是画质可妥协），已撤回；
  修正运动判据后 2.2px 下正常手持即允许 ~131ms（expN≈3.4），无需牺牲纹理。
- [2026-10-02] **曝光上限交用户拍板**：判据与实证冲突时以实证为准（Filmix 同机 1/4s 成功，
  而模型说需近乎静止）⇒ 设置页给 自动/100/250/500ms，固定档跳过运动限制但仍记录 blurPx。
- [2026-10-02] **σ 恒为真实噪声；强度 <1 走输出 mix、>1 才作 σ 乘子**：σ 被压小会让 bilateral
  的 `exp(−0.5d²)` 指数塌陷，降噪不是"少降一半"而是近似归零，且噪声越大的亮部越惨。
- [2026-10-02] **三摄噪声模型改用 GCam 生态标定**：HAL 的 cam2 profile G 通道比 R/B 低一半
  （物理上不该如此），而用户提供的主摄标定是 100 张实测、四通道彼此接近。装配优先级
  = 用户选定 > 内置（`nzSrc:"builtin"`）> Camera2；手动选定是**全局**的（不随镜头切换）。
- [2026-10-02] **帧数才是夜景模式的真杠杆（下一步）**：SNR ∝ √(N×T)；T 的下限由场景亮度定
  （极暗场景就是几百 ms），T 的上限由运动定，N 的上限由内存/算力定。用户提的分档
  （日间 2-3 / 较暗 4-8 / 很暗 8-16）方向正确，建议先用 8 帧 + 流式累加（8×25MB 会撞 OOM）。

## Pitfalls

- **跨图对比前必须验证可比性**：低频相关 <0.95 或中频相关 <0.8 就不许下结论。本窗口用
  "全图统计"把动态区域（电视在播视频）与视角差异一起算进去，得出"纹理差 2.6×"的错误结论，
  被用户当场纠正（"重复区域那么多，为什么不可比"）——应挑静止物体做局部精配准。
- **"噪声大"与"有噪点"是两件事**：先看 lag-1 自相关。碗内壁 σY 高（23.1 vs 19.6）但自相关
  0.939 ≈ Filmix 0.938 ⇒ 是**真实纹理**，我们保留得更好；盘沿（光滑白瓷）才是真噪声。
- **判据量纲必须与物理过程一致**：RMS 是"速度的均方根"，而帧内模糊是"角度积分"——对低频
  敏感、对高频不敏感，两者不是一回事。
- **静默 `return` 是诊断黑洞**：`if (capturing) return` 让"连按两下只有一张"完全无日志；MFNR
  渲染 ~4.3s，用户以为按了没反应。补 `capture.busy` 后即可诊断。
- **macOS 无 `timeout`（本窗口又踩一次）**；shell 管道吞退出码仍在册。
- **改了 GLSL 必须跑 `tools/validate-shaders.sh`**：它抓到 P0FusedTs 的 `ref`/`c0` 笔误——
  否则就是设备端编译失败黑屏（v0.5.13 同类事故）。
- **native 改动必须核对 APK 内 `.so` md5**：本次 exp5 的 `.so` 从 `529384d5` 变为 `0e6a5d62`，
  exp6 无 native 改动故保持不变——两次都核对过。
- **grep 的排除模式会骗人**：`grep -v NoiseCalib.kt` 让我误判"`builtInFor` 没被调用"，
  实际在 CameraController:2560。

## Next

1. **超广角畸变校正**（用户已报障，方案待拍板）：先做 **A**——请求
   `CaptureRequest.DISTORTION_CORRECTION_MODE = HIGH_QUALITY` + 探测 `LENS_DISTORTION`
   是否可用（一次编译即可从日志看出）；不行再做 **B**——引擎加 GPU 自校正 pass（按标准畸变
   模型反向映射，**去马赛克前、逐 CFA 平面采样**保相位，可复用 `linSubZ` 基建）。
   需用户拍板的取舍：校正后要裁边，**视场会窄 5~10%**。
2. **exp6 真机复验**：主摄应显示 `src:"builtin"`；盘沿 σY 应从 4.48 落到 1~2 量级。
3. **帧数档位 4→8**（用户提的分档方案）：前提是**流式对齐累加**（收一帧→对齐→累加→立即
   release），否则 8×25MB direct buffer 会撞 ART OOM；顺带把融合 shader 从 4 输入改累加式
   即可解开帧数上限。注意处理时间：当前 4 帧渲染已 4.3s，8 帧近似线性增长需配套降载。
4. 长曝光保留为"稳定场景加分项"（正常手持白拿 1.25×，无副作用）。
