# 边缘彩边专项收尾与v0.11.0发布

## Summary

v0.10.182→v0.11.0 的边缘彩边专项：新增 `[59]` color_smooth（darktable `color_smoothing` 移植），判据从"色差域中值"一路演化到"**多尺度两侧一致性 + 局部色度峰 + 去饱和**"，并把该 pass **前置到 PC3D 之前**（关键结构改动）。强紫边与蓝/绿伪彩大幅收敛，**残留少量彩边**（用户裁定"观感影响不大，先这样"）记为优化项。期间踩了两次发布级事故（FilmParams 数组越界致启动崩溃、GLSL 多行宏静默失效），均已修复并固化教训。已发布 **v0.11.0**（tag + push，包 `filmkit-0.11.0.apk` 349）。

## Done

- **`[59]` color_smooth 落地**（设置页「色差中值滤波」，默认开）：FilmParams kCount 59→60；新增 `kFsColorSmooth`（完全内联，无宏/无数组/无循环）+ `passColorSmooth` + ping-pong 纹理 + 诊断字段 `csK`/`csOk`/`csOn`。
- **判据四次演化**（每步都有真机数据支撑）：
  1. 色差域 3×3 中值（darktable 原式）→ 真机"完全没效果"（GLSL 数组参数编译失败）
  2. 多尺度两侧一致性（[3,6,12,18]）→ 覆盖 43% 但代价 −6%
  3. 局部色度峰（`ch0 > 1.05×max(两侧)` 且 `min(两侧) < 0.5×ch0`）→ 代价降到 −1.25%
  4. **前置到 PC3D 之前**（v0.10.205）→ 伪彩仍是窄带，判据才成立
- **替换策略定案 = 去饱和**（`r_t=(c0.r-c0.g)×0.15`，保色相保亮度），结构性保证"色度增加的像素 = 0"。
- **两次事故修复**：v0.10.196/197（FilmParams 数组长度 59→60 未同步 Kotlin ⇒ 启动即崩）、v0.10.198（GLSL 多行宏续行不生效 ⇒ pass 静默失效）。
- **两次真机判死并回退**：v0.10.200（梯度门 20/50 ⇒ 紫边大面积回归）、v0.10.208（PC3D 后再跑 + 搬最中性点 ⇒ 中性区染蓝）。
- **发布**：版本 0.10.209 → **0.11.0**（versionCode 349）；提交 `8c6ccfb` 已 push；tag **v0.11.0** 已 push。
- **清理**：旧 APK 31 个（~1.3GB）、`/tmp` 会话产物（14GB）、`tools/__pycache__` 全部清除。

## Decisions

- **伪彩判据 = 边缘"色度过冲"**（中心色度 > 两侧最大值），**不是**"单侧中性" —— 后者实测代价 −18~22%（19.5 万像素里大部分是真实色度边缘），结构性不可用。
- **color_smooth 放在 PC3D 之前**：PC3D 的色度平滑会把 1~3px 伪彩摊成 12~90px 宽带，一旦摊开任何"两侧一致性"判据的探测点都落在带内（覆盖率实测 0.0%）。
- **替换只用本像素信息（去饱和）**，禁止搬邻居色度 —— 邻居可能落在有色背景上，会把背景色搬进被处理像素。
- **梯度门保持 6/16（低门）**：紫边的 gL 多在 6~20 段，提高到 20/50 会让紫边只剩 defringe 单路压制 ⇒ 回归。
- **`[51]` 强边缘色度门在替换档（`[54]=1`）下不生效**：它只在 P4 里执行，而替换档旁路 P4/D-1（日志 `cgK=0` 可证）；且即使切叠加档，它也在 PC3D 之后 ⇒ 面对已摊宽的伪彩，效果有限。
- 用户当前设置基线：`[54]`=1（替换档）、`[51]`=2（实际不生效）、高光重建·RAW 域与去马赛克未改动。

## Pitfalls

- **FilmParams 加槽位必须三处同改**：`FilmParams.h::kCount` + `CameraPresets.neutral()` 的 `DoubleArray(N)` + `fromArray` 的 `if (n > idx)`；下发点还要加 `size` 兜底。漏一处 = 启动崩溃（v0.10.196 实况）。
- **移动 GPU 的 GLSL 禁用三样**：数组作为函数参数、循环内动态索引、多行宏（`\` 续行）。Mali 上分别表现为编译失败与"宏体不生效"，且**都是静默的** —— 必须给新 pass 加 `prog_ != 0` 与"本帧是否执行"的诊断字段进日志。
- **出包后必须 `aapt dump badging` 验证包内版本**：`git revert` 会连带回退 `build.gradle.kts`，随后的 `sed` 匹配串失效 ⇒ 静默打出旧版本号的包（v0.10.201 实况，用户无法区分样片来自哪版）。
- **统计口径必须与用户所见一致**：我一直统计"紫向 B>R>G"（全图 19 像素），而用户截图里最明显的是"蓝向 B>G>R"（13.9 万像素）⇒ 结论南辕北辙。
- **模板匹配在低纹理场景不可靠**（金属杆/白布条 corr 仅 0.36~0.41，会匹配到完全无关区域）；用户整图截图应按**比例换算**，且每轮必须**裁图目视复核**。
- **离线链路不含 PC3D** ⇒ 后链判据改动的离线指标不可用于决策（本轮多版"离线好看、真机判死"皆源于此）。待办：把 `kFsPc3d` 接进 `tools/engine-shader-offline.py`。
- **"中值/分位数只对邻域多数正常时有效"**：邻域也异常时（宽色带、过饱和成片）必须靠迭代或更大核，单纯调分位数无效。

## Next

1. **边缘彩边残留（低优先，优化项）**：现行 peakK=1.05/sideK=0.5/尺度[3,6,12]/去饱和 0.15。最省事的下一步 = **peakK 1.05→1.0**（覆盖↑、色度代价约 −3%）；若仍不足则去 **PC3D 内部**查它的色度重建（过冲源头）；**不要**加"单侧中性"判据。详见 project.md「进行中」。
2. **[58] 加钳后灯盘回平确认**（旧待办）：开"G 位双 pass"拍灯盘场景，对比品红峰（无钳基线 70.3，预期回 ~53）。
3. **P0 边缘结构保护评估**（旧待办）：B σ 大 46% 抹缓边缘，对照 PC Spatial RBF + Sabre。
4. **pc3d 替换档色渗观察**（旧待办）：`pc3dK` 字段 + 大色块/平坦区抽查。
5. **离线执行器接入 PC3D**（本轮新增待办）：否则后链判据改动仍无法离线定标。
