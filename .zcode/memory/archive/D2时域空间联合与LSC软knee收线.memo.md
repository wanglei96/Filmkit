# D2时域空间联合与LSC软knee收线

## Summary

D-2（亮度降噪）第一次真正落地：把 merge 阶段的 P0 从"对**已融合**结果取 9 个空间
样本"改成"对 **4 张原始帧各自**取 3×3 同相位邻域 = 96 个真正独立样本"，真机实测
P0 降噪 2.3×（此前从未测准过）。同时把"整帧噪声差 PC 4.7×"从模糊感受拆成可归因的
数字，并沿这条线定位、修复了用户报的**暗光竖线**（LSC 边缘阻尼的硬 knee 造成增益
斜率突变 → 马赫带）。D-1 色度多尺度保持超 PC。下一窗口主线：**D-2 的下一步是把
对齐精度从 128px tile 提上去**——这是"保纹理地继续加降噪"的唯一剩下的杠杆。

## Done

- **0.10.53（205）D-1 色度多尺度**：半分辨率 à trous 5 级 + Wiener 收缩 +
  detail reconstruction。真机验收：σC 1/4/8/16/32px = 0.81/0.48/0.31/0.18/0.22 vs
  PC 1.33/0.78/0.65/0.44/0.39 → **全尺度优于 PC 1.6–2.4×**；但初版 k=8（8σ）把
  幅度 2–5σ 的**真实彩色纹理**整片压掉（木纹垫被抹平），已改 **k=2.5 / revert=0.20**。
  修正后色度纹理 4/8px 追平（0.91–1.25×），2px 仍偏少（0.60–0.65）。
- **0.10.54–0.10.56 亮度各向异性核：两次真机否决后停用**。0.10.54 切向 ±16 无条件
  施加（33 点平均）抹纹理；0.10.55 加 coherence 门控收到 L=6 仍抹细纹；0.10.56 以
  `uL=0` 停用。**结论：单帧、去马赛克后的空间核在任何核长下都不可能同时保纹理与
  强降噪**（à trous 逐点收缩上限 40–50%、等方双边 r=4/8/12 无差别、各向异性长核
  ≈25–30% 且已证抹纹理）。
- **0.10.58（210）D-2 时域×空间联合 P0**（`kFsRawDenoiseFusedTs`）：对 4 张原始帧
  各自取 3×3 同相位邻域（`dx,dy ∈ {−4,−2,0,2,4}` 步长 2，全同 CFA 相位）=
  **每帧 24 个邻域样本 × 4 帧 = 96 个独立噪声样本**（注意：早期误标为 36，已更正）。
  空间核与旧 P0 完全一致（±4 mosaic = ±2 平面像素，已验证不糊），只增加时域维度
  的独立样本；值域阈值按 √(neff+1) 缩放。回退路径保留（程序/位移场/alt 帧缺失时
  走旧的融合后 9 样本路径）。
- **0.10.59–0.10.63 诊断体系**（每一条都是被误判逼出来的）：`p0s`（P0 实际样本数
  96/9）、`p0w`（中心点权重和，理论期望 26.1）、`cms`/`cmsK`（色度多尺度是否执行 +
  阈值）、`nzPre`/`nzPost`（**去信号**噪声 σ：同相位 lag-2 差分 std/√2）、
  `rmsPre`/`rmsPost`（P0 前后 tile RMS，后被证明**信号主导、不可用作降噪判据**）。
- **0.10.67（219）TPDF dither**：量化前抖动 RPDF ±0.5LSB → **TPDF ±1LSB**，并换掉
  `sin(dot())*43758` 的 hash（3072×4080 大坐标下 highp 精度不足会周期性，dither
  失效）；grain 保留旧 hash 不动观感。最平坦块相邻相同像素 44.7% → 35.6%。
- **0.10.69（221）LSC 边缘阻尼硬 knee → 平滑正部软 knee**（见 Pitfalls 的竖线案）。
  顺带把默认 JPEG 质量 95 → 100（用户本就一直用 100）。
- **工具**：`tools/check-diag-fields.py`（诊断字段所属函数 + 前置调用顺序 + 新 GPU
  程序生命周期六点核对，**出包前必跑**）、`tools/chroma-scale-eval.py`（σC 1–32px）、
  `tools/texture-fidelity-eval.py`（纹理保真 2/4/8/16px + 局部对比度）、
  `tools/check-fft-tile-cover.py`。

## Decisions

- [2026-09-30] **对标口径**：PC 对照样片同为 **4 帧**（上限 20 帧未用）→ **加帧数
  不是追平 PC 的正当路径**；帧数相同才可对标。
- [2026-09-30] **验收流程固化（口径事故五次后）**：出包前**先做同刻 100% 裁剪目视**，
  定量指标只作辅证；纹理保真必须覆盖 **2–4px** 细纹尺度；σ 必须**分解**（亮度分层 +
  色度 1–32px + 纹理多尺度），单一指标不足以放行。
- [2026-09-30] **imageStore 目标纹理一律 `glTexStorage2D`**（glTexImage2D 可变纹理
  在该 Mali 上写入全丢）。
- [2026-09-30] **D-2 的路线**：单帧后段空间核**已被两次真机否决，不再回头**；亮度
  降噪的增量只能来自 merge 阶段（加样本不加空间模糊）。**下一个杠杆 = 对齐精度**
  （现状 CPU 金字塔 SAD，tile 64@1/2 域 = **128 mosaic px 平移**；PC 是 16px 格 +
  flow 插值 + 容差断开）——空间核本身已经证明"放宽权重只会让偏差项吃掉噪声收益"。
- [2026-09-30] **D-1 收缩阈值取标准 1–3σ**（k=2.5），8σ 属过度抑制；色度纹理与
  色度噪声必须同时看。
- [2026-09-30] 量化台阶用 **TPDF dither**（三角分布、±1LSB），RPDF 只能移动台阶
  不能打散；dither 的 hash 不能用大坐标下失精度的 `sin` 风格。

## Pitfalls

- **暗光竖线案（本次最有价值的定位）**：用户报"画面左侧一条竖线，只在光线差时出现，
  开灯就没有"。定位 = 竖线在 **x=105(交付 JPEG) = 原图 x≈181 = W/17**，正是 17×13
  LSC 网格第 1 条边界；固定场景实测 `R−B` 从 x=0 的 8 爬到 105 的 52 再骤降到 26。
  根因 = v0.10.25 的**硬 knee** `f = (2.5+(gMax−2.5)·0.5)/gMax`：每格点各算各的 f，
  本机 corner=3.874 ⇒ 拐点落在第 1/2 列之间（g=3.20/2.62/2.12），硬 knee 只有 C0
  连续、**增益斜率在那里跳变**（离线二阶差 0.1438 vs 曲线本底 0.0898，尖峰正在列 1）；
  插值后是马赫带，暗光下拐点两侧噪声放大差异使其显形。修复 = 平滑正部
  `(d+√(d²+w²))/2`（w=0.3）：二阶差回到 **0.0894 = 本底**，角落增益仍压到 3.179
  （硬版 3.187）意图不变。**通则：图像增益/阈值的硬拐点都会在插值后变成可见边界。**
- **"改错位置"三连（静默失效，全部靠自查才抓到）**：① 0.10.56 加了 `if (uL>0)`
  门控却忘了把 uniform 从 6 置 0 → 核一直在跑而报告称"已停用"；② 0.10.58 按
  `vs_rot_` 替换而实际是 `vs_plain_` → 程序从未 link，运行时静默走回退路径；
  ③ 0.10.59 把诊断字段写进 `submitRawBurst` 的 `c.mfnr_kv`，而日志在
  `finishStillChain` 内发出 → 真机字段直接缺失。**规避 = `tools/check-diag-fields.py`
  六点核对（compile/link/zero/uniforms/use/delete + 字段所属函数与前置调用顺序），
  出包前必跑。**
- **指标假阳性（两次）**：① "相邻像素相同占比"曾被当作 banding 判据 —— PC 最平坦块
  高达 **77%**，但那在 Y=1.2 的纯黑区（信号本就是常数），**该指标不成立**；
  ② 用"最长停滞段"自动搜"渐变中的异常平坦带"，搜到的是本来就平坦的白墙（PC 甚至
  80 行 vs 我们 7 行）。**判据必须先在已知正/负样本上验证。**
- **N_eff 模型漏了偏差项**（0.10.65 的教训）：把 P0 空间 σ² 从 6.48 放宽到 25，理论
  上有效样本数应升、降噪应变好，**真机却是 2.38× → 1.68×（变差）**，且用户看到边缘
  断层。原因：外围样本落在略不同的场景位置（对齐只有 128px tile 精度），带来的是
  **系统偏差而非噪声**，加权平均把偏差带进来。**已回退。**
- **"平坦/平滑"不等于"没问题"**：多次误把"没有突变"当成"没有缺陷"。banding 是
  规则量化斜坡 + 马赫带（人眼放大），不是像素突变；`|Δ|` 中位恰为 1.000、44.7% 相邻
  像素相同，就是它的指纹。
- **4:2:0 不是色度损失的元凶**：`Bitmap.compress` 固定 4:2:0 而 PC 写 4:4:4，但 A/B
  重编码实测 4:2:0 只损失 **6–8%** 色度细节（2–8px 保留率 0.92–0.93）。PC 的 4:4:4
  值得对标，但优先级低于对齐。
- **JPEG 会吃掉 dither**：q95 把 TPDF ±1LSB 的效果从 26.9%(PNG) 拉回 31.2%，且
  **加大 dither 幅度无效**（±2/±3 在 q95 下都饱和在 28.8%）；q100 时才 24.9%。
  用户实际一直用 100，故此项不是其 banding 的主因。
- **诊断需要去信号**：tile RMS 是信号主导的（tile0 RMS 0.43 vs σ 0.0137），噪声降
  8 倍在 RMS 上只动 0.0002 —— 必须用**同相位 lag-2 差分**这类去信号估计量。

## Next

1. **D-2 主线：提高对齐精度**（当前唯一剩下的、能"保纹理地继续加降噪"的杠杆）。
   现状 = CPU 金字塔 SAD，tile 64@1/2 域（= 128 mosaic px）平移；PC = 16px 格 +
   flow 插值 + 容差断开。方向：细化 tile（32@1/2 域起）或局部精修；**成本要实测**
   （当前 alignMs 在 raw.render 里可读），并按项目铁律把"成本 vs 收益"摆给用户拍板。
2. **D-2 备选微调**（若对齐收益不足）：P0 值域阈值 `sr_scale`（现 √(neff+1)=2.236）、
   alt 帧加权（alt 帧 ISO 更低、噪声更小，理应更高权重，当前统一处理）。
3. **验收口径（固定）**：同刻 100% 裁剪目视（前置）+ σY 分层 + σC 1–32px +
   纹理保真 2/4/8/16px（亮度/色度分开）+ 边缘等效宽度；帧数相同才可对标 PC。
4. 未决：dftGpu 850ms 收口（瓶颈在每 tile 输入路径，非 FFT，裸内核实测 207.5ms）。
