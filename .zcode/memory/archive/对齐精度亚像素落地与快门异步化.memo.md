# 对齐精度亚像素落地与快门异步化

## Summary

D-2 最后两个杠杆——**对齐精度**与 **P0 亚像素采样**——同帧实测合起来把降噪倍数从
基线 2.56 抬到 3.68（**+43.7% / +46.5%**，残余噪声降到 70%），并证明二者是**协同
关系**：整数采样会把对齐精度整个丢掉（只换层 +2.5%，加上亚像素才 +45%）。据此
亚像素设为默认开，**D-2 正式收线**（用户：颗粒是胶片感，不是缺陷）。随后转**性能
收口**：DFT 窗函数查表让 dftGpu 冷机 850→500~550ms；JPEG 编码落盘移到后台、快门
解锁点从"渲染完成"提前到"采集完成"→ 快门间隔 **2.5s → 0.54s**。最后一步"拍照独立
线程/context"（PC 同构）真机**失败**（丢照片 + 闪退），已回退，留待带开关重做。

## Done

- **0.10.70 对齐精度**：最细精化层 1/4 域 → **1/2 域**（HDR+ §4 原版：2×2 Bayer
  平均灰度最细层），位移量化 4 → 2 mosaic px。离线基准（真 DNG 金字塔 + FFT 相移
  真值 + 链接真实 Align.cpp）p50 0.68→0.27 px（2.0~2.4×）；**错位 >1px 的 tile
  23%→5%**（中光）、55%→46%（暗光，两版都崩）。成本：对齐 +40~50%（整机 +0.1s）。
- **0.10.71–0.10.74 A/B 基础设施**：`align_l1` 开关；`alignRbMs/alignCpuMs/alignL1`
  诊断；全图 nz 中位（`nzPreMed/nzPostMed/nzN`，48960 tile）；**同帧 A/B 诊断**
  （`align_ab`：一次拍摄跑两遍，第二遍固定 = v0.10.69 基线）。
- **0.10.75/0.10.76 P0 亚像素采样**（`kFsRawDenoiseFusedTs` 的 `uSub` + `linSubZ`）：
  逐通道网格亚像素双线性替代"round 到偶数"。离线（`tools/p0-subpixel-eval.py`，与
  合成真值直接比误差）：σ=0.002 时整数采样 0.00136 **比不做邻域平均的 0.00104 还差
  31%**（错位偏差超过它换来的降噪），亚像素 0.00107；σ=0.004/0.008 好 14%/12%。
  **真机同帧 A/B +43.7%（ISO 1326）/ +46.5%（ISO 1236）**，p0w 抬高、dnMs 未见上升；
  0.10.76 起默认开。
- **0.10.73 日志非法 JSON 修复**：`std::to_string(1139.4).substr(0,5)` = `"1139."`
  非法 → 整行被解析工具**静默丢弃**（实测 4 张照片只有 1 条 raw.render 被解析出来）。
  新增 `jnum()` 替换 68 处截断；`tools/check-log-json.py` 作守卫（历史 12145 行里
  25 行中招）。
- **0.10.77 DFT 窗函数查表**：修改升余弦窗原来在内层循环逐点算 `cos`（4096 次/
  workgroup，而只有 16 个不同值）→ 改算 16 次存 shared。dftGpu **850→500~550ms（冷机）**。
- **0.10.78 第二刀（每相位 LUT + 写回并行）**：实测 789~817ms，当时判负优化并回退；
  后来确认那是**热机状态**（冷机 500~550 可复现），该判断证据不足。
- **0.10.80 JPEG 落盘移后台**：`filmkit-save` 单线程队列，主线程只做"快照参数 + 入队"
  （实测 raw.render→save_queued **8~21ms**，后台 330~350ms 并行）。EXIF 参数改为入队
  时快照（原来读 @Volatile liveIso，异步后会记成下一张的）。
- **0.10.81 快门提前解锁**：`capturing=false` 从渲染回调移到 `processRawBurst` 末尾
  （HAL 槽位其实早已被 `copyRawAndClose` 释放）；渲染回调不再清 burst* 共享数组
  （否则会毁掉下一张的帧）；在飞上限 2（`capture.busy`）。**快门间隔 2.5s → 0.54s**。
- **0.10.82**：删"多帧合成中…"提示条。
- **0.10.83 拍照独立线程/context**（PC 同构）→ **失败回退**（见 Pitfalls）。

## Decisions

- [2026-09-30] **对齐精度定案保留**：最细层 1/2 域。真机 5 帧同帧 A/B 全胜
  （+1.1~6.4%，均值 +2.9%），成本整机 +0.1s。
- [2026-09-30] **P0 亚像素默认开**（用户拍板）：+43.7%/+46.5%、细节无损失、成本未见上升。
- [2026-09-30] **两个杠杆必须一起看**：整数采样把 0.27px 与 4px 的差别抹平（只换层
  +2.5%）。任何"提高对齐精度"的改动都要同时确认采样有没有把它吃掉。
- [2026-09-30] **D-2 收线**（用户拍板）：颗粒 = 胶片感，是风格不是缺陷；降噪对标 PC
  暂缓，归到成品 app 优化阶段。
- [2026-09-30] **性能收口优先于运动补偿**（用户拍板）：参考帧已是最短曝光帧（"回最锐
  帧"待办实际已满足）；NS §3.3 补偿性空间降噪的价值随"颗粒=风格"下降。
- [2026-09-30] **CI 改为仅手动触发**（`workflow_dispatch`）：push 自动构建顶爆 500MB
  Actions 配额；出包本来就在本地做。
- [2026-09-30] **在飞上限 2 张**（1 渲染 + 1 排队），第 3 张记 `capture.busy` 并忽略。
- [2026-09-30] **拍照独立线程/context 重做必须带开关**（默认关）：失败不能再丢照片。

## Pitfalls

- **"完全冻住 1~2 秒"的根因是单渲染线程/context**：预览与拍照共用 `render.looper`
  时，1.6~3.4s 的合成链把预览的 updateTexImage 全排在后面 → 预览停更（不是掉帧）。
  **PC 对照**：预览在 `CameraGLSurfaceView` 的 GL 线程，各后处理器各自
  `eglCreateContext`（GlesMgcRawSpatialStacker / GlesMgcRawBaseFrameSelector /
  OglBokehProcessor 均可查证）。
- **0.10.83 失败复盘**：日志只有 77 行，崩溃前那张照片的记录被 fwrite 缓冲吞掉
  （只留 DNG、没有成像）随后闪退。已确认 `engine.still_start` /
  `render.still_thread_start {"ok":true,"prewarm":true}` 成功、预览正常 → context
  创建本身没问题。三个嫌疑：① `stop()` 在合成在飞时 `quitSafely()` **杀掉正在跑 GL
  的线程**；② 两套引擎实例的内存峰值；③ still context/pbuffer 跨 Activity 重启。
- **GPU 优化不能靠"减少算术量"推断**：每相位 LUT（2048 除法 → 动态索引 uniform）+
  写回并行（32→256 线程、多一道 barrier）实测更慢。
- **跨热状态比性能数字会得出错误结论**：同一 shader 冷机 500~550ms、热机 830~870ms
  （三次佐证）。**规程：冷机 + 连拍 3 张取中位**。
- **字段名会骗人**：`uploadMs` 361ms 里 **91% 是 CPU 对齐**（上传只 4~30ms）——
  先拆 stage 时间戳再判断，别照字段名推理。
- **日志非法 JSON 静默吞数据**：`"1139."` 让 4 张里 3 条 raw.render 从分析中消失，
  差点误判成"引擎不记日志"。分析前先跑 `tools/check-log-json.py`。
- **跨拍摄 A/B 全废**：连拍 3 张的 ISO 从 2368 到 10160（差 4.3×），场景/亮度/手抖
  混杂让端到端指标无意义。**同帧 A/B（一次拍摄跑两遍）才是唯一干净口径**。
- **置信度判据（残差/纹理度）两代都无判别力**：1/4 域误杀 87% 好 tile；换到 1/2 域
  后 38 个失败 tile 检出 0 个。仅留作诊断，门控继续走 mismatch。
- **暗光对齐四方向否证**：层预平滑 46%→56/65%；λ 位移罚项（旋转 5%→39%，每层加则
  88~100%）；搜索半径 ±8（46%→47%，p90 13→49）；L4 步长 1（无变化、成本翻倍）。
  结论：暗光是**信息问题（SNR<1）**，不是参数问题。

## Next

1. **拍照独立线程/context 重做**（PC 同构）：带开关（默认关）+ stop 前排空在飞合成
   （绝不杀正在跑 GL 的线程）+ 懒创建压内存 + 崩溃前关键节点强制 flush。
2. **渲染链后段 676ms**：RCD 335 + 高光重建 245 + 降噪 40。GPU pass，动它需先出画质
   A/B（用户红线：画质不降）。
3. **DFT 继续挖（冷机 500~550ms）**：先做冷机分段测量定位真热点，不再凭代码推断。
4. **单帧 RAW / YUV 拍照路径**仍跑在预览线程（本轮只迁了 MFNR，且已随回退作废）。
5. 若重开降噪：路线二选一（B 全分辨率金字塔降噪 / E 细位移场+各向异性核）；现状
   亮度差 PC **2.26×**（暗部）、色度反超 **2.3~2.9×**。
