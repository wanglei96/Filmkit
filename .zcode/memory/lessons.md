## 环境与构建（常青）
- [2026-09-18] **中文路径 AGP externalNativeBuild 报 CXX1400** ⇒ 自定义 CMake Exec 直驱 NDK；构建 `JAVA_HOME=/opt/homebrew/opt/openjdk@23 ./gradlew assembleDebug testDebugUnitTest`（系统默认 Java 8 跑不动 AGP 8.13）
- [2026-09-20] **shader 改动构建全绿仍可能设备端全黑**（设备运行时编译）——铁律：必须过 `tools/validate-shaders.sh` 且真机验证后才发版
- [2026-09-23/30] **出包与日志三坑**：增量打包残留旧 so（33.7MB vs 28.2MB、zip 条目空洞）⇒ 出包前 `rm -rf app/build/outputs/apk`；shell 管道吞退出码 ⇒ 校验类命令必须 `RC=$?` 判真实退出码（**累计四犯**）；Logger fwrite 缓冲在崩溃时吞关键记录 ⇒ 关键路径主动 `nativeFlushLogs()`，**"日志里没有"≠"没发生"**
- [2026-10-02] **native 改动必须核对进包**：比对 APK 内 `libfilmengine.so` 的 md5 + 构建日志有无重编 `FrameRenderer.cpp.o`；macOS **没有 `timeout` 命令**（两犯）

## GL / Mali 驱动（X300 实测）
- [2026-09-22] **sampler 必须始终有合法绑定**（全黑根因）：关闭态提前 return 不绑纹理 → Mali 预测执行分支里的 texelFetch → pass3_out glErr=1282 整帧丢弃。修法：init 建 1×1 恒等纹理、**无论开关都绑定并下发全部 uniform**（sampler3D 未绑定同理，v0.6.0 全黑）
- [2026-09-30] **Mali 拒绝混链 GLSL 版本**（vs 300 es + fs 310 es → "Shader languages do not match" → init 失败整链黑屏）；**glslang ES profile 的 image 格式只放行 r32f**（compute 校验用 430 core 转换，有 ESSL 严格性盲区）

## Camera2 / HAL（X300）
- [2026-09-29] **burst 必须锁所有帧的 AE**：只锁参考帧不够——alt 帧走 AE AUTO 时 HAL 在拍摄瞬间重收敛（70MM 实测 ISO +10%）→ 曝光量不守恒击穿对齐（confMed=0、位移场全零）

## UI / Compose
- [2026-09-18/22] **UI 要点**：跨会话状态必须 prefs（rememberSaveable 随子页销毁丢失）；setter 改字段后要调 rebuildRepeating；`LaunchedEffect(surface)` 对象相等性 key 在 OriginOS 恢复不换实例；stop 期间 post 失败要回滚 pending；预览框 `weight(1f)` 弹性占满是"快门调不上移"根因（用 `weight(1f, fill=false)`）；预览图分辨率必须 ≥ 显示像素且缓存名带尺寸
- [2026-10-04] M3 ModalBottomSheet 真机返回需两次 → 自绘抽屉（拦截层 + BackHandler + FilmMotion）；删除设置项必须同步锁死读取端（prefs 历史残留 true）

## 色彩、测量与链路域
- [2026-09-22] **色彩对比三条硬约束**：比 C\* 同亮度（跨链比饱和度只用 rel）、比色相按色相带拆开；手搓矩阵链先验证"中性进→中性出"；先排除三混淆项。**色度增强三错**：只增强已浓的色 = 倒置；绝对线性判据混淆饱和与亮度；成片上二次套影调曲线是错的（已过 OETF）
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**；成片反推对过曝区失效（只用 P50–P90）；**先看日志再动手**；离线复现的域差异会掩盖真相（趋势可信、绝对值不可照搬）
- [2026-09-24/28] **跨链对比三条**：① 分布级对比会被亮度映射污染（稳口径 = 同矩形区域 + 多尺度频段能量）；② **不同保真度的数据不能 A/B**；③ **工作域不是色度差主因**，大色块核心区判据可把"降噪抹色度"与"矩阵偏淡"分开

## 方法论与流程（跨窗口反复）
- [2026-09-28] **"先 100% 原版跑通，再评估删不删"（用户批评后写入 AGENTS.md 铁律）**：预删原生代码 = 主动销毁实验对照组；**简化方案替用户做取舍同罪**——以"GPU 成本不现实"否掉 DFT 路线从未实测，性能取舍必须给用户真实数据与选择权
- [2026-09-29/30] **GPU 性能直觉不可靠**：共享内存流量才是 FFT 瓶颈（twiddle 查表仅 +1%）；每相位 LUT + 写回并行实测反而更慢——**瓶颈归因与改动收益都必须变体对照实测，别按 CPU 直觉推断；字段名会骗人（`uploadMs` 91% 是 CPU 对齐），先拆时间戳再判断**
- [2026-09-29/30] **判据类改动真机频繁翻车（179→182 五版）+ A/B 口径三坑**：**改动前先穷举"该量在真机上可能的取值范围"**（用已录日志反查）、**优先修有物理实锤的错位（域/边界）而非调判据参数**；跨时刻/跨拍摄/跨热状态都会骗人（日落光照被当成算法差异、连拍 3 张 ISO 2368→10160、冷机 500ms 热机 830ms）⇒ **同刻连拍 + 同帧 A/B + 冷机取中位是唯一干净口径**
- [2026-09-30] **日志非法 JSON 静默吞行**（`substr(0,5)` 截出 `"1139."`，4 张里 3 条 raw.render 消失）→ 分析前先跑 `tools/check-log-json.py`；**"改错位置"三连全部静默失效**（加门控忘改 uniform、按错名替换致 link 未落、诊断字段写进前置串）→ **规避 = 出包前跑 `tools/check-diag-fields.py`**
- [2026-09-30/10-05] **定量口径坑 + 离线判据必须覆盖所有可感维度**：用顺手的指标代替用户判据会连坑（3×3 高通测不到 8–32px 色斑；跨图比梯度被错位污染；"相邻像素相同占比"在纯黑区 77% 根本不成立）⇒ 规程 = 出包前同刻 100% 裁剪目视、指标只作辅证；0.173 只测"紫边下降 + 平坦区色度"而**没测"色渗/大色块"** ⇒ 真机"一片红一片黄一片紫"，此后补四条色渗判据（块状色相偏移、平坦区色度-亮度相关、大色块方差、门控覆盖率）
- [2026-10-05] **"完整实现"不等于"有效"**：AMaZE 按原版完整实现（CPU 多线程 247ms@12MP、设置三档可选），离线六项指标**五项为负** ⇒ 实现完整性只是前置条件，收益必须靠在目标域上的判据说话

## 拍照线程、OOM 与对比口径（10-01/02）
- [2026-10-01] **Java OOM 绕过崩溃捕获**：JNI `SetByteArrayRegion` 里 pending exception 未清 → ART abort；`crash-latest.txt` 不会更新（只有 logcat/tombstone 有现场）；direct buffer 计入 OOM 额度（8×25MB + 成片 50MB 撞 256MB）

- [2026-10-02] **测量与判据坑合集**：AF 锁前景致 ROI 失焦（判据 = 信号崩半而 σ 正常 + 梯度中位崩）；art4 >1 只说明降噪不足；ret4 中心在 mosaic ≈36px；去直流指标测不出全局亮度偏移（曾压暗 44% 仍"达标"）；grep 的排除模式会骗人（`grep -v NoiseCalib.kt` 让人误判 `builtInFor` 未调用）
- [2026-10-02] **静默 `return` 是诊断黑洞**（`if (capturing) return` 让"连按两下只有一张"零日志）；**改 GLSL 必跑 `tools/validate-shaders.sh`**（曾抓到 P0FusedTs 的 `ref`/`c0` 笔误，否则设备端黑屏）

## 判据域、归因与品红（10-03）
- [2026-10-03] **判据域错位 + 代价与设置项两坑**：曝光判据读的是"最后渲染过的那条链"的统计（拍照前基本是**预览链**，与 RAW 归一化域差 0.58EV 且逐次不同）⇒ 既不准也不稳；为 0.1% 的像素让全图欠曝 ⇒ 噪声整体抬升（**保护少数像素前先算它占多少**）；4 个白点旋钮互相干扰的**根因不是旋钮不够而是分工错了** ⇒ **加 UI 项前先 grep 同类标题**
- [2026-10-03] **改动生效 ≠ 问题解决**（exp9 白点改动生效但白斑没退 = 假设错）；**排除法要排除干净再下结论**（白斑误判"尖峰/缺 DPC"实为饱和像素被全局 σ 误判）；**用户三次方向纠正都是对的**，我三次先按自己假设做包才回头验证
- [2026-10-03] **参数写了 prefs ≠ 进了引擎**：`toneStandard()` 恒 true 把 `FilmParams[37]/[38]` 硬编码成 −8/+4.0，黑白点滑杆静默失效 ⇒ 一整轮 A/B 无效。**改完参数必须核对引擎回读值**
- [2026-10-03] **"物理上更正确" ≠ 实测更好**（σ 的 LSC 传播推导自洽、真机却降噪猛增发糊已回退）；**用户开关实验三次命中 vs 我五次归因全错**（LSC、dn、hr_wavelet）——优先提"一次只动一个开关"的实验

- [2026-10-03/04] **测量的 ROI/对位错一步，后面几轮全白费**：ROI 混入室内天花板稀释结果、坐标尺度混用让结论反向（3072 vs 1777）、定位错 700px 产生"全 0"假象、跨图对比先验证构图（seq1 台灯 vs seq2 窗）；**自动找峰窗口会被红笔/窗外粉色物污染（先看峰位置分布再限定窗口，分区报告）**；CIELAB 放错域全盘错（= 线性→XYZ，无 sRGB 环节）；rawpy `gamma=(1,1,1)`+16bit 断言不可用。**下结论前先把指标画成图看位置**
- [2026-10-03] **改一处必须沿数据流检查所有受影响点**：exp21 把 mask/chroma 输入换成 `tex_fused_` 时顺手换了 apply 判定，修复面 47269→63903 样本 ⇒ 画面**更红**。统计口径与判定口径是两件事
- [2026-10-03] **"物理极限"不能当作结论交差**：用"三通道全饱和、颜色信息已丢失"解释品红残留，但实测该情形只覆盖 **1%** ⇒ **给出解释前先用数据验证它的量级**
- [2026-10-03] **用户指路优于自己推演**：连续多轮在 opposed/inpaint 里打转，用户一句"翻 PC 源码"直接给出答案（PC 用 `MeasureMoire` 逐像素伪彩强度图驱动色度降噪）⇒ **遇到标准做法问题先找一手实现对照**

## 品红专项、曝光事故与紫边（10-04 → 10-05）
- [2026-10-06] **离线/排查结论上真机前必须交叉验证三件事**：① **场景** —— 红笔亮场景「锐化主因」外推到台灯逆光被当场推翻（第四次方向纠正）⇒ 排查与判据必须先在**痛点样片**上做；② **链覆盖度** —— 离线全链不含锐化 ⇒ 测不到「PC3D 收益被锐化打回」（离线全改善 vs 真机关闭更优的矛盾根源）；③ **输入通路** —— PC 核尺寸公式用真机噪声模型算出 9 而非离线假设的 11（σA+σB 小 5.3×）⇒ 公式照抄但输入不同必须真机重算。**A/B 样张还必须逐帧以日志生效值清洗**（`mfnr.timeout` 回落单帧连续四轮出现；用户目视与定量可能来自不同变量 —— 紫边变淡实为替换档 13:49 切换而非 [58] 13:55 才拍）
- [2026-10-06] **移植对照实验必须做域翻译检查**：直译原版 LIM(0,1) 直接用于 WB 域（R 满阱 2.06）把 >1 削顶 ⇒ 伪造"原版 43.8 vs 我们 85.6 的 2× 放大"假象误导一轮立项；公平对照下两者 ≈ +87 无差异。**对照实验的每个常数/钳制都要问"在我们的域里等价于什么"**（`/tmp/rcd_ab*.py`）
- [2026-10-06] **判据/新分支定案前必须先量化命中率**：连坐第三次——10-04"色度高亮度平坦"判据未验证即立项被否；[57] 判据（R 满阱 & G/B 未满）在品红带命中仅 0.1%（X300 场景 G 先饱和 32%>R 19%）⇒ 整轮无效。**实现前先用真实样片/配对 DNG 离线复现判定逻辑跑正负样本区分度**（半天 vs 一轮出包+拍摄）

## 相册与预设（10-11 → 10-13）
- [2026-10-13] **"闪一下"要先分清是哪种机制，同一现象我判错了两次**：第一次按"清晰度阶跃"修（PV-1），第二次用户澄清"是屏幕闪烁"才转到转圈，第三次"一定会显示一下转圈"才锁死根因（PV-2：`bitmap` 被两个协程分别写 ⇒ 中间帧是转圈；PV-3：`Image` 参数在**组合期**取值 ⇒ 必然存在一帧"新页 + 旧页位图"）。**铁律：观感类报障先让用户描述清楚现象，不要按自己的假设先做包**
- [2026-10-13] **单测盖不到"调用点是否真用了判据"，要用源码哨兵补**：PV-3 的 M3（调用点整体绕开 `visibleBitmapFor`）7 例纯函数测试全绿 —— 本项目无 Robolectric/compose-ui-test。同类：PS-8 用 21 个旧形态符号的**反向哨兵**防回退。**mutation 也要防假绿**：一条断言 `contains("mutableStateOf<String?>(null)")` 被同文件 `editorId` 命中看似有牙实则无效；PS-10 还发现"两槽设同值 ⇒ 读错槽照样绿"，须改成另一槽设不同哨兵值
- [2026-10-13] **并行卡会互相阻塞 + "只改一个白点数"是错的**：删符号前必须 grep 全仓（PS-6a 删勾选树符号 ⇒ **测试源集整体编译失败，`--tests` 过滤救不了**）⇒ `compileDebugUnitTestKotlin` 通过要当硬判据；死白起点**不是白点的函数而是"曲线何时到顶"的函数**（只提白点重拟合，理光负片反而更差 3.55→2.65 EV）⇒ 必须在**死白起点硬约束**下重跑拟合（R-3 新增 `--hi-floor/--hi-tol`）。**根因层同类**：引擎的"白点高光感知"只在 `auto_tone=1` 生效而预设走固定 `[37][38]` ⇒ 预设白点一低就死白（待拍板）

## 引擎调研与子代理协作（10-13）
- [2026-10-13] **子代理协作两条**：① **预算耗尽会断在收尾**（5 张调研卡 3 张报告零落盘）⇒ 派卡纪律 = 先落盘骨架 + 每完成一节即存 + 限搜索次数（~15 次）+ 报告 150~350 行，**架构师不能假设子代理会产出，关键取证自己兜底**；② **「库在机器上」≠「路线是活的」**（真机有 `libarmnn.so` 但 Arm NN 已停维护；`MGC` 被文件头注释纠正为**魔改 GCam**）⇒ 清单式取证必须区分「文件存在 / 内容可读 / 路线有效」。
- [2026-10-13] **量化结论对「判据口径」高度敏感，换口径就翻转排序**：死白起点判据 ≤1 → ≤2 LSB per 0.1EV 时 filmic 与 sigmoid **互换名次**；每 0.1 EV 恰好 1 LSB 的**理想均匀曲线**在该判据下被判「从起点就死白」。**任何「某架构更好」的量化结论必须同时给出判据定义与对齐前提**（16 号报告因「同白纸亮度」前提未满足，优势从 0.7~1.05 EV 缩到 0.25~0.30 EV）—— 这正是独立复核卡的价值。
- [2026-10-13] **守卫之间会有缝 + 文件头注释会撒谎**：① `CameraPresetsTest` 守 Kotlin 硬编码长度、`FilmParamKeysTest` 守语义名表 ⇒ **"C++ `kCount` 单独漂移"两边都不红**（正是 v0.10.196 启动崩溃形态）⇒ 补 `tools/check-filmparams-contract.py` 四路对拍，**给契约加守卫前先问"哪一半事实没有任何断言在读"**；② `tools/engine-shader-offline.py` 头部声称"已接入 4. FILM `kFsFilm`"，实读 295 行**没有 FILM 段**（只到 CCM）⇒ **把某工具当判据载体前必须实读它跑到哪一步**（`steps.json`/产物清单比注释可信）。
