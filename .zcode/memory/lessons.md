## 环境与构建（常青）
- [2026-09-23/30] **出包与日志三坑**：增量打包残留旧 so ⇒ 出包前 `rm -rf app/build/outputs/apk`；shell 管道吞退出码（**累计四犯**）⇒ 校验类命令必须 `RC=$?` 判真实退出码；Logger 缓冲在崩溃时吞关键记录 ⇒ 关键路径 `nativeFlushLogs()`，**"日志里没有"≠"没发生"**

## GL / Mali 驱动（X300 实测）
- [2026-09-30] **Mali 拒绝混链 GLSL 版本**（vs 300 es + fs 310 es → 整链黑屏）；**glslang ES profile 的 image 格式只放行 r32f**

## Camera2 / HAL（X300）
- [2026-09-29] **burst 必须锁所有帧的 AE**（只锁参考帧 ⇒ HAL 重收敛击穿对齐）

## 色彩、测量与链路域
- [2026-09-22] **色彩对比三条硬约束**：比 C\* 同亮度（跨链只用 rel）、按色相带拆开、先验证"中性进→中性出"；**色度增强三错**：只增强已浓的色、绝对线性判据混饱和与亮度、成片上二次套影调曲线
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**；成片反推对过曝区失效（只用 P50–P90）；**先看日志再动手**；离线复现的域差异会掩盖真相（趋势可信、绝对值不可照搬）
- [2026-09-24/28] **跨链对比三条**：分布级对比会被亮度映射污染（稳口径 = 同矩形区域 + 多尺度频段能量）；不同保真度的数据不能 A/B；比较前确认工作域

## 方法论与流程（跨窗口反复）
- [2026-09-28] **"先 100% 原版跑通，再评估删不删"**（AGENTS.md 铁律）：预删原生代码 = 销毁对照组；简化替用户做取舍同罪；**性能取舍必须给实测数据与选择权**
- [2026-09-29/30] **GPU 性能直觉不可靠**：共享内存流量才是 FFT 瓶颈；每相位 LUT 实测反而更慢——**瓶颈归因与改动收益都要变体实测；字段名会骗人（先拆时间戳）**
- [2026-09-29/10-05] **判据类改动真机频繁翻车 + A/B 口径三坑**：先穷举"该量在真机可能的取值范围"、优先修物理实锤的错位、**同刻连拍 + 同帧 A/B + 冷机取中位是唯一干净口径**
- [2026-09-30] **日志非法 JSON 静默吞行** ⇒ 分析前先 `check-log-json.py`；**"改错位置"三连全部静默失效** ⇒ 出包前跑 `check-diag-fields.py`
- [2026-09-30/10-05] **定量口径坑**：用顺手指标代替用户判据会连坑（3×3 高通测不到 8–32px 色斑）⇒ 同刻 100% 裁剪目视、指标只作辅证；**"完整实现"不等于"有效"**（AMaZE 六项指标五项为负）

## 判据域、归因与品红（10-03）
- [2026-10-03] **判据域错位三坑**：曝光判据读的是"最后渲染过的链"统计（预览 vs RAW 归一化域差 0.58EV）；为 0.1% 像素让全图欠曝；加 UI 项前先 grep 同类标题
- [2026-10-03/04] **测量的 ROI/对位错一步后面全白费**：ROI 混入无关区域、坐标尺度混用、定位错 700px 产生"全 0"假象、跨图对比先验证构图；**下结论前先把指标画成图看位置**
- [2026-10-03] **改一处必须沿数据流检查所有受影响点**（统计口径与判定口径是两件事）；**"物理极限"不能当结论交差**（先用数据验证覆盖量级）；**遇到标准做法问题先找一手实现对照**

## 品红专项、曝光事故与紫边（10-04 → 10-06）
- [2026-10-06] **离线/排查结论上真机前必须交叉验证三件事**：场景（痛点样片）、链覆盖度（离线是否含锐化）、输入通路（公式输入真机重算）；**A/B 样张必须逐帧以日志生效值清洗**（用户目视与定量可能来自不同变量）

## 相册与预设（10-11 → 10-13）
- [2026-10-13] **删符号前 grep 全仓**（测试源集编译失败 ⇒ `compileDebugUnitTestKotlin` 通过是硬判据）；**死白起点不是白点的函数，而是"曲线何时到顶"的函数**（拟合必须带硬约束）

## 引擎调研与子代理协作（10-13）
- [2026-10-13] **量化结论对判据口径高度敏感**（换口径就翻转排序）⇒ 任何"某架构更好"必须同时给出判据定义与对齐前提
- [2026-10-13] **守卫之间会有缝 + 文件头注释会撒谎**：补 `check-filmparams-contract.py` 四路对拍；把工具当判据载体前必须实读它跑到哪一步；**里程碑式断言必须升级为"与权威源对拍"**
- [2026-10-13] **验证工具自身会假绿**：只锚整体摘要不够（块级锚点）、逐段过滤 `#version` 致整份未校验 ⇒ **判据与 mutation 自检必须同跑**

## 引擎插槽阶段 2/3（10-14）
- [2026-10-14] **⛔ 纯负向判据会集体放过"什么都没做"的实现**（`[28]=0` 空转而六条全绿）⇒ **新引擎必须配正向判据**
- [2026-10-14] **双向复核：采纳验证卡的漏径 A、驳回漏径 B**（`[35]` 经 HR 白点泄漏不成立）⇒ 复核不是照单全收/全盘否定；**读别人的行号断言前先自己 grep**
- [2026-10-14] **用户样片不能直接做 A/B**：构图位移 ⇒ 逐像素差全是错位伪影（改分位数口径或固定机位）；**引擎归属只能读日志**（`engine.film_src slot` 是唯一判据）
- [2026-10-14] **"验证工具/测试自证"也要防假绿**：变异检验（故意改坏 ⇒ 判据必须变红），**没有变异检验的"全绿"不算证据**

## 编码器标定与交付链（10-15）
- [2026-10-15] **共享成员跨帧被覆盖是复发型 bug**（快门瞬间快照冻成局部 val）；**Kotlin 块注释可嵌套**；**`gradle ... | tail` 吞退出码**
- [2026-10-19] **uniform 默认值必须等于"跳过"**（`uContrastOut` 恒等条件写成 `!= 1.0` 而默认 0 ⇒ 平坦灰 0.5）
- [2026-10-19] **"恰好 N 项"是里程碑式断言**（补挂后测试要改 N 并写明依据）；**`git stash` 回 baseline 是分清"预期红 vs 真红"的可靠手段**
- [2026-10-19] **D5 域口径是比色的前提**（`film_d5` 是 Rec.2020 线性，直接套 sRGB OETF 得假结论）；**离线 ROI 坐标必须用 RAW 坐标**
- [2026-10-19] **Ultra HDR 两条路色度不同**：`Bitmap.compress`+`Gainmap` = 4:2:0；4:4:4 + HDR 必须 libultrahdr + 自研编码器

## HDR / 图像容器（10-20）
- [2026-10-20] **GL 状态破坏会静默毁掉成片**：新 pass 必须保存/恢复 FBO+viewport，读回前显式绑回目标
- [2026-10-20] **同进程两套引擎实例**：拍照走 `g_renderer_still`、预览走 `g_renderer`；读多实例状态前先确认"我读的是不是这张的实例"
- [2026-10-20] **`sw999` 曾经是聋的**（只在 auto_tone 开时写）⇒ **判据字段"有值"不等于"在用"**；**两层保护压同一件事 = 双重欠曝**（加第二层前先问它和现有那层的关系）
- [2026-10-20] **超时定时器必须与当前 burst 绑定**（上一张的定时器误杀下一张）

## 自动曝光、编辑器与融合（10-22 → 10-24）
- [2026-10-22] **`脚本 | tail -2 && build` 吞退出码**（0.12.20 黑屏漏出）⇒ 校验脚本一律 `> log; RC=$?`；**按起止锚点整段替换注释会连代码一起删**（只删注释行，改完单独 glslang 校验）
- [2026-10-22] **全图分位 ≠ 同区域对比**（"暗部差 2EV"是假象，同区域只差 0.1~0.3EV）；**测试是设计意图的文档**（改默认值前先搜测试）；**"参数相同"不等于"输出相同"**（差异在链路别处）
- [2026-10-23] **预览链与 HAL 的 AE 是两条独立回路**（在预览上做 EV 闭环必然互相激发）；**节流+小步长=可见台阶、一次性大跳+固定目标=暗场景过曝**；**测量滞后是振荡根因**
- [2026-10-23] **EXIF 对拍比任何推断都快**（一条数据否掉整轮假设）；**别用单场景反推全局参数**；**改共享函数前先问"它的语义为谁而定"**
- [2026-10-24] **"为 A 场景加规则"必然在 B 场景炸**（采集端规则必须对所有场景安全）；**融合端的倍数与噪声同比例**（短帧跨度是"天空层次 ↔ 噪点"的直接兑换）
- [2026-10-24] **懒创建的渲染实例必须走进程快照**；**任何跨张状态都会让"预览≠成片"**；**自创机制会被当场否决（先查一手实现）**；**全屏覆盖阻塞构图**
- [2026-10-24] **融合架构三轮教训（P2 退役）**：固定输入纹理陷阱（侧帧链跑 zero 数据）；数字增益区是假 EV；对比测量必须配准；HR 门只拒 0.96 以上（0.5~0.96 肩部放行）
- [2026-10-24] **GL feedback loop**（融合 pass 输入不能与 fbo attachment 同纹理）；**自创判定在边界条件静默失效**（角色由采集端显式下发）；**σ 低估的方向是"帧回退"不是"噪点"**

## P4 基线与徕卡调研（10-25）
- [2026-10-25] **MPF 解析两坑**（一手依据 = vendored `jpegr.cpp`）：`kMpEndianSize=4`、`kMPEntrySize=16` 非 20（按 20 步长 = 静默读错位）
- [2026-10-25] **numpy 维度语义先查再写**（`np.diff(lut, axis=3)` 是通道轴 → 19059 处假警报；空间轴是 0/1/2）
- [2026-10-25] **把工具当判据前实读其输入面**（`lut-audit.py` 只认 .cube 文本，资产已是 .lut 二进制 → 越界）；**配方资产的域语义不明就不烘**
- [2026-10-25] **单张样张结论会片面**（"白位 172"是场景特例；11 张统计后修正为"高光压缩狠、≥240 中位 0.1%"）；**版本/属性验证用 aapt**（`strings classes.dex | grep -c` 两次静默无输出）

## 徕卡一瞬标定（10-25/26）
- [2026-10-25] **recipe-fit `--json` 不是测试读的文件**：`--json` 落原始记录（顶层=预设 id），`--export` 才生成 `{generated_by, presets}`（BuiltinPresetCurveTest 读它）；跑错模式 → NPE
- [2026-10-25] **拟合必须钉住既有定案**：忘钉 `--white-ev 4.0` ⇒ 白点被推到 4.59；`--lut-min 1.0` 钉 LUT 强度（默认下界 0.30 是旧 LUT 时代记账）
- [2026-10-25] **"双链撞墙"要拆链验证**：minimax 14.75 看似结构极限，单链拍照即 0.51——先确认哪条链在拖；R-1b 两链互斥在新 LUT 下依旧成立
- [2026-10-25] **样张文件名后缀 = LUT 标题**（不是预设名），无后缀 = 无 LUT；**"同场景 A/B"必须用日志核对 apply 时序**（21:04 两张看似"标准 vs 徕卡"，实际都在切标准之后）
- [2026-10-25] **diag `tone:1.000` = 引擎 1（sigmoid）在工作**：20:43 三张徕卡样张实为 sigmoid+LUT，filmic 影调槽被旁路——**真机验收口径必须带引擎槽位归因**
- [2026-10-25] **发黄归因不能拍脑袋**："暖 LED"被用户当场纠正（白光 LED）⇒ 用中性区实测（白墙/白柜 R−B）+ LUT 格点响应定性，不用"光源色温"解释；**拟合目标本身可能错**（M9 样张中高段提亮 ≠ 用户要的观感，p50 +9.3 真机裁决）

## 灰斑/渗水排查（10-28/29）
- [2026-10-29] **跨 libraw 的坐标映射必须用亮度剖面互相关验证**：色比图对转置不敏感，给过 0.94 的假相关 ⇒ 整轮 RAW 结论作废（说"反光是暗部"）。正确做法 = 二维剖面搜索（对映射 0.831 / 错映射 −0.198）
- [2026-10-29] **注释说"逐行移植"不等于实现是那个东西**：Bento support（位移场 w 恒 1 ⇒ pass 自上线起 no-op）、`color_smooth`（注释写 darktable color_smoothing，实为判据式去饱和，且梯度门 `|∇L|·255>6` 在暗部恒不打开、只改 0.05% 像素）。**移植前先跑一次"改了没有"的自检**
- [2026-10-29] **实验性成像改动必须带开关再进包**：0.12.165 把 D4 USM 无条件接进 film 之前，用户装上"画面毁了"且无法关闭 ⇒ 167 补 FilmParams[100] 默认 0
- [2026-10-29] **用户已否决的方向要记牢再动**：关降噪 / 换去马赛克 / 改 tone curve 三条都被明确否定过；本轮反复在这三条上打转，浪费大量轮次

## 高光与掩码（10-29/30）
- [2026-10-29] **"强制输出 1.0 也读回 0"必须当成独立诊断做**：它把"判据错"与"绘制链路坏"分开。R8 作颜色附件在 X300 上 FBO 完整但不落值，换 RGBA8 也没救。
- [2026-10-29] **尺寸域错配会静默吞掉整个 pass**：传 dst 尺寸给按 raw 几何实现的函数，竖拍必现、横拍偶发，日志只显示 0。
- [2026-10-30] **诊断字段自己会撒谎**：`*P/*Tx/*Prg` 全 1 只证明变量被赋值；要判内容必须打"命中数"这类实测量。
- [2026-10-30] **全图统计不能代替局部判断**：拿 hlRgG（整张场景）去决定单个高光点是否偏色，必然把中性高光判成品红。

## 诊断字段与外部对照（10-30）
- [2026-10-30] **`jnum` 第二参是字符数，不是小数位**：`jnum(x,0)` 永远返回 `"0"`；`satmHit=0` 因此骗了整整一轮（含"判据零命中"的错误结论）。判据：同一函数里另一个字段（`satmCov=4`）与它矛盾。
- [2026-10-30] **`raw.render` 的 `gm*` 恒 0 是设计**：`readGainmap` 在日志之后才跑；gainmap 真值看独立的 `gainmap.readback` 事件。
- [2026-10-30] **照注释推断外部实现会错**：先按注释把 gainmap 改成"只提亮高光"，读实现（`RawHdrReferenceMath.evaluate` 的 `if (x <= joinInput) return sampleCurve(...)`）才确认语义；而用户观感仍偏好整体提亮 ⇒ **观感以样片为准、语义以源码为准，两者可以不一致**。
- [2026-10-30] **`(void)mid;` 不是 GLSL**：Mali 宽容编译通过、glslang 报 `explicit typecast required extension`；改了 shader 常量（`constexpr` 也不存在，要写 `const`）必须重跑 `validate-shaders.sh`。
