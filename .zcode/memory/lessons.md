## 环境与构建（常青）

- [2026-09-18] **中文路径下 AGP externalNativeBuild 报 CXX1400**（路径中文段丢失）：自定义 CMake Exec 任务直驱 NDK；本机构建 `JAVA_HOME=/opt/homebrew/opt/openjdk@23 ./gradlew assembleDebug testDebugUnitTest`（系统默认 Java 8 跑不动 AGP，报 requires JVM ≥11）
- [2026-09-18] **Gradle 需写工作区外 `~/.gradle`**：沙箱 workspace-write 下报 `gradle-8.13-bin.zip.lck: Operation not permitted`，需更宽权限
- [2026-09-20] **engine shader 改动构建/单测全绿仍可能设备端全黑**：shader 是设备运行时编译（v0.5.13 非法 step 重载致黑屏）——铁律：shader 改动必须过 `tools/validate-shaders.sh`（glslang，构建期）且真机验证后才发版
- [2026-09-22] **C++ 原始字符串 `R"(...)"` 里出现 `)"` 会提前终止字面量**（GLSL 注释里「0.25(=64/255)」即触发，构建/单测都拦不住）；Kotlin KDoc 里写 `/*` 会开嵌套注释吞文件。规避：注释内数字后接括号用全角
- [2026-09-22] **`git filter-repo` 的 `reset --hard` 会删工作区副本**（本轮 3 张误提交截图不可恢复）——重写历史前先复制文件到 /tmp；**子代理调研会克隆大仓库**（filmulator-gui 184MB），提交前检查未跟踪目录体积
- [2026-09-23] **增量打包残留旧 so**（APK 33.7MB vs 28.2MB，zip 条目 offset gap 5.5MB）——出包前 `rm -rf app/build/outputs/apk`
- [2026-09-27] **shell 管道吞退出码**：`bash validate-shaders.sh | tail && ...` 的 `&&` 看到 tail 的退出码，带病 shader 曾被打进 APK——校验类命令必须 `RC=$?` 判断真实退出码；**Logger fwrite 缓冲在崩溃时丢日志**（关键路径必须主动 flush，同缓冲 FIFO 排序可反证先后）
- [2026-09-27] **mimosa git gate 误报**：env 传不进 hook、realpath 消毒无效、MCP 不被消费——只有 hash-object + update-ref 或重启客户端；**zsh 的 `status` 是只读变量**（脚本内改名 st）
- [2026-09-29] **GL 错误状态会污染判定**：spike 首轮 readbackOk=false 是旧代码把测量循环累积的 GL 错误计入；**先 `glGetError()` 清空再执行+判定**是 GL 校验的标准写法

## GL / Mali 驱动（X300 实测）

- [2026-09-18] **Mali 三坑**：① RG8 TexSubImage2D 静默全黑（无 GL 错误）→ 预览改 SurfaceTexture 系统路径；② RGBA8 FBO 误用 GL_HALF_FLOAT 永不完整；③ GLSL ES3.1 image uniform 无默认精度（S0032）→ 全部显式 highp
- [2026-09-18] **照片类三坑**：Y 未归一化（0–255 直乘系数→灰度）；Y 平面行序与 GL 纹理原点相反（左右颠倒，OES 由 STMatrix 接管/静拍输出 pass v 翻转）；STMatrix 已含裁剪翻转，引擎再叠加 center-crop = 双重裁剪
- [2026-09-22] **sampler 必须始终有合法绑定**（v0.6.0 全黑根因）：关闭态提前 return 不绑纹理→Mali 预测执行分支里的 texelFetch→pass3_out glErr=1282 整帧丢弃。修法：init 建 1×1 恒等纹理、**无论开关都绑定并下发全部 uniform**（与 LSC 关闭档同类）
- [2026-09-27] **GLSL ES 编译期黑屏级坑（glslang 可拦）**：不支持数组初始化器 `ivec2 a[4]={...}`（改条件链）；sampler 类型函数参数必须显式精度（`highp usampler2D t`，已踩两次）；**`half` 是保留字不能做变量名**
- [2026-09-28] **浮点 attachment 的 readback 组合陷阱**：R16F + GL_UNSIGNED_BYTE 在 ES 3.0 不保证、X300 静默回零（HR 统计两版从未触发）；回读改用 RGBA8 目标或确认合法组合；RGBA16F + GL_FLOAT 实测可用（X300）

## Camera2 / HAL（X300）

- [2026-09-18/19] **X300 HAL 三事实**：手动 WB 的 CCT/GAINS/矩阵三路径全不可用（解法=引擎侧补偿，勿再回头调 HAL）；隐藏物理镜头（超广 id4）持续黑帧（设置页按镜头启停）；手动对焦 HAL 报屈光度 0 但硬件支持（默认 10D 试值）
- [2026-09-18] **键名/类型凭记忆必错，javap 核 SDK**：API36 移除 COLOR_CORRECTION_RB_GAINS（改 CONTROL_COLOR_CORRECTION_MODE_CCT）；正确键是 `STATISTICS_LENS_SHADING_CORRECTION_MAP`（非 LENS_SHADING_MAP）；`SENSOR_NOISE_PROFILE` 是 `Pair<Double,Double[]>[]`（`as? List<Any?>` 永远失败、σ 自适应静默失效→`as? Array<*>`）；`SENSOR_REFERENCE_ILLUMINANT2` 是 Byte，标定矩阵键只在 CameraCharacteristics
- [2026-09-18] **session/生命周期三坑**：切镜头置 started=false 后 onConfigured 守卫放弃建 session（恢复 started + 代次丢弃）；异步清理 runnable 读到新实例（post 前捕获旧引用）；触屏对焦 ACTION_UP 不消费事件流永不送达（返回 true）
- [2026-09-18/19] **几何/方向三坑**：AF/AE 区域落点差 90°（按 k=(sensorOrientation/90+step)%4 反推）；预览 center-crop sx/sy 是四象限映射（依赖 STMatrix 换轴，4:3 时掩盖 bug，多画幅验证）；变焦倍率分母用物理焦距错（按当前镜头 35mm 等效换算）
- [2026-09-20] **统计口径与判据三坑**：阈值单阈值必闪（水平仪进入 0.4/退出 1.2° 滞回）；`controls.applied` 的 iso/sec 是滑杆存量值（AUTO 档不代表实际，日志字段语义必须回代码核实）；**EV 补偿范围因机而异**（用 evInfo() 自适应，禁写死 ±4）
- [2026-09-20] **EXIF/DNG 三坑**：Bitmap.compress 不写 EXIF（ExifInterface 经可写 FileDescriptor 补写）；DngCreator.setOrientation 只收 1..8（传 90 抛异常保存失败）；DNG OpcodeList2 内部大端而 TIFF 头小端
- [2026-09-22] **ExifInterface 兼容标签只接受十进制**（"1/125" 抛 NumberFormatException→静默丢弃），21 张成片因此缺 ExposureTime
- [2026-09-27] **ImageReader maxImages 提高且全程持有 Image 的 HAL buffer 压力**：maxImages=5+4 张 25MB 全程持有→HAL 预配 125MB→闪退（进程存活、Activity 销毁、capture 未执行）；修复=拷贝即 close，仅参考帧持 Image（DngCreator 只吃 Image）
- [2026-09-23] **controls/日志类**：`Logger` 头部注释与 `raw.render` 字段是排查主入口；**记忆库过时条目会实际误导判断**（收尾按仓库实际回写）

## UI / Compose

- [2026-09-18/20] **状态持久化与重建**：rememberSaveable 随子页销毁丢失（跨会话状态必须 prefs）；setter 只改字段未调 rebuildRepeating（控制项预览不生效）；`LaunchedEffect(surface)` 对象相等性 key 在 OriginOS 恢复不换实例（改回调内幂等 start + 生命周期感知）；stop 期间 post 失败 pending 卡 true（失败回滚+强制复位）
- [2026-09-20] **布局三坑**：预览框 `weight(1f)` 弹性占满是"快门调不上移"根因（用 `weight(1f, fill=false)`）；`weight(1f,fill=false)+aspectRatio` 空间不足时不报错只缩小（不崩但不可用，比崩溃更难发现）；Box 内 AnimatedVisibility 被 ColumnScope 遮蔽（全限定调用）
- [2026-09-19/22] **杂项**：ColorSpaceTransform 构造收 Rational[] 行主序、无下标；Kotlin 字符串里的英文双引号会截断（中文文案改用「」）；预览图分辨率必须 ≥ 显示像素且缓存文件名带尺寸

## 色彩与测量方法论

- [2026-09-21] **libraw 参照默认 auto_bright=on**（亮度自动拉高 ~2.5×）——"寡淡/饱和 −21%"是亮度差被当成色彩差；测色度首选 CIELAB C\*（与亮度解耦）、跨链比饱和度用 rel=max|cc|/luma；**"文件里没有"≠"API 拿不到"**（DNG 无 ForwardMatrix 是 DngCreator 不写，Characteristics 给全）
- [2026-09-22] **比 C\* 必须同亮度**（否则把"亮"误读成"浓"）；**比色相按色相带拆开看**（黄绿 −5.6° vs 黄橙 +1.0° = 色相相关误差非全局偏）；**"偏淡"按饱和度分箱看缺口剖面**（只看均值会误判"整体欠饱和"而错误全局加饱和）
- [2026-09-22] **手搓色彩链矩阵对比极易出错**：WB 施了两次（libraw 先 WB 再矩阵）——矩阵级对比必须先验证"中性进→中性出"；**DNG 里没有 ForwardMatrix 时 libraw 只能退 ColorMatrix，两条链不可直接等价**（libraw 的 C\* 是偏好非正确）
- [2026-09-22] **判断"某色不准"先排除三混淆项**：A/B 是否受控（曝光差 7.5 的组无效）、有无全局色偏、是否色域到顶（树叶只到 sRGB 上限 25%）；**不同构图的"哪组更好看"不构成 A/B**
- [2026-09-22] **"只增强已浓的色"是倒置色度增强**（工业做法=vibrance 增益∝当前饱和度 或 DCP HueSatMap）；**色度增强绝对线性判据把饱和度与亮度混在一起**（改亮度相对 rel 后树叶 5.05%→12.50%）
- [2026-09-22] **在成片上二次套影调曲线是错的**（成片已过 OETF）；反推必须用生成该成片的参数版本；**离线 CLI 与真机有 5–8 L\* 偏差**（场景光变化+量化损失）——绝对亮度必须真机
- [2026-09-21/23] **降噪量化特征**：σY 恰降 1/2.8 + 强档无变化 = 值域权重饱和/退化成无条件平均（JPEG 体积腰斩同根因）；**σs 不是旋钮**（r=2 下 σs>2 被截断，1.6→2.2 只改善 6%）；**σc 调大是错方向**（吞真实色度）；**大尺度色度平滑**亮度细节保留 1.000 但色度边缘只剩 8–20%（"糊"是彩色边界渗色）
- [2026-09-21/23] **提亮是噪声的乘性放大器**（ag 2.0×lt 1.6≈3.2×，"暗部更亮"与"彩噪更低"物理对立）；**edge 指标必须两边都平滑**（否则分母含噪声，结论反向）；**全图 Laplacian 判细节损失系统性高估**（噪声当细节，正确口径=强边缘锐度）
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**（本轮抓到 rolloff 漏分支、判据取自输入两处真 bug）；**成片反推对过曝区失效、P95/P99 反推值不可信**（只用 P50–P90 段）
- [2026-09-28] **跨链分布级对比会被亮度映射污染**（固定 luma 箱的 rel 剖面在两条链间不可用；稳口径=同矩形区域统计+多尺度频段能量）；**色相+C\* 掩膜统计有幸存者偏差**（跨链物比先区域化）；**不同保真度的数据不能 A/B**（重编码副本 ICC 丢失）
- [2026-09-24/28] **工作域不是色度差主因**（BT2020→LMS 与 sRGB→LMS 偏差 0.0000）；**min 的作用域**（只在 tone 后 L\*>50 的 15% 像素生效，红杯 L*≈21 取 orig）；**大色块核心区判据**可把"降噪抹色度"与"矩阵偏淡"分开（红杯核心 C* 32.03 vs 38.63）

## 链路断裂与域（本项目核心教训）

- [2026-09-27] **C++ uniform 接好 ≠ 链路通**：v0.7.7 只在 C++ 接 uExposure，Kotlin→JNI 的 FilmParams[0] 无人赋值（exp2(0)=1 静默无效）——跨语言参数必须端到端验证（raw.render 加 `ev` 字段才让断链可见）
- [2026-09-29] **引擎侧参数三渲染链只接两条 = 静默漏第三条**：手动 WB 只在预览 OES 与 YUV 静拍下发，RAW 静拍链无人接（"预览变、M 档成片不变"而构建全绿）——新增影响成片的参数必须按预览/YUV/RAW 三链逐一核对；raw.render 的 `wb` 字段是探针
- [2026-09-27] **曝光意图必须放统计之后；直通只是掩盖域差**（HAL 域与 RAW 域差 1.7–3.9×，EV=0 时巧合接近，任何叠加放大立即暴露）；**"恒等的旧层"在域外是失真源**（旧 log 链 ±4EV 内恒等但域外半斜率延展，标定域≠渲染域——应删链而非保留）
- [2026-09-29] **统计域与渲染域错位是高光"整张白"总根因（跨 5 版本）**：统计测于乘 uExposure 之前、filmic 输入含 ×2^ev ⇒ 自适应白点比渲染域 P99 低一个 ev——**任何"统计→判据→曲线"链路必须核对三者同域**；**渲染域视角推理易绕晕**（画"输入→乘 ev→enc→曲线"链路图，别在公式里心算）
- [2026-09-27] **成员变量跨 engine 会话丢失**（nativeEngineStart 每次 new FrameRenderer）——跨会话状态（域比）必须进程级 static 或外部持久化

## 降噪 / MFNR

- [2026-09-21/27] **噪声测量要无偏**：平坦块法+梯度阈值会因噪声水平产生幸存者偏差（裸帧 400 块 vs 融合 77K 块幸存，σ 低估 45%）——跨噪声水平比较必须用与噪声无关的判据（低频 box 图梯度）+块数相当
- [2026-09-27] **MFNR 三个反直觉**：融合=等权均值（自加"残差置信度"加权因暗部噪声主导而系统性不可信）；**σ 融合后必须 ÷√N**（否则残余噪声漏过而纹理被抹="糊+降噪一般"）；**参考实现的"DFT"措辞要核实**（hdr-plus 的 DFT 实为 2× 下采样 L1 反比加权）
- [2026-09-28] **"看日志推机制再打补丁"的连环错误**：v0.10.8 残差衰减基于"误报是噪声性散点"假设，插桩（v0.10.9）实测误报 100% 来自位移判据假峰——**机制假设必须先用插桩证伪/证实再动代码**；同窗口"黑点方向"与"亮度归因"两次同型错误
- [2026-09-28] **插值/复制/平滑各有专属病症**：逐 cell 双线性把大位移**稀释**（漏检→错位 alt→缺肉）；tile 值复制产生 128px **方波**（硬跳变→锯齿）；box 平滑救不了方波——正解=tile 独立投票+3×3 max 传播+cell 平滑
- [2026-09-28] **弱纹理/暗部 tile 的 SAD 精化无区分度**（argmin 随机落搜索边界=假解）——判别=位移空间一致性（真运动连片、假峰孤立）；**对比实验前先核对曝光量与口径**（PC"暗 24%"实为 tone 链差，EXIF 证明 PC 曝光量反而 +11%）
- [2026-09-28] **移植标准实现必须区分「算法职责」与「其所在管线的语境假设」**：darktable filmic 的 Ych min 是跨域比较（场景线性 vs 显示域），移植到无场景归一的手机直出链后变全局去饱和滤镜（暗部 rel −33%）——保留保险丝职责（Y clamp/Yrg/clip chroma），风格级色度再映射留给有该语义的层
- [2026-09-28] **"泛白/发红"类先做同场景 A/B + 分布级统计**（第一组样片构图/ISO 不同曾误导归因）；**A/B 中途用户改设置（auto_black_ev）会污染归因——配对分析必须锁定组内单变量**
- [2026-09-28] **田口式跟拍混杂**：暗光"块状噪不均匀"未必是权重 bug，可能是判据误报的次生现象（回退区单帧高噪 vs 融合区干净）——先看 misD/motD 分布再归因

## 方法论（跨窗口反复）

- [2026-09-28] **"先 100% 原版跑通，再评估删不删"（用户批评后固化为 AGENTS.md 铁律）**：gamut 的 min/desaturate 被"预删"后天空过饱和立即暴露——**预删原生代码 = 主动销毁实验对照组**；自研推演替代不了"完整原版+真机 A/B"
- [2026-09-28] **简化方案替用户做取舍是错的（用户严厉批评）**：以"GPU 成本不现实"否掉 DFT 维纳路线——三宗罪：成本从未实测（16×16 分块 FFT 在 GLSL 是成熟技术）；把 Fig.6"对朴素 DFT 的批评"扩大到整条路线（pairwise 早已解决）；反证在眼前（PC 8× 优势）。**性能取舍必须给用户真实数据与选择权** → 2026-09-29 实测推翻：优化版 DFT 合并 207.5ms 达标
- [2026-09-29] **"PC 优势 = 频域维纳"旧归因不成立（源码核实）**：MGC 多帧合并在空间域（逐 Bayer 相位 RBF / 各向异性核回归），"功率谱"是噪声模型；hdr-plus 是 L1 空间域实现；**HDR+ Fig.6 批的是全 burst 单次 3D DFT（pairwise 是正解）**——引用论文批评前必须核对批评对象是否就是被否方案
- [2026-09-29] **共享内存流量才是 GPU FFT 瓶颈，不是三角函数**：twiddle 查表仅 +1%，寄存器内 1D FFT（shared 128→32 次/FFT）拿 1.93×——**瓶颈归因用变体对照实测，别拍脑袋**（同轮连跑消热状态差 ~3%）
- [2026-09-24/28] **先看日志再动手**（方向链路两缺陷混成一个"方向不对"猜三版，`photo.crop` 日志本就在代码里）；**推荐/判断功能前必须读实现确认语义**（local_tone 实为"抬暗部"被当"局部对比增强"推荐）；**离线复现的域差异会掩盖真相**（趋势可信、绝对值不可照搬）
- [2026-09-23] **判据类改动先问"这个功能的意图是什么"**；**手段与推导必须分开判断**（中位锚定的目标值推导错但方向对，一起毙掉是误判）
