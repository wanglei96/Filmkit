## 环境与构建（常青）
- [2026-09-23/30] **出包与日志三坑**：增量打包残留旧 so（33.7MB vs 28.2MB、zip 条目空洞）⇒ 出包前 `rm -rf app/build/outputs/apk`；shell 管道吞退出码 ⇒ 校验类命令必须 `RC=$?` 判真实退出码（**累计四犯**）；Logger fwrite 缓冲在崩溃时吞关键记录 ⇒ 关键路径主动 `nativeFlushLogs()`，**"日志里没有"≠"没发生"**

## GL / Mali 驱动（X300 实测）
- [2026-09-30] **Mali 拒绝混链 GLSL 版本**（vs 300 es + fs 310 es → "Shader languages do not match" → init 失败整链黑屏）；**glslang ES profile 的 image 格式只放行 r32f**（compute 校验用 430 core 转换，有 ESSL 严格性盲区）

## Camera2 / HAL（X300）
- [2026-09-29] **burst 必须锁所有帧的 AE**：只锁参考帧不够——alt 帧走 AE AUTO 时 HAL 在拍摄瞬间重收敛（70MM 实测 ISO +10%）→ 曝光量不守恒击穿对齐（confMed=0、位移场全零）

## UI / Compose
- [2026-09-18/22] **UI 要点**：跨会话状态必须 prefs（rememberSaveable 随子页销毁丢失）；setter 改字段后要调 rebuildRepeating；`LaunchedEffect(surface)` 对象相等性 key 在 OriginOS 恢复不换实例；stop 期间 post 失败要回滚 pending；预览框 `weight(1f)` 弹性占满是"快门调不上移"根因（用 `weight(1f, fill=false)`）；预览图分辨率必须 ≥ 显示像素且缓存名带尺寸
- [2026-10-04] M3 ModalBottomSheet 真机返回需两次 → 自绘抽屉（拦截层 + BackHandler + FilmMotion）；删除设置项必须同步锁死读取端（prefs 历史残留 true）

## 色彩、测量与链路域
- [2026-09-22] **色彩对比三条硬约束**：比 C\* 同亮度（跨链比饱和度只用 rel）、比色相按色相带拆开；手搓矩阵链先验证"中性进→中性出"；先排除三混淆项。**色度增强三错**：只增强已浓的色 = 倒置；绝对线性判据混淆饱和与亮度；成片上二次套影调曲线是错的（已过 OETF）
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**；成片反推对过曝区失效（只用 P50–P90）；**先看日志再动手**；离线复现的域差异会掩盖真相（趋势可信、绝对值不可照搬）
- [2026-09-24/28] **跨链对比三条**：① 分布级对比会被亮度映射污染（稳口径 = 同矩形区域 + 多尺度频段能量）；② **不同保真度的数据不能 A/B**；③ **工作域不是色度差主因**，大色块核心区判据可把"降噪抹色度"与"矩阵偏淡"分开

## 方法论与流程（跨窗口反复）
- [2026-09-28] **"先 100% 原版跑通，再评估删不删"（用户批评后写入 AGENTS.md 铁律）**：预删原生代码 = 主动销毁实验对照组；**简化方案替用户做取舍同罪**——以"GPU 成本不现实"否掉 DFT 路线从未实测，性能取舍必须给用户真实数据与选择权
- [2026-09-29/30] **GPU 性能直觉不可靠**：共享内存流量才是 FFT 瓶颈（twiddle 查表仅 +1%）；每相位 LUT + 写回并行实测反而更慢——**瓶颈归因与改动收益都必须变体对照实测，别按 CPU 直觉推断；字段名会骗人（`uploadMs` 91% 是 CPU 对齐），先拆时间戳再判断**
- [2026-09-29/30] **判据类改动真机频繁翻车（179→182 五版）+ A/B 口径三坑**：**改动前先穷举"该量在真机上可能的取值范围"**（用已录日志反查）、**优先修有物理实锤的错位（域/边界）而非调判据参数**；跨时刻/跨拍摄/跨热状态都会骗人（日落光照被当成算法差异、连拍 3 张 ISO 2368→10160、冷机 500ms 热机 830ms）⇒ **同刻连拍 + 同帧 A/B + 冷机取中位是唯一干净口径**
- [2026-09-30] **日志非法 JSON 静默吞行**（`substr(0,5)` 截出 `"1139."`，4 张里 3 条 raw.render 消失）→ 分析前先跑 `tools/check-log-json.py`；**"改错位置"三连全部静默失效**（加门控忘改 uniform、按错名替换致 link 未落、诊断字段写进前置串）→ **规避 = 出包前跑 `tools/check-diag-fields.py`**
- [2026-09-30/10-05] **定量口径坑 + 离线判据必须覆盖所有可感维度**：用顺手的指标代替用户判据会连坑（3×3 高通测不到 8–32px 色斑；跨图比梯度被错位污染；"相邻像素相同占比"在纯黑区 77% 根本不成立）⇒ 规程 = 出包前同刻 100% 裁剪目视、指标只作辅证；0.173 只测"紫边下降 + 平坦区色度"而**没测"色渗/大色块"** ⇒ 真机"一片红一片黄一片紫"，此后补四条色渗判据（块状色相偏移、平坦区色度-亮度相关、大色块方差、门控覆盖率）
- [2026-10-05] **"完整实现"不等于"有效"**：AMaZE 按原版完整实现（CPU 多线程 247ms@12MP、设置三档可选），离线六项指标**五项为负** ⇒ 实现完整性只是前置条件，收益必须靠在目标域上的判据说话

## 拍照线程、OOM 与对比口径（10-01/02）
- [2026-10-01] **Java OOM 绕过崩溃捕获**：JNI `SetByteArrayRegion` 里 pending exception 未清 → ART abort；`crash-latest.txt` 不会更新（只有 logcat/tombstone 有现场）；direct buffer 计入 OOM 额度（8×25MB + 成片 50MB 撞 256MB）


## 判据域、归因与品红（10-03）
- [2026-10-03] **判据域错位 + 代价与设置项两坑**：曝光判据读的是"最后渲染过的那条链"的统计（拍照前基本是**预览链**，与 RAW 归一化域差 0.58EV 且逐次不同）⇒ 既不准也不稳；为 0.1% 的像素让全图欠曝 ⇒ 噪声整体抬升（**保护少数像素前先算它占多少**）；4 个白点旋钮互相干扰的**根因不是旋钮不够而是分工错了** ⇒ **加 UI 项前先 grep 同类标题**

- [2026-10-03/04] **测量的 ROI/对位错一步，后面几轮全白费**：ROI 混入室内天花板稀释结果、坐标尺度混用让结论反向（3072 vs 1777）、定位错 700px 产生"全 0"假象、跨图对比先验证构图（seq1 台灯 vs seq2 窗）；**自动找峰窗口会被红笔/窗外粉色物污染（先看峰位置分布再限定窗口，分区报告）**；CIELAB 放错域全盘错（= 线性→XYZ，无 sRGB 环节）；rawpy `gamma=(1,1,1)`+16bit 断言不可用。**下结论前先把指标画成图看位置**
- [2026-10-03] **改一处必须沿数据流检查所有受影响点**：exp21 把 mask/chroma 输入换成 `tex_fused_` 时顺手换了 apply 判定，修复面 47269→63903 样本 ⇒ 画面**更红**。统计口径与判定口径是两件事
- [2026-10-03] **"物理极限"不能当作结论交差**：用"三通道全饱和、颜色信息已丢失"解释品红残留，但实测该情形只覆盖 **1%** ⇒ **给出解释前先用数据验证它的量级**
- [2026-10-03] **用户指路优于自己推演**：连续多轮在 opposed/inpaint 里打转，用户一句"翻 PC 源码"直接给出答案（PC 用 `MeasureMoire` 逐像素伪彩强度图驱动色度降噪）⇒ **遇到标准做法问题先找一手实现对照**

## 品红专项、曝光事故与紫边（10-04 → 10-05）
- [2026-10-06] **离线/排查结论上真机前必须交叉验证三件事**：① **场景** —— 红笔亮场景「锐化主因」外推到台灯逆光被当场推翻（第四次方向纠正）⇒ 排查与判据必须先在**痛点样片**上做；② **链覆盖度** —— 离线全链不含锐化 ⇒ 测不到「PC3D 收益被锐化打回」（离线全改善 vs 真机关闭更优的矛盾根源）；③ **输入通路** —— PC 核尺寸公式用真机噪声模型算出 9 而非离线假设的 11（σA+σB 小 5.3×）⇒ 公式照抄但输入不同必须真机重算。**A/B 样张还必须逐帧以日志生效值清洗**（`mfnr.timeout` 回落单帧连续四轮出现；用户目视与定量可能来自不同变量 —— 紫边变淡实为替换档 13:49 切换而非 [58] 13:55 才拍）

## 相册与预设（10-11 → 10-13）
- [2026-10-13] **"闪一下"要先分清是哪种机制，同一现象我判错了两次**：第一次按"清晰度阶跃"修（PV-1），第二次用户澄清"是屏幕闪烁"才转到转圈，第三次"一定会显示一下转圈"才锁死根因（PV-2：`bitmap` 被两个协程分别写 ⇒ 中间帧是转圈；PV-3：`Image` 参数在**组合期**取值 ⇒ 必然存在一帧"新页 + 旧页位图"）。**铁律：观感类报障先让用户描述清楚现象，不要按自己的假设先做包**
- [2026-10-13] **删符号前 grep 全仓**（PS-6a 删勾选树符号 ⇒ 测试源集整体编译失败，`--tests` 救不了）⇒ `compileDebugUnitTestKotlin` 通过是硬判据；**死白起点不是白点的函数，而是"曲线何时到顶"的函数** ⇒ 必须带硬约束重跑拟合（R-3 的 `--hi-floor/--hi-tol`）

## 引擎调研与子代理协作（10-13）
- [2026-10-13] **量化结论对「判据口径」高度敏感，换口径就翻转排序**：死白起点判据 ≤1 → ≤2 LSB per 0.1EV 时 filmic 与 sigmoid **互换名次**；每 0.1 EV 恰好 1 LSB 的**理想均匀曲线**在该判据下被判「从起点就死白」。**任何「某架构更好」的量化结论必须同时给出判据定义与对齐前提**（16 号报告因「同白纸亮度」前提未满足，优势从 0.7~1.05 EV 缩到 0.25~0.30 EV）—— 这正是独立复核卡的价值。
- [2026-10-13] **守卫之间会有缝 + 文件头注释会撒谎**：① `CameraPresetsTest` 守 Kotlin 硬编码长度、`FilmParamKeysTest` 守语义名表 ⇒ **"C++ `kCount` 单独漂移"两边都不红**（正是 v0.10.196 启动崩溃形态）⇒ 补 `tools/check-filmparams-contract.py` 四路对拍，**给契约加守卫前先问"哪一半事实没有任何断言在读"**；② `tools/engine-shader-offline.py` 头部声称"已接入 4. FILM `kFsFilm`"，实读 295 行**没有 FILM 段**（只到 CCM）⇒ **把某工具当判据载体前必须实读它跑到哪一步**（`steps.json`/产物清单比注释可信）。
- [2026-10-13] **扩槽会牵动 8 个守卫，而它们各自钉着"里程碑事实" + 架构师推断会被实测推翻**：`[98]` 一进 `CAMERA_PATH_SLOTS`，红的还有"U-2 起单侧=0"（5 条）、"只读组 == NO_SLIDER 全集"（2 条）、"可拖 == PATH − NO_SLIDER"（1 条）⇒ **里程碑式断言（"=0"/"为空"）必须升级为"与权威源（文档矩阵 §1.6）对拍"**，否则每次扩槽都要人肉追。我预判"98 塞进 `NO_SLIDER` 后守卫仍绿"，实测**变红**（该集合在 `fullEditReadonlySlots()` 里是**无条件并入**）⇒ **派卡给的"预期"要标明是推断并要求用实测覆盖**（子代理主动报"与你的预期相反"最该鼓励）。
- [2026-10-13] **验证工具自身会假绿，且只有负向自检能抓**（阶段 1 抓到两条）：① 只锚"整体摘要"不够 —— 切分点整体偏 1 行时边界行都只是注释，整体摘要与语义哨兵**都抓不到** ⇒ 必须**块级锚点**；② `validate-shaders.sh` 的"真拆"形态里逐段过滤 `#version` ⇒ 只有 head 带头、拼回整份没进候选、**filmic 实际未校验**（glslang 对缺 `main` 的片段不报错）⇒ 必须**先拼回整份再判断**。**共同点：验证工具出错 = 假绿，比不验证更危险 ⇒ 判据与 mutation 自检必须同跑。**

## 引擎插槽阶段 2/3（10-14）
- [2026-10-14] **⛔ P0：`[28]=0` 让引擎 1 完全空转，而六条判据全部会通过**（架构师引入、验证卡抓出；实跑指纹 `0x189e4126` = "引擎 0 + uToneK=0"）。**教训：判据集必须有正向判据（"它真的在工作吗"）；纯负向判据会集体放过"什么都没做"的实现。** 最危险处正在于"改 filmic 参数 ⇒ 成片不变"对空转实现**天然成立**。
- [2026-10-14] **双向复核：我采纳了验证卡的漏径 A、又驳回了它的漏径 B**：它报的"`[35]` 经 HR 白点泄漏"**不成立** —— `runHighlightReconstruct:12439` 是 `(void)white_ev_input_domain;`，且 v0.10.145 起 threshold = `kSaturationNormCalib × |clip(CCM·(0,gain_G,0))|`，**只依赖 CCM 第二列、不随白点/色温漂移**（旧式用白点曾致命中率 0%、"从未重建过任何像素"）。⇒ **复核不是照单全收，也不是全盘否定。**
- [2026-10-14] **读别人的行号断言前先自己 grep**：验证卡把 `passFilm` 的四个调用点写成 `updateFilmicEV` 的，而后者只有一个无条件调用点 —— 正是"躲不开"才让成员变量副作用逃出引擎边界。
- [2026-10-14] **用户样片不能直接做 A/B（两条独立教训）**：① **构图位移** —— 用户给的"同场景对比"实测中心块最优位移 **−74/−52 px**（11 秒手持），零位移时该块差 46 LSB、对齐后 16 LSB ⇒ 逐像素差 11.6 LSB **全是错位伪影**，必须改用**直方图分位数**口径或固定机位；② **引擎归属只能读日志** —— 用户两次"明确改了引擎"拍的两张**都是引擎 1**，`photo.saved` 时刻的 `engine.film_src slot` 是唯一判据（文件名/肉眼/EXIF 都不行）。
- [2026-10-14] **引擎 1 下 filmic 日志字段仍在变**（`updateFilmicEV` 无条件跑、算完的 uniform 落 location=−1 被丢弃）⇒ 引擎 1 期间 `raw.render` 的 `fCon/whiteEv/fPow` 有值且会变，**不能据此推断"filmic 还在影响画面"**。机器判据 = **`tone=1.0`**。
- [2026-10-14] **"验证工具/测试自证"也要防假绿**：本轮两次靠**变异检验**（故意改坏实现 ⇒ 判据必须变红）证明判据有牙 —— 渲染侧删 `out[98] = effective`、UI 侧把合成改回预设值，各自红了对应用例。**没有变异检验的"全绿"不算证据。**

## 编码器标定与交付链（10-15）

- [2026-10-15] **编码器旋钮的寻找方法**：① 静态图 `frame-rate` 必须 = 1（`KEY_BIT_RATE` 单位是 bps，按 30fps 折算会让体积错位）；② **"设了键"≠"键生效"≠"键是旋钮"** —— 真机把每个键单独设、看 `outputFormat`/`inputFormat` 回显才判定（`quality` 键有效但天花板低；官方 QP 键只在 VBR 下生效；`KEY_BIT_RATE` 编码器根本不读）；③ **`outputFormat` 全键 dump 是找旋钮的最快路径**，vendor 键值全 -1 即未实现。
- [2026-10-15] **日志只留最后一路 = 无法定位**：0.11.39 只 emit 最终生效的那条 `photo.heif_try`，导致"哪条路驱动了质量"只能反推。**每一路都留一条**。同型：**诊断设施要按"一次真机拿全数据"设计**，别让用户为一条字段再跑一轮。
- [2026-10-15] **共享成员跨帧被覆盖是复发型 bug**（`stillRot`/`stillAspect` 这类"快门瞬间快照"必须冻成局部 val 随回调传递，不能读成员）；**Kotlin 块注释可嵌套**（注释里写 `/**` 会提前闭合）；**`gradle ... | tail` 会吞掉退出码**（成功/失败都进 `&&` 分支）。

- [2026-10-19] **uniform 默认值必须等于"跳过"**：`uContrastOut` 的恒等条件写成 `!= 1.0`，而 uniform 默认值是 0 ⇒ 任何没走到下发点的路径（离线执行器、测试夹具）都会执行 `clamp((c−0.5)×0+0.5)` 把画面拉成**平坦灰 0.5**（`check-u4` 抓到 max|Δ| = 119.5 LSB）⇒ 判据必须写 `> 0.0`。同型于"探针取到恒等值"陷阱。
- [2026-10-19] **"恰好 N 项"是里程碑式断言**：设置页 gate 计数"恰好 5 项"因补 `[40]` 变成 6 ⇒ 两个 UI 测试红。补挂是对的（`[40]` **本就在** `FILMIC_OWNED_SLOTS` 真源表里、是设置页漏挂）⇒ 测试改 6 并写明依据，而不是把 `[40]` 撤回去迁就测试。
- [2026-10-19] **`git stash` 回 baseline 对比是分清"预期红 vs 真红"的可靠手段**：本次用它确认 `srgb-oetf`/`hr-pre` 是预先就红，而 `softglow`/`u4`/`style-passthrough` 是被本期改红的。
- [2026-10-19] **判据需要的产物要带配套参数生成**：`check-film-offline` 要求 `--film-tone-k 1 --film-ev 0 --film-gamut 0` 生成的产物；参数不匹配会误报红（我误判过一次"真红"）。

- [2026-10-19] **D5 域口径是比色的前提**：`film_d5` / `film_d5_sigmoid` 是 **Rec.2020 线性**（期 B 工作空间），不是 sRGB 线性。直接套 `srgb_oetf` 等于把 Rec.2020 原色当 sRGB 编码，会得出"ACES 色相显著更好"的假结论；修正为「Rec.2020→sRGB 线性→OETF」后，ACES 的优势消失（Δh 1.58° vs filmic 1.50°）。**任何拿 D5 比色的脚本都必须先转 sRGB。**
- [2026-10-19] **离线 ROI 坐标必须用 RAW 坐标**：DNG RAW 是横的（4080×3072），预览是竖的（rawpy flip=6 旋转 90°）；按预览坐标直接取会跑到叶子/背景上。红杯 RAW 坐标 `Y 1570–1970, X 2300–2700`。
- [2026-10-19] **Ultra HDR 有两条路，色度不同**：`Bitmap.compress` + `Gainmap` 是 **4:2:0**（平台路径）；4:4:4 + HDR 必须走 libultrahdr + 自研编码器（PC 的 `Jpeg444ExportEncoder`）。"PC 在 4:4:4 下也能 HDR"指的是后者。
- [2026-10-19] **Oklab 的 ΔE/Δh 是折中曲线**：A/B/C 变体与混合 w=0.3~0.8 都试过，没有同时满足"ΔE≤3.7 且 Δh<2.5°"的交点；继续调参数只会在曲线上滑动，不会出现拐点。

## 自动曝光（10-20）

- [2026-10-20] **`sw999` 曾经是聋的**：只在 `auto_tone` 开时写（默认 `[35]=0` + 引擎 1 归零）⇒ `sceneHighlightEv()` 恒 NaN ⇒ 高光保护**从来没生效过**。判据字段"有值"不等于"在用"——先确认写入分支。
- [2026-10-20] **两层保护压同一件事 = 双重欠曝**：采集端按上一张 `sw999` 欠 1.98EV，渲染端再按本张压 2EV，同场景两张亮度不一致。**加第二层保护前先问"它和现有那层是什么关系"**，并让它们互斥。
- [2026-10-20] **超时定时器必须与当前 burst 绑定**：`burstActive` 是共享标志，上一张的 5s 定时器会把下一张误杀（`mfnr.timeout images:0`）⇒ 回退单帧、无 MFNR、无 gainmap。**收满即摘定时器**，且超时日志要打"收到几帧"。
- [2026-10-20] **并发拍照时"本张状态"不能用共享成员/最后提交的实例**：`nativeEngineGetStats` 读 `g_renderer` 而拍照走 `g_renderer_still` ⇒ 字段恒 0；gainmap 读回同理。**读多实例状态前先确认"我读的是不是这张的实例"**。
- [2026-10-22] **`脚本 | tail -2 && build` 会吞掉脚本退出码**：`tail` 成功即 `&&` 放行，于是 `validate-shaders.sh` 明明报了“禁止发版”构建照跑。0.12.20 的黑屏（GLSL `Undeclared variable g`）就是这么漏出去的。**校验脚本一律 `> log 2>&1; RC=$?`**，不接管道。
- [2026-10-22] **按起止锚点整段替换注释会连代码一起删**：换 teq 注释时把夹在两段注释中间的 `float g = curveAt(q);` 清掉了 ⇒ shader 编译失败 ⇒ 预览黑屏。**只删注释行，不要切片**；改完必须单独 glslang 校验那个 shader。
- [2026-10-22] **全图分位 ≠ 同区域对比**：拿 p1/p5 比两张图得出“暗部差 2EV”是假象（各自最暗 1% 不是同一个东西）。同区域实测只差 0.1~0.3EV。**跨图比较必须同区域、同尺寸**。
- [2026-10-22] **测试是设计意图的文档**：`local_tone` 那条断言（“默认值必须仍是 0.25（标定旋钮）”）比任何注释都直接。**改默认值前先搜测试**——那次改错被单测当场抓出。
- [2026-10-22] **“参数相同”不等于“输出相同”**：核对 PC 源码后两边 sigmoid 参数逐位相同（0.3544/0.00143/1.5 vs 0.3597/0.00138/1.491），但 PC 局部对比度仍高 6.5 个百分点 ⇒ 差异在链路别处（demosaic/锐化），不在曲线。**别在相同的参数上反复调**。

## AE 回路与编辑器作用域（10-23）

- [2026-10-23] **预览链与 HAL 的 AE 是两条独立回路**：在预览上做 EV 闭环（哪怕 1Hz）必然互相激发 —— 真机表现为室内忽暗忽亮、成片与取景器亮度不一致。"慢速外环"不是解，方向就错了。
- [2026-10-23] **节流+小步长=可见台阶，一次性大跳+固定目标=暗场景过曝**：前者被当场看出"每秒抬一截"，后者把室内拉爆；固定目标闭环在数学上必然毁掉暗场景。
- [2026-10-23] **测量滞后是振荡的根因**：0.7/0.3 EMA（滞后约 3 步）配 0.7 增益必然过冲；先修滞后，再谈增益。
- [2026-10-23] **EXIF 对拍比任何推断都快**：PC 2.02ms 与我们 2.20ms @ISO50 一条数据就否掉整轮"补光/测光"假设 —— 先拿两边 EXIF 再谈算法。
- [2026-10-23] **别用单场景反推全局参数**：从一张图算出 `kSkyLift` 换时刻必失效。全局参数只能来自曲线形状，不能来自场景数据。
- [2026-10-23] **改共享函数前先问"它的语义为谁而定"**：`applyEngineScope` 归零饱和度是拍照链"切引擎观感不跳"的兼容策略，编辑器复用 ⇒ 旋钮失效。

## 交付层与原生能力探测（10-22 晚）

- [2026-10-22] **系统删除请求的 `RESULT_OK` 只代表"用户同意"**：不代表 MediaProvider 执行了（真机"删了但照片还在"）⇒ 删完必须单条查询核实；API 30+ 还要读 `is_trashed` 列（有些 ROM 单条查询不过滤回收站条目，只看"行是否存在"会误判）。
- [2026-10-22] **vendor tag 读值要按类型逐个试**：`CameraCharacteristics.Key<T>` 构造带类型、类型不符抛 `IllegalArgumentException`，而 `c.keys` 的 star projection 推不出 T。写 `probeCharValue` 依次试 Int/Float/Long/Boolean/String/Byte/各数组，先命中先返回。
- [2026-10-22] **RAW 输出尺寸恒定 ⇒ 不能从尺寸反推 HAL 有没有裁**：我一度加过"w ≈ active/z 就当 HAL 已裁"的自愈判据，但 binning 尺寸同样落进该区间 ⇒ 必然误判（已删）。判据只能来自真机行为（成片视角）。
- [2026-10-22] **逻辑相机与物理相机不能混在一张镜头表里**：等效焦距完全相同 ⇒ 去重与选择都不确定，且不同 id 的变焦范围差别巨大（0.67–10 vs 0.6–100）。
