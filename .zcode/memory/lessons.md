## 环境与构建（常青）

- [2026-09-18] **中文路径下 AGP externalNativeBuild 报 CXX1400**（路径中文段丢失）：自定义 CMake Exec 任务直驱 NDK；本机构建 `JAVA_HOME=/opt/homebrew/opt/openjdk@23 ./gradlew assembleDebug testDebugUnitTest`（系统默认 Java 8 跑不动 AGP）
- [2026-09-20] **engine shader 改动构建/单测全绿仍可能设备端全黑**：shader 是设备运行时编译（v0.5.13 非法 step 重载致黑屏）——铁律：shader 改动必须过 `tools/validate-shaders.sh` 且真机验证后才发版
- [2026-09-22] **C++ 原始字符串 `R"(...)"` 里出现 `)"` 会提前终止字面量**（GLSL 注释里「0.25(=64/255)」即触发）；Kotlin KDoc 里写 `/*` 会开嵌套注释吞文件。注释内数字后接括号用全角
- [2026-09-23] **增量打包残留旧 so**（APK 33.7MB vs 28.2MB）——出包前 `rm -rf app/build/outputs/apk`
- [2026-09-27] **shell 管道吞退出码**：`bash x.sh | tail && ...` 的 `&&` 看到 tail 的退出码——校验类命令必须 `RC=$?` 判真实退出码
- [2026-09-30] **Logger 的 fwrite 缓冲会在崩溃时吞掉关键记录**：0.10.83 崩溃后日志只有 77 行，出事那张照片的记录（含崩溃现场）全丢，只剩一个 DNG。关键路径必须主动 `nativeFlushLogs()`；排障时"日志里没有"不等于"没发生"

## GL / Mali 驱动（X300 实测）

- [2026-09-18] **Mali 三坑**：① RG8 TexSubImage2D 静默全黑（无 GL 错误）→ 预览改 SurfaceTexture；② RGBA8 FBO 误用 GL_HALF_FLOAT 永不完整；③ GLSL ES3.1 image uniform 无默认精度（S0032）→ 全部显式 highp
- [2026-09-18] **照片类三坑**：Y 未归一化（0–255 直乘系数→灰度）；Y 平面行序与 GL 纹理原点相反；STMatrix 已含裁剪翻转，引擎再叠加 center-crop = 双重裁剪
- [2026-09-22] **sampler 必须始终有合法绑定**（全黑根因）：关闭态提前 return 不绑纹理→Mali 预测执行分支里的 texelFetch→pass3_out glErr=1282 整帧丢弃。修法：init 建 1×1 恒等纹理、**无论开关都绑定并下发全部 uniform**
- [2026-09-27] **GLSL ES 编译期黑屏级坑（glslang 可拦）**：不支持数组初始化器 `ivec2 a[4]={...}`；sampler 类型函数参数必须显式精度（已踩两次）；**`half` 是保留字不能做变量名**
- [2026-09-28] **浮点 attachment 的 readback 组合陷阱**：R16F + GL_UNSIGNED_BYTE 在 ES 3.0 不保证、X300 静默回零；**R16F fbo + GL_RGBA + GL_FLOAT 同样静默回零**（0.10.50 补证）——成片黑要用 avgLuma/rms 作硬证据；RGBA16F + GL_FLOAT 实测可用
- [2026-09-30] **imageStore 目标纹理一律 `glTexStorage2D`**：glTexImage2D 可变纹理在该 Mali 上 imageStore 静默丢写（同 program/绑定/dispatch 下 micro:false vs microSt:true）；**"计算照跑、写入全丢"用参考路径（spike）对照二分最快**
- [2026-09-30] **GLSL ES 3.2 的 r16f/rgba16f image 禁止 load+store 混用**；image2DArray 的 imageStore 在 X300 同样"计算照跑、写入全丢"——表象相同根因可以完全不同，别在单一路线上重复押注
- [2026-09-30] **Mali 拒绝混链 GLSL 版本**（vs 300 es + fs 310 es → "Shader languages do not match"→ init 失败整链黑屏）；**glslang ES profile 的 image 格式只放行 r32f**，compute 校验用 430 core 转换（有 ESSL 严格性盲区：GL 4.x 允许 int→uint 隐式而 ESSL 不允许）
- [2026-09-30] **批量脚本编辑中途 assert 失败 = 部分修改未写盘**（0.10.41 坏提交：shader 旧声明 + host 新绑定，格式错配污染多轮调试）；`str.replace` 不带 count 会误伤同型代码（本轮把 `mfnr.trigger` 日志的 liveIso 一起改了，编译期才暴露）——多点修改后必须 grep 核对

## Camera2 / HAL（X300）

- [2026-09-18/19] **X300 HAL 三事实**：手动 WB 的 CCT/GAINS/矩阵三路径全不可用（解法=引擎侧补偿）；隐藏物理镜头持续黑帧（设置页按镜头启停）；手动对焦 HAL 报屈光度 0 但硬件支持（默认 10D 试值）
- [2026-09-18] **键名/类型凭记忆必错，javap 核 SDK**：API36 移除 COLOR_CORRECTION_RB_GAINS；正确键是 `STATISTICS_LENS_SHADING_CORRECTION_MAP`；`SENSOR_NOISE_PROFILE` 是 `Pair<Double,Double[]>[]`（`as? List<Any?>` 永远失败）
- [2026-09-18] **session/生命周期三坑**：切镜头置 started=false 后 onConfigured 守卫放弃建 session；异步清理 runnable 读到新实例；触屏对焦 ACTION_UP 不消费事件流永不送达
- [2026-09-18/19] **几何/方向三坑**：AF/AE 区域落点差 90°；预览 center-crop sx/sy 是四象限映射（4:3 时掩盖 bug）；变焦倍率分母用物理焦距错
- [2026-09-20] **统计口径与判据**：阈值必须滞回；`controls.applied` 的 iso/sec 是滑杆存量值（**日志字段语义必须回代码核实**）；EV 补偿范围因机而异
- [2026-09-20] **EXIF/DNG 三坑**：Bitmap.compress 不写 EXIF（ExifInterface 经可写 FileDescriptor 补写）；DngCreator.setOrientation 只收 1..8；DNG OpcodeList2 内部大端而 TIFF 头小端
- [2026-09-27] **ImageReader maxImages 提高且全程持有 Image 的 HAL buffer 压力**：maxImages=5+4 张 25MB 全程持有→HAL 预配 125MB→闪退；修复=拷贝即 close，仅参考帧持 Image
- [2026-09-29] **burst 必须锁所有帧的 AE**：只锁参考帧不够——alt 帧走 AE AUTO 时 HAL 在拍摄瞬间重收敛（70MM 实测 ISO +10%）→ 曝光量不守恒击穿对齐（confMed=0、位移场全零、neff=1.45）

## UI / Compose

- [2026-09-18/22] **UI 要点**：跨会话状态必须 prefs；setter 改字段后要调 rebuildRepeating；`LaunchedEffect(surface)` 对象相等性 key 在 OriginOS 恢复不换实例；stop 期间 post 失败要回滚 pending；预览框 `weight(1f)` 弹性占满是"快门调不上移"根因；预览图分辨率必须 ≥ 显示像素且缓存名带尺寸

## 色彩与测量方法论

- [2026-09-21] **libraw 参照默认 auto_bright=on**（亮度自动拉高 ~2.5×）——"寡淡/饱和 −21%"是亮度差被当成色彩差；测色度首选 CIELAB C\*；**"文件里没有"≠"API 拿不到"**
- [2026-09-22] **色彩对比三条硬约束**：① 比 C\* 必须同亮度、比色相按色相带拆开；② 手搓矩阵链先验证"中性进→中性出"，DNG 无 ForwardMatrix 时 libraw 退 ColorMatrix、两条链不可等价；③ 先排除三混淆项（A/B 是否受控、有无全局色偏、是否色域到顶）；**不同构图的"哪组更好看"不构成 A/B**
- [2026-09-22] **"只增强已浓的色"是倒置色度增强**；**色度增强绝对线性判据把饱和度与亮度混在一起**（改亮度相对后树叶 5.05%→12.50%）
- [2026-09-22] **在成片上二次套影调曲线是错的**（成片已过 OETF）；反推必须用生成该成片的参数版本；**离线 CLI 与真机有 5–8 L\* 偏差**——绝对亮度必须真机
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**；成片反推对过曝区失效（只用 P50–P90）；**先看日志再动手**；离线复现的域差异会掩盖真相（趋势可信、绝对值不可照搬）
- [2026-09-24/28] **跨链对比三条**：① 分布级对比会被亮度映射污染（稳口径 = 同矩形区域 + 多尺度频段能量）；② **不同保真度的数据不能 A/B**；③ **工作域不是色度差主因**，大色块核心区判据可把"降噪抹色度"与"矩阵偏淡"分开

## 链路断裂与域（本项目核心教训）

- [2026-09-27] **C++ uniform 接好 ≠ 链路通**：Kotlin→JNI 的 FilmParams[0] 无人赋值（exp2(0)=1 静默无效）——跨语言参数必须端到端验证（raw.render 加 `ev` 字段才让断链可见）
- [2026-09-29] **引擎侧参数三渲染链只接两条 = 静默漏第三条**：手动 WB 只在预览 OES 与 YUV 静拍下发，RAW 静拍链无人接（"预览变、M 档成片不变"而构建全绿）——新增影响成片的参数必须按三链逐一核对
- [2026-09-27] **曝光意图必须放统计之后**；**"恒等的旧层"在域外是失真源**（旧 log 链 ±4EV 内恒等但域外半斜率延展，标定域≠渲染域——应删链而非保留）
- [2026-09-29] **统计域与渲染域错位是高光"整张白"总根因（跨 5 版本）**：统计测于乘 uExposure 之前、filmic 输入含 ×2^ev ⇒ 自适应白点比渲染域 P99 低一个 ev——**任何"统计→判据→曲线"链路必须核对三者同域**
- [2026-09-27] **成员变量跨 engine 会话丢失**（nativeEngineStart 每次 new FrameRenderer）——跨会话状态必须进程级 static 或外部持久化

## 降噪 / MFNR

- [2026-09-27] **MFNR 三个反直觉**：融合=等权均值（自加"残差置信度"加权因暗部噪声主导而系统性不可信）；**σ 融合后必须 ÷√N**；**参考实现的"DFT"措辞要核实**（hdr-plus 的 DFT 实为 2× 下采样 L1 反比加权）
- [2026-09-28] **"看日志推机制再打补丁"的连环错误**：残差衰减基于"误报是噪声性散点"假设，插桩实测误报 100% 来自位移判据假峰——**机制假设必须先用插桩证伪/证实再动代码**
- [2026-09-28] **插值/复制/平滑各有专属病症**：逐 cell 双线性把大位移稀释；tile 值复制产生 128px 方波；box 平滑救不了方波——正解=tile 独立投票+3×3 max 传播+cell 平滑
- [2026-09-30] **加权平均的 N_eff 模型不能只算噪声项**：P0 空间权重放宽后理论 N_eff 升、实测降噪反降（2.38×→1.68×）——外围样本带进的是**系统偏差**（对齐仅 128px tile）；**先修对齐精度再谈权重**。**诊断量必须去信号**（tile RMS 信号主导；用同相位 lag-2 差分 std/√2）
- [2026-09-30] **"对齐更准"必须与"采样精度"一起看**：整数采样（round 到偶数）会把 0.27px 与 4px 的差别整个抹平——只换层 +2.5%，加上亚像素采样才 +45%。**离线评估要有已知真值**（合成金字塔 + FFT 相移），否则中位残差被噪声底主导、分不出两种对齐（实测只差 0.4%）

## 方法论与流程（跨窗口反复）

- [2026-09-28] **"先 100% 原版跑通，再评估删不删"（用户批评后写入 AGENTS.md 铁律）**：预删原生代码 = 主动销毁实验对照组；自研推演替代不了"完整原版+真机 A/B"
- [2026-09-28] **简化方案替用户做取舍是错的（用户严厉批评）**：以"GPU 成本不现实"否掉 DFT 维纳路线——成本从未实测+把论文对朴素 DFT 的批评扩大到整条路线+无视眼前反证。**性能取舍必须给用户真实数据与选择权**
- [2026-09-29] **共享内存流量才是 GPU FFT 瓶颈，不是三角函数**（twiddle 查表仅 +1%，寄存器内 1D FFT 拿 1.93×）——**瓶颈归因用变体对照实测**
- [2026-09-29] **判据类改动真机频繁翻车（179→182 五版）**：**每次改动前先穷举"该量在真机上可能的取值范围"**（用已录日志反查）；**优先修有物理实锤的错位（域/边界），不调判据参数**
- [2026-09-29] **跨时刻对比是两次误判的直接原因**（日落光照被当成算法差异）——**真机 A/B 必须同刻连拍**；**"模拟与实测的残差先怀疑模拟"**
- [2026-09-30] **跨拍摄的端到端 A/B 会被场景/亮度/手抖彻底污染**：连拍 3 张 ISO 从 2368 到 10160（4.3×），降噪倍数在 1.50~2.36 间跳——**同帧 A/B（一次拍摄内跑两遍）是唯一干净口径**
- [2026-09-30] **性能数字不能跨热状态比较**：同一 shader 冷机 500~550ms、热机 830~870ms（三次佐证）——**冷机 + 连拍 3 张取中位**；据此曾把一次"热机噪声"误判为负优化并回退
- [2026-09-30] **GPU 上"减少算术量"不等于更快**：每相位 LUT（2048 除法 → 动态索引 uniform）+ 写回并行（32→256 线程、多一道 barrier）实测更慢——**改动必须真机 A/B，别按 CPU 直觉推断**
- [2026-09-30] **字段名会骗人，先拆时间戳再判断**：`uploadMs` 361ms 里 91% 是 CPU 对齐（上传只 4~30ms）——差点又优化错方向
- [2026-09-30] **日志非法 JSON 会静默吞掉整行数据**：`std::to_string(1139.4).substr(0,5)` = `"1139."` 非法 → 4 张照片只有 1 条 raw.render 被 json 解析出来，差点误判"引擎不记日志"。分析前先跑 `tools/check-log-json.py`
- [2026-09-30] **单渲染线程 + 单 EGL context 会让长链阻塞预览**：拍完挪手机画面**完全冻住 1~2s**（不是掉帧）——预览的 updateTexImage 全排在 1.6~3.4s 的合成链后面。PC 的对照解法=各后处理器独立 `eglCreateContext`
- [2026-09-30] **杀正在跑 GL 的线程 = 崩溃 + 丢照片**：0.10.83 把合成搬到独立线程后，`stop()` 直接 `quitSafely()`（可能在渲染中途）→ 只留 DNG 没有成像、随后闪退。**架构改动要带开关（默认关），失败不能代价是用户的照片**
- [2026-09-30] **"改错位置"三连（全部静默失效）**：加 shader 门控却忘改 uniform；按错误 shader 名替换致 link 从未落上；诊断字段写进"pass 执行前"组装的串。**规避 = 出包前跑 `tools/check-diag-fields.py`**
- [2026-09-30] **图像增益的硬拐点 = 可见边界**：LSC 阻尼硬 knee 使增益斜率在跨阈值格点跳变（二阶差 0.1438 vs 本底 0.0898，位置 = 第 1 列 = W/17），插值后成马赫带；改用平滑正部 `(d+√(d²+w²))/2` 即回本底
- [2026-09-30] **定量口径五连坑**（用顺手的指标代替用户判据）：3×3 高通测不到 8–32px 色斑；低码率样片高频被抹平；跨图比梯度被 ±5px 错位污染；局部对比度只测 8px 单尺度漏掉 2–4px 细纹；**"相邻像素相同占比"在 PC 纯黑区高达 77%，该指标根本不成立**。规程：出包前先做同刻 100% 裁剪目视，指标只作辅证
- [2026-09-30] **暗光对齐四方向否证**（层预平滑 46%→56/65%、λ 位移罚项旋转 5%→39%、搜索半径 ±8 无改善且 p90 恶化、L4 步长 1 无变化）→ 暗光是**信息问题（SNR<1）**，不是参数问题；原版答案是"tile 随噪声放大"或合并侧鲁棒性
- [2026-09-30] **置信度判据（残差/纹理度）两代都无判别力**：1/4 域误杀 87% 好 tile、1/2 域对 38 个失败 tile 检出 0 个。**判据先在已知正/负样本上验证**，无判别力就别拿它做门控（本项目门控走 mismatch）

## 拍照线程、OOM 与调度（10-01）

- [2026-10-01] **Java OOM 会绕过 Java 崩溃捕获**：OOM 发生在 JNI `SetByteArrayRegion` 里 → pending exception 未清 → ART 直接 abort（`Fatal signal 6 in tid FilmStill`）；`crash-latest.txt` **不会更新**（那份还是 0.5.6-m2 的陈年记录），只有 logcat 的 `crash`/`events` buffer 与 tombstone 有现场。**"文件没更新"≠"没发生"**
- [2026-10-01] **direct buffer 计入 ART 的 OOM 额度**：OOM 报 `target footprint 248965720 (237MB) / growth limit 268435456 (256MB)`，而 Java 侧只有 direct buffer 在涨（8 帧 × 25MB + 成片 50MB）——`ByteBuffer.allocateDirect` 的外部内存照样吃上限
- [2026-10-01] **同一 context 内销毁重建 FrameRenderer 会让 Mali 分配失败**：表现为 `raw.upload_failed`；而且 `uploadRawTex` 的 `glGetError()` 抓到的是上一步 `ensureRawTex` 留下的错误，**报错位置会骗人**。修法 = 连 context 一起销毁（与首次启动同构）
- [2026-10-01] **Mali 不在 context 间轮转命令流**：DFT 分片开/关的 `dftGpu` 几乎相同（881/904 vs 855/922）、帧率也没动 —— `glFlush` 交出去的活照样排队；**真 sleep** 能让出但合成变慢、卡顿窗口拉长（用户体感"关掉开关反而更好"，数据证实 totalMs 5133 vs 2091、最低 fps 20 vs 27）
- [2026-10-01] **性能结论必须同条件对比**：`totalMs` 5133 vs 2091 里混了冷热机（首次合成 vs 热机），先把条件对齐才敢下"负优化"结论
- [2026-10-01] **方向错了要回退，不要在调度上反复试**：四轮实验证明无效后正确动作是删干净（引擎 diff 归零）+ 换定位手段（用现成开关做瓶颈定位），而不是继续微调参数

## UI 手势与 LUT 资产（10-01）
