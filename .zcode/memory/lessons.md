## 环境与构建（常青）
- [2026-09-23/30] **出包与日志三坑**：增量打包残留旧 so ⇒ 出包前 `rm -rf app/build/outputs/apk`；shell 管道吞退出码（**累计四犯**）⇒ 校验类命令必须 `RC=$?` 判真实退出码；Logger 缓冲在崩溃时吞关键记录 ⇒ 关键路径 `nativeFlushLogs()`，**"日志里没有"≠"没发生"**

- [2026-09-30] **Mali 拒绝混链 GLSL 版本**（vs 300 es + fs 310 es → 整链黑屏）；**glslang ES profile 的 image 格式只放行 r32f**

- [2026-09-29] **burst 必须锁所有帧的 AE**（只锁参考帧 ⇒ HAL 重收敛击穿对齐）

## 色彩、测量与链路域
- [2026-09-22] **色彩对比三条硬约束**：比 C\* 同亮度（跨链只用 rel）、按色相带拆开、先验证"中性进→中性出"；**色度增强三错**：只增强已浓的色、绝对线性判据混饱和与亮度、成片上二次套影调曲线
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**；成片反推对过曝区失效（只用 P50–P90）；**先看日志再动手**；离线复现的域差异会掩盖真相（趋势可信、绝对值不可照搬）
- [2026-09-24/28] **跨链对比三条**：分布级对比会被亮度映射污染（稳口径 = 同矩形区域 + 多尺度频段能量）；不同保真度的数据不能 A/B；比较前确认工作域

## 方法论与流程（跨窗口反复）
- [2026-09-28] **"先 100% 原版跑通，再评估删不删"**（AGENTS.md 铁律）：预删原生代码 = 销毁对照组；简化替用户做取舍同罪；**性能取舍必须给实测数据与选择权**
- [2026-09-29/30] **GPU 性能直觉不可靠**：共享内存流量才是 FFT 瓶颈；每相位 LUT 实测反而更慢——**瓶颈归因与改动收益都要变体实测；字段名会骗人（先拆时间戳）**
- [2026-09-29/10-05] **判据类改动真机频繁翻车 + A/B 口径三坑**：先穷举"该量在真机可能的取值范围"、优先修物理实锤的错位、**同刻连拍 + 同帧 A/B + 冷机取中位是唯一干净口径**
- [2026-09-30] **日志非法 JSON 静默吞行** ⇒ 分析前先 `check-log-json.py`；**"改错位置"三连全部静默失效** ⇒ 出包前跑 `check-diag-fields.py`
- [2026-09-30/10-05] **定量口径坑**：用顺手指标代替用户判据会连坑（3×3 高通测不到 8–32px 色斑）⇒ 同刻 100% 裁剪目视、指标只作辅证；**"完整实现"不等于"有效"**（AMaZE 六项指标五项为负）

## 判据域、归因与品红（10-03）
- [2026-10-03] **判据域错位三坑**：曝光判据读的是"最后渲染过的链"统计（预览 vs RAW 归一化域差 0.58EV）；为 0.1% 像素让全图欠曝；加 UI 项前先 grep 同类标题
- [2026-10-03/04] **测量的 ROI/对位错一步后面全白费**：ROI 混入无关区域、坐标尺度混用、定位错 700px 产生"全 0"假象、跨图对比先验证构图；**下结论前先把指标画成图看位置**
- [2026-10-03] **改一处必须沿数据流检查所有受影响点**（统计口径与判定口径是两件事）；**"物理极限"不能当结论交差**（先用数据验证覆盖量级）；**遇到标准做法问题先找一手实现对照**

- [2026-10-06] **离线/排查结论上真机前必须交叉验证三件事**：场景（痛点样片）、链覆盖度（离线是否含锐化）、输入通路（公式输入真机重算）；**A/B 样张必须逐帧以日志生效值清洗**（用户目视与定量可能来自不同变量）

- [2026-10-13] **删符号前 grep 全仓**（测试源集编译失败 ⇒ `compileDebugUnitTestKotlin` 通过是硬判据）；死白起点 = "曲线何时到顶"，不是白点的函数。

- [2026-10-13] **量化结论对判据口径高度敏感**（换口径就翻转排序）⇒ 任何"某架构更好"必须同时给出判据定义与对齐前提。
- [2026-10-13] **守卫之间有缝 + 文件头注释会撒谎**：补 `check-filmparams-contract.py` 四路对拍；**验证工具自身会假绿**（只锚整体摘要不够、逐段过滤致整份未校验）⇒ 判据与 mutation 自检必须同跑。

## 引擎插槽阶段 2/3（10-14）
- [2026-10-14] **⛔ 纯负向判据会集体放过"什么都没做"的实现**（`[28]=0` 空转而六条全绿）⇒ **新引擎必须配正向判据**；**双向复核不照单全收**（漏径 A 采纳、B 驳回）；**用户样片不能直接 A/B**（构图位移 ⇒ 逐像素差全是错位伪影）；**引擎归属只能读日志**。
- [2026-10-14] **"测试自证"也要防假绿**：变异检验（故意改坏 ⇒ 判据必须变红），没有变异检验的"全绿"不算证据。

## 编码器标定与交付链（10-15）
- [2026-10-15] **共享成员跨帧被覆盖是复发型 bug**（快门瞬间快照冻成局部 val）；**Kotlin 块注释可嵌套**；**`gradle ... | tail` 吞退出码**
- [2026-10-19] **uniform 默认值必须等于"跳过"**（`uContrastOut` 恒等写成 `!=1.0` 而默认 0 ⇒ 平坦灰）；**"恰好 N 项"是里程碑式断言**（补挂后改 N 并写依据）；`git stash` 回 baseline 是分清"预期红 vs 真红"的可靠手段。


## 自动曝光、编辑器与融合（10-22 → 10-24）
- [2026-10-22] **按起止锚点整段替换注释会连代码一起删**（只删注释行，改完单独 glslang 校验）；**全图分位 ≠ 同区域对比**（"暗部差 2EV"是假象，同区域只差 0.1~0.3EV）；**测试是设计意图的文档**；**"参数相同"≠"输出相同"**。
- [2026-10-23] **预览链与 HAL 的 AE 是两条独立回路**（在预览上做 EV 闭环必然互相激发）；节流+小步长=可见台阶、一次性大跳+固定目标=暗场景过曝；**测量滞后是振荡根因**。
- [2026-10-23] **EXIF 对拍比任何推断都快**；**别用单场景反推全局参数**；**改共享函数前先问"它的语义为谁而定"**。
- [2026-10-24] **"为 A 场景加规则"必然在 B 场景炸**；**融合端倍数与噪声同比例**；懒创建实例走进程快照、任何跨张状态都会让"预览≠成片"；**全屏覆盖阻塞构图**。
- [2026-10-24] **GL feedback loop**（融合 pass 输入不能与 fbo attachment 同纹理）；**自创判定在边界条件静默失效**（角色由采集端显式下发）；**σ 低估的方向是"帧回退"不是"噪点"**

## P4 基线与徕卡调研（10-25）
- [2026-10-25] **把工具当判据前实读其输入面**（`lut-audit.py` 只认 .cube 文本，资产已是 .lut 二进制 → 越界）；**配方资产的域语义不明就不烘**
- [2026-10-25→11-02] **单张样张的结论会片面**：白位 172 是场景特例（11 张统计后修正为"高光压缩狠、≥240 中位 0.1%"）；室内白墙 + 深色桌面天然低饱和，被读成"预设发灰"（叶实测 L\*24.4、白 L>95 占 0%）。**采纳前先量、先看多张**。版本/属性验证用 aapt（`strings classes.dex | grep -c` 两次静默无输出）。

## 徕卡一瞬标定（10-25/26）
- [2026-10-25] **recipe-fit 模式别跑错**：`--json` 只落原始记录、`--export` 才生成测试读的 `{generated_by, presets}`；拟合必须钉住定案（`--white-ev 4.0` / `--lut-min 1.0`）。
- [2026-10-25] **"双链撞墙"要拆链验证**：minimax 14.75 看似结构极限，单链即 0.51——先确认哪条链在拖。
- [2026-10-25] **样张后缀 = LUT 标题**（不是预设名）；**"同场景 A/B"必须用日志核对 apply 时序**（曾有三张"看似的对比"其实都在切标准之后）；**引擎归属只看 `engine.film_src`/`preview.filmic`**，`diag tone` 是 `[28]` 影调强度不能判引擎。
- [2026-10-25] **发黄归因不能拍脑袋**（"暖 LED"被当场纠正）⇒ 用中性区实测 + LUT 格点响应定性；**拟合目标本身可能错**（M9 样张提亮 ≠ 用户要的观感）。

## 灰斑/渗水排查（10-28/29）
- [2026-10-29] **灰斑排查与开关纪律**：跨 libraw 坐标映射必须用亮度剖面互相关验证（色比图对转置不敏感，给过 0.94 假相关）；"注释说逐行移植"≠实现是那个东西（Bento support 自上线起 no-op、color_smooth 实为判据式去饱和）；**实验性成像改动必须带开关再进包**（0.12.165 无条件接 D4 USM ⇒ "画面毁了"无法关）；**用户已否决的方向要记牢**：关降噪 / 换去马赛克 / 改 tone curve 三条反复被打转。

## 高光与掩码（10-29/30）
- [2026-10-29/30] **两个静默失败必须单独验**：①强制输出 1.0 也读回 0 ⇒ 分开"判据错"与"绘制坏"（R8 附件在 X300 上 FBO 完整但不落值）；②尺寸域错配会吞掉整个 pass（传 dst 尺寸给 raw 几何函数）。**诊断字段会撒谎**：变量全 1 只证明赋值，要判内容必须打命中数；全图统计不能代替局部判断。

## 诊断字段与外部对照（10-30）
- [2026-10-30] **`jnum` 第二参是字符数，不是小数位**：`jnum(x,0)` 永远返回 `"0"`（`satmHit=0` 因此骗了一轮）；判据是同一函数里另一个字段（`satmCov=4`）与它矛盾。**`raw.render` 的 `gm*` 恒 0 是设计**：`readGainmap` 在日志之后才跑，gainmap 真值看独立的 `gainmap.readback` 事件。
- [2026-10-30] **照注释推断外部实现会错**：先按注释把 gainmap 改成"只提亮高光"，读实现（`RawHdrReferenceMath.evaluate` 的 `if (x <= joinInput) return sampleCurve(...)`）才确认语义；而用户观感仍偏好整体提亮 ⇒ **观感以样片为准、语义以源码为准，两者可以不一致**。
- [2026-10-30] **`(void)mid;` 不是 GLSL**：Mali 宽容编译通过、glslang 报 `explicit typecast required extension`；改了 shader 常量（`constexpr` 也不存在，要写 `const`）必须重跑 `validate-shaders.sh`。

## 预设与样片标定（11-01）
- [2026-11-01] **"值没变就不写"的缓存 + 换数组 = 静默失效**：`setFilmParams` 换预设数组后，只有 5 个 applier 有哨兵，其余 21 个把基线值留在数组里（027 的 local_tone 0.25 / color_smooth 0 / sat 0.76）。新增 applier 必须同步置哨兵。
- [2026-11-01] **用带自定义参数的样片定目标会骗方向**（12 张里 5 张是作者 `+B5` ⇒ 把负片定成全图偏蓝）；**bug 现场的 DNG 不能做影调标定**（中性像素 L\* 7.5 vs 45.1）。
- [2026-11-01] **自烘 LUT 轴序是 `[b][g][r]`**（.cube 里 R 最快 ⇒ x 轴 = R）；按 `[r][g][b]` 采样会得到"红→蓝"的假象。
- [2026-11-01] **`fit/builtin-curves.json` 的 `editor` 是历史实测**：换 LUT/改配方后必须重算，否则曲线交叉校验必红。
- [2026-11-01] **改 assets 后单测要 `--rerun-tasks`**：否则 up-to-date 缓存报"1 秒成功"的假绿。

## 预设群与 LUT 归一（11-01→11-02）
- [2026-11-02] **"发灰"别急着提饱和**：`C\* p50` 被白墙/桌面主导，`sat` 对它们零作用（1.18 时 C\* p50 只从 3.2 变 3.1）；真凶是 LUT 抬黑。
- [2026-11-02] **判据基线必须是"改动前 vs 改动后"**（拿"输入灰阶 vs 输出"会把源 LUT 自身的中调提亮记成失败）；**白点判据要按 LUT 目标参数化**（电影负片高光本就暖白）。

- [2026-11-02] **我自己的两次错判**：①"DLT 降颗粒 ⇒ 不加颗粒"（DLT 是减少不是消除，500T 该加）；②"摄影师 LUT 归一后可直接当资产"（色偏是签名，白墙 a\* −4.1 发绿）。
- [2026-11-02] **归一工具的三处必需保护**：暗部端点 guard（否则纯黑被染成 (0,0,9)）、超域硬裁（缩 C 更难看）、.cube 的 reshape 顺序 `[b][g][r]`（R 最快）。

## 取景器对齐与蓝天（11-04）

- [2026-11-04] **拿阴天街景天空当蓝天目标，连错两轮**：阴天散射天空 h 258 / C\* 13.1，晴天深蓝天 h 270.9 / C\* 17.8。据此把 h 从 271 往青转到 251、C\* 压到 10.2 ⇒ 用户「天空看不到颜色」。定色彩目标前先确认样片的光照条件。
- [2026-11-04] **LUT 里做「只作用于某段亮度」的补偿必然造带**：钟形窗（clip 相乘或高斯）在连续渐变里留下一圈色相凹陷，视觉上就是天空一条「假云」。要压某段色相只能回 filmic 的场景线性域。
- [2026-11-04] **半成品链路能挂两周 + 标量顶替度量会留系统性误差**：0.12.51 建显示域统计、0.12.56 拆掉积分交给「Kotlin 外环」，外环从未实现 ⇒ `aeDispP50` 恒 0、取景器差 0.9 EV；`g_domain_ratio` 标量 clamp 上限 4.5 而真实有 6.71 的帧，PC 用同一把尺量两张图差值天然为零。
- [2026-11-04] **注释里的「等价写法」可能是错的**（`hdrLin−1/anchor` 与 `hdrLin*anchor−1` 差 anchor 倍）；**闭环增益不等于 1 时会过冲**（`ev_shift` 联动，实测 1.0~1.76；全量步进 `dispErr` 冲到 −0.9，0.7 阻尼+两轮后 0.02）。
- [2026-11-04] **诊断字段跟着开关走会撒谎**：`last_wmax_` 曾在关自动白点时写 0，日志看起来像统计失败（15:29:30 误判过一轮）。诊断量应无条件记录，开关只影响计算。

## LUT 影调与采集端判据（11-11）

- [2026-11-11] **归一 LUT 的代价是隐形的**：灰阶恒等看起来"分层干净"，实际削掉了原厂曲线，症状是"发灰 + 天空偏紫"（同场景 hue 276.2 vs 260.8）而不是"少一点味道" ⇒ 判据不能只看 L 是否恒等，要看整张观感。
- [2026-11-11] **预览统计不能当 RAW 高光判据**：预览经厂家 ISP tonemap，RAW 等效 P99.9（1.03）比成片（2.91）低 **1.88EV** ⇒ `hlEv` 太小、高光保护不触发；两条链的统计不通用。
- [2026-11-11] **filmic 白点 probe 闸与 gainmap 折点都会留可见边**：前者在 P99 撞 RAW 白点时把白点钉在 `w99+0.5`（低于场景最亮）⇒ 整片天空压进最后 15 级 8bit；后者 `max(0,·)` 一阶导突变 ⇒ boost 场沿等值线出硬边（实测 boost 1.26 vs 周围 1.00）。

## 天空白块与闭环（11-12）

- [2026-11-12] **用全局 EV 补"中灰差"必然推白高光**：真机 08:57 闭环一轮补满 0.60EV（读数 0.084 vs 预览 0.152），天空 8bit 230+/L* 90。成片与取景器的差是**曲线/域差**，不是曝光差；正解是当帧补 + 天空 P99 护栏（涨 >0.03 或 >0.88 撤销）。**vivo 预览被 ISP tonemap 4.59×**（`pvLastMid/stillMid`）：PC 的"YUV 即场景线性"假设在 X300 不成立；标量域比只影响预览、跨场景会失真（2.0→4.59），不能拿来校准成片。
- [2026-11-12] **诊断掩码会筛错域**：`skyOut` 在 sRGB 域用 `b>=r` 判天空，成片里常不成立，`n` 只有 D4/Fm 的一半 ⇒ 判断天空只用 `skyD4`/`skyFm`。另：contrast 对接近白点（s≈0.97）的天空几乎无效（1.23→0.9 只压 6 LSB），压它只能靠曲线形变/teq。

## 性能专项（11-12）

- [2026-11-12] **跨场景/跨热状态对比会造出假收益**：热降频（Thermal 2）被当成版本差异，同场景严格 A/B 后只剩几十毫秒；判据必须同场景 + 冷机（Thermal 0）+ 支架固定 + 每版 3 张。**`dirMs` 的 `d0` 打在 HR/P0 之前**曾把 RCD 误判成最大热点；"某 pass 很慢"先确认计时区间只包住它。源码注释矛盾以实测为准（DFT 现场编译实测 0.5~2.5ms）。
- [2026-11-12] **`preview_gap` 的 400ms 阈值会漏报体感卡顿**：用户说的卡顿是 200~260ms 的反复断续（快门后 4 次），日志一条都没有；且固定机位测不出（画面本来不动）——必须录屏（`tools/preview-stall.py`）才能量到"画面冻结"。
- [2026-11-12] **⛔ 绝不能用 `pm clear` 清数据**：为绕过 prefs 缓存清了 app 数据，把用户的 M 档/RAW/预设/导入 LUT 全清掉（用户严厉批评）。release 包不能 run-as 时应让用户点开关，或加文件哨兵（`files/xxx`），不能动用户数据。

## 预览体感与动画（11-13）

- [2026-11-13] **⛔ 安装必须用 `dumpsys package` 验版本**：0.13.40 的 install 被后续 `echo ok` 掩盖，设备实际仍是 0.13.38，排查"动画没生效"白绕一圈。凡"装完测效果"先读 versionCode。
- [2026-11-13] **暂停预览必须继续消费 buffer**：SurfaceTexture 队列满会堵死 HAL producer，恢复后预览永不回来（`preview_gap` 6654ms）；`resumePreview` 先 `updateTexImage` 清 ≤4 帧。
- [2026-11-13] **`boxW` 首帧为 1px**：用它算飞入图尺寸会退化成 1dp + 20dp 阴影 ⇒ 屏幕上只剩"一圈阴影"。尺寸用稳定值（屏幕宽比例）。
- [2026-11-13] **飞入图与背景同内容时必须有边界**（白边/微阴影）；大图 + 大阴影反而像 bug；动画状态必须在 draw 阶段读，组合里读会每帧重组整个相机页。

## HDR 与高光判据（11-13）

- [2026-11-13] **`pw999/sw999` 是 log2 值（EV），可为负**：用 `>0` 判有效性会把"高光低于中灰"当"没统计"⇒ 一张压 3.3EV、一张不压 = **隔张紫**（13:57:01 `hlEv=-99` / 13:57:27 `hlEv=4.948`）。0.0 才是"没写过"的哨兵。
- [2026-11-13] **单锚点线性换算近似不了 filmic 的 S 曲线**：固定 anchor 2.56 和"本张 stillMid/aeP50=0.42"都让全图 ratio 顶满 4x（中灰对齐了暗部就崩）。HDR 参考必须是同曲线、更宽白点渲出的第二张图。
- [2026-11-13] **预览统计不能代表 RAW 高光**：`p999pv 0.68 / dom 2.0` ⇒ 0.89EV，而离线复算融合后灯面 3.04EV，低报 2.15EV；`dom` 是中位比，ISP tonemap 高光段压 7~14×。
- [2026-11-13] **gainmap 输入必须与 SDR 同 exposure**：SDR 已乘 `uExposure`，参考帧是曝光前场景值，漏乘 ⇒ EV 一大整张退化成 1.0（伴随发紫）。
