## 环境与构建（常青）

- [2026-09-18] **中文路径 AGP externalNativeBuild 报 CXX1400** ⇒ 自定义 CMake Exec 直驱 NDK；构建 `JAVA_HOME=/opt/homebrew/opt/openjdk@23 ./gradlew assembleDebug testDebugUnitTest`（系统默认 Java 8 跑不动 AGP 8.13）
- [2026-09-20] **shader 改动构建全绿仍可能设备端全黑**（设备运行时编译）——铁律：必须过 `tools/validate-shaders.sh` 且真机验证后才发版
- [2026-09-22] **C++ 原始字符串 `R"(...)"` 里出现 `)"` 会提前终止字面量**（GLSL 注释里「0.25(=64/255)」即触发）；Kotlin 块注释支持嵌套，KDoc 里写 `/*`（如 `assets/luts/*.cube`）会吞掉整个文件、报错指向文件末尾
- [2026-09-23/27] **出包与校验两坑**：增量打包残留旧 so（APK 33.7MB vs 28.2MB、zip 条目空洞）⇒ 出包前 `rm -rf app/build/outputs/apk`；shell 管道吞退出码 ⇒ 校验类命令必须 `RC=$?` 判真实退出码（**累计四犯**，`cmd | tail` 后看的是 tail 的退出码）
- [2026-09-30] **Logger fwrite 缓冲崩溃时吞关键记录**（0.10.83 日志只剩 77 行）→ 关键路径主动 `nativeFlushLogs()`；**"日志里没有"≠"没发生"**
- [2026-10-02] **native 改动必须核对进包**：比对 APK 内 `libfilmengine.so` 的 md5 + 构建日志有无重编 `FrameRenderer.cpp.o`；macOS **没有 `timeout` 命令**（两犯）

## GL / Mali 驱动（X300 实测）

- [2026-09-18] **Mali 与照片各三坑**：Mali —— RG8 TexSubImage2D 静默全黑 ⇒ 预览走 SurfaceTexture；RGBA8 FBO 误用 GL_HALF_FLOAT；image uniform 无默认精度 ⇒ 显式 highp。照片 —— Y 未归一化；Y 平面行序与 GL 纹理相反；STMatrix 含裁剪翻转再叠 center-crop = 双重裁剪
- [2026-09-22] **sampler 必须始终有合法绑定**（全黑根因）：关闭态提前 return 不绑纹理 → Mali 预测执行分支里的 texelFetch → pass3_out glErr=1282 整帧丢弃。修法：init 建 1×1 恒等纹理、**无论开关都绑定并下发全部 uniform**（sampler3D 未绑定同理，v0.6.0 全黑）
- [2026-09-27] **GLSL ES 编译期黑屏级坑（glslang 可拦）**：不支持数组初始化器 `ivec2 a[4]={...}`；sampler 类型函数参数必须显式精度（已踩两次）；**`half` 是保留字不能做变量名**
- [2026-09-28] **浮点 attachment 的 readback 组合陷阱**：R16F + GL_UNSIGNED_BYTE 在 ES 3.0 不保证、X300 静默回零；**R16F fbo + GL_RGBA + GL_FLOAT 同样静默回零**；RGBA16F + GL_FLOAT 实测可用。成片黑要用 avgLuma/rms 作硬证据
- [2026-09-30] **imageStore 目标纹理一律 `glTexStorage2D`**（glTexImage2D 可变纹理写入全丢）；r16f/rgba16f image 禁止 load+store 混用；image2DArray 同样"计算照跑写入全丢"——**表象相同根因可不同，别在单一路线重复押注**
- [2026-09-30] **Mali 拒绝混链 GLSL 版本**（vs 300 es + fs 310 es → "Shader languages do not match" → init 失败整链黑屏）；**glslang ES profile 的 image 格式只放行 r32f**（compute 校验用 430 core 转换，有 ESSL 严格性盲区）
- [2026-09-30] **批量脚本编辑中途 assert 失败 = 部分修改未写盘**（0.10.41 坏提交：shader 旧声明 + host 新绑定）；`str.replace` 不带 count 会误伤同型代码——多点修改后必须 grep 核对

## Camera2 / HAL（X300）

- [2026-09-18/19] **X300 HAL 三事实**：手动 WB 的 CCT/GAINS/矩阵三路径全不可用（解法=引擎侧补偿）；隐藏物理镜头持续黑帧（设置页按镜头启停）；手动对焦 HAL 报屈光度 0 但硬件支持（默认 10D 试值）
- [2026-09-18] **键名/类型凭记忆必错，javap 核 SDK**：API36 移除 COLOR_CORRECTION_RB_GAINS；正确键是 `STATISTICS_LENS_SHADING_CORRECTION_MAP`（Android 没有 `STATISTICS_LENS_SHADING_MAP`）；`SENSOR_NOISE_PROFILE` 是 `Pair<Double,Double[]>[]` 但 **X300 真机 second 是标量 Double**（`as? List<Any?>`/`as? DoubleArray` 永败，σ 自适应自 v0.5.32 潜伏至 C 专项）
- [2026-09-18] **session/生命周期三坑**：切镜头置 started=false 后 onConfigured 守卫放弃建 session；异步清理 runnable 读到新实例；触屏对焦 ACTION_UP 不消费事件流永不送达
- [2026-09-18/19] **几何/方向三坑**：AF/AE 区域落点差 90°；预览 center-crop sx/sy 是四象限映射（4:3 时掩盖 bug）；变焦倍率分母用物理焦距错
- [2026-09-20] **统计口径与判据**：阈值必须滞回；`controls.applied` 的 iso/sec 是滑杆存量值（**日志字段语义必须回代码核实**）；EXIF/DNG 三坑（Bitmap.compress 不写 EXIF、setOrientation 只收 1..8、OpcodeList2 大端）
- [2026-09-27] **ImageReader maxImages 提高且全程持有 Image 的 HAL buffer 压力**：maxImages=5+4 张 25MB 全程持有 → HAL 预配 125MB → 闪退（进程存活、Activity 反复销毁、capture() 从未执行）；修复=拷贝即 close，仅参考帧持 Image
- [2026-09-29] **burst 必须锁所有帧的 AE**：只锁参考帧不够——alt 帧走 AE AUTO 时 HAL 在拍摄瞬间重收敛（70MM 实测 ISO +10%）→ 曝光量不守恒击穿对齐（confMed=0、位移场全零）
- [2026-10-05] **rawpy 报告的 `black_level_per_channel` 是取整值**：曾据此误判"R 相位黑电平 63 导致暗部偏红"，DNG 真值是 `[63.99,64.01,64.01,64.01]`（相位极差 ≤0.03 ADU）⇒ 假设被推翻；**离线工具的输出要当"近似"审**

## UI / Compose

- [2026-09-18/22] **UI 要点**：跨会话状态必须 prefs（rememberSaveable 随子页销毁丢失）；setter 改字段后要调 rebuildRepeating；`LaunchedEffect(surface)` 对象相等性 key 在 OriginOS 恢复不换实例；stop 期间 post 失败要回滚 pending；预览框 `weight(1f)` 弹性占满是"快门调不上移"根因（用 `weight(1f, fill=false)`）；预览图分辨率必须 ≥ 显示像素且缓存名带尺寸
- [2026-10-01] **M3 Slider 按下即 snap 到手指位置**：拇指微调必误跳（"数值固定跳 N"类报障先上回调日志再修，纯猜修了三轮没中）；正解 = 手写 `awaitPointerEvent` 相对拖动滑杆（foundation `drag()` 真机不产生拖动回调）
- [2026-10-04] **adaptive 图标前景用 bitmap 会被桌面非等比渲染**（前景占比 88%/72%/61% 三版全部"又小又扁"复现）、纯 legacy 被垫白色圆托，**vector 前景正常**——PC 同构完整套（vector fg + color bg + monochrome + legacy 全密度并存）缺一即出渲染异常；**黑盒机制不确定时，解包成熟 App 的资源结构照抄**优于反复试错
- [2026-10-04] M3 ModalBottomSheet 真机返回需两次 → 自绘抽屉（拦截层 + BackHandler + FilmMotion）；删除设置项必须同步锁死读取端（prefs 历史残留 true）

## 色彩、测量与链路域

- [2026-09-21] **libraw 参照默认 auto_bright=on**（亮度拉高 ~2.5×）——"寡淡/饱和 −21%"是亮度差被当色彩差；测色度首选 CIELAB C\*；**"文件里没有"≠"API 拿不到"**（DNG 无 ForwardMatrix 只是 DngCreator 不写）
- [2026-09-22] **色彩对比三条硬约束**：比 C\* 同亮度（跨链比饱和度只用 rel）、比色相按色相带拆开；手搓矩阵链先验证"中性进→中性出"；先排除三混淆项。**色度增强三错**：只增强已浓的色 = 倒置；绝对线性判据混淆饱和与亮度；成片上二次套影调曲线是错的（已过 OETF）
- [2026-09-24/28] **反推/重放框架必须自带"原参数重放能还原成片"的自检**；成片反推对过曝区失效（只用 P50–P90）；**先看日志再动手**；离线复现的域差异会掩盖真相（趋势可信、绝对值不可照搬）
- [2026-09-24/28] **跨链对比三条**：① 分布级对比会被亮度映射污染（稳口径 = 同矩形区域 + 多尺度频段能量）；② **不同保真度的数据不能 A/B**；③ **工作域不是色度差主因**，大色块核心区判据可把"降噪抹色度"与"矩阵偏淡"分开
- [2026-10-05] **旧诊断照片是二次传输重编码的副本**（1777×2360 ≠ 原生 3072×4080、DQT 非标准表）⇒ **用户截图不能作证据，必须取相册原图**

- [2026-09-27/29] **C++ uniform 接好 ≠ 链路通**（FilmParams[0] 无人赋值静默无效）；**三渲染链只接两条 = 静默漏第三条**（手动 WB 漏 RAW 静拍链）——跨语言/多链参数必须端到端逐一验证
- [2026-09-27/29] **曝光意图必须放统计之后**；**"恒等的旧层"在域外是失真源**（应删链而非保留）；**成员变量跨 engine 会话丢失** ⇒ 跨会话状态进程级 static 或外部持久化；**统计域与渲染域错位是高光"整张白"总根因**——任何"统计→判据→曲线"链路必须核对三者同域
- [2026-10-05] **死参数是"改一处即全改"的结构性根因**：`uStat` 在原实现里全文件 0 命中（`texelFetch(uStat` 无匹配），统计/mask/apply 共用 `uMos` ⇒ 历史 exp21"换统计源却顺手改了 apply 判定"由此而来。**换输入前先 grep 该参数是否真被消费**

## 降噪 / MFNR

- [2026-09-27] **MFNR 三个反直觉**：融合=等权均值（自加"残差置信度"加权因暗部噪声主导而系统性不可信）；**σ 融合后必须 ÷√N**；**参考实现的"DFT"措辞要核实**（hdr-plus 的 DFT 实为 2× 下采样 L1 反比加权）
- [2026-09-30] **加权平均的 N_eff 模型不能只算噪声项**：P0 空间权重放宽后理论 N_eff 升、实测降噪反降（2.38×→1.68×）——外围样本带进的是**系统偏差**（对齐仅 128px tile）；**先修对齐精度再谈权重**。**诊断量必须去信号**（tile RMS 信号主导；用同相位 lag-2 差分 std/√2）
- [2026-09-30] **"对齐更准"必须与"采样精度"一起看**：整数采样（round 到偶数）会把 0.27px 与 4px 的差别整个抹平（只换层 +2.5%、加亚像素才 +45%）；**离线评估要有已知真值**（合成金字塔 + FFT 相移），否则中位残差被噪声底主导
- [2026-09-30] **置信度判据（残差/纹理度）两代都无判别力**（1/4 域误杀 87% 好 tile、1/2 域对 38 个失败 tile 检出 0）；**暗光对齐四方向否证**（层预平滑/λ 罚项/搜索半径/L4 步长全部无效或更差）⇒ 暗光是**信息问题（SNR<1）**，不是参数问题
- [2026-10-05] **`hr_wavelet` 与 RAW 域高光重建职责重叠**：小波高光重建在 RAW HR 落地后成为冗余层（默认关、省 ≈752MB 纹理 + ≈103 pass/张）；移除 `w=(w>0.9)?w*w:0` 去掉 +29% 梯度来源

## 方法论与流程（跨窗口反复）

- [2026-09-28] **"先 100% 原版跑通，再评估删不删"（用户批评后写入 AGENTS.md 铁律）**：预删原生代码 = 主动销毁实验对照组；**简化方案替用户做取舍同罪**——以"GPU 成本不现实"否掉 DFT 路线从未实测，性能取舍必须给用户真实数据与选择权
- [2026-09-29/30] **GPU 性能直觉不可靠**：共享内存流量才是 FFT 瓶颈（twiddle 查表仅 +1%）；每相位 LUT + 写回并行实测反而更慢——**瓶颈归因与改动收益都必须变体对照实测，别按 CPU 直觉推断；字段名会骗人（`uploadMs` 91% 是 CPU 对齐），先拆时间戳再判断**
- [2026-09-29] **判据类改动真机频繁翻车（179→182 五版）**：**改动前先穷举"该量在真机上可能的取值范围"**（用已录日志反查）；**优先修有物理实锤的错位（域/边界），不调判据参数**
- [2026-09-29/30] **A/B 口径三坑：跨时刻、跨拍摄、跨热状态都会骗人**——日落光照被当成算法差异、连拍 3 张 ISO 从 2368 跳到 10160、冷机 500ms 热机 830ms；**同刻连拍 + 同帧 A/B + 冷机取中位是唯一干净口径**
- [2026-09-30] **日志非法 JSON 静默吞行**（`substr(0,5)` 截出 `"1139."`，4 张里 3 条 raw.render 消失）→ 分析前先跑 `tools/check-log-json.py`；**"改错位置"三连全部静默失效**（加门控忘改 uniform、按错名替换致 link 未落、诊断字段写进前置串）→ **规避 = 出包前跑 `tools/check-diag-fields.py`**
- [2026-09-30] **定量口径五连坑**（用顺手的指标代替用户判据）：3×3 高通测不到 8–32px 色斑；跨图比梯度被错位污染；**"相邻像素相同占比"在纯黑区 77% 根本不成立**。规程：出包前同刻 100% 裁剪目视，指标只作辅证
- [2026-10-05] **离线验证漏判据导致真机翻车**：0.173 只测"紫边下降 + 平坦区色度"，**没测"色渗/大色块"** ⇒ 真机"一片红一片黄一片紫"；此后新增四条色渗判据（块状色相偏移、平坦区色度-亮度相关、大色块方差、门控覆盖率）。**离线的判据集合必须覆盖该改动的所有可感维度**
- [2026-10-05] **"完整实现"不等于"有效"**：AMaZE 按原版完整实现（CPU 多线程 247ms@12MP、设置三档可选），离线六项指标**五项为负** ⇒ 实现完整性只是前置条件，收益必须靠在目标域上的判据说话

## 拍照线程、OOM 与对比口径（10-01/02）

- [2026-10-01] **Java OOM 绕过崩溃捕获**：JNI `SetByteArrayRegion` 里 pending exception 未清 → ART abort；`crash-latest.txt` 不会更新（只有 logcat/tombstone 有现场）；direct buffer 计入 OOM 额度（8×25MB + 成片 50MB 撞 256MB）
- [2026-10-01] **同 context 销毁重建 FrameRenderer ⇒ Mali 分配失败**（`raw.upload_failed`）；`glGetError()` 抓到的是上一步残留错误，**报错位置会骗人**。修法 = 连 context 一起销毁
- [2026-10-01] **Mali 不在 context 间轮转命令流**（DFT 分片/glFlush/sleep/线程降优先级实测全部无效）——**方向错了要回退，不要在调度上反复试**；**暗光空闲 fps 17–21 是曝光时间封顶**（帧率对比必须看场景亮度）；**prefs"变化才写"守卫会吃默认值**

- [2026-10-02] **NN 判死（跨域 + 数据量）**：口径三处误读（常数当公式 / bayer pattern 决定通道语义 / anchor 必须用训练口径）已修但观感零改善；微调训练 loss 全降而留出集全升 ⇒ **只看训练 loss 会误判成功**。**多帧平均做训练目标 = "更干净"与"更平滑"不可分**（三次监督微调 ret4 全降、目视更软）
- [2026-10-02] **测量与判据坑合集**：AF 锁前景致 ROI 失焦（判据 = 信号崩半而 σ 正常 + 梯度中位崩）；art4 >1 只说明降噪不足；ret4 中心在 mosaic ≈36px；去直流指标测不出全局亮度偏移（曾压暗 44% 仍"达标"）；grep 的排除模式会骗人（`grep -v NoiseCalib.kt` 让人误判 `builtInFor` 未调用）
- [2026-10-02] **静默 `return` 是诊断黑洞**（`if (capturing) return` 让"连按两下只有一张"零日志）；**改 GLSL 必跑 `tools/validate-shaders.sh`**（曾抓到 P0FusedTs 的 `ref`/`c0` 笔误，否则设备端黑屏）

## 判据域、归因与品红（10-03）

- [2026-10-03] **判据域错位是连续两轮定位失败的根源**：曝光判据读的是"最后渲染过的那条链"的统计，拍照前基本是**预览链**（OES / ISP 已 tonemap），与 RAW 归一化域差 0.58EV 且逐次不同 ⇒ 判据既不准也不稳
- [2026-10-03] **代价与设置项两坑**：为 0.1% 的像素（且是"爆了也不可惜"的窗/灯）让全图欠曝 ⇒ 噪声整体抬升，**保护少数像素前先算它占多少**；4 个白点旋钮互相干扰最终"修一个坏一个"，**根因不是旋钮不够而是分工错了**（影调该固定、曝光该自适应）——**加 UI 项前先 grep 同类标题**
- [2026-10-03] **改动生效 ≠ 问题解决**（exp9 白点改动生效但白斑没退 = 假设错）；**排除法要排除干净再下结论**（白斑误判"尖峰/缺 DPC"实为饱和像素被全局 σ 误判）；**用户三次方向纠正都是对的**，我三次先按自己假设做包才回头验证
- [2026-10-03] **`jnum(v, n)` 的 n 是字符数不是小数位**（`jnum(40077,1)` 被截成 `"4"`，据此误判"highlights 没生效、样本只有 4 个"）；整数字段一律 `std::to_string`
