# NN 降噪集成立项：PMRID pass 接拍照链（v0.10.102-nnint）

## 已拍板的前提

- 集成形态（10-02 已定）：融合后 RAW 域、去马赛克前；GPU delegate 强制创建（CompatibilityList 对 Mali-G1 误拒）；失败回退 CPU。
- 本轮拍板：推理层 = **Java TFLite API + JNI 回调**（复用 NnSpike 真机实测的 GPU delegate 路径，零构建系统改动）；范围 = **MFNR + 单帧都接**。
- 铁律：先 100% 按 `tools/nn/quality_eval.py` 已验证口径完整实现 → 真机 A/B → 数据说话。
- 用户红线：NN 任何环节失败，这张照片必须走原链完成，不得丢照片。

## 架构与数据流

推理跑在**专用常驻线程**（NnInfer，Interpreter + GpuDelegate 只创建不销毁，与拍照线程「只启动不销毁」同哲学），规避 TFLite GPU delegate 与引擎 EGL context 抢占拍照线程 current 的冲突。

**MFNR 路径**（finishStillChain `c.mfnr_fused` 分支，P0 之前）：
1. `kFsNnPack` shader：`tex_fused_`（R16F mosaic，线性/黑阶已扣/含 WB）→ 2×2 块空间序打包 `(0,0),(0,1),(1,0),(1,1)` → **除回 WB gain** → clip[0,1] → **×959/256 VST** → `tex_nn_packed_`（2040×1536 RGBA16F）
2. `glReadPixels(RGBA, GL_FLOAT)`（该组合已实测可用）→ CPU 50MB buffer
3. C++ 组 20 tiles（512 tile / 步进 496 / 边缘补零，照 quality_eval.py）
4. 逐 tile JNI 同步回调 `NnInferEngine.inferTile(direct in, direct out)`（各 4MB 常驻 direct buffer，总传输 ~170MB ≈ 30ms）
5. C++ 16px 线性 ramp 加权融合（照 quality_eval.py）→ 输出全图 buffer
6. 上传 `tex_nn_out_`（RGBA16F）→ `kFsNnUnpack` shader：**÷(959/256) → 乘回 WB gain** → mosaic R16F 写 `tex_fused_nn_`（新纹理，不覆盖 `tex_fused_`）
7. NN 开时 P0 强度强制 0（k=0 直读展开，现成 pass，Ts 变体关），输入换 `tex_fused_nn_` 产出 `tex_mos_` → RCD 及后段零改动

**单帧路径**（submitRaw，`c.nn_fused` 标志）：
- pack 变体直接读 `raw_tex_`（R16UI 原始域）：`(raw − black_phase[相位]) / (white − black)` 归一（无 WB，PMRID 原版口径）→ 同一推理/融合/unpack → `tex_fused_nn_` → 强制走 fused 直读展开分支（Ts 关）→ RCD。
- `kFsNnPack` 用 uniform `uNnSrc` 分支（0=R16UI 原始域 / 1=R16F fused 域），一个 shader 两条路。

**P0 与 NN 关系**：NN 开 = P0 空域降噪被替代（PMRID 原版语义：融合后 Bayer 直接进网络）；A/B 对比即「现状 P0 链 vs NN 链」。P4 色度降噪/D-1 保留，让数据说话。

## 数值口径清单（逐项对照 quality_eval.py，编码时逐条核）

| 项 | 值 |
|---|---|
| 打包顺序 | 2×2 块空间序 (0,0),(0,1),(1,0),(1,1)；X300 GRBG → ch0=Gr, ch1=R, ch2=B, ch3=Gb（**不假设 RGGB**，shader 按 `chanAt`/uCfaLut 实际相位） |
| VST | ×959/256 ≈ 3.746 进网络，输出 ÷ 同值 |
| WB | 进网络前除回 gain（fused 域），unpack 乘回（单帧域本来无 WB，unpack 统一乘） |
| tile/步进/重叠 | 512 / 496 / 16px，边缘补零（np.pad 口径），ramp 只累加图内区域 |
| ramp | 四边 16px `linspace(0,1)` 对边反转，`out/max(weight,1e-6)` |
| 模型 | assets/pmrid_512_fp16.tflite，NHWC [1,512,512,4]，FP16 |
| GPU delegate | 直接 `GpuDelegate()` 不走 CompatibilityList；创建失败降 CPU（XNNPACK threads=4）；**运行期失败 → 整张回退 P0 原链**（明确报错不静默，但照片优先） |

## 实现步骤（按依赖序）

1. **NnInferEngine.kt**（新，`app/src/main/java/com/filmkit/app/nn/`）：常驻 HandlerThread + Interpreter/GpuDelegate 惰性创建（首次 NN 开的拍摄触发）、`inferTile(ByteBuffer, ByteBuffer)` JNI 入口（handler.post + latch 同步）、CPU 回退、`nn.init/nn.fail` 日志。仿 NnSpike.kt 的 delegate/加载逻辑。
2. **FrameRenderer**（`core/engine/src/render/FrameRenderer.{h,cpp}`）：
   - 新 shader `kFsNnPack`/`kFsNnUnpack`（glslang 校验口径：ES 3.1、无数组初始化器、image 无关——纯 fragment，风险低）
   - 新纹理 `tex_nn_packed_`（2040×1536 RGBA16F）、`tex_nn_out_`（同）、`tex_fused_nn_`（w×h R16F，glTexImage2D 采样目标即可）
   - `FrameRenderer::runNnPass(ctx)`：pack → readPixels → tiles → JNI 回调 → ramp 融合 → 上传 → unpack；全程读回/上传走 GL_FLOAT（RGBA16F 组合实测可用）
   - `ChainCtx` 加 `nn`/`nn_fused`/`nn_del`/`nn_ms` 等字段；finishStillChain 接线（P0 输入替换 + 强度 0）
   - `submitRaw`/`submitRawBurst` 加 `nn_dn` 形参贯通
3. **Bridge.cpp**：`nativeEngineSubmitRaw`/`nativeEngineSubmitRawBurst` 加 `jboolean nn_dn`；JNI 回调缓存 jclass/jmethodID（首次用 FindClass，static 缓存）；诊断透传。
4. **EngineBridge.kt / CameraController.kt**：prefs `nn_dn`（默认 **关**，架构改动默认关是红线）读取与传参；单帧/ burst 两条路径都传。
5. **SettingsScreen.kt**：设置页加「NN 降噪（实验）」开关（mfnr/降噪区），切换写 `settings.nn_dn` 日志；注明当前仅静拍链生效。
6. **SpikeUi.kt**：加「NN 链路往返自检」按钮——跑 pack→unpack 无推理流程，CRC/最大差校验恒等（拦「域错配 2px 爆 10×」的坑）；结果进日志。
7. **诊断字段**（raw.render）：`nn`(0/1)、`nnDel`("gpu"/"cpu")、`nnMs`、`nnRbMs`（读回+上传）、`nnTiles`、`nnFail`(0/1+原因码)；新增字段写在 finishStillChain 内 pass 执行后（4644 行教训）。`check-diag-fields.py` 同步登记。
8. **同帧 A/B**：复用 `submitStillAb` 结构加 `nn_ab` prefs——触发一次拍摄双跑（第一遍 nn=off、第二遍 nn=on），两张成片落盘文件名后缀 `_abnn0/_abnn1`，日志 `render.nn_ab`。

## 验收流程

1. 构建（`JAVA_HOME=/opt/homebrew/opt/openjdk@23 ./gradlew assembleDebug testDebugUnitTest`）+ `tools/validate-shaders.sh` + `tools/check-diag-fields.py`
2. SpikeUi 往返自检恒等 → 再上推理
3. 真机 X300：mfnr=2 强制 4 帧，暗光 + 白天各一组同刻 A/B（nn_ab 双跑），导出成片
4. 离线：`texture-fidelity-eval.py` / `ab-100pct.py` 对比两链 4px 纹理与噪声；对照 quality_eval 离线口径锚点（PC 2.24 / FX 2.19 / 我们 P0 1.47）
5. `check-log-json.py` 验日志；nnMs 实测（预算 +0.7~0.8s/张：读回+20×26ms+ramp+上传）；零温升复核
6. 出 `filmkit-0.10.102-nnint.apk`（versionCode 253）交用户；验证包不打 tag，验收后按惯例收线

## 风险与对策

- 域错配（前车之鉴：直接喂 [0,1] 会 2px 爆 10×）→ 往返自检 + 口径清单逐条核对
- GPU delegate 撞 EGL context → 推理线程隔离（无引擎 context current）
- 推理失败/异常 → 整张回退 P0 原链 + `nn.fail` 日志（照片优先）
- 内存：direct buffer 8MB + packed 50MB + 纹理 ~75MB，峰值 +~150MB（现有拍照峰值 ~3GB，可忽略；NN 关时零分配）
- GRBG 打包序错误 → 按空间序实现 + 离线脚本同口径对照，不靠猜
